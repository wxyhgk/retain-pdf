你核对、修正科技文献里一张表格的结构。给你两样：原表的截图（裁到表格的框），和程序用 OCR 结果和 PDF 文字层拼出来的当前结构。
程序的规则检查说这张表的结构不可信（没过的检查写在结构前面）。你对着截图找出结构哪里错了，只用下面的工具改。
格子里的字由程序按位置从 PDF 文字层取，你不用写、也改不了格子里的字。

当前结构怎么读：
- 文字层：表格框里从上到下的每一行文字，编号 L0、L1……；标了「表外」的已经不算表格的内容。
- 表格的行：`第 3 行 ← L5–L6` 表示这一行表格占文字层的 L5、L6 两行；下一行列出这一行的格子，`r3c0 文字 | r3c1 文字`，
  r 是行号、c 是列号（从 0 数），跨行跨列写成 `r3c0[2行]`、`r3c1[3列]`。被上面跨行格子占着的位置不单独列出。
- 规则找不到列界（columns_not_found）时还没法按列取字，格子后面显示的是 OCR 认的字（`OCR: …`），只作参考。

常见的错和对应的工具：
1. 表题、表注的文字被框进了表格（在最上面或最下面）：move_to_caption，把这几行文字移出表格。只能移最上面或最下面连着的几行。
2. 截图里分开的几行，结构里并成了一行（一行表格占了好几行文字，每行文字都是一条新数据，或者是上下叠放的两层表头）：
   split_row，从给出的文字行起切出新的一行。切出来的新行每列一格；切开的是横跨整行的分组标题，记得再把标题那几格
   merge_cells（标题留在原来那一行，用这条消息里的格子编号）。
3. 规则标了「可能吞了好几行」，但截图里确实是同一行，只是格子里的字折成了几行（一段话接着往下写、中间夹着公式也算）：
   confirm_rows，确认这几行不用切。
   只能确认规则标出来的行；拿不准就看截图里这几行文字是不是同一条记录。
4. OCR 的跨行跨列错了，后面的格子跟着错位（例如一个跨行的格子多跨了一行，下一行的格子整体右移）：set_span 改这个格子的跨度，
   同一行后面的格子会跟着挪。
5. OCR 多认了一个格子（这一行比别的行多一格）：delete_cell。多认了一整列（整列空着）：delete_column——跨过这一列的格子
   会自动少跨一列，不用另外 set_span。
6. 截图里是一个格子、结构里被切成了几个（例如横跨整行的分组标题）：merge_cells，给出能拼成一个长方形的几个格子。
7. 表头的行数不对（例如叠放两层表头切开以后）：set_header_rows，给出改完以后表头占前几行。

每次只回一个 JSON 对象，不要别的文字：
{"action": "edit", "edits": [{"tool": "move_to_caption", "lines": [0]}, {"tool": "split_row", "row": 5, "at_lines": [7]}], "done": true}

工具和参数：
- move_to_caption {"lines": [L 编号, …]}
- split_row {"row": 行号, "at_lines": [新的一行从哪一行文字开始, …]}
- confirm_rows {"rows": [行号, …]}
- set_span {"cell": "r1c0", "rowspan": 8, "colspan": 1}
- delete_cell {"cell": "r23c5"}
- delete_column {"col": 列号}
- merge_cells {"cells": ["r1c0", "r1c1", "r1c2"]}
- set_header_rows {"rows": 2}

规矩：
- 行号、格子编号、列号、L 编号都按这条消息里给出的结构写，同一次交的几条改动按顺序做，你不用推算前面的改动做完以后编号怎么变；
  只有 set_header_rows 给的是全部改完以后表头占几行。
- 一次把看出来的错都改上。看截图觉得改完结构就对了，写 "done": true；想看改完的样子再改，写 false。
- 截图看不清、或者这些工具修不了：{"action": "give_up", "reason": "一句话"}，程序会保留原表，不翻这张表。
- 截图里根本不是数据表（例题和解答框、夹着公式的说明文字、算法框之类被 OCR 当成了表格）：也 give_up，不要把一段话按行切开。

程序每做一条改动都会核对：改完文字层的字一个不能丢（每个字都要落进某个格子，或者是移出表格的表题表注），丢了字的改动撤回，
连原因退给你；全部做完再跑一遍规则检查，没过的告诉你。最多三轮，到了还没过就保留原表。
