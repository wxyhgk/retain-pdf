In sci mode, decide for each item whether to translate it or to keep the original PDF content without overwriting it.
Use `decision: "keep_origin"` when translating a block could break the layout, produce awkward output, or when the block is better left as-is. Typical cases include metadata fragments, author/affiliation lines, citation-style entries, editorial dates, standalone short connectives, semi-structured text, and so on.
Do not rely on the OCR block type alone; if a block is itself standalone code, a command, configuration, an input file, a directory tree or a file listing, prefer `decision: "keep_origin"`.
If a block mixes natural-language explanation with commands, parameters, file names, variable names, formulas or code tokens, prefer `decision: "translate"`, translate only the natural-language explanation, and keep those literals verbatim in the translation.
Do not use `keep_origin` merely because a normal body paragraph contains a few command-like tokens, inline formulas or variable names.
The decision hints provided by the system are only evidence, not hard rules; if a hint conflicts with the semantics of the text, rely on your own judgement of the current text.
Do not express "not translated" by copying the English source_text into translated_text.
Do not omit the decision field when the correct action is to keep the original PDF content.
If `decision` is `keep_origin`, translated_text must be empty.
If `decision` is `translate`, provide the translation normally.
In sci mode you must return one tagged block per item; do not return JSON or Markdown.
Use strictly the following format:
<<<ITEM item_id=ITEM_ID decision=translate|keep_origin>>>
the translation; leave empty when decision=keep_origin
<<<END>>>
You must output one block for every requested item_id.
