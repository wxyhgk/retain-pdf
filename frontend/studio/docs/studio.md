# Studio 使用说明

Studio 是本机的写作工具，像 Notion 和思源笔记，写出来的是普通 Markdown。它只在 `npm run dev` 时存在，博客上线后没有它。

## 打开

第一次：

```sh
npm install
npm run milkdown:setup   # 拉取编辑器（Milkdown 的 fork）并安装依赖
```

以后每次：

```sh
npm run dev
```

然后打开 <http://localhost:4321/studio>。Studio 只接受本机访问，而且只认它自己的页面：本机别的网站（别的端口）、小程序都调不了它的接口。

### Mac 应用

也可以把 Studio 做成一个 Mac 应用，从启动台或程序坞打开，不用先开终端：

```sh
tools/studio-app/build.sh      # 需要 Rust（cargo）；生成 /Applications/Studio.app
```

- 打开时，如果博客的服务器已经在跑（比如 `npx astro dev --background` 起的），就直接用它，退出时也不动它。
- 没有就由应用自己启动一个，它跟着应用走：退出应用（⌘Q 或关掉窗口），哪怕应用崩溃，它都会停掉。
- 服务器用的是你终端里的环境（登录 shell 的 PATH），所以 node、cargo、conda 里的程序都能找到，Studio 的终端里也一样。
- 文章里 `target="_blank"` 的链接、「打开博客」、打开文件，都在默认浏览器里打开。下载的文件放进「下载」文件夹。
- 应用记住的是生成它时的博客文件夹。博客挪了地方就重新运行一次 `build.sh`；也可以 `build.sh <博客文件夹>` 指定，或者 `STUDIO_APP_DIR=~/Applications tools/studio-app/build.sh` 换个安装的地方。
- 服务器启动失败时，窗口里会显示它最后的输出，完整记录在 `.astro/dev.log`。

## 界面

- **左边**：页面树，所有文章。顶部「＋」新建页面，⌘K 搜索。
- **中间**：编辑器。上面是标题和属性（图标、封面、日期、标签、发布状态），下面是正文。
- **右边**：AI、这篇文章的文件、终端、资料库等面板。

写的东西会自动保存，⌘S 立刻保存。

## 页面和页面树

### 新建

- 顶部「＋」：新建一篇，放在最上层。
- 鼠标放到某篇上，点右边的「＋」：在它下面新建一篇。
- 右键（或 ⋯）→「在下面新建页面」：同上。
- 正文里打 `/页面`（或 `/page`、`/yemian`）：像 Notion 一样，在当前页面下面新建一页，光标处留一行指向它的链接，然后直接进入新页面。

新建的页面直接打开，标题是选中的，直接打字就行。

正文里一行只有一个指向本站文章的链接时，显示成带页面图标的一行，单击就打开那一页（普通链接要 ⌘ 点击）。它在文件里就是普通的 Markdown 链接 `[标题](/blog/文件夹名/)`。页面改了标题，所有文章里文字和旧标题一样、指向它的链接会跟着改（标题停下来 3 秒后改一次，打字过程中的半截标题不算；被改的文章先存一份历史版本）；自己另写了文字的链接不动。删掉这一行不会删掉那一页。文件夹名由 Studio 自动起（`note-日期-时间`），草稿阶段不用管它；**发布时按标题自动换成可读的网址**（中文转拼音，比如「基组的选择」→ `/blog/ji-zu-de-xuan-ze/`）。已经发布的页面不会再自动改名。

### 移动和排序

把一篇拖到另一篇上：

| 落在哪里 | 结果 |
|---|---|
| 上部 | 放在它上面（和它同一个上级） |
| 中间 | 放进去，成为它下面的页面 |
| 下部 | 放在它下面 |
| 列表下方的空白 | 回到最上层 |

拖的时候会显示一条线或一个框，告诉你会落在哪里。不能放到它自己或它下面的页面下面。顺序写在属性 `order:` 里，博客上「下面的页面」也按这个顺序。标题里的数字按数字排：「第2章」在「第10章」前面。

右键 →「移到…」：搜索要放到哪个页面下面，每个结果显示它的路径；第一行是「最上层」。

### 多选

| 操作 | 作用 |
|---|---|
| ⌘ 点击 | 逐个选上或取消 |
| ⇧ 点击 | 选中一段 |
| Esc | 取消选择 |

选中几篇后：右键可以一起「移到…」「移到最上层」「移到回收站」；拖其中任意一篇，几篇一起走；⌫ 一起删除。

### 键盘

焦点在页面树上时：↑↓ 在页面间移动，→ 展开或进入第一个子页面，← 收起或回到上级，回车打开，⌫ 删除。

### 拆分和合并

- **转成子页面**：在正文里，鼠标放到一个标题上，点左边的手柄 →「转成子页面」。这个标题和它下面的内容（到下一个同级或更高级的标题为止）变成当前页面下的新页面，用到的图片一起复制过去，原处留一条链接。
- **并入上级页面**：在页面树里右键子页面 →「并入上级页面…」。它的内容作为一节回到上级，替换掉指向它的那条链接；它的图片和文件一起回到上级（上级已有同名的不同文件时，它的那份改名为 `名字-2` 并改好正文里的引用，`refs.bib` 合并条目）；它下面的页面挂到上级下面，它自己进回收站；上级改动前的版本存进历史版本。

### 改名、复制、删除

右键菜单里：

- **改文件夹名…**：也就是改网址。别的页面里指向它的链接会一起改好。已经发布的页面改名后旧网址会失效。
- **复制一份**：复制成一篇草稿。
- **移到回收站**：页面下面还有页面时，会问你是连同它们一起删，还是只删这一篇、让下面的上移一级。有别的页面链接到它时会先列出来。删完点提示里的「撤销」可以全部恢复；回收站（项目的 `.studio-trash/`）保留 30 天。

打开子页面时，标题上方显示它的上级路径（「项目 › 本篇」），点上级跳过去，点 › 列出那一级下面的所有页面。

## 写作

### 块

每一段、标题、列表、图、公式都是一个「块」。鼠标放上去，左边出现手柄：

- 拖手柄：移动这个块。拖到别的块左右两边：并排成分栏；按住 ⌥ 是复制。
- 点手柄（或右键）：块菜单，可以转换类型、创建副本、删除、转成子页面等。
- Esc：选中光标所在的块；从页面左边的留白拖动：选中几块。

### 快捷输入

| 输入 | 结果 |
|---|---|
| `/` 或 `、` | 斜杠菜单：插入标题、列表、表格、公式、分子、计算任务……（可以打拼音找） |
| `[[` 或 `【【` | 链接到另一篇文章；打一个还没有的标题，可以直接新建子页面 |
| `# ` `## ` | 标题 |
| `> ` 或 `》` | 引用 |
| `[] ` 或 `【】` | 待办 |
| ```` ``` ```` 或 `···` 加空格 | 代码块 |
| `$…$`、`$$` | 行内公式、独立公式 |

独立公式比版面宽时不用左右滑动（Studio 和博客一样，手机上也是）：

- 一串等式（`a = b = c`，`≈`、`<` 也算）在关系符号处换行，等号上下对齐；没有等式链的长加减式在 `+`、`−` 处换行，下一行缩进。
- 换了行还放不下，再缩小，最多缩到 60%；再长才保留滑动，这时最好自己用 `aligned` 分行。
- 编号照旧；括号、分式、`\text{}`、`\ce{}` 里面的符号不拆；文章里写的 LaTeX 不变。

### 常用快捷键

| 快捷键 | 作用 |
|---|---|
| ⌘K | 搜索文章（选中文字时：加链接） |
| ⌘S | 保存 |
| ⌘J | 把选中的块交给终端里的 AI 问问题 |
| ⌘A | 第一下选中这一块的文字，第二下选中全部块 |
| ⇧↑ / ⇧↓ | 先选到行首或行尾，再按选中整块，继续按多选几块 |
| ⌘⇧↑ / ⌘⇧↓ | 把块上移或下移 |
| ⌘D | 创建副本 |
| ⌘C / ⌘X（没选东西时） | 复制或剪切光标所在的整块 |
| Tab / ⇧Tab | 列表缩进、取消缩进 |

### 粘贴

- 网址粘在选中的文字上：变成链接。
- 从网页（ChatGPT、维基百科）复制的公式：还原成 `$…$` 公式。
- 从聊天应用复制的「其实是 Markdown」的内容：按 Markdown 粘贴。
- 从表格软件或终端复制的几列文字：变成表格。

## 粘贴链接

在空的一行里单独粘贴一个网址，下面会弹出一个小菜单（和 Notion 一样）：

- **视频**：B 站、YouTube 的视频链接排在第一个，变成它们的播放器。
- **网页书签**：任何网页都行，变成带标题、简介和图片的卡片（网页只读一次，写进文章）。
- **保持链接**：就是一个普通链接。

↩ 选高亮的那个（一开始是第一个），↑ ↓ 换着选；按 Esc 或者接着打字，就保持链接。粘在一句话中间的网址只是链接，不弹菜单。

已经写好的、单独一行的链接，在块菜单（拖动手柄点开）的「转换成」里也能变成视频或书签；视频和书签也能从这里转回链接。

## 视频

最快的是直接粘贴视频链接（见上面）。也可以在斜杠菜单输入「视频」，然后：

- **网上的视频**：粘贴 B 站或 YouTube 的视频链接，回车。Studio 和博客上都显示它们自己的播放器。B 站 App 分享出来的短链接（`b23.tv/…`）也行，会先打开成完整链接。
- **本机的视频**：点「选本地视频…」，或者直接把视频文件拖进正文。文件放进文章的 `assets/`，Studio 里能播放，并自动截一帧做封面（`img/` 里的 jpg）。想换封面，把视频停在想要的那一帧，点右上角「做封面」。
  - 视频文件**只在这台电脑上**：不进 git，也不发布。博客上只显示封面和说明。
  - 发布前检查会提醒没有封面的视频。

写在文章里是这样的（普通 Markdown，可以手改）：

````
```video
./assets/实验.mp4
cover: ./img/实验.jpg
caption: 实验录像
width: 80%
```
````

## 反应能量图

在斜杠菜单输入「能量图」（在「化学」那一组），插入一个能量图块。它是纯文本，点块上的「编辑」改，下面的图跟着重画：

````
```energy
y: ΔG / kcal·mol⁻¹
title: SN2 反应
# 气相
Cl⁻ + CH₃Br 0
TS 3.1
CH₃Cl + Br⁻ -14.8
# 水中
Cl⁻ + CH₃Br 0
TS 26.4
CH₃Cl + Br⁻ -8.9
```
````

- 一行一个物种：名字在前，能量在最后，中间空格隔开。名字里可以有空格、上下标字符。
- `# 名字` 开始另一条路径，用不同的虚线区分，上面有图例。只有一条路径时不用写。
- 后面的路径里和前面同名的物种，放在同一列；中间的物种均匀排开。所以不同步数的路径（分步和协同）也能对齐。
- `y:` 是纵轴的名字（不写就是「相对能量」），`title:` 是图下面的说明。
- 博客上是直接画好的 SVG，不需要脚本，暗色模式也跟着变。
- 写错的行（比如没写能量）在 Studio 里列在图下面，发布前检查也会提醒。

## 计算结果（Gaussian、ORCA）

把 Gaussian 的 `.log` 或 ORCA 的 `.out` 直接拖进正文，它会放进文章的 `assets/`，正文里变成一张卡片：

- 第一行是结果：能量 E、自由能 G、有没有虚频（有就列出来）、开壳层的 ⟨S²⟩、激发态。
- 第二行是怎么算的：方法/基组、任务（优化、频率、过渡态优化、激发态……）、化学式、电荷和多重度。
- 旁边是最后结构的小图。
- 没收敛、出错结束的，卡片上用红字说明原因。

双击卡片（或选中后按回车）打开详情：

- **结果**：所有数值（E、ZPE、H、G、HOMO/LUMO 和能隙、⟨S²⟩、偶极、用时），优化过程的能量曲线，红外光谱（点谱线看那个振动的动画，虚频单独标出），或者结构；做了 TD-DFT 的还有激发态表。
- **输出**：输出文件原文。
- **设置**：改标题、换文件。

也可以在斜杠菜单输入「计算结果」（在「化学」那一组）再选文件。拖进来的 `.log`、`.out` 会先看文件开头：是 Gaussian 或 ORCA 写的才变成卡片，别的照旧显示成普通输出。

写在文章里是这样的：

````
```qc
@file ./assets/co2-opt.log
title: CO₂ 的优化和频率
```
````

- 博客上是同一张卡片，点开是同样的详情（只读）。输出文件跟文章一起发布，读者可以下载。
- 发布前检查会提醒：找不到输出文件、认不出程序、计算没正常结束，以及**输出里留着服务器路径**（比如 `/home/你的用户名/…`，发布后谁都能看到）。Gaussian 用 `#p` 时会把每个程序段的路径打印出来，结尾的归档块里还有主机名和用户名，发布前可以替换掉。

## 识别图片（AI）

图片的块菜单（拖动手柄点开，或右键）里有「识别…」，选一种读法，大模型就读这张图，结果放在图下面：

| 读法 | 放到图下面的 |
|---|---|
| 公式 → LaTeX | `$$ … $$` 公式块 |
| 文字 → 段落 | 普通段落（里面的公式写成 `$…$`） |
| 表格 → Markdown 表格 | 表格 |
| 分子结构 → SMILES | ```smiles 化学块 |

- 结果和终端里 AI 改文章一样，是「外部改动」：逐处接受或拒绝；改之前的文章存进历史版本。大模型读错了，拒绝就好。
- 第一次用会先弹出「AI 设置」（左栏底部也能打开）：
  - **Claude（Anthropic）**：模型默认 `claude-opus-5-5`；key 可以不填，用环境变量 `ANTHROPIC_API_KEY`（或 `ant auth login`）；用代理时填接口地址。key 如果属于整个组织、不属于某个工作区（报错说 not scoped to a workspace），在「工作区 ID」里填 `wrkspc_…`（Claude Console 的 Workspaces 页能看到；也可以设环境变量 `ANTHROPIC_WORKSPACE_ID`），或者换一个在工作区里建的 key。
  - **OpenAI 兼容接口**：通义千问、DeepSeek、智谱、OpenRouter 等都行，填接口地址（例如 `https://dashscope.aliyuncs.com/compatible-mode/v1`）和一个能看图的模型名（例如 `qwen-vl-max`）；key 可以用环境变量 `OPENAI_API_KEY`。
- key 只存在这台电脑的 `.studio-settings.json` 里（不进 git，只有你自己能读），网页拿不到它。
- 只能识别 PNG、JPEG、GIF、WebP，SVG 不行。
- 想加别的读法（图表取数、手写笔记……），见 `plugins/README.md` 的「加一种识别」。

## 小程序

左侧「小程序」列出仓库根目录 `apps/` 里的小工具，点一个就在悬浮窗里打开：拖标题栏移动，拖四边或四角改大小，双击标题栏放大到整个窗口、再双击还原，下次打开还是原来的位置和大小；可以同时开几个。

- 现在有两个：**能量单位换算**（Hartree、eV、kcal/mol、kJ/mol、cm⁻¹ 互换，点「插入」把值以 `\pu` 写法插到光标处）和 **Gaussian 输入生成**（选任务、方法、基组、色散、溶剂，结构取自文章里的 XYZ 或粘贴；插进正文，或存成 `assets/` 里的 `.gjf`）。
- **让 AI 做新的**：在终端里说「做一个……的小程序」，它会照技能 `studio-mini-apps` 写进 `apps/<名字>/`（`app.json` 加 `app.html`），不用重启，「小程序」里就有了；改了代码点标题栏的 ↻ 重新加载。
- 小程序在沙盒里运行，碰不到 Studio；要读当前文章、往正文插入、读写文章的文件、联网、在后台运行命令，都得在 `app.json` 的 `permissions` 里写明（`article`、`insert`、`files`、`net`、`run`），没写的会被拒绝。
- 联网（`net`）只能访问互联网，不能访问本机和局域网（Studio 自己、路由器、本机的其他服务）。小程序里点开的别的网页用不了这些权限：Studio 会断开它，点 ↻ 回到小程序。
- 小程序只给自己用，不随文章发布；要随文章发布的交互内容用交互模块（```widget）。

## PDF 识别成子页面（PaddleOCR）

把 PDF 拖进正文（它会变成一行指向它的链接），点这一行左边的手柄 →「OCR 成子页面（PaddleOCR）」；或者在文件面板里右键 PDF → 同一项。

- 马上在当前文章下面建一个子页面，标题是 PDF 的文件名，PDF 那一行下面多一行指向它。PDF 留在原处，不复制：放在 `ai/` 里的 PDF 不会因此被发布。
- 识别在后台进行，右下角能看进度和日志。几百页的书要等一阵（最多等两小时）。等的时候可以在子页面里先写东西，识别结果会接在后面，不会覆盖；识别失败或取消，子页面上会写明。
- 识别完，子页面里是识别出的文字：标题、段落、公式（转成 `$…$` 和 `$$`）、表格（转成 Markdown 表格，有合并单元格的保留 HTML）、图（放进子页面的 `img/ocr/`，图下的「图 1 …」变成图注）。很长也没关系，长文章会分段显示。
- 用的是本机的 `paddleocr api` 命令（PaddleOCR 官方的在线文档解析），需要先装好 `paddleocr`，并在终端环境里设好 AI Studio 的 token：`PADDLEOCR_ACCESS_TOKEN`。

## 发布和提交

- 页面上方的「发布」按钮：先做发布前检查（会让博客构建失败的问题会拦下来），再把草稿改成已发布。网站在推送到 GitHub 之后才更新。
- 页面树右键 →「提交到 git…」：只提交这一篇。推送由你自己做。
- 历史版本：像 Notion 一样，写作时每 10 分钟自动存一份（「自动存档」，存的是保存前的样子）；文章在磁盘上被别的程序（比如 AI）改动前，也会先存一份。都在文章的 `ai/history/` 里，只在本机，不发布、不进 git（整个 `ai/` 都不进 git：Studio 提交文章时会跳过它）。
  - 页面右上角的 ⋯ 菜单 →「历史版本…」按天列出，选一份「对比并恢复」，逐处接受或拒绝。
  - 自动存档：一天内的全留，30 天内每天留最后一份，每篇最多 50 MB；其他的留最新 50 份。

## 编辑器里的 AI

像 Notion 一样，在正文里直接让 AI 改写或续写：

- **改写**：选中一段（或者光标放在某一段里），按 ⌘J，或者点选中文字上方工具栏最后的「AI 改写」、块菜单里的「AI 改写…」。弹出的小框里可以直接输入要求，也可以选现成的：改得更通顺、更简洁、扩写、修正错别字和语法、翻译成英文或中文、改成要点列表。
- **续写**：在一个空行上按空格，弹出同样的框（接着写下一段、写一个小结、列出要点、举个例子，或者自己写要求），AI 写的内容放在这一行。
- AI 写好以后，结果直接显示在原处，和审阅磁盘改动一样逐处标出来，可以一处一处接受或拒绝。上方的条可以「全部接受」「全部拒绝」，不满意点「重试」再写一遍。接受的部分和平常的编辑一样保存。
- 用的是 AI 面板里选的那个 AI 和模型（以及「模型和账号」里的设置）。后台会先把它准备好，所以通常几秒就有结果；写的时候小框里显示用了几秒，按 Esc 可以停下。
- 框里最后一项「在终端里问 AI…」是原来 ⌘J 的做法：把选中的几行写进终端，交给终端里的 AI。

## AI 面板

右边的「AI」面板像图形界面的 Claude Code：说一件事，AI 自己读文件、运行命令、改文件，面板上一步一步显示它在做什么。背后就是你本机的 Claude Code 或 Codex（用它们自己的登录和设置），Studio 通过 Agent Client Protocol（ACP）和它们说话，转接程序 `claude-agent-acp`、`codex-acp` 已经装在项目依赖里。

- **模型和账号**（面板右上角 ⚙）：Claude Code、Codex、pi 都随项目依赖装好了，用的人只要有账号或 API key：
  - **Claude Code 用哪家的模型**：
    - Claude 账号（订阅）：点「登录 Claude 账号」，在终端里按提示登录（会打开浏览器）。
    - 或者填一个兼容 Anthropic 接口的 API key：Anthropic、DeepSeek、Kimi、智谱、通义千问、MiniMax，或「其他」填接口地址。主模型、快速模型预先填了各家推荐的名字，可以改（各家常改名字，以官网为准）；「检查」用一句话试一下能不能用。
    - 换了以后新对话才用新的设置；输入框下面的模型就是这家的模型。
  - **pi 用哪家的模型**：pi 自带各家的接口和模型列表（DeepSeek、Kimi、智谱 GLM Coding、MiniMax、通义千问 Token Plan、小米 MiMo、OpenRouter、OpenAI、Gemini、Anthropic、xAI），选一家、填 key 就行，模型从输入框下面选（只列这一家的）；「检查」用一句话试一下，并列出这家的模型。也可以选「pi 自己的设置」，用这台电脑上 pi 的登录和设置（~/.pi）。pi 不问就运行命令、改文件。
  - **Codex**：用 ChatGPT 账号登录。
  - 两边都显示是否已登录。API key 只存在这台电脑的 `.studio-settings.json` 里（不进 git），页面上不会再显示出来。
- **在哪里做**：AI 在 `blog/` 里工作（会读 `blog/AGENTS.md` 和技能），所有文章都能读、能改。切换文章不用开新对话：输入框上方的「📄 当前文章」标签跟着你打开的文章变，说话时会告诉 AI 你在看哪篇，以及这篇有没有写作要求 `ai/brief.md`（有就让它先读，没有它就不去找）；文章里选中了内容，还会多一个「选中的内容」标签，把那几行一起告诉它。输入 `@` 可以从列表里选别的文章，也成为一个标签。标签上的 × 是这次不带上它。「＋」开一个新对话，「≡」回到之前的对话，或删除正在看的这个。
- **对话记录**：每个对话说过话以后，都存在仓库根目录的 `chats/` 里，一个对话一个文件夹（`chats/chat-20261025-153012/`）。`index.md` 是一页 Markdown，你问的话写成 ` ```ask ` 块，AI 的回答原样放在后面，和文章的块一样；`ai/conversation.json` 是全部记录（思考、运行的命令、改的文件），还有 AI 自己那边的会话号。`chats/` 不进 git，也不发布。Studio 重启后对话都还在，打开就是原来的样子；再说话时会重新启动那个 AI，接上它原来的会话，它记得之前说过什么（Claude Code、Codex、pi 都可以）。万一接不上（比如 AI 那边的记录被删了），会开一个新会话，并告诉它之前的对话记在哪个文件里。
- **显示什么**：
  - 它的回答，Markdown 和公式照常显示，一块一块的（段落、公式、列表、代码、表格）：鼠标移上去左边有「⋮⋮」，拖到文章里就放在那里，点一下放在光标处；回答下面的「插入到文章」把整段放进去，「复制」复制它的 Markdown；
  - 「思考过程」，折叠着，点开看；
  - 每次调用工具一行：运行命令（显示命令本身）、读文件、搜索、改文件，右边是状态（等待、转圈、✓、✗）；点开看命令输出，改文件看删掉和加上的行；
  - 它列的计划，做一项勾一项；
  - 要你允许的事：显示要运行的命令，「允许 / 总是允许 / 拒绝」。
- **输入框下面**：用哪个 AI（换一个就开新对话），什么要问你，用哪个模型，思考多深。选过的会记住，下次新对话照样用。右边是用掉的上下文和这次对话的花费。
- **什么要问你**（Claude Code）：
  - 每步都问；
  - 自动改文件（命令要问）：改文件不问，但运行做事的命令（python、删除、安装）照样会问；
  - 自动（只问危险的）：Claude 自己判断，只有危险的才问；
  - 全部允许（不再问）；
  - 只做计划：先列计划，不动手。
  
  Codex 的四档是：只读、可改文件夹（联网要问）、自动（只问不安全的）、完全访问。
- Enter 发送，Shift+Enter 换行（中文输入法选字时按 Enter 不会发送）。它在做的时候发送键变成 ■，点一下让它停下。
- 它改了正打开的文章时，和终端里的 AI 一样，Studio 把改动逐处标出来让你接受或拒绝。
- 停掉 Studio 时，面板里的 AI 也一起停掉。

## 终端和 AI

右边的「终端」面板是一个真正的 shell，可以开在仓库根目录、当前文章的文件夹或资料库里。

**启动 AI**：终端上方的「启动 AI：Claude · Codex · pi」，点一下就在当前文章的文件夹里（没打开文章时在仓库根目录）开一个新的终端，启动那个 AI。这台机器上没装的按钮是灰的，鼠标放上去能看到怎么装。终端里正有程序在跑时，会先问一声。

**AI 助手设置**：终端那一行最后的 ⚙。每个 AI 有三条命令：终端里启动、Alt+Enter 后台跑一次、Alt+Enter 接着上次（`{prompt}` 换成交给它的话）。预先填好了 Claude、Codex、pi，可以改，也可以添加别的（比如 omp），并选 Alt+Enter 默认用哪个。只存在这台电脑上。

**Alt+Enter：把一件事交给 AI**：在正文里写一句要做的事，比如「画一个 sin x 的图，横轴 0 到 2π」，光标放在这一行，按 Alt+Enter。

- 选中的 AI 在这篇文章的文件夹里后台去做，这几行变灰，写着「AI 处理中…」；右下角列出后台任务，能看日志、能取消。
- 交给它的只是这几行和它们的位置（第几行、在哪一节），不是整篇文章；它要更多上下文会自己去读。
- 默认接着这篇文章文件夹里最近的会话，所以它记得刚才做过什么（这篇文章里第一次用时，没有可接的，就开一个新的）；⇧Alt+Enter 是另开一个新会话。同一篇文章里连按几次，会排队一件一件做，不会两个 AI 同时改它。换了 AI 也接得上：每次做的事都记在文章的 `ai/work/log.md`，用到的脚本、数据也放在 `ai/work/`。
- 做完，它把这几行换成结果（图、表、公式……），像别的外部改动一样逐处让你接受或拒绝。
- Claude 的预设开了沙箱：只能写这篇文章的文件夹，不能联网。Codex 的预设是 workspace-write。pi 没有沙箱：它能改这台电脑上你能改的任何东西。文章里如果有别人写的文字（OCR 出来的书、资料库里的文件），里面混着的指令可能被它照做，处理这类文章时用 Claude 或 Codex 更稳妥。
- 停掉 Studio（关掉应用，或在终端里 Ctrl+C）时，还在跑的后台任务会一起停掉。

在终端里用 AI 时：

- 终端设好了 `STUDIO_ARTICLE`（当前文章的文件夹名）等环境变量；
- 可以直接用 `studio` 命令操作页面，见[给大模型用的接口](ai-tools.md)；
- AI 改了正打开的文章时，Studio 会把改动逐处标出来，让你接受或拒绝。

**规则、技能、偏好**：用哪个 AI 都读同一份，换着用不会忘：

- **写作约定**：[blog/AGENTS.md](../blog/AGENTS.md)。Codex、pi 直接读它，Claude Code 经由同一文件夹里只有一行 `@AGENTS.md` 的 `CLAUDE.md` 读它。在文章文件夹里打开时，它们都会往上找到它。
- **技能**：写法细节和做事的步骤（分子、计算输出和能量图、交互模块、引用文献、资料库），在仓库根目录的 [.agents/skills/](../.agents/skills/)。用到时才读，不占地方；Claude Code 从指向同一处的 `.claude/skills/` 读。AI 做完一件以后还会再做的事，会问你要不要存成新技能。
- **你的偏好**：你纠正 AI 的写法、或者说「以后都……」，它会记进仓库根目录的 `.agents/memory/preferences.md`，下次不管用哪个 AI 都先读它。这个文件只在本机，不进 git，可以直接打开改。
