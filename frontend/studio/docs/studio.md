# Studio 使用说明

Studio 是本机的写作工具，像 Notion 和思源笔记，写出来的是普通 Markdown。它有自己的服务器（`npm run studio:serve`，或 Mac 应用），博客上线后没有它。

## 打开

第一次：

```sh
npm install
npm run milkdown:setup   # 拉取编辑器（Milkdown 的 fork）并安装依赖
```

以后每次：

```sh
npm run studio:serve
```

然后打开 <http://localhost:4321/studio>（4321 被占着就用下一个空着的端口，终端里会写出地址）。Studio 只接受本机访问，而且只认它自己的页面：本机别的网站（别的端口）、小程序都调不了它的接口。

这是 Studio 自己的服务器，不是博客的：写作不需要 `npm run dev`（Astro），博客那边出错也不会把 Studio 拖下去。要看博客本身（「博客首页」、在博客上打开一篇），Studio 会把你带到博客自己的服务器：已经开着 `npm run dev` 就用它；没开就替你开一个（端口在 Studio 的下一个，比如 4322，第一次要等几秒），Studio 关掉时它也跟着关。它的输出在 `.studio-cache/blog.log`。

### Mac 应用

也可以把 Studio 做成一个 Mac 应用，从启动台或程序坞打开，不用先开终端：

```sh
tools/studio-app/build.sh      # 需要 Rust（cargo）；生成 /Applications/Studio.app
```

- 打开时，如果 Studio 的服务器已经在跑（比如终端里 `npm run studio:serve` 起的），就直接用它，退出时也不动它。
- 没有就由应用自己启动一个，它跟着应用走：退出应用（⌘Q），哪怕应用崩溃，它都会停掉。
- 关掉窗口（红色按钮或 ⌘W）只是把窗口藏起来，像别的 Mac 应用一样：服务器还在，点程序坞里的图标马上回来，不用重新启动。真要退出用 ⌘Q。
- 窗口记得上次的大小和位置（AI、小程序的独立窗口也是），下次在原处打开；那块屏幕不在了就用默认大小。记在 `~/Library/Application Support/blog.studio.app/windows.json`。
- 服务器用的是你终端里的环境（登录 shell 的 PATH），所以 node、cargo、conda 里的程序都能找到，Studio 的终端里也一样。
- 文章里 `target="_blank"` 的链接、「打开博客」、打开文件，都在默认浏览器里打开。下载的文件放进「下载」文件夹。
- 应用记住的是生成它时的博客文件夹。博客挪了地方就重新运行一次 `build.sh`；也可以 `build.sh <博客文件夹>` 指定，或者 `STUDIO_APP_DIR=~/Applications tools/studio-app/build.sh` 换个安装的地方。
- 服务器启动失败时，窗口里会显示它最后的输出，完整记录在 `.astro/dev.log`。

### 其他设备访问（别的电脑的浏览器、iPad）

在别的电脑（浏览器）或 iPad 上用这台 Mac 上的 Studio：文章、AI（Claude Code、pi）、终端、计算都还在 Mac 上跑，别的设备只是用它。Mac 要开着，Studio 要开着。

1. Mac 上：设置 › 其他设备访问，打开「允许别的设备访问这台 Mac 上的 Studio」。下面列出能连进来的地址（`https://…:4343`）：局域网（同一个 Wi-Fi）的，开着 Tailscale 时还有 Tailscale 的（出门也能连，两边登录同一个 Tailscale 账号）。
2. 点「配对一台设备」，出现一个二维码和一个 8 位配对码，5 分钟内有效，只能用一次。
3. 别的电脑：浏览器打开上面的地址。浏览器会提示证书不受信任（证书是 Studio 自己生成的）：点开证书看它的 SHA-256 指纹，和 Mac 上显示的一样再继续（Chrome 里「高级 › 继续前往」，Safari 里「显示详细信息 › 访问此网站」）。然后输入配对码，就进到 Studio 了；这个浏览器以后直接打开。
4. iPad：用 Studio 的 iPad App 扫码。配对好以后它就记住了，以后直接打开。App 用 Xcode 装到 iPad 上，步骤见 `tools/studio-ipad/README.md`。
5. 配对过的设备（浏览器还是 App）列在同一页，不想让它再进来就「移除」。

- 默认关着；关掉以后谁也连不进来。
- 只有配对过的设备能进：每台设备有自己的钥匙（浏览器里是一个只能在这个地址用的 cookie；Mac 上只存它的哈希）。没配对的浏览器只看到输配对码的页面。
- 传的东西用 HTTPS 加密。iPad App 只认二维码里那张证书的指纹，所以在局域网里也没人能看到或改掉。浏览器做不到这样：第一次打开时核对一下指纹，或者走 Tailscale（只有你自己的设备在里面）。在咖啡馆、会场这类别人也连着的 Wi-Fi 上，指纹对不上就别继续。
- 进来的设备能做 Mac 上能做的事，包括终端：只配对自己的设备，不用的及时移除。
- 其他设备访问本身（开关、配对、移除）只能在 Mac 上设置。
- 别的设备拿到的是打包好的 Studio：打开一次约 1 MB（分子的三维查看、终端这些用到时才下载），Mac 上是按源码跑的那一份（改了代码马上看到）。Studio 的代码改了，几秒钟内会重新打包；还没打包好时，别的设备拿到的是 Mac 上那一份（大得多，约 11 MB）。别的设备上已经打开的页面不会跟着代码自动更新，刷新一下就是新的。
- 「在 Finder 中显示」「用默认程序打开」这类操作是在 Mac 上做的；博客预览（「博客首页」）在别的设备上暂时打不开。

## 界面

- **左边**：页面树，所有页面。顶部「＋」新建页面，⌘K 搜索。（界面上统一叫「页面」；发布到博客的页面在博客上是文章。）
- **中间**：编辑器。上面是标题和属性（图标、封面、标签、简介；发布到博客的页面还有发布日期、类型、状态），下面是正文。
- **右边**：AI、这篇文章的文件、终端、资料库等面板。

写的东西会自动保存，⌘S 立刻保存。

**亮色 / 暗色**：设置 › 外观选「亮色」「暗色」或「跟随系统」（系统切换时跟着变）；⌘K `>切换亮色 / 暗色` 一下切换。和博客页面用同一个设置，独立窗口、小程序也跟着变。

顶栏的 ‹ › 在打开过的页面之间后退、前进（⌘[ / ⌘]，鼠标侧键也行）。每篇文章记得上次看到哪里：回到一篇（点页面树、‹ ›、链接，或者重开 Studio）时停在上次离开的地方，不是从头开始（和思源一样；记在这个浏览器里，最近 200 篇）。

## 页面和页面树

### 新建

- 顶部「＋」：新建一篇，放在最上层。
- 鼠标放到某篇上，点右边的「＋」：在它下面新建一篇。
- 右键（或 ⋯）→「在下面新建页面」：同上。
- 正文里打 `/页面`（或 `/page`、`/yemian`）：像 Notion 一样，在当前页面下面新建一页，光标处留一行指向它的链接，然后直接进入新页面。

新建的页面直接打开，标题是选中的，直接打字就行。正文是空的（编辑器里灰色的提示不写进文件）；日期按本机的日子记（以前按 UTC，早上 8 点前新建的会记成前一天）。

### 导入和导出 Markdown

**导入**：左栏底部的工作区菜单 →「导入 Markdown 文件…」或「导入 Markdown 文件夹…」（⌘K `>导入` 也行）；放到某一页下面：那页的 ⋯ →「导入 Markdown 到这页下面…」。

- 可以选 `.md` 文件（连同它们用到的图片一起选）、一个 `.zip`（Notion 导出的、Obsidian 库打的包），或者整个文件夹。
- 每个 `.md` 变成一页。标题用它属性里的 `title`，没有就用开头的 `# 标题`，再没有就用文件名（Notion 文件名后面那串 id 会去掉）。
- 文件夹变成一页，里面的笔记是它的子页面；如果文件夹旁边有同名的 `.md`（Notion 的导出就是这样），那个 `.md` 就是这一页。
- 文章里引用的图片和文件（`![](images/a.png)`、`[数据](files/x.csv)`、Obsidian 的 `![[a.png]]`）复制进新页面的 `img/`、`assets/`，链接跟着改；互相之间的链接（`[b](b.md)`、`[[b]]`）改成指向导入的那页。找不到的文件会提示。
- 属性里除了标题，别的（标签、日期）暂时不带过来；导入的页面都是草稿。

**导出**：页面的 ⋯ →「导出 Markdown」，文件放进「下载」文件夹。

- 没有图片和文件的页面就是一个 `<标题>.md`；有的话是 `<标题>.zip`，里面是 `.md` 加 `img/`、`assets/`（`ai/` 不带）。
- 有子页面时多一项「导出 Markdown（连同子页面）」：每个子页面一个文件夹（`第一章/第一章.md`），页面之间的链接改成指向对方的 `.md`，指向别的页面的链接改成博客上的完整网址。
- 页面在树里的位置（`parent:`、`order:`）在别处没有意义，导出时去掉。

### 模板和今天的日志

模板放在仓库根目录的 `templates/` 里，一个模板一个 `.md`（照思源的模板）：

```markdown
---
name: 计算记录
description: 体系、方法、输入、结果、问题
title: '{{date}} 计算记录'
---

## 体系
……
```

- 正文和 `title` 里可以写 `{{date}}`（2026-10-29）、`{{time}}`、`{{datetime}}`、`{{year}}`、`{{month}}`、`{{day}}`、`{{weekday}}`（星期四）、`{{title}}`（新页面的标题），新建时填进去。
- **用模板新建**：⌘K 输入 `>` 和模板名，选「新建：计算记录」。
- **插入模板**：正文里打 `/模板`，选一个，内容放在光标处。
- **存为模板**：页面右上角 ⋯ →「存为模板…」，起个名字，这篇的正文就存成一个模板（里面的图片和文件不带：它们还是这篇的）。
- **今天的日志**：左栏的「今天的日志」（或 ⌘K `>今天的日志`）。打开「日志」下面以今天日期为标题的页面；今天还没有，就用 `templates/journal.md` 新建一篇；「日志」这一页第一次用时也一起建好。
- 仓库里带了三个：`journal.md`（日志）、`calculation.md`（计算记录）、`paper-note.md`（文献笔记），随便改、删、加。

正文里一行只有一个指向本站文章的链接时，显示成带页面图标的一行，单击就打开那一页（普通链接要 ⌘ 点击）。它在文件里就是普通的 Markdown 链接 `[标题](/blog/文件夹名/)`。页面改了标题，所有文章里文字和旧标题一样、指向它的链接会跟着改（标题停下来 3 秒后改一次，打字过程中的半截标题不算；被改的文章先存一份历史版本）；自己另写了文字的链接不动。删掉这一行不会删掉那一页。文件夹名由 Studio 自动起（`note-日期-时间`），草稿阶段不用管它；**发布时按标题自动换成可读的网址**（中文转拼音，比如「基组的选择」→ `/blog/ji-zu-de-xuan-ze/`）。已经发布的页面不会再自动改名。

### 移动和排序

把一篇拖到另一篇上：

| 落在哪里 | 结果 |
|---|---|
| 上部 | 放在它上面（和它同一个上级） |
| 中间 | 放进去，成为它下面的页面 |
| 下部 | 放在它下面 |
| 列表下方的空白 | 回到最上层 |

拖的时候会显示一条线或一个框，告诉你会落在哪里。不能放到它自己或它下面的页面下面。顺序写在属性 `order:` 里，博客上「下面的页面」也按这个顺序。标题里的数字按数字排：「第2章」在「第10章」前面。

右键 →「移到…」：搜索要放到哪个页面下面，每个结果显示它的路径；第一行是「最上层」。

移到某个页面下面时（拖过去、「移到…」都一样），像 Notion 一样在那个页面末尾加一个页面块（一行只有指向它的链接）；原来的上级页面里指向它的页面块会去掉（写在句子里的链接不动）。正打开的就是这两个页面之一时，它直接显示新的样子，不弹审阅。

### 多选

| 操作 | 作用 |
|---|---|
| ⌘ 点击 | 逐个选上或取消 |
| ⇧ 点击 | 选中一段 |
| Esc | 取消选择 |

选中几篇后：右键可以一起「移到…」「移到最上层」「移到回收站」；拖其中任意一篇，几篇一起走；⌫ 一起删除。

### 键盘

焦点在页面树上时：↑↓ 在页面间移动，→ 展开或进入第一个子页面，← 收起或回到上级，回车打开，⌫ 删除。

### 拆分和合并

- **转成子页面**：在正文里，鼠标放到一个标题上，点左边的手柄 →「转成子页面」。这个标题和它下面的内容（到下一个同级或更高级的标题为止）变成当前页面下的新页面，用到的图片一起复制过去，原处留一条链接。
- **并入上级页面**：在页面树里右键子页面 →「并入上级页面…」。它的内容作为一节回到上级，替换掉指向它的那条链接；它的图片和文件一起回到上级（上级已有同名的不同文件时，它的那份改名为 `名字-2` 并改好正文里的引用，`refs.bib` 合并条目）；它下面的页面挂到上级下面，它自己进回收站；上级改动前的版本存进历史版本。

### 改名、复制、删除

右键菜单里：

- **改文件夹名…**：也就是改网址。别的页面里指向它的链接会一起改好。已经发布的页面改名后旧网址会失效。
- **复制一份**：复制成一篇草稿。
- **移到回收站**：页面下面还有页面时，会问你是连同它们一起删，还是只删这一篇、让下面的上移一级。有别的页面链接到它时会先列出来。删完点提示里的「撤销」可以全部恢复；回收站（项目的 `.studio-trash/`）保留 30 天。

打开子页面时，标题上方显示它的上级路径（「项目 › 本篇」），点上级跳过去，点 › 列出那一级下面的所有页面。

## 写作

### 块

每一段、标题、列表、图、公式都是一个「块」。鼠标放上去，左边出现手柄：

- 拖手柄：移动这个块。拖到别的块左右两边：并排成分栏；按住 ⌥ 是复制。
- 点手柄（或右键）：块菜单，可以转换类型、创建副本、删除、转成子页面等。
- Esc：选中光标所在的块；从页面左边的留白拖动：选中几块。

### 快捷输入

| 输入 | 结果 |
|---|---|
| `/` 或 `、` | 斜杠菜单：插入标题、列表、表格、公式、分子、计算任务……（可以打拼音找） |
| `[[` 或 `【【` | 链接到另一篇文章；打一个还没有的标题，可以直接新建子页面 |
| `# ` `## ` | 标题 |
| `> ` 或 `》` | 引用 |
| `[] ` 或 `【】` | 待办 |
| ```` ``` ```` 或 `···` 加空格 | 代码块 |
| `$…$`、`$$` | 行内公式、独立公式 |

独立公式比版面宽时不用左右滑动（Studio 和博客一样，手机上也是）：

- 一串等式（`a = b = c`，`≈`、`<` 也算）在关系符号处换行，等号上下对齐；没有等式链的长加减式在 `+`、`−` 处换行，下一行缩进。
- 换了行还放不下，再缩小，最多缩到 60%；再长才保留滑动，这时最好自己用 `aligned` 分行。
- 编号照旧；括号、分式、`\text{}`、`\ce{}` 里面的符号不拆；文章里写的 LaTeX 不变。

### 常用快捷键

| 快捷键 | 作用 |
|---|---|
| ⌘K | 搜索文章（选中文字时：加链接） |
| ⌘S | 保存 |
| ⌘[ / ⌘] | 后退 / 前进到打开过的页面（光标在列表里时是列表缩进，在表格里是换格） |
| ⌘F | 在这篇里查找替换 |
| ⌘⇧F | 在全部页面里查找替换 |
| ⌘J | 把选中的块交给终端里的 AI 问问题 |
| ⌘A | 第一下选中这一块的文字，第二下选中全部块 |
| ⇧↑ / ⇧↓ | 先选到行首或行尾，再按选中整块，继续按多选几块 |
| ⌘⇧↑ / ⌘⇧↓ | 把块上移或下移 |
| ⌘D | 创建副本 |
| ⌘C / ⌘X（没选东西时） | 复制或剪切光标所在的整块 |
| Tab / ⇧Tab | 列表缩进、取消缩进 |

### 查找替换

- **⌘F（这一篇）**：编辑器右上角出现查找栏，找到的地方标灰，当前那处深一点；↩ 下一处、⇧↩ 上一处，「Aa」区分大小写。下面一行填「替换为」：「替换」换当前这处，「全部替换」换这篇里的每一处（⌘Z 能撤销）。Esc 关掉。
- **⌘⇧F（全部页面）**：或 ⌘K `>查找替换`，或查找栏里的「⋯」。先列出每篇文章里的每一处（第几行、前后的字、会换成什么），默认全勾上，不想换的取消勾选，再「替换勾选的 N 处」。每篇改之前的样子存进它的「历史版本」，改错了能找回来；查找之后又被改过的文章不动，会说一声。
- 两种都**不碰代码和公式**（代码块、`行内代码`、`$…$`、`$$…$$`），全部页面那种也不碰链接和图片的地址，也不碰页面开头的属性：这些地方换一个词可能就坏了（全部页面那种可以取消勾选「不改代码、公式和链接地址」）。

### 选中文字、链接、表格

- **选中一段文字**：旁边弹出一张小卡片（像 Notion）：最上面是这一块现在是什么（「正文 ›」，点开换成标题、列表、引用……），中间是粗体、斜体、删除线、行内代码、公式、链接、清除格式（去掉粗体、斜体、删除线和代码，链接留着），最下面是「AI 改写」。
- **链接**：点一下就打开：网址在浏览器里打开，文章链接打开那篇文章。鼠标指着链接停一下，下面出来它指向哪里，旁边能复制、「编辑」（改地址）。要改链接上的字，用键盘把光标移进去，或者拖着选中。
- **表格的列宽**：鼠标移到两列之间的竖线上，出现一条蓝线，拖它把左边那列变宽或变窄。宽度记在表格前面的一行注释里，比如 `<!-- colwidths: 120 240 80 -->`（每列多少像素），博客和别的 Markdown 软件都看不见它；删掉这行注释，表格就回到自动平分宽度。行高跟着内容走（Notion 也是这样）。

### 粘贴

- 网址粘在选中的文字上：变成链接。
- 从网页（ChatGPT、维基百科）复制的公式：还原成 `$…$` 公式。
- 从聊天应用复制的「其实是 Markdown」的内容：按 Markdown 粘贴。
- 从表格软件或终端复制的几列文字：变成表格。

## 粘贴链接

在空的一行里单独粘贴一个网址，下面会弹出一个小菜单（和 Notion 一样）：

- **视频**：B 站、YouTube 的视频链接排在第一个，变成它们的播放器。
- **网页书签**：任何网页都行，变成带标题、简介和图片的卡片（网页只读一次，写进文章）。
- **保持链接**：就是一个普通链接。

↩ 选高亮的那个（一开始是第一个），↑ ↓ 换着选；按 Esc 或者接着打字，就保持链接。粘在一句话中间的网址只是链接，不弹菜单。

已经写好的、单独一行的链接，在块菜单（拖动手柄点开）的「转换成」里也能变成视频或书签；视频和书签也能从这里转回链接。

## 反应能量图

在斜杠菜单输入「能量图」（在「化学」那一组），插入一个能量图块。它是纯文本，点块上的「编辑」改，下面的图跟着重画：

````
```energy
y: ΔG / kcal·mol⁻¹
title: SN2 反应
# 气相
Cl⁻ + CH₃Br 0
TS 3.1
CH₃Cl + Br⁻ -14.8
# 水中
Cl⁻ + CH₃Br 0
TS 26.4
CH₃Cl + Br⁻ -8.9
```
````

- 一行一个物种：名字在前，能量在最后，中间空格隔开。名字里可以有空格、上下标字符。
- `# 名字` 开始另一条路径，用不同的虚线区分，上面有图例。只有一条路径时不用写。
- 后面的路径里和前面同名的物种，放在同一列；中间的物种均匀排开。所以不同步数的路径（分步和协同）也能对齐。

- 博客上是直接画好的 SVG，不需要脚本，暗色模式也跟着变。
- 写错的行（比如没写能量）在 Studio 里列在图下面，发布前检查也会提醒。

## 计算结果（Gaussian、ORCA）

把 Gaussian 的 `.log` 或 ORCA 的 `.out` 直接拖进正文，它会放进文章的 `assets/`，正文里变成一张卡片：

- 第一行是结果：能量 E、自由能 G、有没有虚频（有就列出来）、开壳层的 ⟨S²⟩、激发态。
- 第二行是怎么算的：方法/基组、任务（优化、频率、过渡态优化、激发态……）、化学式、电荷和多重度。
- 旁边是最后结构的小图。
- 没收敛、出错结束的，卡片上用红字说明原因。

双击卡片（或选中后按回车）打开详情：

- **结果**：所有数值（E、ZPE、H、G、HOMO/LUMO 和能隙、⟨S²⟩、偶极、用时），优化过程的能量曲线，红外光谱（点谱线看那个振动的动画，虚频单独标出），或者结构；做了 TD-DFT 的还有激发态表。
- **输出**：输出文件原文。
- **设置**：改标题、换文件。

也可以在斜杠菜单输入「计算结果」（在「化学」那一组）再选文件。拖进来的 `.log`、`.out` 会先看文件开头：是 Gaussian 或 ORCA 写的才变成卡片，别的照旧显示成普通输出。

写在文章里是这样的：

````
```qc
@file ./assets/co2-opt.log
title: CO₂ 的优化和频率
```
````

- 博客上是同一张卡片，点开是同样的详情（只读）。输出文件跟文章一起发布，读者可以下载。
- 发布前检查会提醒：找不到输出文件、认不出程序、计算没正常结束，以及**输出里留着服务器路径**（比如 `/home/你的用户名/…`，发布后谁都能看到）。Gaussian 用 `#p` 时会把每个程序段的路径打印出来，结尾的归档块里还有主机名和用户名，发布前可以替换掉。

## 数据库（像 Notion）

正文里打 `/数据库`：插进一张空表，每一行是这一页下面的一个页面（像 Notion，行就是页面）。最上面可以给数据库起个名字。

- **行属于数据库**：每个数据库有自己的 id（写在块的 JSON 里），它的行在属性里写着 `database: <id>`。所以一页可以放几个数据库，各管各的行；这一页下面的普通子页面还是子页面，不算哪张表的行。把一行拖到别的页面下面，它就成了那里的普通页面。
- **左边的页面树**：行不一个个挂在树上，树上只有数据库（表格图标和名字，收起时旁边是行数），展开看到它的行；点数据库打开它所在的页面并滚到它。
- **以前建的数据库**（块里没有 id、这一页下面的子页面都是行）：第一次打开时 Studio 给它一个 id，给那些子页面写上 `database:`（改之前的版本都存进历史版本），之后就和新的一样。

- **列（属性）**：表头最右边的 `+` 选一种类型（文字、数字、单选、多选、日期、勾选、网址），新列先用类型当名字，弹出的菜单里直接改名。点列名打开它的菜单：改名、换类型、筛选、升序降序、隐藏、向左/向右插入、删除。表头右边缘拖动改宽度，拖动表头换位置。
- **像表格软件一样用键盘**：点一个格子选中它（⇧ 加点击、⇧ 加方向键选一块，⌘A 全选）；方向键、Tab 在格子之间走；回车（或直接打字）开始改，单选、多选、日期回车打开选择框，勾选按空格；⌫ 清空选中的格子；⌘C 复制成表格文字，贴进 Excel、Numbers 就是一格一格的；⌘V 把 Excel 或别处复制的一块从选中的格子开始填进去（多出来的行自动新建，没有的选项自动加上，「是/yes/✓」算勾上，2026/1/5 这样的日期也认）。每一行只写一次文件、存一份历史版本。
- **一次选几行**：鼠标移到行上，左边出现小方框（⇧ 点选一串，表头的方框全选）；选中后工具栏下面变成「已选 N 行」：编辑属性（把某一列都设成一个选项、勾上/取消、今天，或清空）、复制（连表头复制成表格文字）、删除（问一次，可以撤销）、×。Esc 也能放开。
- **表格分组**：⋯ →「分组…」按一个单选或勾选列分组，每组一个标题（选项、行数），点 ▸ 收起；每组下面的「新建」带上这一组的值。记在块里（`tableGroup`），和看板的分组分开。
- **底部的计算**（像 Notion）：表格最下面每一列下有一格，鼠标移上去出现「计算」，按列的类型选：计数、已填、为空、不重复、已填/为空占比；数字还有求和、平均、中位数、最小、最大、范围；日期有最早、最晚、跨度；勾选有已勾选、未勾选、勾选占比。按筛选后看得到的行算，记在块里（`calcs`）。标题列默认是计数。
- **表格往右伸到编辑区边上**，横着滚时标题列留在左边；列菜单里「换行显示」让长文字、多个选项换行显示全。
- **格子**：点一下就能改。单选、多选在格子上弹出选择框，打字筛选，没有的直接新建；选项右边的 ⋯ 可以改名、删除（会改到每一行）。日期用日历选，也可以直接写 `2026-10-20`。勾选点一下就勾上。标题也能直接改，鼠标移到行上点「打开」进那个子页面。
- **行**：鼠标移到行上，左边出现 ⋮⋮：拖动排顺序（和左边页面树的顺序是同一个），点一下可以打开或删除。
- **新建**：表格下面的「新建」或右上角的「新建」加一行，就是在这一页下面建一个子页面（草稿）；「新建」旁边的小箭头选新页面用哪个模板。
- **筛选、排序、搜索**：右上角的按钮。筛选按类型来：文字「含 / 不含 / 是」，数字「= ≠ > <」，日期「早于 / 晚于」，单选多选「是其中之一 / 都不是」，勾选「已勾选 / 未勾选」，都可以选「为空 / 不为空」。用着的筛选和排序显示成工具栏下面的小标签，点开就能改。排序可以有好几条。
- **⋯**：哪些列显示，新页面用的模板，看板按哪一列分组。
- **看板**：按一个单选或勾选列分组，每个选项一列；卡片拖到另一列就改了它的值，拖到卡片之间就排了顺序；每列的「新建」带上这一列的值，最右边「新分组」加一个选项。
- **侧边预览**（像 Notion 的 side peek）：行上的「打开」、看板上点卡片，这一行从右边滑出来，表格还在旁边：标题直接改；每一列的值和表格里一样改；下面是正文（显示成页面上的样子，要改正文点「在整页里写」或右上角「整页打开」）；↑↓ 换到上一行、下一行；Esc 或 × 关上。⋯ →「打开方式」可以改成直接整页打开。
- **打开一行**：子页面的标题下面列出数据库的每一列和它的值（隐藏的列不列），在这里改也一样；选一个没有的选项，会加到数据库里。

数据都在 Markdown 里：列和视图写在这个 ```` ```database ```` 块里（JSON），每一行属于哪个数据库、值是什么写在那一页自己的属性里：

```yaml
database: "k3f9x2ab"
props: { "方法": "B3LYP", "能量": -76.4, "状态": "完成" }
```

所以 AI 或者手改子页面的 `props:` 也行，回到 Studio 表里就是新的。

## 文章里的文件：点链接打开

**`@` 插入**：正文里打 `@`（像 Notion 一样），弹出「插入」：先列这篇文章的文件，再列页面；打字筛选，也会找到正文里有这些字的页面和资料库里的文件。选中的放在光标处，和文字在同一段：页面是页面链接，文件是带类型图标的文件链接；资料库的文件先复制进这篇文章的 `assets/`（图片进 `img/`）。不想插了按 Esc，`@` 照样留着。紧跟在字母、数字后面的 `@`（邮箱 `a@b.com`）不弹；`[@` 照旧是引用文献。

文件链接**单独占一行**时显示成**文件卡片**：类型图标、名字、是什么（PDF、代码、数据、表格……）和多大；点卡片打开，⋯ 里有打开、用默认程序打开、在 Finder 中显示、历史版本、复制路径。**写在句子里**时，链接前面带一个类型小图标，和文字在同一段里。博客上也一样：单独一行的是可以下载的卡片，句子里的带图标。Markdown 里都还是普通链接 `[名字](./assets/文件)`。


脚本、数据表、文本（`.py`、`.sh`、`.js`、`.f90`、`.json`、`.yaml`、`.csv`、`.txt`……）、PDF 这类文件拖进文章，或从「文件」栏拖进来，是一个普通的链接，比如 `[opt.py](./assets/opt.py)`。在 Studio 里点它就打开，怎么打开看怎么点（和思源笔记的「资源打开方式」一样）：

| 怎么点 | 默认 |
|---|---|
| 单击 | 在 Studio 里打开：脚本、数据、文本在弹窗里看和改（行号、高亮、⌘F 搜索，⌘S 保存回文件，有改动直接关掉也保存，Esc 关）；PDF、图片（适应窗口、100%、放大缩小，双击切换）、音频视频、CSV/TSV 表格（「编辑文本」改它的文字）、Word/PPT/Excel 在弹窗里预览，旁边是历史版本、用默认程序打开、在 Finder 中显示。压缩包这类 Studio 看不了的，用默认程序打开 |
| ⌘ 单击 | 用默认程序打开（系统给这种文件定的程序：脚本是 VS Code 之类，PDF 是预览），和在 Finder 里双击一样 |
| ⌥ 单击 | 在 Finder 中显示 |

- 每一种点法换成哪种打开方式，在 **设置 › 打开文件** 里选，改了马上生效（存在这个浏览器里）。想像思源那样单击就用默认程序打开，把「单击」改成「用默认程序打开」。
- ⇧ 单击照旧是选中文字。要改链接本身，用键盘把光标移进去。
- 弹出窗口顶上也有「用默认程序打开」（先保存再打开）。
- 「文件」栏里双击文件和单击链接一样；右键有「编辑」「用默认程序打开」「在 Finder 中显示」。
- 博客上就是下载链接。
- 计算化学的输入输出（Gaussian/ORCA 输入、`.log`、`.out`、VASP 的文件）照旧把内容显示在文章里（见上面），它的顶栏也有「编辑」。

### 文件的历史版本

`img/`、`assets/` 里的文件被覆盖之前（替换上传、在弹窗里保存、恢复别的版本），先留一份旧的，像文章的历史版本一样（思源也这样做）：

- 存在文章自己的 `ai/history/files/` 里，不进 git，不发布。每个文件留最近 20 份；和上一份一样的不再存；超过 50 MB 的（比如 `.chk`）不存。
- 文件弹窗里的「历史版本」页签：左边是各个版本（什么时候、为什么留的），右边是那一版的内容，「恢复这个版本」放回去，恢复前的那份也会留着。
- 「文件」栏右键「历史版本…」：图片、PDF 这类不在弹窗里编辑的文件也能看、能恢复。

## 小程序

左侧「小程序」列出仓库根目录 `apps/` 里的小工具，点一个就在悬浮窗里打开：拖标题栏移动，拖四边或四角改大小，双击标题栏放大到整个窗口、再双击还原，下次打开还是原来的位置和大小；可以同时开几个。

- 现在有两个：**能量单位换算**（Hartree、eV、kcal/mol、kJ/mol、cm⁻¹ 互换，点「插入」把值以 `\pu` 写法插到光标处）和 **Gaussian 输入生成**（选任务、方法、基组、色散、溶剂，结构取自文章里的 XYZ 或粘贴；插进正文，或存成 `assets/` 里的 `.gjf`）。
- **让 AI 做新的**：在终端里说「做一个……的小程序」，它会照技能 `studio-mini-apps` 写进 `apps/<名字>/`（`app.json` 加 `app.html`），不用重启，左栏「小程序」页面里就有它的卡片，点开整页用，⧉ 在浮动窗口里用；改了代码点标题栏的 ↻ 重新加载。
- 小程序是作者自己的工具，不在沙盒里：跟 Studio 同一个来源（`/studio-apps/<名字>/`），自己文件夹里的文件和 `/vendor/` 里的库照普通网页加载，`studio.*` 的调用（读当前文章、插入、读写文章的文件、联网、在后台运行命令）全部直接可用，不用在 `app.json` 里申请权限。别的网站打开小程序的地址会被拒绝（按浏览器带的 `Sec-Fetch-Site`），只有 Studio 自己的页面和直接在地址栏打开时才给。
- 联网（`net`）只能访问互联网，不能访问本机和局域网（Studio 自己、路由器、本机的其他服务）。小程序里点开的别的网页用不了这些权限：Studio 会断开它，点 ↻ 回到小程序。
- 小程序只给自己用，不随文章发布；要随文章发布的交互内容用交互模块（```widget）。

## 书库（RetainPDF）

左侧「书库」（2026-11-02 以前叫「翻译」）在中间打开 RetainPDF 自己的页面：书库、上传翻译、阅读，和在 RetainPDF 里用一样。再点一下回到文章；切到别处再回来，RetainPDF 的页面还停在原来的地方。地址栏带 `?translate` 打开 Studio 时直接是这一页。

- **RetainPDF 要先开着**：桌面版或开发环境都行，Studio 不替它启动。默认地址是 `http://127.0.0.1:40001/`（RetainPDF 桌面版和开发环境的默认端口）；端口不一样就在设置 › RetainPDF 里改，存在笔记文件夹的 `.studio-settings.json`（`retainpdfUrl`）。
- **连不上**时中间写出用的地址，「重试」再连一次，「改地址」打开设置。
- 第一次点开才加载，Studio 启动时不去连它。
- 从别的设备（其他设备访问）打开 Studio 时，`127.0.0.1` 指的是那台设备自己，看不到这台 Mac 上的 RetainPDF。

**摘到笔记**：在 RetainPDF 的阅读页上，鼠标放在一段上，点「摘到笔记」，这一段就放进**这本书的笔记**（见下面「边读边记」）：笔记没开就在右边打开它。放在最后；在这页笔记里点过、写过以后，放在光标处。放进去的那一段滚到眼前、闪一下，右下角说一声「已摘到「…」」。

放进去的就是笔记里的普通段落：这一段的**译文**（没翻译的段落放原文；公式照样画出来），和自己写的字一样能改、能搜、能拖。唯一不同的是第一段右上角有一个小的 RetainPDF 标志，鼠标放上去说是哪本书第几页，点它这本书在笔记旁边打开、翻到那一页那一段（见下面「笔记旁边的书」；在「书库」里的书的笔记上点，是「书库」的阅读页翻过去）。

在 Markdown 里，出处是段落开头的一个链接，地址是 `retainpdf:任务编号/块编号?page=页&document=书的编号`：

````text
[Quantum Chemistry · 第 12 页](retainpdf:20261101112937-ad912a/p012-b0003?page=12&document=doc-1) 变分原理告诉我们……
````

- 编辑器把这个链接画成右上角的标志（`editor/retainpdf-source.ts`），存的时候照原样写回；删掉标志就只剩一段普通的字。`page` 从 1 数。
- 以前摘的是一个 ```` ```retainpdf ```` 代码块（原文、译文都在里面，显示成卡片）。打开时照上面的样子读成译文段落，下次保存就写成新的样子，块里的原文不再留在笔记里（点标志回到书里看）。
- 博客上没有 RetainPDF 可开：链接变成写在段落末尾的出处（`<cite>`，「书名 · 第几页」）。
- 两边用 `postMessage` 说话，格式是 RetainPDF 仓库里的契约 `contracts/studio-bridge.v1.schema.json`：Studio 加载 RetainPDF 时地址带 `embed=studio`，每次加载完说 `hello`（亮色还是暗色），RetainPDF 回 `ready`；之后 Studio 换亮暗色会告诉它，摘录是它发来的 `quote`。Studio 只认来自这个框、地址是设置里那个的消息（`wiring/retainpdf-view.ts`）。
- RetainPDF 还没有「摘到笔记」（旧版本）时，点标志照样能回到原文：直接打开它的阅读页地址。AI 回答里的 `retainpdf:` 链接点了也一样。

**边读边记（笔记）**：RetainPDF 阅读页上点「笔记」，右边出来这本书的笔记，用的就是 Studio 的编辑器；左边照样读，摘到笔记的段落当场出现在右边。中间的竖线能拖（宽度记在这个浏览器里），竖线中间的 › 或 RetainPDF 上再点「笔记」收起。

- 笔记开着时，右侧面板（文件、终端……）先收起来，笔记要地方；收起笔记或离开「书库」就回来（不改你设的布局，点右上角的按钮照样能打开）。
- 笔记窄，页头也跟着收紧：标题小一些，发布日期、类型、草稿/发布这些属性和「添加图标」「添加封面」不显示（单独打开这页时都在）。
- 顶栏写「翻译 › 这本书的笔记」，和打开一篇文章一样显示编辑时间、保存状态、页面菜单。
- 笔记开着时从页面树打开了别的页，再回到「书库」，右边还是这本书的笔记。
- 阅读页翻到哪一页，笔记里从这一页摘的段落就淡淡地铺一层底色、标志变深，一眼看到这页记过什么；离开阅读页就不标了。
- 从页面树单独打开一本书的笔记，顶栏「书」把这本书打开在笔记旁边，翻到上次读到的那一页（记在这个浏览器里）：见下面「笔记旁边的书」。

- 一本书一页笔记，都放在「读书笔记」下面：第一次唤出时新建（标题是书名，类型是「维基」，开头是空的，不是「从这里开始写作。」），以后按书找回同一页，改了标题、挪了位置也找得到。靠的是页面属性里的 `retainpdf:`：书的那一页写 `{ "document": 书的编号, "job": 任务编号 }`，「读书笔记」写 `{ "books": true }`（`server/retainpdf-notes.mjs`）。
- Studio 在 `hello` 里说自己认 `open-notes`，RetainPDF 才显示「笔记」；开着收着由 Studio 告诉它（`notes`）。

**笔记旁边的书**（以笔记为根）：笔记是根本，书是在笔记旁边打开的资料，一篇笔记可以开好几本，调研一件事时几本书对着看。任何一篇笔记，顶栏点「书」，左边出来这篇笔记的书，笔记在右边；再点一下（或竖线中间的 ›）收起。

- 这篇笔记摘过哪些书，就有哪些书，一本一个标签（照第一次摘的先后）；「书」是一本书的笔记时，那本书排第一。标签上的 ＋ 从 RetainPDF 书库里挑一本没开的（最近读的在前），× 关掉这本，以后这篇笔记就不再自动开它。开着哪几本、看的是哪一本、关掉了哪几本，按笔记记在这个浏览器里；书开没开着也记着，下次打开 Studio 还是那样。
- 打开「书」时右边栏（文件、AI……）先收起来，书和笔记要地方；收起「书」就回来（阅读页上的「AI」照样打开 Studio 的 AI，右边栏跟着出来）。
- 每本书是 RetainPDF 自己的阅读页（地址带 `embed_pane=beside`，阅读页就不出自己的「关闭」），第一次点到它的标签才加载，之后切走切回都不重新加载，停在原来那一页；最多留着最近看的 6 本，再多的下次点到时重新加载。同一本书在别的笔记旁边开着也是同一个，不重新加载。
- 点笔记里摘录右上角的标志：那本书在旁边打开（没有它的标签就加一个），翻到那一段；笔记不动。
- 在旁边的书里「摘到笔记」，放进**这篇笔记**：在这篇笔记里打过字以后放在光标处，没打过放在最后（光是点了标志不算）。旁边的书没有自己的「笔记」按钮，笔记就在旁边。
- 看的那本书翻到哪一页，笔记里从这一页摘的段落照样淡淡标出来；问 AI 时它知道你在看哪本书、第几页，笔记就是这一篇。
- 「书库」里照旧是 RetainPDF 的全部页面（书库、上传翻译、进度、阅读），在那里点「笔记」照旧是这本书自己的那页笔记。

**AI 读书**：Studio 的 AI（AI 面板里的、Claude Code 通过 MCP、终端里的 `studio` 命令）能读 RetainPDF 书库里的书：列书、在书里找字、读某几页的原文和译文、取一段（操作见 [给大模型用的接口](ai-tools.md) 里的 `list_books`、`search_books`、`read_book`、`read_passage`、`reading_now`）。

- 在「书库」里读书时问 AI，它知道你在读哪本书、第几页、这本书的笔记是哪一页：「这一页讲了什么」「把这段的推导记到笔记里」都是对着眼前这一页。RetainPDF 阅读页翻页停下来会告诉 Studio（契约里的 `reading`），Studio 的服务器记着最后一条（`server/retainpdf-reading.mjs`），每次问 AI 时附上；离开「书库」或离开阅读页就不附了。旧版本的 RetainPDF 不说读到哪，那时只在打开这本书的笔记以后知道是哪本书。
- 只有一个 AI：放在 Studio 里时，RetainPDF 阅读页右边的「AI」不再打开 RetainPDF 自己的终端，而是打开 Studio 的 AI 面板（笔记开着也一样，右侧面板回来、停在 AI 上）。RetainPDF 先说读到哪一页、再说要问 AI（契约里的 `ask-ai`；Studio 在 `hello` 里说认它，旧版本的 Studio 不说，阅读页照旧打开自己的终端）。
- 读到某一页时，AI 面板空着的时候给的几个问法是对着这一页的（「讲讲这一页在说什么」「这一页的公式是怎么推出来的」……），上面写着它读得到哪本书、第几页；不在阅读页时照旧是对着文章的。
- AI 把书里的一段写进笔记时，用的是和「摘到笔记」一样的写法（`read_passage` 给的 `quote`）：普通段落，右上角的标志点了回到原文。
- AI 走 RetainPDF 的只读接口（`GET /api/v1/documents`、`/api/v1/search`、`/api/v1/documents/:id/reading`、`/api/v1/jobs/:id/reader/regions`），由 Studio 的服务器去问（`server/retainpdf-library.mjs`），不改 RetainPDF 里的任何东西。
- **接口地址和 API 密钥不用填**：Studio 的服务器从 RetainPDF 自己的页面找（和「书库」里的阅读页用的一样）：先读它的 `runtime-config.js`、`runtime-config.local.js`（开发环境的服务器会把后端的密钥写进后一个），再读页面本身（桌面版把配置写在页面里），里面的 `apiBase`、`xApiKey` 后说的算；没写接口地址（或者写的是一段算出来的代码）就和 RetainPDF 的页面一样，用同一台机器的 41000 端口（https 的页面用它自己的地址）。找到的记 30 秒；RetainPDF 说密钥不对或者连不上时马上再找一次，所以先开 Studio、后开 RetainPDF 也行（`server/retainpdf-settings.mjs`）。
- 设置 › RetainPDF 里写着找到的接口地址、有没有找到密钥。自己填了**接口地址**、**API 密钥**就用填的（存在 `.studio-settings.json` 的 `retainpdfApiUrl`、`retainpdfApiKey`）。密钥不管是找到的还是填的，都只有 Studio 的服务器用，不发给页面，设置页上不显示出来。「测试连接」看连不连得上。

## PDF 识别成子页面（PaddleOCR）

把 PDF 拖进正文（它会变成一行指向它的链接），点这一行左边的手柄 →「OCR 成子页面（PaddleOCR）」；或者在文件面板里右键 PDF → 同一项。

- 马上在当前文章下面建一个子页面，标题是 PDF 的文件名，PDF 那一行下面多一行指向它。PDF 留在原处，不复制：放在 `ai/` 里的 PDF 不会因此被发布。
- 识别在后台进行，右下角能看进度和日志。几百页的书要等一阵（最多等两小时）。等的时候可以在子页面里先写东西，识别结果会接在后面，不会覆盖；识别失败或取消，子页面上会写明。
- 识别完，子页面里是识别出的文字：标题、段落、公式（转成 `$…$` 和 `$$`）、表格（转成 Markdown 表格，有合并单元格的保留 HTML）、图（放进子页面的 `img/ocr/`，图下的「图 1 …」变成图注）。很长也没关系，长文章会分段显示。
- 用的是本机的 `paddleocr api` 命令（PaddleOCR 官方的在线文档解析），需要先装好 `paddleocr`，并在终端环境里设好 AI Studio 的 token：`PADDLEOCR_ACCESS_TOKEN`。

  - 页面右上角的 ⋯ 菜单 →「历史版本…」按天列出，选一份「对比并恢复」，逐处接受或拒绝。
  - 自动存档：一天内的全留，30 天内每天留最后一份，每篇最多 50 MB；其他的留最新 50 份。

## 编辑器里的 AI

像 Notion 一样，在正文里直接让 AI 改写或续写：

- **改写**：选中一段（或者光标放在某一段里），按 ⌘J，或者点选中文字上方工具栏最后的「AI 改写」、块菜单里的「AI 改写…」。弹出的小框里可以直接输入要求，也可以选现成的：改得更通顺、更简洁、扩写、修正错别字和语法、翻译成英文或中文、改成要点列表。
- **续写**：在一个空行上按空格，弹出同样的框（接着写下一段、写一个小结、列出要点、举个例子，或者自己写要求），AI 写的内容放在这一行。
- AI 写好以后，结果直接显示在原处，和审阅磁盘改动一样逐处标出来，可以一处一处接受或拒绝。上方的条可以「全部接受」「全部拒绝」；逐处决定过一些以后，这两个按钮变成「其余接受」「其余拒绝」，只管还没决定的（比如留下几处，其余一键拒绝）。不满意点「重试」再写一遍。接受的部分和平常的编辑一样保存。
- 用的是 AI 面板里选的那个 AI 和模型（以及「模型和账号」里的设置）。后台会先把它准备好，所以通常几秒就有结果；写的时候小框里显示用了几秒，按 Esc 可以停下。
- 框里最后一项「在终端里问 AI…」是原来 ⌘J 的做法：把选中的几行写进终端，交给终端里的 AI。

- **空的对话不留**：新开的对话在你说第一句话之前不列出来，也不存进 `chats/`；点「＋」时当前这个一句没说，就直接关掉，不会留下一个个空的「新对话」。

- **显示什么**：
  - 它的回答，Markdown 和公式照常显示，一块一块的（段落、公式、列表的每一项、代码、表格，和编辑器里一样）：鼠标移上去左边有「⋮⋮」，拖到文章里就放在那里，点一下放在光标处；回答下面的「插入到文章」把整段放进去，「复制」复制它的 Markdown；
  - 「思考过程」，折叠着，点开看；
  - 每次调用工具一行：运行命令（显示命令本身）、读文件、搜索、改文件，右边是状态（等待、转圈、✓、✗）；点开看命令输出，改文件看删掉和加上的行；
  - 它列的计划，做一项勾一项；
  - 要你允许的事：显示要运行的命令，「允许 / 总是允许 / 拒绝」。
- **输入框下面**：用哪个 AI（换一个就开新对话），什么要问你，用哪个模型，思考多深。选过的会记住，下次新对话照样用。右边是用掉的上下文和这次对话的花费。
- **什么要问你**（Claude Code）：
  - 每步都问；
  - 自动改文件（命令要问）：改文件不问，但运行做事的命令（python、删除、安装）照样会问；
  - 自动（只问危险的）：Claude 自己判断，只有危险的才问；
  - 全部允许（不再问）；
  - 只做计划：先列计划，不动手。
  
  Codex 的四档是：只读、可改文件夹（联网要问）、自动（只问不安全的）、完全访问。

- 它改了正打开的文章时，和终端里的 AI 一样，Studio 把改动逐处标出来让你接受或拒绝。它边做边改的时候不打扰你（提示一句「AI 在改这篇文章，做完后一起给你过目」），这一轮做完（或你停下它）再把所有改动一起标出来。审阅还没做完时文件又被改了，审阅马上换成最新的版本。

- **图片**：回答里用 `![图](路径)` 放的本机图片（比如 AI 用 Python 画好存在 `ai/work/plot.png` 的图）直接显示出来，绝对路径或相对 `blog/` 的路径都行（`blog/AGENTS.md` 告诉了 AI 这样给你看图）。AI 当附件发来的图存进 `chats/<对话>/ai/pictures/`，也显示在回答里。AI 用读文件工具看过的图，在那一段过程的行上显示小图，点开弹窗里是大图。回答里的图缩小显示（最宽 420、最高 300 像素），点一下看大图。把带本机图片的块拖进文章（或点「插入」），图会先复制到这篇文章的 `img/`，链接改成 `./img/…`，文章里照常显示。
- **插件的块**：回答里的分子（SMILES 等 2D、XYZ 等 3D，可以转）、能量图、交互模块、书签，和编辑器里画得一样，拖进文章就是那种块；3D 分子在回答里没有「保存视角到文章」。计算块、结果卡片、视频在回答里显示为代码，拖进文章后照常是卡片。
- **回答里能操作的小界面**（像 ChatGPT、Claude 对话里的小应用）：AI 可以在回答里写一个交互模块（```widget），给你滑块、选项、按钮。
  - 模块里点「重算」这类按钮，会替你对 AI 说一句话（`note.ask`），出现在对话里，就是你说的；AI 正在做事时排在后面。只有你点了、按了键才算，模块自己发不出去，两次之间至少隔两秒。
  - 你调的值，模块可以交给 AI（`note.tell`）：不发消息，你下一次说话时一起告诉它，你那条消息下面标着「交互模块：标题」。只告诉一次，之后再说话不重复。
  - 模块右上角有放大按钮，在大窗口里操作（Esc 或 × 关掉）；放大后调的值，回到回答里接着用。换对话再回来也一样（Studio 重新打开后从头开始）。
  - AI 还没写完这个模块时，那里只显示「正在写交互模块…」的框，不会运行写了一半的代码。
  - 文章里的交互模块也能 `note.ask`：点了以后话放进 AI 面板的输入框，由你决定发不发。博客上没有 AI，`note.ask` 什么也不做。
- **交互模块出错了**：Studio 里（文章和回答里都是）模块下面用红字写出错在哪（「交互模块出错了：第 4 行：T is not a function」，行号是模块源码的第几行；脚本没加载到也会说），改好重新运行后就消失。博客上的读者看不到。
- **AI 自己验交互模块**：`check_widgets`（命令行 `studio check-widgets --slug …`）在后台浏览器里把文章的交互模块真的跑一遍，告诉 AI 报错和行号、显示的字、画布是不是空的，给它一张截图（存在文章的 `ai/shots/`，不发布）。AI 写完、改完模块先跑它，不再自己截图、写桩测试。
- **过程收成一行**：AI 回答前后的思考、读文件、运行命令、改文件、计划，每一段合成一行灰色的小字，比如「⚙ 思考 · 读了 8 个文件 · 运行了 2 个命令 · 改了 index.md ›」；正在进行时这一行写着当前这一步（「正在运行 python opt.py」，带转圈），有失败的步骤会标出「1 步失败」。点这一行弹出窗口看这一段的细节（思考内容、每条命令和输出、改了什么、计划），Esc 或点外面关掉。要你允许的请求、出错、停下了，照常显示在对话里。
- **它在等你、做完了**：AI 面板不在眼前时（换到了别的页签、面板收起来了、窗口在别的程序后面），AI 要你批准、问你问题，或者这一轮做完了，AI 页签上出现一个黑点，窗口标题前加「● 」，下面弹一句「AI 在等你：…」/「AI 做完了：…」，点「去看看」回到面板；看到面板后都消失。做了 10 秒以上，输入框上方写着做了多久（「正在做… · 1 分 05 秒」）。
- **停下、出错、重启**：一轮结束时还没做完的步骤（停下了、出错了、Studio 关了，或者 AI 没报它做完）标成灰色的「已中断」，子代理也一样，不再一直转圈。按了停止 10 秒还停不下来（适配器卡住、模型不回应），Studio 强制停下它，对话里说一声，再说话时重新接上。pi 连不上模型时会自己重试，对话里写着第几次、几秒后再试，试完还不行也会说。
- **子代理**（pi 的 subagent 扩展：`~/.pi/agent/extensions/subagent`，派 scout、planner、worker 这些代理去做事）：每次派出去的子代理在对话里单独一张卡片，不收进上面那一行。
  - 卡片标题写着是一个、几个并行（「3 个子代理并行」）还是接力；右上角是完成了几个、失败了几个。
  - 每个子代理一行：转圈（在做）、○（准备中）、✓（完成）、✗（失败），名字、任务、用了多久（在做时每秒跳）。下面一行是它此刻在做什么（正在运行的命令、读的文件），失败了是原因（红色）；右边是调用了几次工具、用了多少 tokens、花了多少钱。
  - 点一行展开：完整的任务、用的模型、它的每一步（最近 40 步）、它最后说的话。
  - 输入框上方的状态写着「正在做… · 2 个子代理在跑」。
  - 这是 Studio 自己跑的 pi 才有的（AI 面板里选 pi）；Claude Code、Codex 的子代理还是收在那一行里。

### AI 问答（整页）

左边栏上方可以在「页面」和「AI 问答」之间切换（像 Notion）。「AI 问答」把右边的 AI 面板**本身**挪到中间、放宽（右边的「AI」页签这时收起来），左边列表换成所有对话（最近的在上面）；「页面」把它放回右边，中间回到文章。AI 面板顶上的「显示方式」按钮（像 Notion 的 AI 聊天）有三种：**侧栏**（在右边的「AI」页签里）、**悬浮**（浮在 Studio 上面，拖顶栏移动、拖边和角改大小，下次打开还在那里，写文章、看页面时一直开着）、**全屏**（就是「AI 问答」）；还有**新窗口**：AI 变成一个单独的窗口，能拖到别的屏幕、和别的软件并排，它照样知道 Studio 里打开的是哪篇、选中了什么，能把内容插进文章；这时 Studio 里的 AI 收起来，关掉那个窗口就回来（在那个窗口的「显示方式」里也能放回侧栏、悬浮、全屏）；它在那边改你打开的文章时，和在 Studio 里一样，先攒着，做完一起给你逐处过目。选的侧栏或悬浮会记住；从全屏回到页面时，它回到原来的侧栏或悬浮。新窗口要 Studio 开着才能用。

- 回答里插件的块也画出来：能量图、分子、交互模块……和编辑器里一样。

## 终端和 AI

右边的「终端」面板是一个真正的 shell，可以开在仓库根目录、当前文章的文件夹或资料库里。

**启动 AI**：终端上方的「启动 AI：Claude · Codex · pi」，点一下就在当前文章的文件夹里（没打开文章时在仓库根目录）开一个新的终端，启动那个 AI。这台机器上没装的按钮是灰的，鼠标放上去能看到怎么装。终端里正有程序在跑时，会先问一声。

**AI 助手设置**：终端那一行最后的 ⚙。每个 AI 有三条命令：终端里启动、Alt+Enter 后台跑一次、Alt+Enter 接着上次（`{prompt}` 换成交给它的话）。预先填好了 Claude、Codex、pi，可以改，也可以添加别的（比如 omp），并选 Alt+Enter 默认用哪个。只存在这台电脑上。

**Alt+Enter：把一件事交给 AI**：在正文里写一句要做的事，比如「画一个 sin x 的图，横轴 0 到 2π」，光标放在这一行，按 Alt+Enter。

- 选中的 AI 在这篇文章的文件夹里后台去做，这几行变灰，写着「AI 处理中…」；右下角列出后台任务，能看日志、能取消。
- 交给它的只是这几行和它们的位置（第几行、在哪一节），不是整篇文章；它要更多上下文会自己去读。
- 默认接着这篇文章文件夹里最近的会话，所以它记得刚才做过什么（这篇文章里第一次用时，没有可接的，就开一个新的）；⇧Alt+Enter 是另开一个新会话。同一篇文章里连按几次，会排队一件一件做，不会两个 AI 同时改它。换了 AI 也接得上：每次做的事都记在文章的 `ai/work/log.md`，用到的脚本、数据也放在 `ai/work/`。
- 做完，它把这几行换成结果（图、表、公式……），像别的外部改动一样逐处让你接受或拒绝。
- Claude 的预设开了沙箱：只能写这篇文章的文件夹，不能联网。Codex 的预设是 workspace-write。pi 没有沙箱：它能改这台电脑上你能改的任何东西。文章里如果有别人写的文字（OCR 出来的书、资料库里的文件），里面混着的指令可能被它照做，处理这类文章时用 Claude 或 Codex 更稳妥。
- 停掉 Studio（关掉应用，或在终端里 Ctrl+C）时，还在跑的后台任务会一起停掉。

在终端里用 AI 时：

- 终端设好了 `STUDIO_ARTICLE`（当前文章的文件夹名）等环境变量；
- 可以直接用 `studio` 命令操作页面，见[给大模型用的接口](ai-tools.md)；
- AI 改了正打开的文章时，Studio 会把改动逐处标出来，让你接受或拒绝。

**规则、技能、偏好**：用哪个 AI 都读同一份，换着用不会忘：

- **写作约定**：笔记文件夹里的 `blog/AGENTS.md`。Codex、pi 直接读它，Claude Code 经由同一文件夹里只有一行 `@AGENTS.md` 的 `CLAUDE.md` 读它。在文章文件夹里打开时，它们都会往上找到它。
- **技能**：写法细节和做事的步骤（分子、计算输出和能量图、交互模块、引用文献、资料库），在仓库根目录的 [.agents/skills/](../.agents/skills/)。用到时才读，不占地方；Claude Code 从指向同一处的 `.claude/skills/` 读。AI 做完一件以后还会再做的事，会问你要不要存成新技能。
- **你的偏好**：你纠正 AI 的写法、或者说「以后都……」，它会记进仓库根目录的 `.agents/memory/preferences.md`，下次不管用哪个 AI 都先读它。这个文件只在本机，不进 git，可以直接打开改。
