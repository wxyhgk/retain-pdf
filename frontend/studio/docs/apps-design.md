# 在 Studio 里造应用（设计）

作者经常做小组件、小应用（比如结构式编辑器 structura）。以前要在别处单独开发，做完再集成进笔记。目标是**在 Studio 里直接开发，做好就能在笔记里用**，像 Emacs 那样：用和改是同一件事，改了立刻生效，做出来的东西就是一个可以复用的包。

这页是 2026-10-28 调研和讨论后定下的方向（6 份调研：笔记软件的先例、一个宿主跑多个 Vite 项目、组件同时在编辑器和博客里用、AI 造应用和实时预览、第三方扩展的安全与分发、Emacs 和「可塑软件」；再由两个方案互相评议）。

## 作者眼里只有两种东西

- **应用**（原来的「小程序」）：`apps/<名字>/` 下的一个文件夹，在悬浮窗里打开，能用 `studio.*`（读写文章和它的文件、往正文插内容、代发请求、跑命令）。它可以是
  - 一页网页：`app.json` + `app.html`，改了保存，窗口自己重新加载；
  - 一个完整项目（React、TypeScript、npm 包、WASM、自己的后端）：`app.json` 里写 `dev`，Studio 用项目自己的开发服务器跑它，改了热更新。
- **模块**：文章里的块。现有的 ```` ```widget ```` 不变；以后应用也能提供自己的块（第二阶段）。

「包」「权限」这些是内部的东西，作者不用学。清单一直是 `app.json`，字段只增不改，没认识的字段一律忽略，所以以后加功能不用推倒重来。

## 项目型应用（第一阶段）

```json
{
  "name": "结构式编辑器",
  "icon": "⬡",
  "description": "画键、稠环，导出 MOL",
  "width": 1000,
  "height": 700,
  "dev": {
    "command": ["npm", "run", "dev", "--", "--port", "{port}", "--strictPort", "--base", "{base}"],
    "backend": ["npm", "run", "backend"]
  }
}
```

- `dev.command`：启动它的开发服务器。`{port}` 换成 Studio 挑的空闲端口，`{base}` 换成 `/studio-apps/<名字>/`。
- `dev.backend`：可选，它自己的后端，另起一个进程。
- `dev.cwd`：在哪个文件夹里运行，默认是应用自己的文件夹。项目在仓库外面（structura 有自己的仓库）时，写在**不提交的** `app.local.json` 里：

  ```json
  { "dev": { "cwd": "/本机/路径/structura" } }
  ```

  `app.local.json` 的字段盖过 `app.json` 的同名字段。提交的 `app.json` 里写了绝对路径，Studio 会说出来，不运行它（仓库是公开的）。

Studio 怎么跑它：

- 打开它的窗口时才启动（文章里提到它不会让它自己跑起来），关掉 Studio 时一起停。程序在自己的进程组里，崩了不会带走 Studio；崩了窗口标题栏显示「已停止」，点「重启」再起。
- 页面挂在 Studio 同源的 `/studio-apps/<名字>/` 下（反向代理，热更新的 WebSocket 也转过去），所以 `studio.*` 照样能用，React 版本和 Studio 的互不相干。Studio 在它的网页里加上 `studio` 桥和颜色变量。
- 它自己的请求要带上 base：用 `import.meta.env.BASE_URL` 开头，不要写死 `/api/…`（写死的会打到 Studio 上）。
- 输出留在窗口的「日志」里（最近几百行）。

## 出错交给 AI（第一阶段）

窗口里的网页出错（没接住的异常、Promise 拒绝、`console.error`、脚本加载失败），标题栏出现红点和次数。点开能看到错误，「让 AI 修」把应用名、它的文件夹、错误和最近的日志放进 AI 面板的输入框，作者看过再发。技能里规定 AI 自己修三次还不行就停下来问作者。

## 应用的块（第二阶段）

应用在 `app.json` 里写 `blocks`，文章里就能用它的块：

```json
"blocks": [{ "fence": "structura", "entry": "block.html", "height": 460, "title": "结构式" }]
```

- 文章里是 ```` ```structura ````（info string 里可以写 `height=…`），**正文就是块的状态**（structura 的是它的文档 JSON），所以文章还是纯 Markdown。斜杠菜单里按 `title` 找得到。
- 编辑器里，块显示成应用的页面 `entry`（同源 iframe，有 `studio`），页面用 `studio.block.get()` 读状态、`studio.block.set(状态)` 写回正文、`studio.block.picture(SVG 或 PNG 的 data: 地址)` 存博客上用的图。页面自己写回的改动不会让块重画（框不会重新加载）。项目型应用没启动时，块上是「启动」按钮，不会自己启动。
- 块下面一条：由哪个小程序画、↗ 在窗口里打开、「AI」让 AI 改它（出错时有红点）。
- 博客上，块就是它的图：`assets/<块名>-<内容的哈希>.svg`（或 .png），由内容算出名字，内容一变就是另一张，旧的那张进回收站（别的块还用着就不动）。还没有图时块不显示，发布前检查会提醒（`app-block-picture`）。插件 `plugins/app-blocks/`。

## 检查点、看源码（第二阶段）

- 小程序窗口标题栏的 ⋯：看源码（在访达里显示它的文件夹）、让 AI 改这个、存一个检查点、回到检查点。
- 让 AI 改之前（「让 AI 修」「AI」「让 AI 改这个」）自动存一个检查点。检查点是应用文件的一份拷贝（git 会管的那些：跟踪的和没被忽略的新文件，不含 node_modules、dist、.claude 之类，单个不超过 5 MB），放在 `.studio-cache/app-checkpoints/`，每个应用留最近 12 个。回到某个检查点时，先把现在的样子也存一个，所以回去也能撤销。

## 新建、命令、AI 的工具、能运行的代码块（第三阶段）

- **新建小程序**：「小程序 → 新建小程序…」或 ⌘K `> 新建小程序`：起名、选模板（一页网页；Vite + React + TS 项目，用仓库已有的 React 和 Vite，建好就能跑），建好就打开，并把「做小程序……我想要：」放进 AI 面板。模板在 `src/studio/server/apps/templates/`。
- **`studio.*` 清单**：`STUDIO_CALLS`（mini-apps.mjs）、技能 studio-mini-apps 的表、React 模板的 `studio.d.ts` 三处一致，测试管着。
- **AI 的工具**：`list_apps`（有哪些小程序、代码在哪、给了什么块）、`app_status`（开发服务器在不在跑、最近的输出、页面最近的错误：窗口和块里出的错都报给服务器）。
- **命令（Emacs 的 M-x）**：⌘K 输入 `>` 列出所有命令：插件的、每个小程序的「打开」、小程序在 `app.json` 的 `commands` 里给的（打开窗口停在某个页面）、「新建小程序…」。
- **能运行的代码块（org-babel）**：插件 `plugins/run-blocks/`。python、sh、js、R、julia 的代码块，⌘⇧↵（在块里）、块菜单「运行」或 ⌘K `> 运行` 就在文章的文件夹里跑（经登录 shell，最多 10 分钟），输出写在下面的 ```` ```output title="运行结果" ````，再跑就换掉。顺带：插件的块菜单可以叠加（每个插件拿到前面留下的再加），插件可以登记不认领代码块名的块（只加菜单）。

## 最小启动

怎么改都得能用：插件坏了只算它自己失败，安全模式不载入插件，Studio 自己的代码改坏了就用上次能正常启动的版本打开。细节见 `docs/development.md`「最小启动」。

## 不学的

Emacs 的 advice（随便包住别人的函数）、全局可变状态、一上来全量加载；以及「花时间调工具不写文章」——每个应用都从一次写作的需要出发，用不着就扔。
