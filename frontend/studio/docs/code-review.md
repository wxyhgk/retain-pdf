### P2：健壮性

- 后台任务在 `Ctrl+C` 停掉开发服务器后还在跑（任务在独立进程组里）；取消只发 SIGTERM，不升级到 SIGKILL。
- 同一篇里连按两次 ⌥↩ 会起两个 agent 同时改 `index.md`；选中的内容太长会超过命令行长度上限。
- 需要核实：一个从没跑过 agent 的文件夹里，`codex exec resume --last`、`claude -p --continue` 会不会报错。⌥↩ 默认就是「接着上次」。
- 传文件的管道、终端子进程的写入、终端输出的 JSON 解析，有几处出错没处理，可能让开发服务器崩溃。
- 提交时文件夹已经被删（vanished），会让 git 报错，之后每次提交都失败。
- ~~`/studio-apps/%ZZ/` 这类坏地址会让请求一直挂着~~（已修 27df566）；同一秒发起两次 PDF 识别，文件夹名会冲突。
- PDF 识别的格式转换有几处边界情况：两个相邻的居中块、`$ 5` 这样的货币、表格里的 `|`、带空格的图片名、嵌套的 div、一行两个公式。
- `commandWords` 处理双引号里的反斜杠和全角空格，和 shell 的规则不一样；fish 这类非 POSIX 的 shell 下，任务和「找 AI 命令」都用不了。
- pi 没有沙箱，⌥↩ 时它会读文章；文章里如果混进别人写的指令（OCR、资料库的文字），可能被它照做。
- 打开文章时服务器把全文发了两遍（旧字段 `content`、`hash`）。那篇 500 页的文章每次要传 1.27 MB，其实只需要 0.62 MB。

### P3：耦合，重构时再做

依赖图里**没有循环**。`packages/` 和 `plugins/` 都没有反过来依赖 `src/studio`。`document/`、`state/` 和后端各个模块分得很干净。问题集中在几个「大杂烩」：

1. `StudioPage.astro` 里有 970 行 CSS 和整个界面的 id，18 个模块去查 108 个 id。CSS 应该跟着各自的功能拆开。
2. `studio-dev.mjs` 把约 60 个接口挤在一个函数里，安全检查靠一个个手动加（有 3 个漏了内容类型检查）。应该按领域拆成多个文件，交给统一的路由，检查在一个地方做。这一步也是 P0 第 5 条的根本解法。
3. 前后端的接口约定靠手写，已经对不上了：多余的旧字段、`retitled` 没有被用上、`HistoryReason` 写了两份；后台任务的类型靠字符串，页面标题靠从任务名里去前缀拿。
4. Markdown 的语法配置散在六处，配置还不一样。比如反向链接没开 GFM，正文里裸写的 `https://…/blog/x/` 不会被算作反向链接，改名时也不会跟着改。
5. 服务器和 CLI 各自组装同一套服务；「转成子页面」有两种实现，CLI 版遇到标题里有 `]` 会生成坏链接；新页面的文件夹名在页面里有四处各自生成。
6. 越层引用：CLI 和服务端引用了 `workspace/page-names.ts`、`editor/split-section.ts`；编辑器引用了全局的插件注册表。
7. 已有常量没被用上：`/blog/${slug}/` 硬写了 7 处、`img|assets` 硬写了 6 处；插件快捷键的保留表漏了 ⌥↩。
8. `main.ts` 混着六类事，还依赖声明的先后顺序。拆法：页面的新建和打开、AI 相关的动作、文献库、插件宿主、视图切换。
9. `inline-math.ts`（1317 行）可以机械地拆成几块；它自己又写了一套公式切分规则，和 remark-math 不一致。
10. `studio-editor.ts` 应该拆成 Crepe 配置、长文章分段加载、审阅、⌥↩ 标记几块。
11. 目录、滚动锚定、页面快照读的是编辑器的 DOM，不是文档本身。所以折叠块、分栏里的标题不在目录里。
12. 「这次写入是 Studio 自己发起的」要靠约 15 处调用各自记得包一层，应该收进 `client.ts` 里统一处理。
