# 恢复备份期间不建任务、不收上传（2026-10-28）

[备份恢复和同步脱离请求](../api-reorg/20261022-备份恢复和同步脱离请求.md)"没做"里的第一条："「恢复中」标记、建任务入口 409"。
用户 2026-10-28 让做。

## 问题

恢复备份要几秒：检查备份（解压、完整性、版本）、存一份恢复前备份、在副本上补结构、最后一步换库。换库前会再查一次有没有排队、
在跑的任务（`restore_blocked`），但查完到换库之间、以及这几秒里别的时候：

- 新建的任务：行被换库盖掉，任务目录却建了，变成没有记录的目录；
- 上传：上传记录和书被盖掉，文件留在 `uploads/` 里（48 小时后孤儿清理也找不到它，因为清理是按库里的记录删的）。

## 做法

- 数据库包 `Db` 加一把进程内的读写锁 `restore_gate`（同一个 `Db` 的克隆共用）：
  - `Db::begin_restore()`：恢复拿写锁，守卫丢掉就算结束；
  - `Db::hold_off_restore()`：建任务、上传落库前 `try_read`，恢复中立刻返回 `RestoreInProgress`（不等），否则守卫拿到落库完。
- 平台包 `restore_in_place` 一开头 `begin_restore`，拿到换库完。正在建的任务、上传（拿着读锁）先做完才开始；它们建出来的任务
  在换库前那次复查里照样挡住恢复（`restore_blocked`），上传则正常落库后被换库盖掉——这一点没变，但窗口只剩"恢复开始前已经在
  落库"的那些。
- 入口：任务包 `submit_job`（所有新建任务都走它）、`relaunch_in_place`（原地重跑）；入口包 `publish_upload`（上传落库前，在硬链接
  共用之前）。拒绝时回 409 `restore_in_progress`：任务在建目录之前就拒，上传的临时目录随 `PendingUpload` 删掉。
- 锁是同步的 `std::sync::RwLock`：`submit_job`、上传落库都在阻塞线程里跑，恢复也在阻塞线程里，守卫不跨 `await`。

## 没做

- 只管本进程：jobsd 不建任务（只跑 rust_api 建好的），CLI 离线恢复时服务不该开着。
- AI 对话写消息、改术语表、改书的元数据、同步收进来的改动这些别的写入不挡：这几秒里写的会随换库丢掉。AI 先不管；同步在恢复期间
  本来就停着。
- 前端没有专门的提示（交接文档写了可选做法）。

## 验证

- 数据库包：`work_is_refused_while_a_restore_runs_and_allowed_again_after`（克隆共用、恢复完放开、读锁之间不互斥）、
  `a_restore_waits_for_work_already_in_progress`。
- 平台包：`a_restore_waits_for_work_already_holding_off_the_restore`：有人拿着读锁时，整个恢复（`BackupService::restore`）等着，
  放开后恢复成功、锁重新打开。
- rust_api：`api_tests::restore_in_progress`：恢复中建任务、上传都 409 `restore_in_progress`，没有任务行、任务目录、上传目录；
  恢复结束后同一个请求 200。
- 反向检查：去掉 `restore_in_place` 里的 `begin_restore`，平台包那条红；去掉 `submit_job` 里的 `hold_off_restore`，rust_api 那条红；
  放回来都绿。
