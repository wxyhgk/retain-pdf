# OCR 框略微超出页边时夹回页内（2026-10-29）

[OCR 归一化的快照守卫](./20261029-OCR归一化快照守卫.md)里人造样例查出的第 1 个问题，用户让先修。

## 问题

OCR 的坐标有取整误差，块常常超出页边一两个单位。适配器出来以后、缩放之前就跑校验（`adapters.py` 的 `adapt_payload_to_document_v1_with_report`
里 `build_validation_report`），校验要求块在页内（容差 0.001），超出的一个块就让整份文档校验失败、任务直接失败：

- `mineru_rare_labels_geometry` 的被拒版本：一个块的右边超出 1.5 点，`$.pages[0].blocks[12].geometry.bbox: must stay within page bounds [0, 0, 612.0, 792.0]`；
- `paddle_rare_labels_geometry` 的被拒版本：页脚右边超出 2 像素，`$.pages[0].blocks[3].geometry.bbox: must stay within page bounds [0, 0, 1224.0, 1584.0]`。

适配器不会把块夹回页内（MinerU 只把行、片段夹进块里：`mineru/geometry.py` 的 `clamp_descendant_bboxes`）。

## 做法

新模块 `document_schema/page_bounds.py` 的 `clamp_page_overflow`，在适配器里补完契约字段之后、第一次校验之前跑（坐标还是 OCR 自己的单位，按 OCR
自己的页面尺寸比）：

- 只夹"略微"超出的：每条边超出不超过页面那一边长的 1%（`PAGE_OVERFLOW_TOLERANCE_RATIO`；612 点宽的页是 6 点、1224 像素宽的是 12 像素）。超得
  更多的不动，让校验照样报错——那多半是单位弄错、配错了页，不该悄悄藏起来。
- 块夹了以后，行、行里的片段、块的片段跟着收进块里（校验要求它们在块内）；整个落在块外的不动，照样让校验报出来。
- 夹过的块 `metadata.page_overflow_clamped = {"original_bbox": [...]}`；文档 `derived` 和报告记 `page_overflow_clamped_block_count`。没夹的文档
  一个字都不改（9 份快照不变）。

这一步将来归到拆分方案里的"几何"层（只依赖标准库）。

## 验证

- `test_page_bounds.py`（4 个）：右边超出 2 点连行、片段一起夹回；左上角是负坐标的夹到 0；超出页宽 5% 的不动；页内的块一个字都不改。
- 快照守卫：两个被拒版本改名 `raw_page_overflow.json`，测试改成"夹回页内而不是失败"：能归一化、报告记 1 个、那个块贴着页边、原来的框记在元数据里、
  块数和不越界的那份一样。9 份快照不变。去掉这一步，这两个测试红。
- `document_schema` 测试 311 个全过；全套合并前检查和管线、翻译测试见合并说明。
