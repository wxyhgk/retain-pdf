# OCR 归一化的快照守卫（2026-10-29）

归一化拆分方案（`docs/ocr-normalize-decoupling-plan` 分支的 `ocr-normalization/20261029-归一化拆分方案.md`，还没合）的第 0 步：拆分之前先把"现在的输出"整份钉住，之后每一步
拆分都要求输出逐字节不变。用户 2026-10-29 定：先用人造样例，"因为我们知道具体的 OCR bbox 的类型"；让多个 Sonnet 造多篇文章。

## 样例

`backend/pipeline/devtools/tests/document_schema/fixtures/synthetic/` 下 9 份（23 页、327 个块），8 个 Sonnet 子代理按各家适配器真实读的字段造的，
每份带 `case.json`（原文 PDF 页尺寸、每个要点的页和原始路径和期望，共 213 条）。我逐份审过：能适配、能校验、页数和 `case.json` 一致、块在页内、
行在块内、片段在行内、没有零面积框；里面没有本机路径。

|---|---|---|---|

## 测试

`test_synthetic_snapshots.py`：每份走和 normalize worker 一样的路径（适配 → `finalize_normalized_document`：缩放到按 `pdf_pages` 临时生成的 PDF、
补行、按最终文档刷新报告），整份 `document.v1` 和报告逐字节对 `expected.document.v1.json`、`expected.report.json`（键排序、缩进 1）。对不上时把新输出
写成 `*.actual.json`（不提交）方便 diff；确实该变时 `UPDATE_OCR_SNAPSHOTS=1` 重新生成、看 git diff。被拒版本另有测试钉住"现在被哪条规则拒"，
将来修了（缩放时把框夹回页内）它会红，到时候改成期望通过。

验证：
- 生成以后再跑 12 个全过，连跑两遍一样（输出是确定的；期望文件里没有临时路径、时间戳）。
- 把 2026-10-29 修掉的"行重建覆盖原生行"临时放回去：带原生行的 4 份（3 份 MinerU、1 份通用格式）红，Paddle 的照常过，和预期一致。

## 样例顺带查出的问题（还没修）

1. **块超出页边一两点，整份文档校验失败、任务直接失败**：适配器不把框夹回页内，MinerU、Paddle 两份样例都撞上。真实输出里取整误差很常见，建议先修
  （缩放时夹回页内，报告里记下夹了几个）。
2. 同一种竖排文字，MinerU 当正文翻译、Paddle 当 unknown 不翻译（翻不翻分散在各家适配器的直接后果）。
3. 中文片段之间、行与行之间用空格拼接：「定态薛定谔方 程」。
4. 代码行去首尾空白，缩进丢了。
5. 列表合成一块，项和项只剩空格隔开；全角「（1）」编号不认。
6. 一个图注配多张子图时只有第一张挂上图注。
7. 跑出块框的行另拆一块以后，这一页后面所有块的编号往后挪一位（翻译按编号对回原文）。
8. 超链接的网址丢了；有的标签重复写两遍；页眉页脚上的图片和普通图片不分。
9. content_list_v2：表格、图片的内容和图注表注全丢，标题层级丢，片段都只有整块的框。
10. 中文「参考文献」标题被当成正文标题翻译（例外规则只认英文）；图下注、表下注没和对应的图表连上。

拆分是纯重构、不改这些行为；这些逐条单独开分支修，修一条快照变一次、看 diff 确认只有预期的变化。
