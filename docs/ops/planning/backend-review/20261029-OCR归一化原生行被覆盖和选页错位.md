# OCR 归一化：原生行被覆盖、选页时错位（2026-10-29）

OCR 归一化审查（2026-10-29，三个只读子代理分看公共核心、MinerU、Paddle）找出的确定的 bug，用户让"先修 bug"。这个分支修
第 1、3 条，第 6 条核实下来是误报；第 2、4、5 条和图注子串那条在别的分支。

## 1. 缩放后的行重建覆盖了 MinerU 的原生行

`normalize_pipeline.py` 的 `build_normalized_artifacts` 对所有服务商都调 `post_rescale_rebuild_paddle_text_geometry`，函数里不分服务商，
最后 `block["lines"] = rebuilt_lines`。这一步本来是给 Paddle 的（Paddle 只给块，行要按字数估），MinerU 的 middle.json 每行、每段都有框
（`bbox_precision = provider_layout`），也被换成了估的行。

反向检查时量到：没有修正时，一个三行的 MinerU 段落被压成 **1 行**，行内公式的片段类型也丢了。生产环境里每个走 MinerU 的多行段落都是这样，
渲染、阅读器拿到的行位置都不对。

改法：块里只要有 `provider_layout` 的行，就保留原行、块边不按文字高度收紧（片段带 `provider_layout` 框时本来就不收紧），目录条目从原行生成。
没有真实行的块照旧重建。

## 3. 选了页的远程任务按位置配页，从第 1 页错起

上传的任务在 OCR 之前就把原文截成所选的页（`page_subset.rs` 的 `prepare_uploaded_source_pdf`），清掉交给 OCR 服务的页范围。远程 URL
任务没有：页范围交给 OCR 服务，OCR 只认所选的页，原文却是整本（Paddle 从 URL 下载的；MinerU 回传的 `*_origin.pdf` 要看它是不是整本，
代码里看不出来）。后面归一化、渲染都按位置把 OCR 的第 n 页对到原文的第 n 页。

改法：

- Rust：`recover_remote_source_pdf` 拿到原文以后调新的 `subset_downloaded_source_pdf`，按页范围截成所选的页、原地改写，记任务日志和
  `ocr_page_numbers`。已经只有所选页的原文不再截：它的页数正好是所选页数，按范围解析要么越界、要么选出来就是全部，两种都原样返回。
- 归一化：缩放时 OCR 比原文多页直接报错（以前多出来的页留在原始坐标里往下走）；比原文少照常缩放、记在 `derived.page_count_mismatch`
  并打日志（末尾空白页没给这类情况不该让任务失败）；有块的页没有原始尺寸直接报错（以前换上 PDF 尺寸、块留在原始坐标里）。

## 6. 校验器的两项"写死为通过"——误报

报告里的 `geometry_bbox_consistent`、`segment_bbox_within_block` 恒为 `True`，审查当成"没真查"。核实下来 `validate_document_payload` 已经
强制检查了：`geometry.bbox` 和 `block.bbox` 一致（不一致抛错）、行在块内、片段在行内和块内；报告是校验通过以后才生成的，所以恒为 `True`
是对的。只加了一句注释说明。没有面积的框不算越界，另记在 `zero_segment_bbox_count`，这一点没变。

## 没做

- 页码之外的配页依据：MinerU 的 `page_idx` 还是不读，靠"原文已经截成所选页"保证按位置对得上。MinerU 远程任务选页时回传的原文到底是
  整本还是子集，要有真实输出才能确认；两种情况新代码都处理了。
- 旋转、裁剪框（cropbox）仍不处理：缩放只按页面宽高比例换算。
- 审查里的其余条目在别的分支或以后做（审查结论记在开发记录和这几份修复记录里）。
