# 拆条目规则修正（本机 13 本有目录页的书）

2026-11-25。[目录页拆条目第一步](./20261125-目录页拆条目第一步.md)只在一本书（`20261125022856-16ddda`）上调过；
[线 1 的实测](./20261125-线1：目录agent翻译.md)发现两本书拆错了（目录 agent 的检查拦下了，退回普通翻译，但拆本身是错的）。
这次把 [D0 摸底](./20261125-D0摸底.md)里认出目录页的 13 本全拿来当回归集，逐本看文字层，修 `ocr/document_schema/toc_pages.py` 的规则。
只记数量和版式，不记书名、不抄书里的字。

## 哪里错了

| 版式 | 以前怎么拆 | 原因 |
|---|---|---|
| 点线引导，标题、点线、页码写在文字层的**同一个片段**里（`Title . . . . 105`），章号「4-2」式 | 一整页条目粘成一条（一条里十几行、页码夹在标题里） | 页码只认「单独一个片段、在右边一列」的；「4-2」不算章号，新的一条起不了头 |
| 页码紧跟在标题后面，不排成一列（`Some Title 37`） | 页码留在标题里；没页码的附录行接着往下粘 | 同上，页码不在块宽右侧 40% 就不认 |
| 点线是单独的片段 | 点线留在标题里 | 没去点线 |
| 页码是「1-7」「3-10」（章-页）、「S2」（补充材料）、「5-35」（起止页）、「57.1」 | 认不出页码，或整块不拆 | 页码只认纯数字和罗马数字 |
| 上下标（H₂⁺ 的「2」「+」）在文字层里比本行高半格 | 自成一行，成了一条只有「+」的目录 | 按 y 中心聚行，上下标离得远 |
| 文字层的分音符写成「¨」加字母 | 标题里是「o」前面一个空格加分音符 | 没合回去 |
| 扫描书的文字层认错一个页码（149 认成 159） | 整页不拆 | 页码倒退一次就整页不认 |

## 新规则

1. **页码**：行尾的阿拉伯数字（可带字母前缀、短横、点：「12」「S2」「A-3」「1-7」「5-35」「57.1」「16-16.1」）或罗马数字
   （按罗马数字的写法认，「Civil」「Mix」这种词不再算）。可以是单独的片段，也可以和标题、点线写在同一个片段里——
   改用 PyMuPDF 的 `rawdict`，按每个字的位置把片段切开，条目框不压住页码。
   - **靠得住**：在右边一列，或前面有点线引导。
   - **靠不太住**：紧跟在标题后面、只隔空格的阿拉伯数字（同一片段里的只认纯数字）。这一块的页码**排成一列**
     （六成以上左边或右边对齐，±3pt）时不认——那是标题里的数字（「Part 2」）；排不成一列时认，认了以后页码倒着走，
     就不认这种再读一遍。
2. **点线引导**（`. . .`、`....`、`…`、`·`、`•` 等两个以上，扫描书里夹着零星短横的也算）：从标题里去掉，当成标题和页码之间的空当。
   有点线没页码的行也算一条结束（以前会接着往下粘）。
3. **章号**：「1」「1.2」「4-2」「4–2」「A-3」「A.」「IV.」；单独的片段里，数字章号直接算（字母、罗马数字还要和标题隔 4pt 以上，免得把「A」当章号）；
   和标题粘在一个片段里的「4-2 Title」「A-3 Title」也拆开（按字的位置）。级别按章号里的分隔符数（「4-2」「1.2」二级）。
4. **新的一条从哪里开始**：有章号的行；Appendix / Annexure / Annex / Chapter / Part / Приложение / Глава / Раздел / Часть / 附录开头的行
   （词留在标题里，交给模型一起翻）；比正在攒的**没章号**的那条起点往左缩出去 8pt 以上的行（论文集里标题下面一行作者，
   作者自成一条、不带页码）。带章号的条目折行常从章号列甚至更左写起，照旧当折行。只有页码（或点线加页码）的一行，结束上面折行的标题。
5. **上下标**：字号不到这一块中位数 0.8 倍、最多 3 个字的片段，挂到最近的一行上（离哪行都远的照旧自成一行）。
6. **重音**：「¨ ´ ˆ ˜ ˇ ˚」加字母合成一个字（只合元音和常见的几个辅音，「don´t」不动）。
7. **认不认这一块是目录**（不是就整块照旧）：条目至少 3 条；带页码的至少 2 条、且不少于三分之一（论文集的作者行占一半上下照样认，
   项目符号列表、正文段落不认）；页码不往回走——同一个字母前缀里比，只和上一条比，每 15 个页码容一处倒退（认错的页码），
   索引页、正文被认成目录的页码来回跳，远不止这些。
8. **级别**（没章号的条目）：在最左的章号列上或更左是一级；和更深一级的章号同列就是那一级；和一级标题同列是它的小节；
   和二级以下的标题同列是同级（「习题」「小结」和带编号的小节并排）。这一页没有带章号的条目时，按起点从左到右一列一级。
9. 条目块的 metadata 多一个 `toc_entry_page_bbox`（页码在原图上的框，没读出页码是 `null`），给下面说的补画页码用。

目录 agent 跟着改了一处：正文标题的章号前缀认「4-2」式（`match.py`、`validate.py` 的 `tidy`），以前只认「2.3」。

## 还没做 / 发现的问题

- **擦原文会把页码一起擦掉**（第一步就有，不是这次引起的）：渲染擦原文按 PDF 的绘字指令删，一条指令只要大半落在条目框里就整条删。
  不少书一行的标题、点线、页码是同一条绘字指令，条目框不压页码也会把页码擦掉，译文里又不带页码，排出来这一行就没页码了。
  按条目框模拟擦一遍、看页码还在不在：16ddda 62 个全在、02eb34 23 个全在、d4f8c4 16 个全在；
  3bfb0b 348 个丢 248、14e352 200 个丢 82、d41f5f 241 个丢 195、80c3ad 102 个丢 46。
  要在排版那边补：按 `toc_entry_page_bbox` 把页码（和点线）补画回去，或者擦的时候把这种指令切开。
- 扫描件（25e53c）的目录页、文字层认得很烂的书（8e0722：页码认成符号、作者和标题挤在一起）：第二步看图认。
- 一两行的小目录块（4bdc13 有 17 块，章首的小目录、跨页的尾巴）不够 3 条，照旧整块。
- 两栏的目录（一行左右两条）没处理；会被「页码往回走」拦下，照旧整块。
- 扫描书文字层的个别错字（「71 .1」「11 О」、点线里夹着冒号）：那几条没读出页码或点线没去干净，照旧交给翻译。
- 已有任务要从 OCR 归一化重跑才有新拆法。
