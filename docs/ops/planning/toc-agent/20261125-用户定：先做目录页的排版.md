# 用户定：目录问题先做目录页的排版

> 日期：2026-11-25
> 前一份：[用户定：模型加简单规则建 harness](./20261125-用户定：模型加简单规则建harness.md)、D0 摸底、D1 harness（分支 `feat/toc-agent-harness`，没合）。

## 用户说的

「6000 多页都关掉，我说的目录问题主要是目录的排版，比如 20261125022856-16ddda」。问了做法后定：**按「目录页 agent」做**；
前面的「整本书结构」先停，分支留着不合。

## 那个任务的毛病（3 页目录，rpr 排版引擎）

- 译文页变成左对齐的流水行：页码贴在标题后面、不再右对齐成一列；章号和标题挤在一起；小节不缩进；章与章之间没有空行；字偏大、页面下三分之一空着。
- 第一页最后一条「References 47」跑到第二页开头，和第二页的页眉「xvi Contents」并成「参考文献 47 xvi 目录」。

原因（按代码和产物核对）：

1. OCR（GLM-OCR）把一页目录给成一整块，每行的框是估的（左边全一样），缩进丢了；按行解析条目的规则要标题和页码之间有引导点或两个以上空格，
   小节一条都没认出（第二页 27 行只认出 6 条），排版退回纯文字。
2. 两页的目录块被串成一个跨页接续组（`cg-001-001`），按行切回两页时切错。
3. OCR 把页眉「xvi Contents」并进了目录块。
4. 排结构化目录条目只有旧的 Typst 路线有；现在默认的 rpr 路线不看 `toc_entries`。另外 Typst 路线条目少于行数时，第 i 行译文配第 i 条，标题会错位。

## 做法

**不动排版引擎，把目录块拆成一条条只框住标题的小块。**原书的章号、页码列、页眉不进任何块，留在原图上不动；每条标题是一个独立的短块，
按原位置、原缩进放译文。缩进、页码右对齐、章与章的间隔自然和原书一样；翻译时每条独立，不再跨页接续。

**目录页 agent（模型 + 简单规则）认条目：**

- 有文字层：规则从文字层量出每行的字和位置（章号列、标题、页码列），拼出候选条目（多行标题合成一条、页眉单独标出）；
  模型拿到「行 + 位置 + 候选」核对、纠正（合并、拆开、页眉、级别）；规则检查（每行都有着落、同一页里页码不倒退、编号和页码原样）。
- 没有文字层（扫描件）：只有 OCR 的行，位置不可信，模型从文字认条目；放回时退回整块按目录样式重排（第二步做）。

## 先后

1. 文字层这条路：拆块 + 模型核对，这个任务的 3 页做出来，和现在的版本并排看。
2. 本机书库里其它认出目录页的书（D0：13 本）跑一遍，看拆得对不对。
3. 扫描件的目录页。
