# 线 1：目录 agent 翻译（和普通翻译同步跑）

2026-11-25。[两条线的安排](./20261125-用户定：表格和目录的agent翻译与排版.md)里线 1 的目录部分。用户提议「目录 agent 和普通的翻译同步进行」，
定的做法：依赖方向反过来——不是目录抄正文标题，而是目录先定译名、正文标题跟着目录走；这样不用等正文翻完、也不用事后改写译文。

## 做了什么

1. **新包 `backend/toc-agent`**（`retainpdf-toc-agent`），照表格 agent 的样子：核心 `retainpdf_toc_agent` 只用标准库，
   接线 `retainpdf_toc_agent_engine`（模型调用接翻译底座、从 document.v1 取条目和标题、缓存）。
   - 一本书的目录一次翻：同样的原文只问一次，每段最多 80 条，模型回 `{"translations": [{"k", "zh"}]}`。
   - 逐条检查：空、没译（两个词以上的原文没有中文；一个词的名字、缩写可以照留）、多出原文没有的数字（章号页码混进来）、
     丢了数字、太长、没按术语表、写成多行。没过的连原因退回重交，最多 3 轮；还没过的不给定译。
   - 正文标题对上目录：`heading` 和 `document_title`（GLM-OCR 的章标题）块，原文一样就用同一个译名；
     比的时候不计大小写、空白、首尾标点、重音（文字层把「ö」拆成「o」加单独的分音符）；带「1.2 」「Chapter 1: 」「Appendix A 」
     前缀的去掉前缀比，译文是「1.2 译名」「第1章 译名」「附录A 译名」。
2. **底座：定好的译文**（`retainpdf_translation/workflow/fixed_translations.py`）。翻译请求多了 `fixed_translations_fn`；
   建计划时在另一个线程里调它，和领域识别、译前准备同时跑，引擎开始翻之前等它。结果写进块的 `metadata.fixed_translation`，
   抽取时经元数据桥带到条目上（渲染那份副本也加了），`core/execution_policy.item_fixed_translation` 读它：
   - 普通翻译：当成不发请求的直接结果（和单个连接词的字典直译同一条路，`fast_path_fixed_translation`）；
   - 翻译 agent：`BlockInput.fixed_translation`，通读定的标题译名不覆盖它。
   - 只给自成一个翻译单元的块；续段组成员、带公式的块照旧自己翻。
   - 有定译时它的哈希进翻译 checkpoint 指纹（`fixed_translations_sha256`）；没有时参数和以前逐字节相同。
   - 算定译失败只打日志，照常翻。
3. **流水线开关** `translation.toc`：`translate`（默认，和以前一样）/ `agent`。`translate/toc_stage.py` 在 `agent` 时把目录 agent 交给翻译请求。
   结果和缓存：`translated/toc-agent.v1.json`（输入一样续跑直接用，请求失败的不缓存）。用量阶段记成 `toc_translation`。
   Rust 侧的任务参数还没加这个键（界面建的任务现在拿不到 `agent`），等定了默认再接。

## 实测（Haiku，本地，花费很小）

- `20261125022856-16ddda`（3 页目录，整条流程：拆条目 → 翻译 → rpr_fit 排版）：62 条一次请求翻完（约 3.6k token），0 退回；
  普通翻译那边 62 条全部走定译、没发请求；同一个词全书一个译法（以前逐条翻时同一个英文词有两种译法）。排版和第一步一样。
- 另外 6 本书只跑目录 agent（复制文档、文字层拆条目、不写任务目录）：

| 任务 | 条目 | 请求 | 退回 | 对上的正文标题 |
|---|---|---|---|---|
| 20261125011331-d4f8c4 | 19 | 1 | 0 | 章标题全对上（`document_title`） |
| 20261107112510-8e0722 | 12 | 2 | 0 | 5 |
| 20261102084544-02eb34 | 23 | 1 | 0 | 10（「Chapter N:」「Appendix A:」前缀） |
| 20261102003842-3bfb0b | 348 | 4 | 0 | 326 / 351 |
| 20261102054308-d41f5f | 83 | 3 | 15 | 60 |
| 20261102093422-80c3ad | 98 | 6 | 51 | 41 |

退回的都是**第一步拆条目拆错了**：d41f5f 的目录是点线引导（`. . . .`）加「4-2」式章号，一整页的条目粘成一条；80c3ad 的页码没拆出去、
留在标题里。目录 agent 的检查拦下了（数字对不上），这些条目照旧交给普通翻译，不会更坏。修拆条目的规则是「另外 13 本逐本看」那件事。

## 还没做

- 默认还是 `translate`；要不要改成 `agent`、Rust 任务参数加不加这个键，等用户定。
- 扫描件目录页（没有文字层、没拆出条目）：看截图认条目。
- 第一步拆条目的规则：点线引导、「4-2」式章号、页码不在右边一列的目录。
- 跟着 OCR 翻时，后面才到的页上的正文标题拿不到定译。
