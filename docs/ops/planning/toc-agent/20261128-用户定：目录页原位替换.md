# 用户定：目录页原位替换，不重排

> 日期：2026-11-28
> 前一份：[用户定：表格和目录的 agent 翻译与排版](./20261125-用户定：表格和目录的agent翻译与排版.md)（线 2「目录：规则排版」这一条作废）、
> [目录页码补画](./20261125-目录页码补画.md)。

## 用户说的

「下一步我们得做目录排版的 agent，你先让一个 agent 去找各种目录的资料，然后我们只需要替换目录部分的文字就行了，两个 agent 协作干」。
看过「规则重排」的样稿（同级统一字号、照原缩进、页码对齐、补点线）后否掉：「我们只需要替换原始的文字就行了，目录里面，我们不去重新排版……
很多目录都是很杂乱的，根本不可能排版成功的！我们要做的是搞清楚上下文的关系，有些的目录是非常复杂的，比如有的文字是分两行写的」。
标题后面到点线之间空一段：「没有事情，问题不大，人是可以明白的」。

## 调研和原型（不花钱，都在副本上）

- 样本：91 页目录（本机 15 本 71 页，公开 PDF 12 份 20 页），分 28 类（点线、页码右列 / 紧跟标题 / 在左 / 在首行、多行标题、
  标签列、论文集带作者、双栏、跨页、扫描件、中日文原文……）。现在的译文最常见的毛病：缩进层级丢（35 页）、页码贴到标题后面（29 页）、
  点线擦掉或画错（17 页）、字号和原文不一致（13 页）——都是「整块重排」带来的，原位替换没有这些。
- 原位替换原型：从文字层按字取出标题的字，只擦这些字（同一条绘字指令里的章号、点线、页码留在原图上），译文写在原首字的 x、原基线上，
  宽度到本行右边第一个留下的字（点线或页码）为止；多行标题按原来每行的宽度切回原行。
  已有译文的 5 本小任务 16 页 537 条：527 条原字号放下、0 条缩字号（另 10 条是模型原样交回的 References，原字不动）；
  页码 534/534、点线 2361/2361 都还在；42 条多行标题译文都一行放下。复杂样本（居中条目、Part 分隔、俄文图框五行长标题）也放下了；
  失败的是扫描书 8e0722（看不见的 OCR 文字层，擦文字层擦不掉图上的字）。

## 定下的

| # | 问题 | 定的 |
|---|---|---|
| 1 | 原文两行、译文一行放得下时放哪行 | 和页码同一行；有章号的放首行（章号在首行，免得分家） |
| 2 | 放不下时 | 这一条缩字号，最低 0.8 倍；再放不下交模型看（认错条目、要拆行），模型也不行就这一条保留原文 |
| 3 | 标签列（Chapter 1、Annexure I、Part II） | 不翻，留在原图上（和章号一样） |
| 4 | 译文的粗细、颜色、字体 | 一律常规体、黑色（宋体，和正文同一套字体） |
| 5 | 没翻的条目（References、人名、代码名） | 原字不动，不擦不重画 |
| 6 | 目录页上不是条目的字 | 大标题（Contents）照普通翻译；页眉留原文 |
| 7 | 认上下文什么时候问模型 | 规则拿不准才问（条目少、页码不单调、双栏、页码在左、有作者行、看不见的文字层、和正文标题对不上……） |
| 8 | 扫描件 | 第一版就一起做：按 OCR 的行框在图上盖底色再写；框不准会擦到点线页码，要看图核对 |
| 9 | 旧的「重排 + 页码补画」 | 留作备用：开关 `reflow` / `replace`，合进去先不改默认，用户看过本机几本书的对比图再定 |
| — | 标题到点线之间空出来的一段 | 不管，只记数 |

技术上的按推荐：认上下文放在 toc-agent 里（线 1「认条目」的具体化，不另起包）；测宽、断行用排版引擎那一套；默认值分步定。

## 分几步（每步能单独合，合了不改默认行为）

| 步 | 分支 | 做什么 | 花钱 |
|---|---|---|---|
| R0 | `feat/toc-title-spans` | 拆条目时记下每条只框标题的字的每一行（框、基线、字号、文字）、章号框、标签列；标题自带的句号不再当点线 | 不 |
| R1 | 原位替换 | 渲染：按字擦标题、在原基线写译文、页码块不擦不画、有章号的不挪行；扫描件按 OCR 行框在图上盖底色；开关 `replace`；回归集出三栏图和检查表 | 不 |
| R2 | 认上下文的 agent | 规则拿不准的页给模型看截图 + 行片段，模型只能改归属和角色（合并、拆开、挂行、标签、作者、不翻、不是目录），改完就检查，最多 3 轮 | 不（录好的回复回放） |
| R3 | Haiku 实测 | 回归集里拿不准的页：问了几页、改对几页、花多少 | 要用户同意 |
| R4 | 定默认 | 用户看过 R1 的图再定默认用不用 `replace`；任务参数、契约跟着加 | — |

R1、R2 都只靠 R0 记下的数据对接，可以两个 agent 各在一个 worktree 里同时做。
