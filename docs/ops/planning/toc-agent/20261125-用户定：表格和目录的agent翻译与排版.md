# 用户定：表格和目录都做 agent 翻译、agent 排版

2026-11-25。用户：「我觉得得做两个：1. agent 表格翻译和目录翻译 2. agent 表格排版和目录排版」，看过下面的安排后说「可以，按这个做」。
表格那边原来的方案（[表格 agent 独立成包](../table-translation/20261123-表格agent独立成包.md)，G1–G6）照旧，这里把它和目录放进同两条线、定先后。

## 现在到哪了

| | 翻译 | 排版 |
|---|---|---|
| 表格 | 表格 agent 已独立成包（G1）；只看文字，Haiku 翻不翻判对 98.9%、数字全对；结构不可信的表整张跳过 | 规则 + 引擎重排（`rpr-table.js`），排进才换；不看图，没翻的格子丢上下标 |
| 目录 | [第一步](./20261125-目录页拆条目第一步.md)：文字层规则拆条目，每条交普通翻译 | 两行条目排在页码那一行；字号引擎自己定（比原文小、条目之间不全一样） |

两条线都卡在同一处：**Rust 模型执行器只收文字**（[模型请求带图](../layout-agent/20261122-模型请求带图.md)里没做的那条）。
界面建的任务多半走执行器，看图的那几步在它上面跑不了。

## 安排

**第 0 步（两条线共用，不花钱）**：执行器收图片片段（表格方案里的 G3）。请求体带图，缓存键算进图，请求日志只记图片哈希、不记内容；
纯文字请求和以前一字不差。

**线 1：agent 翻译**

- 目录：新包 `backend/toc-agent`（`retainpdf-toc-agent`），照表格 agent 的样子：核心只用标准库，模型调用、截图、取文字层由调用方传进来；
  接线另一个 Python 包、extra `[engine]`。
  - 认条目：有文字层的用第一步的规则结果当草稿，模型核对、用工具改；扫描件看页面截图认（原来说的第二步）。
  - 翻译：先查正文里对应章节标题的译法（条目连到正文标题），目录和正文标题一字不差；查不到的再自己翻，同一本书前后一致。
  - 规则检查：页码只增不减、章号原样、条目数对得上；不过的退回，到上限整页保留原样。
- 表格：G4 的「定结构」半段——结构不可信的表看截图用结构工具修，不再整张跳过；翻格子加全书搜索。

**线 2：agent 排版**（规则先排、规则检查，不过才给模型看排好的截图，模型只能用工具改，最多 3 轮，按规则得分取最好的一版）

- 表格：G2（规则检查、引擎旋钮 `columns` / `noWrap`、`table-layouts.v1.json`、规则能修的先修）+ G4 的排版循环。
- 目录：规则——同一页条目字号统一、按级别缩进、和页码对齐、排不进先压行距；检查不过才看图。

**最后**：Haiku 实测——表格评测集 55 张 + 回归样本，加 14 本有目录页的书。花钱，跑之前问用户。

## 定下的细节

- 目录 agent 单独一个包，不和表格合包：两边的工具和检查几乎不重合；看图排版的循环等两边都做出来再看要不要抽成公共的。
- 顺序：第 0 步 → 线 1 → 线 2 → 实测。每一步能单独合，合了不改默认行为，直到实测过了再定默认开不开。
