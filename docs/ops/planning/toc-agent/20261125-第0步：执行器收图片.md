# 第 0 步：Rust 模型执行器收图片

2026-11-25。[两条线的安排](./20261125-用户定：表格和目录的agent翻译与排版.md)里两条线共用的第 0 步，也就是
[表格 agent 方案](../table-translation/20261123-表格agent独立成包.md)的 G3、[模型请求带图](../layout-agent/20261122-模型请求带图.md)里没做的那条。

## 做了什么

- **执行器的消息**（`retainpdf-providers` 的 `model_executor/policy.rs`）：`content` 从只收字符串改成「字符串或片段列表」。
  片段照 OpenAI Chat：`text`、`image_url`（`url` + 可选 `detail`）。执行器只走 `/chat/completions`，原样发给服务商，不换写法。
- **规矩**：图只在 `user` 消息里；只收 data URL（png / jpeg / webp / gif），不收网址（不让服务商替我们去拉外部地址）；一次最多 4 张、
  每张解码后不超过 4 MB（和问模型接口一样）；文字合计仍是 512 KB；片段列表不能空；不认识的片段类型、多出来的字段一律退回。
- **指纹不变**：纯文字的消息序列化出来和以前一字不差（测试钉着），已经落库的操作照旧认得出是同一次请求。库里只存指纹，不存消息内容。
- **提交接口**（`POST /internal/model/jobs/:job_id/requests`）挂 `large_body`（24 MB），另外两个照旧 2 MB。
- **Python**：`request_chat_content` 走执行器时不再一律拒带图的请求；交出去之前用 `model_wire.executor_accepts_images` 查一遍，
  网址图、system 里的图、超过 4 张在 Python 这边就报错，不提交（免得执行器记一次失败、停掉整个任务）。

## 没做

- 没有真调看图模型（等线 1、线 2 的实测，花钱先问）。DeepSeek 这类不收图的服务商会由上游拒掉，执行器照常记失败；调用方要看图时自己选收图的连接。
- 私有请求采集（`RETAIN_TRANSLATION_CAPTURE_DIR`，基准测试用，默认关）照旧原样存消息，带图时也存图；它本来就是为了回放存的完整输入。
- 执行器每个单元最多两次请求（主请求 + 一次修复）：agent 的多轮循环要每轮一个单元（表格 agent 现在就是按请求内容的哈希各开一个），
  目录 agent 照这个做。
