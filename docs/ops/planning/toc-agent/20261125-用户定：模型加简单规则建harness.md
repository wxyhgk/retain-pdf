# 用户定：结构另存一份，模型加简单规则一起干，先建 harness

> 日期：2026-11-25
> 前一份：[目录 agent 方案](./20261125-目录agent方案.md) 第 5 节的四件事。

## 用户定的

1. **结构另存一份**：`<任务>/structure/toc.v1.json`，不往 `document.v1` 里加字段（用户：「单独存成文件」）。
2. **不走「规则先做、对不上才问模型」**：「我不建议用规则做，我建议直接用模型 + 简单规则一起干，建立 harness」。
   原方案的 D1（规则版）和 D3（模型那段）合并成一步：一开始就是模型读证据、用工具出结构，规则只做简单的事（整理证据、事后检查）。
3. 页眉只从结构里剔、翻译不动；4. 先目录、后表格 G2：用户没改，按原建议。

## 改后的做法

**harness**：一个能反复跑、能录回放、能打分的 agent 运行框架，模型是主角，规则是脚手架。

- **证据包**（规则整理，不下结论）：每页的标题候选块（文字、字号、粗体、页面位置、编号样式、OCR 给的角色和原始级别）、
  书里目录页解析出的条目、原书书签（有的话）、页码标签、重复出现的页眉页脚文字。整本书压成一份文字版，几百页的书也放得进上下文；
  放不下时按页段分批，结构在批与批之间接着往下写。
- **模型的工具**（JSON 动作，和表格 agent 一样不依赖哪家的原生工具调用）：`view_pages`（看某几页的候选细节）、`propose`（交一版结构）、
  `set_level`、`drop_heading`、`promote_block`、`link_entry`、`insert_heading`。
- **简单规则只当检查**：级别不跳级、页码单调、每条都落在真实的块上、目录页条目和书签都有去处。检查结果回给模型改，最多几轮；
  过不了就交最好的一版并标出问题。
- **录回放和打分**：每次请求的回复可以录下来、离线回放（测试不花钱）；评测集上和标准答案比（条目对齐率、级别准确率、页眉剔除）。
  **有书签的书自带标准答案**：评测时把书签藏起来让 agent 从正文和目录页推，再和书签比，不用人一本本标。

包照两个 agent 的样子：`backend/toc-agent`，核心只用标准库（循环、工具、检查、证据格式、交接格式），接线接底座的模型调用。

## 分几步（改后）

| 步 | 做什么 | 花钱吗 |
|---|---|---|
| D0 | 摸底：书库里多少书有书签、有目录页；页眉当标题、级别乱的有多少；挑评测集（有书签的书优先，自带答案） | 不花 |
| D1 | harness：证据包、工具、检查、循环、录回放、打分、`toc.v1.json`；离线测试用录好的回复 | 不花 |
| D2 | Haiku 实测：评测集上量准确率和花费 | **要用户同意** |
| D3 | 接到各处：阅读页目录、书文件夹、翻译 agent 的章节、译文书签、标题和目录页统一译文 | 不花 |
