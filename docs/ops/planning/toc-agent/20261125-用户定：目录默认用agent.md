# 用户定：目录默认用目录 agent

2026-11-25。看过[线 1 的实测](./20261125-线1：目录agent翻译.md)（7 本书，目录一次翻完、同一个词全书一个译法、请求更少；
拆错的条目被检查拦下、退回普通翻译）后，用户：「要改成 agent」。

## 改了什么（同一个分支 feat/toc-agent）

- 流水线 `translation.toc` 默认 `agent`（`translate/toc_stage.py` 的 `DEFAULT_TOC_MODE`，三种 spec 和各入口的默认值）；旧 spec 没有这个键也按 `agent`。
- Rust 任务参数加 `translation.toc`（`TRANSLATION_TOC_MODES = translate / agent`，默认 `agent`）：建任务校验、任务详情回显、
  写给流水线的 translate / provider spec 都带上；Rust 的取值表和 Python 的 `TOC_MODES`、默认值有测试钉着。
- 契约 `create-job.v1`、`library-documents.v1`、`job-status.v1` 加 `toc`，`backend/contracts` 的镜像同步，TS 重新生成；黄金 fixture 的两份 spec 加 `toc`。
- 前端不用改（不提交就是 `agent`），交接文档记了一笔。

## 影响

- 新建的任务、以前的任务重跑翻译：有按文字层拆出目录条目的书（要从 OCR 归一化重跑才有条目），翻译一开头多几次目录 agent 的请求，
  目录条目和对上的正文标题不再单独发请求。没有目录条目的书什么都不变。
- 要关掉：建任务时 `translation.toc = "translate"`。
