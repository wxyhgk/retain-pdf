# 目录页拆条目（第一步：文字层，不花模型钱）

2026-11-25。用户定先做目录页的排版（例子：任务 `20261125022856-16ddda`，3 页目录），整本书结构先停。
这一步只用 PDF 文字层；扫描件的目录页、文字层读不准的页，留给第二步用模型认。

## 以前的问题

- GLM-OCR 一页目录给一整块，行框是估的（左边全是 50）；翻译把整块当一段，第 1、2 页还被接成跨页的一组，
  「参考文献 47」跑到第 2 页、和页眉混在一起。
- 页眉「xvi Contents」在目录块里，跟着被翻译、被擦。
- 引擎按一大块排，章号、缩进、右对齐的页码全丢了。

## 这一步做的

1. **归一化**（`ocr/document_schema/toc_pages.py`，接在 `pdf_geometry.py` 的文字层恢复后面）：有文字层的目录块，
   按文字层的行拆成一条一条：
   - 每行最右的数字（或罗马数字）在右边 40% 里就是页码；行首的数字是章号（和标题粘在一段里的也拆开）；
   - 标题折行时一直攒到出现页码；新的章号把前一条结掉；
   - 页眉（顶部 10% 里、只有「Contents/目录」加页码的行）不进条目；
   - 级别：有章号的按点数（`1` 一级、`1.2` 二级）；没章号的，起在章号那一列的是一级（结论、附录、索引），
     起在章标题那一列的是二级，再往里缩 8pt 以上加一级。
   - 条目少于 3 条，或者页码倒着走，就当没认出来，整块照旧。
2. **条目块**：`structure_role = toc_entry`、`layout_role = toc`、`semantic_role = unknown`（不进跨页接续）；
   框从章号（有的话）到页码列前 6pt；文字是「章号 标题」——擦原文按内容流里的整段文字删，章号常和标题在一段里，
   只框标题会把章号擦掉，所以章号跟着重画；页码列、页眉留在原图上不动。policy 照抄原目录块（服务商不翻目录的照旧不翻）。
   metadata 记 `toc_entry_number`、`toc_entry_page_label`、`toc_entry_level`、`toc_entry_source_font_size`、
   `toc_entry_line_count`、`toc_split_parent_block_id`。多行标题一行一个行框。
3. **块号**：拆过的页整页重编号，块号的数字等于块在本页的位置（各家适配器都这么编，翻译条目号 `pNNN-bNNN`、
   渲染引擎配译文都按位置算；一开始从最大号往后编，引擎把译文配错了一格）。文档里别处写着的旧号一起换成新的。
4. **翻译**：`toc_entry` 加进主翻译的结构角色（翻译包 `json_extractor.py` 和渲染那份副本 `source_page_records.py` 两处），
   每条单独一项，只翻标题。
5. **排版**（rpr_fit，`render/output/rpr_fit/toc_entries.py`）：原文两行、译文一行放得下的条目，给引擎的文档副本里
   框只留最后一行（页码那一行），译文和页码对齐；盖底色按 visual_profile 的整条框、擦原文按译文条目的框，都不受影响。
   估宽按原文字号的 0.8 倍（引擎排中文目录一般小一圈）。

## 结果（`20261125022856-16ddda`，Haiku）

- 三页拆出 16 + 26 + 20 条，页眉两行留在原图；翻译 63 项（另 1 项是第 1 页的「Contents」标题），没有跨页接续组，QA 0 问题。
- 译文：章号、小节缩进、右对齐页码都在；结论、附录 A–D、术语表、索引是一级；多行条目和页码在同一行。
- 中文比原文页码小一圈（引擎排的 9.1pt，原文 11.46pt），条目之间字号大多一致，个别长条目引擎排大了一点（9.8pt）。
