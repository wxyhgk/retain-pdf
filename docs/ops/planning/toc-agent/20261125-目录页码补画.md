# 目录页码补画

2026-11-25。接[拆条目规则修正](./20261125-拆条目规则修正.md)里发现的问题：目录页拆成条目以后，本来想让页码列留在原图上，
但擦原文（`pikepdf_text_strip`）是按 PDF 的绘字指令整条删的，不少书一行的标题、点线、页码是**同一条**指令，
擦标题时页码一起没了，译文里又不带页码，排出来的目录没有页码。按条目框模拟擦一遍：3bfb0b 348 个丢 248、
14e352 200 个丢 82、d41f5f 241 个丢 195、80c3ad 102 个丢 46；16ddda、02eb34、d4f8c4 不丢。
只记数量和版式，不抄书里的字。

## 做法：每条后面跟一个页码小块，定译就是页码本身

1. **归一化**（`ocr/document_schema/toc_pages.py`）：读出页码的条目后面紧跟一个小块，
   `structure_role = toc_page_label`，框是 `toc_entry_page_bbox`（页码在原图上的位置），文字是页码。
   - metadata：`fixed_translation` = 页码、`fixed_translation_source = "toc_page_label"`（翻译不发请求）、
     `toc_page_label`、`toc_page_label_source_font_size`、`toc_split_parent_block_id`、
     `toc_page_label_entry_block_id`（跟着的条目，整页重编号以后再写）。
   - `layout_role = toc`、`semantic_role = unknown`：和条目一样不进跨页接续；policy 照抄原目录块，
     服务商不翻目录的，页码小块也不翻，整页照旧。
   - 块号照旧等于块在本页的位置（标题、页码、标题、页码……）；重跑归一化不会把条目和页码小块再拆一遍。
   - **压着别的块的不要**：标题折行、页码紧跟在最后一行字后面（页码不排成一列的书），页码落在条目框里，
     引擎为了不压字把条目译文缩得很小。这种页码照旧留在原图上。本机 13 本书 3992 个页码里有 42 个
     （80c3ad 10、7826ab 22、4bdc13 6、8e0722 3、bb6190 1）。
2. **翻译**：`toc_page_label` 加进主翻译的结构角色（翻译包 `json_extractor.py` 和渲染那份副本 `source_page_records.py`）。
   两个引擎都认 `item_fixed_translation`：普通翻译把定译排到「整块只有一个编号就保留原文」前面
   （`translation-classic` 的 `fast_path/keep_origin.py`；以前「12」这种块直接判保留原文，保留原文的块排版不擦也不画）；
   翻译 agent 当成 `BlockInput.fixed_translation`。目录 agent 只收 `toc_entry`，页码小块不进它的条目，它给的定译也只写条目。
3. **排版**（Typst 和 rpr_fit 共用的 `render/layout/payload/render_item.py`）：
   - 页码小块译文和原文一样也照样擦掉、在原处重画（以前「译文和原文一样就不排」）。
   - 条目译文和原文一样（模型把「References」「Index」原样交回）也重画：擦页码时同一条指令里的标题也会没了，不重画这一行就空了。
   - 条目自己没有译文要排（翻译失败、模型判保留原文）时，它的页码小块也改成保留原文
     （`render/layout/payload/toc_page_labels.py`，在 `render_plan.py` 读完译文后做），标题和页码一起留在原图上。
     页码小块紧跟在条目后面，块号是条目的加一，按这个配对。

### 一直补画，不是只在会被擦掉时补

选**一直补画**（有页码就有页码小块）：

- 一页里有的页码和标题同一条指令、有的不是（14e352、3bfb0b 都这样：章标题行的页码是单独的指令，小节行的不是），
  只补丢了的那些，同一列页码一半是原书字体、一半是引擎字体，参差不齐；以前没补的时候也是这样东一个西一个；
- 章号本来就跟着标题重画（擦原文时章号常和标题在一条指令里），页码也重画，一行里的数字是同一种字体；
- 要知道哪些会被擦，得在归一化时解析内容流、模拟擦法——归一化不该依赖排版的擦除代码。

代价：原来不丢页码的书（16ddda），页码也从原书字体换成了引擎字体（衬线、不加粗、比原文小一圈，和条目译文同一个字号）。

### 点线引导不补

点线引导（`. . . .`）和标题、页码常在同一条指令里，擦掉就没了，这次不补。中文目录不用点线也常见，
页码右对齐成一列已经能看出对应关系；真要补，可以在排版时按条目框右端到页码框左端画点线，留到以后。

## 结果

复制任务（`data/` 只读：从原任务抽几页目录 PDF 和规范化文档，放临时目录），Haiku 翻、rpr_fit 排（日志确认没回退 Typst），
「以前」是同样拆条目但去掉页码小块。数的是译文 PDF 上页码框里还读得出这个页码：

| 任务 | 抽的页 | 页码 | 以前在 | 现在在 |
|---|---|---|---|---|
| 20261102003842-3bfb0b | 4 | 164 | 9 | 164 |
| 20261102054308-d41f5f | 3 | 116 | 0 | 116 |
| 20261103005046-14e352 | 3 | 90 | 38 | 90 |
| 20261102093422-80c3ad | 3 | 92 | 90 | 92 |
| 20261125022856-16ddda | 3 | 62 | 62 | 62 |

逐页看了图：页码在原来的位置、右对齐成一列，和标题（两行原文排成一行时在页码那一行）对齐；没有压字；
条目翻译照旧走目录 agent（3bfb0b 2 个请求、d41f5f 3 个、16ddda 1 个，页码小块不发请求）。
重画的页码是引擎的字体，字号和条目译文一样（16ddda：页码 8.85pt，条目 9.13pt，原文 11.46pt），粗体页码变常规。

## 还没做 / 已知问题

- 上面那 42 个压着条目框的页码照旧留原图，和标题在同一条指令里的照样被擦掉（80c3ad 抽的第一页就有 5 个）；
  要处理得让引擎的排版框绕开页码（只改给引擎的文档副本，擦原文仍按整条框）。
- 没拆开的目录块（读不出条目的、扫描件、「Preface vii」这种两三行的小块）不在这次范围，页码照旧可能被擦。
- 点线引导不补；粗体、斜体页码重画成常规体。
- 已有任务要从 OCR 归一化重跑才有页码小块；只重翻译、只重排版用的还是旧的。

## 对前端

不用改。阅读页多了一种小块（页码），悬停框落在页码上；块号和以前不一样（只影响新跑的任务）。
