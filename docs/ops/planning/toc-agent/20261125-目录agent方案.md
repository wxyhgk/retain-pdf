# 目录 agent 方案

**状态：** 方案，等用户定第 5 节的几件事。
**日期：** 2026-11-25
**起因：** 用户 2026-11-25：「我认为值得做的是目录 agent」。

## 1. 现在的毛病

现在没有一步是「把整本书的章节结构理清楚」。下面四处各自从 OCR 的块上猜标题和级别，规矩各不一样。现状调查见第 6 节，按代码核对过。

| 毛病 | 证据 | 影响到哪 |
|---|---|---|
| 标题级别丢了或者是编的 | `document.v1` 没有级别字段；MinerU 的级别只留在 `metadata.raw_title_level`；Paddle / GLM-OCR 不给（GLM 的 `#` 被去掉）；后端读区块时没有就按 title→1、heading→2，翻译 agent 按 `2.3` 这种编号算、其余一律 3，阅读页再压成 1–2 | 阅读页目录、书文件夹按章拆、翻译 agent 的章节上下文 |
| 页眉被认成标题 | 电磁学 74 块；唯一的防线是「页眉里的数字等于印刷页码」 | 进阅读页目录、`toc.md`，能把书文件夹切出一章一页 |
| 原书书签没当依据 | 只在渲染时原样抄进译文 PDF，标题还是英文 | 译文 PDF 的书签是英文；有书签的书（出版社 PDF 多半有）最可靠的结构没用上 |
| 目录页和正文标题没连起来 | 目录页能解析出条目（编号、标题、页码、级别），但不知道指向哪个正文标题；翻译各译各的，样本 24 条有 6 条对不上；MinerU 认不出目录页 | 目录页的译文和正文标题对不上；目录页点了也跳不到地方 |
| 章名不在正文里 | 章首页的「CHAPTER TWO」、大号章名 OCR 漏认或认成正文；认成正文的被排成小字（排版清单「识别错的大标题被压成小字」，修过 3 处） | 章节切分、章名字号 |

`skip_title_translation` 这个开关是空的（传下去了，没人读），和本方案无关，单独记一笔。

## 2. 做法：先把结构算出来存成一份产物，各处只读它

一本书一份**目录结构**：`<任务>/structure/toc.v1.json`，每条是

- 级别（1 起）；
- 原文标题、译文标题；
- 落在哪个块上：`block_id`，以及书的页码和任务自己的页码；
- 来源：书签、目录页、正文标题或模型，加一个置信度；
- 被剔掉的「假标题」单独列一份（页眉、图注里的大字），写明原因。

`document.v1` 只加不改，这里不往里加字段：结构是整本书的事，放在逐块的文档里不合适；另存一份，重算也不用动 OCR 结果。

### 怎么算：规则先做，对不上才问模型（和表格 agent 一样）

证据按可靠程度排：

1. **原书书签**（`get_toc`）：有就是骨架，级别、标题、页码都现成；规则把每条对到那一页的标题块上（文字相似度加位置）。
2. **书里印的目录页**：已经能解析出条目，同样对到正文标题块上；和书签互相印证。
3. **正文里的标题块**：按字号聚类、看编号（`2.3`、`第二章`、`CHAPTER TWO`）、看页面位置定级别。页眉的认法：多页同一位置反复出现、文字重复或只差页码。

三样能互相对上的直接采用。对不上的才交给模型，例如：

- 没有书签也没有目录页，只能看正文标题；
- 字号和编号给出的级别打架；
- 目录页的条目在正文里找不到对应的块（章名漏认）。

模型只能用给定的工具改：

- `set_level`：改级别；
- `drop_heading`：剔掉假标题，要写原因；
- `promote_block`：把认成正文的大字提成标题；
- `link_entry`：把目录条目连到正文块上；
- `insert_heading`：标题漏认、但目录页有这一条时补进来。

改完再用规则检查：级别不能跳级，页码单调，每条都落在真实的块上。检查不过就退回给模型，最多 3 轮，还不行就用规则版。

### 谁读它

| 用的地方 | 现在 | 有了以后 |
|---|---|---|
| 阅读页目录（`reader/regions` 的 `heading_level`） | 1–2 级、带页眉 | 读结构里的级别，去掉假标题；没有结构的老任务照旧 |
| 书文件夹按章拆、`toc.md` | 自己猜章 | 按结构的 1 级切 |
| 翻译 agent 的章节上下文 | 自己按编号算 | 读结构 |
| 译文 PDF 书签 | 原样抄英文 | 用结构里的译文标题写书签；原书没书签也给一份 |
| 标题和目录页的译文 | 各译各的 | 一条结构条目只译一次，正文标题和目录页条目用同一个译文 |
| 排版 | 认成正文的大标题被压小 | `promote_block` 过的块按标题排 |

## 3. 跑在哪

结构要看整本书，放在 **OCR 规范化之后、翻译之前**，作为一个独立的小步骤。规则那一部分不调模型，几秒钟能算完。

OCR 和翻译并行（流式）时，翻译会先于 OCR 结束就开始。这时翻译先用每页的临时判断；OCR 全部结束后算出结构，标题的译文统一、书签在渲染时用上。这一点要在实现时确认流式那条路的时序。

模型调用照表格 agent 的做法：先走文字，不看图。章首页认不出的大字要看图才判得准，等 Rust 模型执行器支持带图（表格的 G3）以后再加。

## 4. 分几步

| 步 | 做什么 | 花钱吗 |
|---|---|---|
| D0 | 摸底：书库里多少书有书签、有目录页；页眉被认成标题、级别错的有多少；挑 8～10 本做评测集，人标结构 | 不花 |
| D1 | 规则版：书签、目录页、正文标题三方对齐，剔页眉，写 `toc.v1.json`；阅读页、书文件夹、翻译 agent 改读它（没有就照旧） | 不花 |
| D2 | 译文书签、标题和目录页统一译文（结构条目译一次）；`promote_block` 的块按标题排 | 不花（译文沿用翻译阶段的） |
| D3 | 模型那一段：工具、循环、规则检查；离线测试用录好的回复 | 不花 |
| D4 | Haiku 实测：评测集上量对齐率、级别准确率、页眉剔除；人眼抽查 | **要用户同意** |

D1、D2 不调模型就能解决大部分问题：有书签、有目录页的书本来就有现成答案，只是没用上。

包怎么放照两个 agent 的样子：`backend/toc-agent`，核心只用标准库，接线接底座的模型调用。D1、D2 的规则部分也放进核心，规则和模型共用一套检查。

## 5. 要用户定的

1. **产物另存一份**（`structure/toc.v1.json`），还是往 `document.v1` 里加级别字段？建议另存，理由见第 2 节。
2. **先做规则版（D1、D2）再上模型**，还是一开始就把模型放进来？建议先规则：有书签、有目录页的书占多数时，规则就够了，D0 量出来再定。
3. **页眉剔掉以后去哪**：只从结构和目录里剔掉，还是连翻译也跳过？以前定过「页眉就这样吧」，这里建议只从结构里剔，翻译不动。
4. **和表格 agent 的先后**：表格 G1 已做完待合，G2（排版规则）不花钱。建议两条线交替推进：先做目录 D0、D1，再回来做表格 G2。

## 6. 现状调查（2026-11-25，按代码核对）

- 标题识别：MinerU `ocr/document_schema/provider_adapters/mineru/projection.py`（级别只进 `metadata.raw_title_level`）；Paddle `paddle/legacy_projection.py`、
  `paddle/roles.py`（不给级别）；GLM-OCR `glm_ocr/adapter.py`（去掉 `#`）。整本书统一级别的步骤：没有。
- 书签：`render/document/metadata.py` 的 `copy_toc` / `copy_toc_for_page_map`、`render/document/pikepdf_outline.py`，只在渲染时原样抄，不翻译。
- 目录页：Paddle / GLM 的 `content` 标成 `table_of_contents`；`ocr/document_schema/toc.py` 解析出条目；翻译有专门的提示；渲染按级别缩进。
  条目没连到正文标题；`toc_entry` / `toc_target` 只在开发工具里。MinerU 没有目录页标签。
- 标题翻译：普通翻译有标题风格提示；翻译 agent 的通读角色要求「目录和正文标题一字不差」，但目录页先翻，对不上（6/24）。
- 阅读页：目录来自 `GET /jobs/{id}/reader/regions` 的 `heading_level`（`retainpdf-jobs/src/reader/reader_regions/value_extract.rs`），前端再压成 1–2 级。
- 书文件夹：`retainpdf-library/src/book_export/render.rs` 按出现两次以上的最高级别切章，只剔页眉页脚页码这几种 sub_type。
- 排版：按标题角色和原书字号排，不看级别；角色认错（正文）时章名被排成小字。
