# D0：本机书库摸底

> 日期：2026-11-25
> 范围：开发机书库（单用户开发数据目录）里有成功 OCR 结果、找得到原书 PDF 的 52 本书，每本取最新的一次 OCR。只统计数量，不记书名和内容。
> 脚本：一次性统计，没进仓库（读 `jobs.db` 只读、每本书的 `ocr/normalized/document.v1.json` 和原书 PDF 的 `get_toc`）。D1 的评测集脚本会进仓库。

## 对 harness 的影响

1. **评测集不用人标**：书签 10 条以上的 24 本，评测时把书签藏起来，让 agent 只看正文标题候选和目录页推结构，再和书签比
   （条目对齐率、级别准确率）。有书签的书在实际运行时书签就是最强的证据，评测时藏起来才量得出 agent 自己的本事。
2. **级别全靠推**：OCR 一个级别都不给，现在各处的级别全是猜的；agent 要从编号、字号、目录页缩进、书签推级别。
3. **页眉要能认**：18 本有成片的页眉当标题，证据包里要把「同一句话在很多页反复出现、位置固定」整理出来给模型看。
4. **大书要分批**：几千页、上万个候选放不进一次上下文。证据包按页段分批，结构在批与批之间接着往下写，书签 / 目录页条目做全书骨架。
5. **目录页识别率低**：13 本认出目录页，长书里也有认不出的（例如 250 页那本 4 个目录块、0 条条目）。证据包里要带「疑似目录页」
   （一页里很多行以页码结尾），让模型判。
