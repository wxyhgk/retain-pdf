# AI 怎么拿到书的数据

2026-11-24。RetainPDF 自己的 AI 11-03 暂时去掉了（旧代码在提交 `56f396dc3^` 的 `backend/ai`），以后要加回来。
旧实现自己写了一整套调度和传输，用户觉得太复杂。这次的目标：**传输简单**；AI 能检索书库里其他 PDF；
外部 AI（Claude Code、Codex、Gemini CLI……）和我们自己的 AI 面板用同一套东西。知识库整理先放一放。

方案由三个 agent（文件优先、工具优先、落地）各出一稿、互相挑毛病两轮，再由用户定了分歧。

## 接入方式：ACP + 只读的书文件夹 + 少量 MCP 工具

- AI 一侧按 [ACP（Agent Client Protocol）](https://agentclientprotocol.com/)接：客户端把 agent 当子进程起，stdio 上走 JSON-RPC，
  `session/update` 流式推回答，`session/request_permission` 让用户确认，`session/new` 里可以把 MCP 服务交给 agent。
- 读书、检索靠文件；文件做不好的两件事（改译文、看整页）用 MCP 工具。

## 书文件夹

```
<data_root>/books/
  library.md                 全部书的书目：书名、作者、标签、合集、有没有识别 / 翻译（没识别的书也列，说明为什么没有正文）
  <书名>-<短编号>/
    meta.json                书编号、页数、用的哪次识别、哪个译文版本、来源指纹、生成时间
    toc.md                   章节标题 → 页码 → 在哪个文件哪一行
    text/03-第三章.md        按章拆，每个文件 200KB 以内；原文和译文对照放一起
    images/                  图、公式、表格截图；扫描页、复杂表格页预先截整页
    source.pdf               指向原文 PDF 的链接（Windows 建不了链接时在 meta.json 写路径）
```

- 内容从 `reader/regions` 生成（原文、译文、页码、`sub_type` 都有），页眉、页码不导出；没翻译的页只放原文。
- **锚点**：`<!-- p012-b0034 job=<真正有这页的任务> -->`，页号用那个任务自己的页号（和全文索引 `blocks_fts` 同一规则）。
  合并阅读的虚拟任务 `merged-…` 改了页号、而且只读，所以不能只写「书编号 + item_id」。不写代次（`generation` 是整个任务共用的，
  写进锚点会改一处重写整章）。
- **引用**写「书编号 + 任务 + item_id + 一小段原文」，重新识别后块号变了按原文找回。
- 位置：`data_root/books`，从数据库派生，**不同步、不备份**，每台设备自己生成（选了哪个译文版本本来就只在本机，
  见 [多设备同步](../../../api/09-同步/01-多设备同步.md)）。

### 什么时候重写

- 各写入点只往库里记一笔「这本书要更新」，后端一个后台任务统一消费：写临时目录再整体改名；`library.md` 攒几秒合并一次。
  只让一个进程写（jobsd 模式下任务收尾在另一个进程）。
- 要记的地方：任务完成、删任务（全文索引已有的两处）；**改译文、切换译文版本、同步收进别的设备的改动**（全文索引现在漏了这三处）。
- 兜底对账：启动时、数据库恢复后，按 `meta.json` 的来源指纹（`reader_regions` 已有指纹）逐本比对，对不上就重写。
- **全文索引一起重建，并按用户选的译文版本**。现在它只在任务完成、删任务时重建，每页取最新任务、不看选的版本，
  改译文后搜到的是旧的——这是现有的毛病，顺带修掉。

## MCP 工具：`retainpdf mcp`

命令行的子命令，stdio，作为 agent 的子进程跑，不开端口（局域网共享碰不到）。只做两个工具：

| 工具 | 参数 | 做什么 |
|---|---|---|
| `revise_translation` | `document_id`、`item_id`、`job`（锚点里的）、`new_text`、`expected_old_text`、`reason` | 找到真正有这一块的源任务，`PATCH` 改译文，`source: "agent"`；当场返回成功、校验失败（422）或冲突（409） |
| `view_page` | `document_id`、`page`、`side`（原文 / 译文）、`width`（压低上限） | 取页预览图，返回图片；给读不了 PDF 的 agent 用，读得了的也省得整本 PDF 发上云 |

- 改译文**每次都要用户确认**：ACP 对工具调用发 `session/request_permission`，面板弹窗。书的正文里可能藏提示注入，写操作不能自动放行。
  改错了用修改历史撤回。
- `PATCH` 加一个 `expected_translated_text`，服务端比对旧译文，关掉「先读再写」之间的竞争窗口。
- 不做 `search_library`：本机用 grep + 按章拆的文件；我们自己的面板直接调 `GET /search`。不做向量检索，书多到不够用再说。

## 安全前提（先做）

- 桌面版的接口密钥是写死的 `retain-pdf-desktop`（`frontend/desktop/main.js`），并明文写在 `~/.retainpdf/run/backend.json`；
  单用户模式下任何有效密钥都能调全部接口（`retainpdf-accounts` 的 `authorize_route` 在没有 `owner_filter` 时直接放行）。
  能跑 shell 的 agent 读到它就能删书、恢复备份，books/ 只读拦不住。
- 要做：
  1. **AI 专用密钥**（后端）：只能读、检索、`source=agent` 改译文。接口登记表加一个调用方 `agent`，凭这把密钥只放行标了它的接口。
     `retainpdf mcp` 从环境变量拿这把密钥。
  2. **主密钥每次安装随机生成**，不写进 agent 能读到的位置（`frontend/desktop/`，前端会话做）。
  3. 我们自己的面板默认拒绝 agent 跑命令、写文件的权限请求。

## 我们自己的 AI 面板

- 桌面版主进程（Cordis 插件）当 ACP 客户端，把 agent 作为子进程起，工作目录设成 `books/`，`session/new` 里传 `retainpdf mcp`。
- 界面和主进程走 IPC（preload 已有调用 + 推送两种通道），**不走 HTTP**：局域网共享会把 `/api` 转发给同网段的其他设备。
- 前端会话做。

## 先后顺序

1. 安全前提：后端发 AI 专用密钥；前端会话改主密钥。
2. 导出书文件夹 + 记「要更新」+ 对账 + 全文索引按选中版本重建。做完就能用 Claude Code 打开文件夹跨书检索、阅读。
3. `retainpdf mcp`：`revise_translation`、`view_page`；`PATCH` 加 `expected_translated_text`。
4. 桌面 AI 面板（前端会话）。
5. 网页版：以后再说。讨论里倾向 AI 跑在用户电脑上、用个人令牌远程调服务器，服务器不跑 AI；不做压缩包下载（下载下来就不会再更新）。

## 没定的

- 知识库（AI 把整理结果写成 `wiki/`）先放一放；到时候要定它和书库「条目主表」里笔记的关系。
- 页图生成和阅读器共用生成名额，AI 连翻几十页会不会堵住阅读器，做 `view_page` 时量一下。
