# 失败简报带失败码，地区不支持单独成码（2026-11-24）

分支 `feat/failure-brief-code`。起因是 `fix/llm-request-codes` 交接里留给前端的两件事：
书详情失败卡片想给「模型不可用」专门的标题，编辑部要给 `model_unavailable`、`region_unsupported` 两种停下原因写中文。

## 问题

- 书详情的失败卡片读的是任务列表里的失败简报（`JobFailureBriefView`），简报只有 `category`。`upstream_model_unavailable`
  和 `auth_failed` 同属 `auth`，卡片只能说「凭据被拒」「去设置换 Key」，用户要改的其实是模型名。
- 所在地区不支持更糟：失败码就是 `auth_failed`，卡片说「去换 Key」，下面的 `suggestion` 却写「换 API Key 没用」；
  恢复目录（`recovery_hint`）给的也是 `auth_failed` 的换 Key 说法。

## 决定（用户 2026-11-24 同意）

1. 简报加可选的 `failure_code`，取任务失败里的 `failure_code`。只增不改；读库时缺失败码会拿旧 `category` 兜底出 `unknown`，
   简报不带这种值（和 `category` 取法一致）。键集合测试显式放行。
2. 地区不支持单独成码 `upstream_region_unsupported`：分类照旧 `auth`、不可重试、从翻译续跑；恢复目录加一条，
   提示说换网络或换服务商、换 Key 没用。三条路径（普通翻译 `UpstreamRegionUnsupported`、Rust 执行器
   `ExecutorRegionUnsupported`、agent `AgentRegionUnsupported`）都改；它们仍是「Key 被拒」类的子类，停下整份翻译的逻辑不变。
   已经失败的老任务记录不改，仍是 `auth_failed`。
3. Rust 兜底推断分类时 `upstream_model_unavailable`、`upstream_region_unsupported` 也归 `auth`，和 Python 一致。
4. 编辑部停下原因是纯前端的事（后端早就发这两个值），后端只补 `docs/api/02-进度事件/03-编辑部事件.md` 漏写的取值。

不选的做法：让前端认 OpenAI 的原始业务码 `unsupported_country_region_territory`——只对一家有效，换服务商就认不出来。

## 前端随后要做

见 [后端改动交接](../../../core/frontend/backend-changes-handoff.md) 最上面一节：失败卡片按 `failure_code` 先查一张表，
编辑部 `STOP_REASON_TEXT` 加两条。
