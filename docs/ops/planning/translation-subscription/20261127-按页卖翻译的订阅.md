## 成本（本地真实任务的用量台账算的）

|---|---|---|---|
| 普通翻译（Haiku 5.5，几本几百页的书） | 约 7000–10000 | 约 900–1500 | 约 3000 |

| 普通 | 约 ¥0.012 | ¥0.025 | 约 52% |

## 怎么做：桌面版 + 中转服务

```
桌面版 ──(登录拿到的令牌 + 这单的凭证)──> 中转服务 ──(我们的 GLM-OCR / 大模型 key)──> 智谱 / 模型服务商
                                            │
                                            └ 账号、订阅、页额度、开单、计量、限流、结算
```

- **key 只在中转服务上**，桌面版里一个都不放（装进安装包等于公开）。用户自带 key（BYOK）照旧能用，订阅只是设置里多一个服务商选项。
- **中转服务做薄**：认令牌、查额度、换上我们的 key 转发、按实际用量记账。对外的形状和现在客户端认的一样
  （Anthropic Messages、OpenAI Chat Completions、GLM-OCR），客户端已经支持自定义 `base_url`（翻译、GLM-OCR 都能配，
  `retainpdf-config/src/providers.rs`），改动集中在登录、开单、显示额度。
- **不能变成通用的大模型接口**（卖的是翻译，不是 API）。每次翻译先**开单**，之后的请求都要带这单的凭证，额度和 token 都按单算：

  1. 开单：客户端报页数和档（普通 / agent），中转服务按 `页数 × 1 或 3` **预扣**页额度，回一个这单的凭证和 token 上限
     （每页上限比如是平常用量的 3 倍：普通约 4 万、agent 约 8 万 token/页，按台账再定）。
  2. 转发：只认这单的凭证；模型由中转服务定（客户端选不了贵的）；超过这单的 token 上限就拒绝；每个账号、每台设备限并发和速率。
  3. 结算：翻完按**实际译成的页**扣，没用到的预扣退回；整单失败全退。页数以中转服务自己看到的为准（OCR 也走它，它知道几页），
     客户端报的只用来对账。
  4. 没结算的单超时（比如 24 小时）自动按已用 token 折算后关掉，防止预扣一直占着额度。

- 现成的可以照着做：「请求结果不明不自动重发」（不重复扣钱）、「翻译阶段失败从翻译续跑、不重付 OCR」、多用户版里的按页扣额度
  （数据库 v23 `page_quota`，只借思路，不启用多用户代码）。

## 密钥安全（用户 2026-11-27 交代「记得避免 key 什么的泄露」）

我们的 GLM-OCR、大模型 key 一旦漏了，别人就能用我们的钱调模型，所以按「默认会被盯上」来做：

- **key 只在中转服务的服务器上**：不进桌面版安装包、不进前端、不进仓库、不进 CI 日志。放在服务器的环境变量或密钥管理里
  （仓库里只有变量名），`.env` 之类进 `.gitignore`；开发、内测、正式各用各的 key。
- **客户端拿不到 key，只拿短期、窄权限的凭证**：
  - 登录令牌：可吊销，库里只存哈希，不存原文；
  - 每单的凭证：只对这一单有效、带 token 上限、单结算或超时就失效。
  漏了的话，最坏也只是这一单的额度，不是我们的 key。
- **转发时不把 key 带回去**：上游的报错原样转给客户端前去掉请求头、请求体回显，只留状态码和服务商的错误码；
  中转服务自己的日志、用量表（`usage`）里不记 key、不记完整的请求头，记录前统一过一遍脱敏（`sk-…`、`Bearer …`、`x-api-key`）。
- **只走 HTTPS**；中转服务不提供任何「读配置」「看环境变量」的接口，管理后台单独鉴权、只在内网或加白名单。
- **服务商控制台设上限**：每个 key 设每日 / 每月花费上限和告警（智谱、Anthropic 都能设），中转服务自己也按天汇总成本，
  超过预期（比如某个账号一天用掉平常十倍）自动停这个账号并告警。
- **漏了怎么办**：key 能随时换（换 key 只改服务器配置、不用发客户端新版）；登录令牌、单的凭证能整批吊销。
  这套流程写进运维文档，第一步上线前演练一次。
- 仓库照旧守 CLAUDE.md 的规矩：不提交、不打印密钥和 token；用户贴进来的 key 不写进文件，提醒作废重发。

## 中转服务的数据（草案）

| 表 | 存什么 |
|---|---|
| `accounts` | 账号（登录方式待定）、状态 |
| `devices` | 登录过的设备、令牌（可吊销）、最近使用时间 |
| `subscriptions` | 档位、本期起止、本期页额度、续费方式、状态 |
| `credit_ledger` | 页额度流水，只追加：发放（订阅、加购、补偿）、预扣、结算、退回、清零；余额由流水算 |
| `orders` | 一单：档（普通 / agent）、页数、预扣额度、token 上限、已用 token、状态（open / settled / refunded / expired） |
| `usage` | 每个转发请求：单、模型、输入 / 输出 / 缓存 token、成本、结果；对账和看毛利用 |

## 第 1 步的设计（用户 2026-11-27 定：先做中转服务最小版，支付放着）

用户又定了三件（一次问一个）：

- **登录**：内测用**邀请码直接当账号**——后台建邀请码发给内测用户，桌面版填一次就绑定这台设备（后台能吊销、换设备）；以后加邮箱或手机号时把账号平移过去。
- **模型**：「我们可以后台自己控制」——每一档（普通、agent）在后台各配一个连接（协议、地址、模型名、用哪把 key），随时能改、不发新版；默认 Haiku 5.5。
  用户在客户端选不了模型，请求里带的模型名中转服务一律换成这一档配的。
- **服务器**：**海外**（日本、新加坡、美国的小云服务器）。Anthropic 不向中国大陆提供服务，服务器放国内就调不了 Haiku；海外不用 ICP 备案，国产模型、GLM-OCR 照样能调。

### 放哪、用什么写

- 仓库里新开一个独立的 Rust 服务 `backend/relay`（可执行文件 `retainpdf-relay`，axum + 自己的一个 SQLite 库），不依赖 rust_api、不碰冻结的多用户代码。
- 部署：一台海外小服务器，前面一个自动签证书的反向代理（比如 Caddy）只放 HTTPS；key 放服务器的环境变量，库里只记变量名。
- **没有管理网页、没有管理接口**：后台操作是服务器上的命令（`retainpdf-relay admin …`，ssh 上去跑，直接改那个 SQLite 库），对外的攻击面只剩下面两类接口。
  以后真要管理网页再单独做、单独鉴权。

### 接口

客户端用的（桌面版的后端去调，带设备令牌 `Authorization: Bearer <设备令牌>`）：

| 方法 | 地址 | 做什么 |
|---|---|---|
| `POST` | `/v1/devices/activate` | `{invite_code, device_name}` → `{device_token}`。一个邀请码绑一台设备，再绑要后台先解绑 |
| `GET` | `/v1/me` | 档位、本期到哪天、本期页额度、还剩多少 |
| `POST` | `/v1/orders` | 开单 `{mode: "classic" \| "agent", pages, job_ref}` → `{order_id, order_token, credits_reserved, token_budget, expires_at, endpoints}`；额度不够 `402`，不扣 |
| `POST` | `/v1/orders/{order_id}/settle` | 结算 `{translated_pages}` → `{credits_charged, credits_refunded}` |
| `POST` | `/v1/orders/{order_id}/cancel` | 整单没做成，预扣全退 |

转发（带这单的凭证 `order_token`，放在各家原来放 key 的位置：Anthropic 的 `x-api-key`、OpenAI 和智谱的 `Authorization: Bearer`）：

| 地址 | 转到 |
|---|---|
| `POST /relay/anthropic/v1/messages` | 这一档配的 Anthropic 连接 |
| `POST /relay/openai/v1/chat/completions`、`/relay/openai/v1/responses` | 这一档配的 OpenAI 协议连接（国产模型） |
| `POST /relay/glm/api/paas/v4/layout_parsing` | 智谱 GLM-OCR |

每个转发：单要是开着的、没过期；模型名换成这一档配的；**已用 token 到了上限就拒绝**（`token_budget = 页数 × 每页上限`，每页上限后台可调，
先按台账定普通约 4 万、agent 约 8 万 token）；从回答里读用量记进 `usage`；回给客户端的只有回答本身，上游的响应头、报错里的回显去掉（见「密钥安全」）。
一个账号同时开着的单、每分钟请求数都有上限。

### 结算规则

- 开单按 `页数 × 1（普通）或 × 3（agent）` 预扣；结算按 `min(预扣, 译成的页 × 倍数)` 扣，剩下的退回。
- OCR 也走中转，中转自己知道 OCR 了几页：客户端报的译成页数比 OCR 看到的还多就按 OCR 的算，并记一笔异常。
- 单超过 24 小时没结算：按已用 token 折成页（除以每页平常用量，不超过预扣）扣掉，其余退回、单作废。

### 后台命令（第一版）

- `admin invite create --plan basic|standard|pro --months 1` / `admin invite revoke` / `admin device unbind`
- `admin credits grant --account … --pages …`（补偿、内测加额度）
- `admin tier set --tier classic|agent --protocol anthropic|openai --base-url … --model … --key-env …`、`admin tier show`
- `admin usage report --since …`：按账号、按天的页数、token、成本、毛利

### 客户端（第 2 步）要改的

- 设置里多一个服务商「RetainPDF 订阅」：填邀请码激活、显示档位和剩余页额度。
- 选了它提交翻译时，桌面版的后端先开单，把这单的 `order_token` 和中转地址当成这个任务的翻译凭证和 OCR 凭证（翻译 `base_url`、GLM-OCR 的地址本来就能改）；
  任务结束按译成的页结算，失败取消。用户自带 key 的路完全不变。
