# 说明书按模块分页

2026-11-23 第一步合并时用户提出：「按照模块来做，这样后续代码不会冗余」。改掉第一步「按用户要做的事分章」的做法。

## 定下来的

- **一个前端模块一页**：`docs/guide/<模块>.md`，文件名就是 `frontend/web/src/features/<模块>` 的目录名。一个功能只在它自己模块那页写，
  别的页链过去（以前第 3、4 章都讲了实时译文、改这段译文）。
- **快速上手**：`docs/guide/README.md` 只串一遍流程（安装 → 填 Key → 添加 PDF → 看进度 → 阅读），细节链到各模块页；下面一张「按功能查」表列出所有页。
  安装不对应模块，单独一页 `install.md`。
- **没有自己一页的模块**：`artifacts`、`jobs`、`job-detail`、`editorial-room` 写在 `book-detail.md` 里；`admin`、`auth` 只有已停的多用户版用，不写。
  登记在测试的 `COVERED_ELSEWHERE` 里。
- **设置页的「?」**：设置分区登记 `SettingsSection` 加必填的 `guide`（模块名，多用户才有的分区写 `null`），外壳按它拼出
  `https://github.com/wxyhgk/retain-pdf/blob/main/docs/guide/<模块>.md`，不另外维护链接表。功能自己登记的分区，`guide` 就是它所在的模块名。
- **截图**：截图脚本里每张图写明属于哪个模块，存到 `docs/guide/images/<模块>/`。
- **测试** `frontend/web/tests/architecture/user-guide-coverage.test.mjs`：每个模块都有说明页或登记了写在哪；每个 `guide` 都有对应的页、功能分区的 `guide`
  等于自己的模块名；每页都对得上一个模块、都列进 README 的表。
