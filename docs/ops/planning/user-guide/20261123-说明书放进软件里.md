# 说明书放进软件里

2026-11-23 用户：「直接变成网页前端的一个按钮，不只是桌面端，这样不是更方便？我也好检查」。以前设置里的「?」链到 GitHub，
要联网，推送之前还打不开。

## 定下来的

- **说明书跟着网页一起发**：从 `docs/guide/` 挪到 `frontend/web/guide/`（Markdown 和截图都在这里，只有一份）。网页版、桌面版、
  局域网共享、Docker 网页版都从同一个站点根下取 `guide/*.md`，不联网也能看。GitHub 上照样能直接读这些文件。
  - 桌面打包的文件白名单（`frontend/desktop/scripts/prepare-app.mjs`）加 `guide`；桌面本机网关和局域网共享网关加 `.md` 的类型。
  - Docker 网页镜像本来就整个拷 `frontend/web/`。
  - 不放进 `dist/`：`dist/` 提交进仓库，再拷一份截图会让仓库多一倍。
- **入口**：主页底部加「使用说明」按钮（任务中心和设置之间），设置每栏标题旁的「?」改成在软件里打开说明书的那一页。
  两处都派同一个事件 `retainpdf:open-user-guide`，主页上挂的 `UserGuideHost` 接住（和任务中心一样）。
- **新模块 `features/user-guide`**：弹窗左边目录、右边当前页。
  - 目录不另写：读 `guide/README.md` 里「按功能查」那张表。
  - 页内链接（`页.md#标题`）在说明书里翻页，锚点规则和 GitHub 一样；外部链接新窗口打开；图片拼上说明书目录。
  - 弹窗和 marked 都是第一次打开时才下载，不进主页首屏。
  - 内容是跟着软件发的文件，不是用户输入，渲染时不另做清洗。
- **测试**：`tests/home/user-guide.test.mjs` 拿真的说明书逐页画一遍，查每个页内链接指到的页、锚点、图片都存在；再用假 fetch 走一遍弹窗翻页。
  覆盖测试 `user-guide-coverage` 改读 `frontend/web/guide/`，`user-guide` 模块登记为写在首页。
- 「给写说明书的人」那段挪进 README 末尾的 HTML 注释里，软件里和 GitHub 上都不显示。

以前的文件（`20261123-使用说明书.md`、`20261123-按模块分页.md`）里写的 `docs/guide/` 是当时的位置，不改。
