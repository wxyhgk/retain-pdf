# GLM-OCR 接进任务

2026-10-31，接入 GLM-OCR 的第 3 步（前两步：[适配器](./20261031-GLM-OCR适配器.md)、[调用层](./20261031-GLM-OCR调用层.md)）。

## 决定

- **走配置型命令 provider，不加 Rust 枚举**：`backend/config/ocr_providers.json` 加 `glm_ocr`，`kind: remote_command`。
  Rust 已有的路：`is_configured_command_provider` 为真 → 当 `Local` 处理、交给 Python provider worker（`uses_provider_worker`），
  任务校验、凭据导入（`ocr.options.credential` → 托管凭据）、stage spec 的凭据引用（`env:RETAIN_GLM_OCR_API_TOKEN`）都现成。
  加 `OcrProviderKind::GlmOcr` 要动十几处 `match`（调研过），换不来任何东西。Rust、Python 两处"没有配置文件时"的内置定义也加上。
- **一个智谱 key**（用户："只用一个 api key，因为 glm5.3-flash 也可以一起用"）：GLM-OCR 自己没有 key（凭据库、请求、
  服务器环境变量都没有）、翻译的 `base_url` 主机是 `open.bigmodel.cn` 时，worker 注入凭据时用翻译的 key
  （`retainpdf-runner` `worker_process.rs` 的 `shared_zhipu_translation_key`）。别家的翻译 key 不发给智谱；借来的 key 也进日志脱敏名单。
- **纯 OCR 任务借不到**：建任务时 `clear_translation_secret_sources` 清掉了翻译凭据。要改得动建任务的凭据处理，这次不做；
  文档写明纯 OCR 任务要单独给 key。
- 列表顺序 mineru、paddle、glm_ocr、local；能力沿用命令型的（只收上传的本地文件）。

## 前端要跟着改的（交给前端会话）

| 文件 | 现在 | 要改成 |
|---|---|---|
| `frontend/web/src/platform/config/providers.ts` | `OCR_PROVIDER_DEFINITIONS` 写死 paddle、mineru | 加 `glm_ocr`（显示名 GLM-OCR），或改成读 `GET /api/v1/providers/ocr` |
| 建任务的 OCR 凭据（`app/home/composition/create-credentials.ts`、`features/ingest/domain/workflow/payload.ts`、`features/credentials/domain/save-flow.ts`） | 按 `paddle_token`/`mineru_token` 特判 | `glm_ocr` 的 key 走 `ocr.credential_ref`（`ocr_provider_token`，provider `glm_ocr`）或 `ocr.options.credential`；翻译选了智谱时可以不填（后端借翻译的 key），界面上写一句 |
| `frontend/desktop/app/backend/config/ocr_providers.json` | 桌面版自带的配置副本 | 同步 `backend/config/ocr_providers.json` 里新加的 `glm_ocr` 一项 |
| 选来源 | — | 选了 `glm_ocr` 时不提供 URL 来源（`supports_remote_url_submit=false`） |

## 没做的

- 命令行 `retainpdf` 的 OCR 服务商表（`retainpdf-config` `OCR_PROVIDERS`）只有 paddle、mineru，接 GLM 要改它拼任务的方式，另做。
- 多用户的平台设置（`PLATFORM_OCR_PROVIDERS`）不加：多用户已停（2026-10-16）。

## 验证

- Rust 新用例：借智谱翻译 key（`RETAIN_OCR_CREDENTIAL`、`RETAIN_GLM_OCR_API_TOKEN` 都是它，且进脱敏名单）、别家翻译 key 不借、
  自己的 key 优先、别的命令型 provider 不借；`glm_ocr` 是 `remote_command`、只收本地文件、凭据走 `RETAIN_GLM_OCR_API_TOKEN`。
- 列服务商的用例（catalog、`GET /providers/ocr`）加上 `glm_ocr`；契约说明更新、DTO 重新生成。
- 开发栈端到端（建任务 → OCR → 翻译）：见合并说明。
