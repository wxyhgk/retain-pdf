# 行间公式编号挂到公式块上

2026-11-26。分支 `feat/formula-number-normalize`。document.v1 里的行间公式块以前拿不到自己的编号：Paddle、MinerU 的编号是单独一块、
不和公式关联，GLM-OCR 多半干脆没有。阅读器、渲染、以后的「引用跳转」都要先知道「这个公式是 (2.19)」。

## 三家怎么给编号

| 服务商 | 编号在哪 | 我们以前怎么处理 |
|---|---|---|
| PaddleOCR-VL | `parsing_res_list` 里单独一块 `block_label: "formula_number"`，有框，内容 `"(1)"`，通常紧跟在公式后面、在公式右侧同一行 | 归成 `metadata` 大类、`structure_role = "formula_number"`，不和公式关联。官方只在 Markdown 里有 `showFormulaNumber`，拼成 `\tag*{(1)}`，条件很窄：阅读顺序里公式的下一块必须是编号 |
| MinerU | `formula_number` 块（标签表里有） | 归成 metadata（`structure_role = "metadata"`，原始标签在 `provenance.raw_label`），`NORMALIZATION.md` 写着不与公式块关联 |
| GLM-OCR | 没有编号块（版面检测和 Paddle 同一套，但本机 45 个有原始分片的任务里 `formula_number` 0 个）。少数公式把编号识别进 LaTeX：`\tag{2}`、`\tag{2.19}`；极少数写成末尾 `\quad (u)` 或者单独一个 text 块 `"(1)"` | 编号多半丢了 |

## 怎么配（`ocr/document_schema/formula_numbers.py`）

和服务商无关，按顺序补，宁可不配也不配错：

1. **编号块按几何配**（`layout_block`）：适配器出块、补完契约字段、夹回页内之后（坐标还是 OCR 自己的单位，阈值都按页宽、公式高度的比例）。
   - 编号块认 `structure_role = "formula_number"`、`sub_type = "formula_number"` 或 `provenance.raw_label = "formula_number"`（MinerU）。
   - 编号的纵向中心落在公式上下沿各放宽「公式高度 × 0.4」的范围里（至少放宽编号高度的一半）；在公式右侧，也认左侧；水平间隔不超过页宽一半。
   - 代价 = 水平间隔 / 页宽 + 0.5 × 纵向偏离（编号中心离公式中心多远，按公式高度算）+ 左侧加价 0.03。纵向权重大：上下挨着的两个公式，
     编号跟同一行的那个，哪怕另一个横向更近（真实数据里第一版只看水平距离，配错过）。
   - 不配：中间隔着别的公式、编号、图表或多行段落；编号上下附近（页高 10% 以内）的段落盖着编号的横坐标、却和公式横向不沾边（不同栏）；
     两个候选代价差不到 0.02（页宽的 2%，算有歧义）；跨页（只在同一页里找）。单行的短文字（公式后面的「, x > 0」）不挡。
   - 几个编号都挑中同一个公式：只有一个落在公式上下沿之间就给它，否则都不配（多行公式每行一个编号，一个公式最多一个编号）。
   - 编号块的文字要像编号：`(1)`、`(2.19)`、`（3）`、`(A.1)`、`(3a)`、`(2-5)`，也认罗马数字、单个字母、星号；`by Eq. 1.2` 这种不配。
2. **LaTeX 的 `\tag`**（`latex_tag`）：没配上编号块的公式，LaTeX 里正好一个 `\tag{X}`（显示成 `(X)`，记 `text = "(X)"`）或 `\tag*{X}`
   （原样显示，`text = X`）。几个不同的 `\tag` 不取。
3. **原文 PDF 文字层兜底**（`pdf_text_layer`）：缩放到 PDF 的点之后（`pdf_geometry.rescale_document_geometry_to_pdf` 里，恢复乱码之后），
   还没有编号的公式：公式框外、同一行（公式上下沿各放宽 0.2 倍高）的字按 PyMuPDF 的行拼起来，整行就是带圆括号、带数字的编号
   （`[4]` 是引文、`(a)` 是列表，不要）；落在别的块里（正文里引用 `(1)`）、和公式之间还有别的字或块、跨栏、被编号块框着（那是第 1 步的事）的不要；
   左边的编号要求公式右边同一行没有字（OCR 只框了半行时，左边的列表序号不算）；两边都找到、或者两个公式找到同一串字的不配。
   页上一个字都取不出来（扫描件）就不做。

**同时有编号块和 `\tag`**：以编号块为准。它是版面上单独印出来的那串字，能双向挂上块 id；`\tag` 是公式识别顺手认出来的。
`in_latex = true` 记着公式原文里已经带了编号，渲染时别再补一遍。真实数据里 Paddle 有 8 个公式带 `\tag`：6 个旁边没有编号块，从 `\tag` 取；2 个同时有编号块，`\tag` 里只认出了编号的前一段（章号，少了点后面的序号），编号块是完整的，以编号块为准是对的。

## 怎么记

沿用图注挂图（`paddle/caption_asset_relations.py` 的 `_attach_relation`）的写法：关系记在 `content` 里、双向。只增不改：
公式原文不动；编号块照旧是 `metadata`、照旧不翻译（`policy.translate = false` 不变）。

- 公式块 `content.formula_number`：`text`（原样，`"(2.19)"`）、`label`（去掉括号，`"2.19"`）、`source`（`layout_block` / `latex_tag` /
  `pdf_text_layer`）、`in_latex`、`block_id`（编号块 id，只有 `layout_block` 有）。
- 编号块 `content.number_of_block_id`（名字沿用开发工具 `ocr_viewer/taxonomy.py` 的关系 `number_of`），`content.related_block_ids` 追加公式 id。
- 文档 `derived.formula_numbers`、报告同名一份：公式数、各来源配上几个、编号块数、编号块没配上的原因计数。没有公式也没有编号块的文档不写。
- `document.v1.schema.json` 加 `$defs/formula_number` 和 `content` 的三个字段；`validator.py` 查 `formula_number` 只在 formula 块上、
  `source` 取值、`block_id` 和 `number_of_block_id` 同页互指。说明在 `document_schema/README.md`「行间公式编号」。

例子：

```json
{"block_id": "p012-b0007", "content": {"kind": "formula", "text": "E = m c^{2}",
  "formula_number": {"text": "(2.19)", "label": "2.19", "source": "layout_block", "in_latex": false, "block_id": "p012-b0008"}}}
{"block_id": "p012-b0008", "structure_role": "formula_number", "block_class": "metadata",
  "content": {"kind": "text", "text": "(2.19)", "number_of_block_id": "p012-b0007", "related_block_ids": ["p012-b0007"]}}
```

## 真实数据（本机 `data/jobs`，只读）

用本分支的代码对本机原始结果重跑归一化（Paddle：11 个任务的 `ocr/paddle_result.json`；GLM：`ocr/glm_ocr_raw/` 46 个目录里 45 个有分片，
按调用层的 `merge_chunks` 拼起来），原文 PDF 用任务自己的（选了页的用 `.pages.pdf`）。没有改 `data/` 里任何东西。

| | 行间公式 | 配上编号 | 编号块 | 编号块（没配上） |
|---|---|---|---|---|
| PaddleOCR-VL（11 个任务） | 821 | 478：编号块 470、`\tag` 6、文字层 2 | 481 | 11：不像编号 7、一个公式抢到两个编号 4 |
| GLM-OCR（45 个任务） | 14385 | 7593：`\tag` 108、文字层 7485 | 0 | — |
| MinerU | 本机没有 MinerU 的原始结果，只有人造样例（快照里 3 个编号块全配上） | | | |

Paddle 没配上的 11 个，逐个看过框：

- 7 个「不像编号」：Paddle 把公式旁边的说明（形如 `by Eq. x.y` 的引用、一句短语）也标成了 `formula_number`。不配是对的。
- 4 个「抢同一个公式」：两处多行公式，Paddle 框成一个公式块、右边每行一个编号。一个公式最多一个编号，按约定都不配。
- 第一版（只看水平距离、不认栏）还有 9 个歧义或配错：上下挨着的公式里编号跟了横向更近的那个、两栏页上左栏的编号被右栏公式抢走、
  公式和编号之间夹着一小段文字。按真实数据改了代价（纵向权重 0.5）、加了栏的判断、单行短文字不挡之后都配上了，抽看画出来的页都对。
- 配上的 470 个里，8 个编号的中心在公式下沿之下（编号换到公式下一行），抽看是对的。

GLM 的 7485 个来自文字层：抽 16 个画框核对，全对（右侧的「章-号」「附录字母+章-号」、三级编号、粗体编号，左侧的「附录字母.号」，多行公式共用一个编号）。
按书查标签重复（92 处）和倒序（73 处）：大多在编号按节、按附录重新从 (1) 开始的书里（720 页那本重复 59 处），不是配错。
看到的一类边界：一页上一列「(1) 公式」「(2) 公式」的列表（OCR 把每行框成一个公式），左边的 (1)、(2) 会被当成编号——它们排版上就是给这几行编的号，
留着；另加了一条「左侧编号要求公式右边同一行没有字」，防 OCR 只框了半行、右边还有别的公式时把列表序号认成编号。
GLM 没配上的主要原因：扫描件没有文字层（两个任务、2008 个公式，只能靠 `\tag`，配上 18 个）；本来就没编号的公式（推导中间步、例题）；
编号和公式之间还有字、或编号落在 OCR 的正文块里（保守不配）。

## 没做的

- GLM 极少数写在 LaTeX 末尾的 `\quad (u)`、单独一个 text 块 `"(1)"`：没专门认（有文字层时第 3 步一般能从原文找到，单独 text 块整块就是编号时文字层那一步允许）。
- 渲染引擎 `backend/rendering-engine/engine/src/render.js` 的 `splitTeXEquationTag` 只认 `\tag{…}`、不认 `\tag*{…}`；这次不改。
- 阅读接口、前端还没读 `content.formula_number`；要用时在阅读接口那边另加（只增不改）。
- 已经跑完的任务要重跑归一化（或重跑任务）才有这些字段。
