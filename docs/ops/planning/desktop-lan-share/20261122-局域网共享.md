# 局域网共享（2026-11-22）

## 起因

用户想在手机上用 RetainPDF。iOS App 要把 Python 嵌进 App（iOS 不许起子进程）、交叉编译 PyMuPDF / pikepdf，
还有 PyMuPDF 的 AGPL 和 App Store 冲突，用户听完成本后放弃了。退一步：桌面版本来就在本机跑着网页前端和后端，
把它安全地开放给局域网，手机、平板用浏览器打开就行。

用户定的两条：

- 别的设备能用**全部功能**（看书库、阅读、下载，也能上传、发起翻译）；
- 翻译和 OCR 用**这台电脑上存好的 Key**，别的设备不用再填。

## 做法

### 单独的局域网网关（`frontend/desktop/src/main/lan-share.js`）

本机网关（`local-gateway.js`）只听 `127.0.0.1`、只给 Electron 窗口用，页面里带着后端接口密钥和所有 Key。
局域网共享**不改它**，另起一个网关：

- 听 `0.0.0.0:40100`（被占往后找 20 个），默认关，设置里打开；开关和访问码存在应用数据目录的
  `lan-share.json`（0600）。下次启动照旧开。
- 和本机网关一起在网关插件（`plugins/gateway.js`）里建；复用外部后端时没有它，设置页显示不可用。
- 关掉、重置访问码时断开所有已有连接（包括进度流）。

### 访问码

- 二维码 / 链接里带 `?k=<访问码>`（24 字节随机）。第一次打开时换成 `HttpOnly; SameSite=Lax` 的 cookie，
  302 跳回去掉 `k` 的地址，访问码不留在地址栏。之后没有 cookie 的请求一律 401（页面给一句「去电脑上扫码」）。
- 比较用 `timingSafeEqual`。「重置访问码」后旧 cookie 立刻失效。

### Key 不出电脑

- 页面拿到的运行配置（`window.__FRONT_RUNTIME_CONFIG__`）去掉后端接口密钥 `xApiKey`，`apiBase` 指回局域网地址本身。
- 名字像密钥的字段（`…apiKey`、`…token`、`…secret`、`…password`，`developerConfig` 里的也算）一律换成占位符
  `@desktop:<字段在配置里的路径>`，空的照旧空（页面能如实提示缺 Key）。页面照常当 Key 已填好、照常组装请求。
- 转发 JSON 请求时把占位符换成电脑上真正的 Key；路径不存在、不是密钥字段、值为空、或者是 `xApiKey` 的占位符一律
  400，不把占位符发给服务商。上传（multipart）和 GET 照旧流式转发。
- 转发时网关自己加后端接口密钥，去掉浏览器的 `Origin` / `Referer` / `Cookie`（单机后端只放行本机来源），
  去掉后端返回的 `Access-Control-Allow-Origin`。
- 开发态的前端目录里有 `runtime-config.local.js`（开发者本机的 Key），局域网上一律给空脚本；点开头的文件 404。
  打包版本来就不带它（`check-frontend-bundle.mjs`）。

### 局域网上不开放的接口

网关替访问者带后端密钥，等于给了电脑主人的权限（后端会话提醒）。「全部功能」指看书、上传、翻译、改书库；
碰得到电脑本身的管理接口只能在电脑上用，网关直接 403（`LAN_BLOCKED`）：

- `/admin/*`（账号管理）、`/backups*`（恢复会覆盖数据库）、`/sync*`（同步文件夹能指向电脑上任意路径）、
  `/fonts/upload`、`/runtime-assets/download`、`/internal/*`、`/jobs/:id/files/internal/*`；
- `/credentials*` 只许读（读接口不含明文），不许建、改、删。

路径先解码、合并重复斜杠、解析点段、转小写再比，编码、`//`、`..` 绕不过去。执行本地命令的路本来就堵着：
建任务带 `ocr.options.command` 后端直接 400。经局域网打开的页面不显示「同步」「备份」两栏。

### 安全边界（写在设置页上）

拿到访问码的人能用你的 Key 发起翻译，甚至能把翻译请求指向别的服务地址（等于能拿到 Key）。所以访问码只发给信任的
设备；发错了点「重置访问码」。只走 HTTP（局域网里没有证书），同一 Wi‑Fi 里能抓包的人看得到访问码 cookie。

### 前端

- 设置里新一栏「局域网共享」（`features/lan-share`，order 65），只在桌面版单机模式列进表：开关、状态、每个局域网
  地址的二维码（主进程用 `qrcode-generator` 生成 SVG）、复制完整链接、重置访问码。
- 桌面桥 `platform/desktop/host.ts` 加 `lanShareStatus` / `setLanShareEnabled` / `resetLanShareToken`
  （IPC `lan_share_status` / `lan_share_set_enabled` / `lan_share_reset_token`）。
- 经局域网打开的页面（运行配置里 `lanShared: true`）在「接口设置」顶上说明 Key 在那台电脑上。

## 验证

- 网关单测（`lan-share.test.mjs`）：管理接口被拦（含编码、重复斜杠、大小写、点段）、没访问码 401、访问码换 cookie、页面配置不含真 Key、占位符替换和拒绝、
  去掉 Origin 加后端密钥、重置后旧 cookie 401、关掉后连不上、`runtime-config.local.js` 和点文件不给。
- 面板测试（`tests/settings/lan-share-panel.test.mjs`）：开 → 地址和二维码 → 复制 → 重置 → 关。
- 本机实测：另起一个临时后端（独立端口和数据目录），网关指向它，从本机局域网 IP 打开：无访问码 401、扫码链接 302
  换 cookie、页面配置只有占位符、任务列表 200、上传 PDF 200，无头 Chrome 打开首页正常显示书库、没有弹首次配置。

## 没做的

- HTTPS、设备列表和逐台踢掉（现在只能重置访问码全踢）、只读模式。
- 手机上的阅读体验专门适配：先看实际用起来哪里不顺。
