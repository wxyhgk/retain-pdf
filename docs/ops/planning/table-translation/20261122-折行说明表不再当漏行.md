# 表格模型：折行的说明表不再当成 OCR 漏行

2026-11-22。

## 问题

回归样本 editable-tables.pdf 的表 2（三种包覆路线对比，4×4，每格三五行说明文字）没翻：表格模型标了
`row_swallows_rows`，表格 agent 把它当结构不可靠跳过（`structure_unreliable:row_swallows_rows`）。
实际结构完全对（格子原文和 OCR 一致，置信度 1.0）。

这条检查原来的规则：一行表格里有两行以上"大半列都有字"的文字，就当 OCR 把几行表格并成了一行。
说明文字表每格都折行，每一行文字都横跨各列，正好撞上。

## 改法

`ocr/tables/model.py` 的 `_wrapped_prose_row`：一行表格里相邻两行文字，大半有字的列满足下面两条，就当同一批格子折行，
不标漏行：

- 下一行这一列是小写字母开头（接着上一句写）；
- 上一行这一列写到了这一列文字范围的 70% 以上（写满了才折）。

漏行的下一行是新数据（"B-02"、"265.9"，大写、数字开头），上一行也写不满，照旧标。没有大小写的文字（中文等）判断不了，照旧标。

## 结果

- 评测集 55 张表两家 OCR：各项数字和改之前一样（GLM 格子原文一致 97.3%、PaddleOCR 94.7%；结构错的表 PaddleOCR 5/5、
  GLM 3/5 标出来，结构对的误标 GLM 4/50、PaddleOCR 5/50），评测集里被这条规则标的 13 次一次没少。
- 回归样本 8 张表：表 2 不再标问题，其余 7 张结果不变。
- 已经翻过的任务要重新翻表格才会用上（表格模型在翻译阶段建）。
