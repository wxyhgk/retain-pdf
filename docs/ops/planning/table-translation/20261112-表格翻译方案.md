# 表格翻译方案

**状态：** 定方案，按第 5 节的分支一个个做
**日期：** 2026-11-12
**范围：** 流水线（OCR 之后的表格定位、翻译、渲染）、翻译包、建任务的一个新开关；前端只在最后一步跟着加开关和展示

## 1. 为什么

正文都翻成中文了，表格还是整块英文，读的人一眼就看见。用户定：表格翻译先于排版 agent 做（排版 agent 的方案见
[layout-agent](../layout-agent/README.md)，暂缓）。翻译 agent 的方案里早就把它列为后做的一项
（[翻译 agent 方案](../translation-agent/20261029-翻译agent方案.md)「图片和表格」）。

## 2. 现在的情况

- **OCR 给的表格是一段 HTML**：行、列、合并单元格都有，但**格子在页面上的位置没有**，整张表只有一个框
  （document.v1 里 `type=table`，`lines/segments` 的 `bbox_precision` 是 `block_fallback`）。
- **翻译直接跳过**：`policy.translate=false`、`translate_reason=provider_non_text:table`
  （`retainpdf_translation/core/classification.py` 把 table 和 formula、image、code 归在一起）。表题、表注照常翻。
- **渲染原样保留**：表格框里的原文不动。
- **模型请求只能带文字**：Rust 模型执行器的消息内容是字符串，Python 请求体也是。翻译 agent 包自己发请求，加图容易。
- **能复用的**：读原文 PDF 文字层的词和位置（`page.get_text("words")`，`render/source/cleanup/text_extract.py` 等处已在用）；
  量原文字号（`render/layout/title_source_size.py`）；盖掉原文的清理（`render/source/cleanup`）；排不下就缩字的排版
  （`rpr_fit` 引擎和 Typst 路线）。

## 3. 怎么做：格子位置用规则定，agent 只管翻

### 3.1 定格子（不用模型）

1. 解析 HTML 成网格：每格一个编号（`r{行}c{列}`），记下跨几行几列、格子里的原文。
2. 读原文 PDF 文字层里落在表格框内的词，按行（y）分组、按 HTML 的格子顺序对齐，得到每格的框和原文字号。
3. 对不上就不翻：对齐上的字数占比低于阈值（先定 90%），或者框里没有文字层（扫描件），这张表保留原文，原因写进报告。

产物：每本书一份 `table_cells.v1.json`（每张表：block_id、能不能翻、原因、每格的编号/跨度/框/原文/字号）。

### 3.2 哪些格要翻

先用规则挑掉不用翻的：纯数字、带单位的数、正负号和百分号、化学式、公式占位符、≤4 个字母的缩写、DOI 和网址。
剩下的交给模型；规则判不准的（比如 `Control`、`SB-3`）也交给模型决定翻还是保留。

### 3.3 翻译（模型，一张表一次）

- 输入：网格（格子编号、跨度、原文）、每格的长度预算（按格宽和原文字号估能放几个汉字）、表题的译文、书的术语表。
- 输出：`{格子编号: 译文 | "keep"}`，一个都不能少。
- 校验：每个格子都有回答；数字原样保留（译文里的数字和原文一致）；占位符和公式不坏；同一张表里同样的原文译法一样；
  超长的软提示、超太多的重试一次。
- 失败（重试后仍不过、模型报错）：这张表保留原文，不影响正文翻译。
- 第一版只给文字不看图：走现有的翻译请求（`request_chat_content`），所以所有服务商、Key 失效时立刻停、请求日志、用量记账
  都照旧可用。看图放到第 6 节"以后"。

### 3.4 放回（渲染）

- 每个要翻的格子当一个新的排版条目（`table_cell`）：盖掉格子里的原文，在格子框里排译文，从原文字号开始，排不下往小缩，
  最小不低于正文最小字号。
- **整表兜底**：任何一格缩到最小还放不下，整张表退回原文（不盖、不排），不出现半张表翻了半张没翻。
- 表格线、底色不动（只盖文字）。

### 3.5 开关和接口（只增不改）

- 建任务加 `translation.tables`：`keep`（默认，行为不变）/ `translate`。评测达标后再把默认改成 `translate`。
- 翻译清单里每个翻了的格子是一个条目（`item_id` 用 `<表格 block_id>:<格子编号>`），已有的译文列表、单条修改（PATCH）、
  重翻自然能用。
- 质量报告加一项：表格翻了几张、保留原文几张、各自原因。

## 4. 怎么评测

- 评测集：从仓库里已有的黄金样例和合成样例里挑表格，不够再从公开论文里补（不提交用户的文件）。覆盖：简单表、合并单元格、
  带化学式和单位、窄列、跨页表。
- 指标：能定位的表格占比；翻了的格子占比；**数字保留 100%**；整表兜底的比例和原因；人眼抽查（用户看前后对比）。
- 每一步的分支都要把指标写进开发记录，达不到就不往下走。

## 5. 分支

| 步 | 分支内容 | 行为变化 | 做完的标志 |
|---|---|---|---|
| T1 | 评测集 + 定格子（`table_cells.v1.json`）+ 定位报告 | 无（只多一个产物） | 评测集上能定位的表格占比、对不上的原因有数 |
| T2 | 表格翻译：挑格子、请求、校验、写进翻译清单；`translation.tables` 开关，默认 `keep` | 开关打开才有 | 数字保留 100%；失败整表保留 |
| T3 | 渲染放回 + 整表兜底 | 开关打开才有 | 评测集上排不下的比例、人眼抽查通过 |
| T4 | 接口和文档：开关进契约、质量报告、前端交接（开关、展示） | 无（前端会话做界面） | 前端能选、能看到哪些表翻了 |
| T5 | 默认改成 `translate` | 默认翻表格 | 用户看过评测结果点头 |

## 6. 以后

- 扫描件的表格：没有文字层，要看图定格子（或者用 OCR 给的行框），再看图翻。前提是模型请求支持图片
  （Rust 模型执行器的消息加内容分段，只增不改）。
- 图片里的文字：同样要看图。
- 跨页表：先各页按各自的表处理，再看要不要合起来统一译法。

## 7. 风险

- 文字层和 OCR 的表格对不上（双栏、旋转的表、文字层错位）：对不上就保留原文，报告里看比例。
- 格子太窄、中文放不下：先缩字，再整表兜底；必要时让模型给更短的译法（在长度预算里提示）。
- 成本：一张表一次请求，比正文少得多；先只测 Haiku（`claude-haiku-5-5`）和 qwen3.8-flash。
