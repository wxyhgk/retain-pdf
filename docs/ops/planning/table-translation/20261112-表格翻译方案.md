# 表格翻译方案

**状态：** 定方案（第一稿被用户指出"考虑得太简单"，本稿按难点重写），按第 7 节的分支一个个做
**日期：** 2026-11-12
**范围：** 流水线（表格理解、翻译、放回）、翻译 agent 包、建任务的一个新开关、阅读页的表格译文；前端界面由前端会话做

## 1. 为什么、要什么

正文都翻成中文了，表格还是整块英文。用户定：表格翻译先于排版 agent 做，**让一个 agent 去做**
（排版 agent 暂缓，见 [layout-agent](../layout-agent/README.md)）。

## 2. 现在的情况（逐条核对过代码）

- **OCR 给的表格是整表一段 HTML**（行、列、合并单元格），**没有格子在页面上的位置**，整张表一个框
  （document.v1 `type=table`，`bbox_precision=block_fallback`）。MinerU 还给表格截图（`provider_image_paths`）。
- **翻译整块跳过**：`policy.translate=false`、`provider_non_text:table`（`retainpdf_translation/core/classification.py`）。
  表题、表注照常翻。
- **PDF 和 Word 里表格都是原文**：渲染不碰表格框；Word 导出是"原页做背景图 + 排版层的文本框"
  （`retainpdf2doc/src/body.mjs`），表格跟着 PDF 走，PDF 里有了 Word 里才有。
- **阅读页**：悬浮框按区域显示译文，读条目上的 `translated_markdown` 等字段（`reader_regions/value_extract.rs`）。
  表格条目有了整表译文，悬浮框就能显示——**不用等 PDF 放回**。
- **模型请求**：Rust 模型执行器的消息只能是文字；翻译 agent 包自己发请求，已经有严格的工具调用（`call_tool`、`strict_tool`），
  加图容易，但只走 anthropic 协议。
- **能复用的**：读原文文字层的词和位置（`get_text("words")`）、量原文字号（`title_source_size.py`）、盖掉原文
  （`render/source/cleanup`）、排不下缩字（`rpr_fit`、Typst 路线）、翻译清单 / 单条修改（PATCH）/ 重翻、编辑部事件。

## 3. 难在哪（第一稿漏掉的）

### 3.1 认表：OCR 给的结构不能直接当真

- OCR 的 HTML 会错：漏格、合并单元格合错、列错位、多层表头被压成一层、两张挨着的表被认成一张、流程图被认成表。
- **表格是图片**（期刊常见）：没有文字层，格子位置和原文只能从图上来。
- 旋转的表（横排页）、**跨页的续表**（"Table 2 (continued)"）、超长表（几百格）。

### 3.2 翻什么、怎么翻

- 要翻：表头、行标签、文字格。不翻：数字、单位、样品编号（`SB-3`）、化学式、表注里定义过的缩写、`n.d.` / `N/A` / `—`
  这类（要按中文习惯处理还是保留，要定规则）。
- 格子里的**脚注上标**（`Yield^a`、`*`、`†`）、行内公式、化学式要原样保留并跟着走。
- 表头里带单位：`Temperature (°C)` → `温度 (°C)`。
- **一致性**：同一个术语在正文、表题、表头、别的表里要一个译法；缩写的含义常写在表注里，要一起看。
- 长表一次放不下，要分段，但分段后表头要跟着每段。

### 3.3 放回 PDF

- 中文更宽、列很窄；**行高是死的**，不能长高。
- **全表字号要统一**（不能每格各缩各的，看起来乱）；对齐方式（左、中、右、按小数点）要保留。
- 表格线、底色不能被盖掉；**数字格一个字都不碰**（保住对齐，也少出错）。
- 图片表：要先抹掉格子里的原文（估底色），再写译文。
- 放不下的退路要分档，而不是一律放弃。

### 3.4 产品

- 表格译文要出现在：PDF、Word（跟着 PDF）、阅读页悬浮框、复制。
- 用户要能改某一格（复用单条修改）、看到哪些表翻了哪些没翻、为什么。
- 进度、续跑（重启不重复花钱）、成本（一本书上百张表）。

## 4. 总体设计：三层 + 一个 agent

```
OCR 的 HTML ─┐
文字层的词 ──┼─► ① 表格模型 table.v1 ──► ② 表格 agent 翻译 ──► ③ 放回
表格截图 ────┘    （结构、格子角色、位置、置信度）  （格子译文挂在模型上）   PDF/Word：原位覆盖 → 重排整表 → 保留原表
                                                                   阅读页：整表译文（不等 PDF）
```

### 4.1 ① 表格模型 `table.v1`（每张表一份）

- 网格：格子编号、跨行跨列、**角色**（表头 / 行标签 / 数据 / 空）、**内容类型**（文字 / 数字 / 单位 / 化学式 / 公式 / 混合）。
- 几何：每格的框和原文字号（文字层对齐得到；图片表没有，标 `geometry=none`）、对齐方式、表格线和底色的大致位置。
- 来源和置信度：结构来自 OCR 的 HTML、文字层、还是 agent 看图修过；对齐上的比例。
- 先用规则合：OCR 的 HTML 定结构，文字层定位置和原文，两者对不上的格子标出来。**只有对不上、或者没有文字层时才让 agent
  看图裁决**（省钱，也可复现）。

### 4.2 ② 表格 agent（一张表一个任务，有上限的循环）

agent 不直接改文件，只通过工具做事；工具都是确定性的代码：

| 工具 | 做什么 |
|---|---|
| `view_table` | 看表格截图（MinerU 给的，或者从原文 PDF 裁） |
| `read_table` | 读表格模型（网格、角色、内容类型、对不上的格子） |
| `read_context` | 读表题、表注（含缩写定义）、正文里引用这张表的段落 |
| `lookup_terms` | 查术语表和正文、别的表里已有的译法 |
| `fix_structure` | 提交结构修正（合并 / 拆格、改表头层级），只能改标出来对不上的地方 |
| `try_fit` | 按当前译文试排，返回每格放不放得下、全表统一字号是多少 |
| `submit` | 提交格子译文（`{格子: 译文 | keep}`），代码校验：格子不能少、数字原样、上标和公式不坏、同表同译 |

- 上限：每张表最多几轮（先定 6）、token 上限；超了或校验不过就整表保留原文，原因写进报告。
- 先规则后模型：数字、单位、化学式这类格子规则先标成 `keep`，agent 可以推翻但要说理由。
- 长表：按行分段交给 agent，每段带上表头和已定的译法。
- **跨表一致**：同一本书的表格共用一份"表格术语记忆"（复用翻译 agent 的记忆机制），后翻的表查得到先翻的译法。
- 引擎：放在翻译 agent 包里（已有工具循环和严格工具，加图容易）。**看图第一版只支持 anthropic 协议**；别的协议的任务
  不看图、只用文字版（文字层表）或整表保留（图片表）。Rust 模型执行器加图片以后再做。
- 模型：测试只用 Haiku（`claude-haiku-5-5`），文字版也测 qwen3.8-flash。

### 4.3 ③ 放回（按顺序试，前一档不行才下一档）

1. **原位覆盖**（文字层表）：只盖要翻的格子的原文，数字格不动；全表一个字号（取所有格子都放得下的最大值，不低于下限），
   对齐照原来的。
2. **重排整表**：原位放不下、或者图片表：在原表框里按表格模型重新排一张中文表（画线、底色近似），样子会变但结构不变。
3. **保留原表**：重排也放不下（或结构置信度太低）：原表不动，可选在表下附一份中文译表（看版面有没有空）。

每张表最后用了哪一档、为什么，写进报告。阅读页的整表译文和放回无关，只要②成功就有。

### 4.4 接口和数据（只增不改）

- 建任务加 `translation.tables`：`keep`（默认，行为不变）/ `translate`。评测达标后再改默认。
- 产物：`table.v1`（每本书一份，含每张表的模型、译文、用了哪档放回、原因）。
- 翻译清单：每个翻了的格子一个条目（`<表格 block_id>:<格子编号>`），已有的译文列表、单条修改、重翻都能用；表格 block 上加
  整表译文（`translated_markdown`，阅读页悬浮框直接用）。
- 质量报告：表格翻了几张、各档放回几张、保留原文几张和原因；编辑部事件里有表格 agent 的进度。
- 续跑：每张表的结果按表格内容哈希缓存，重启不重复请求。

## 5. 评测

- **先摸底**：在本机已有的任务产物上（只读、不提交）统计：一本书平均几张表、文字层表和图片表各占多少、OCR 结构错的比例、
  长表和跨页表的比例。摸底结果决定先做哪类。
- 评测集（只用仓库里的样例和公开论文，不提交用户文件）：简单表、多层表头、合并单元格、带化学式和单位、带脚注上标、窄列、
  长表、跨页续表、图片表，每类若干张，人工标好"该翻 / 不翻"和参考译文。
- 分层的指标：结构正确率（格子、表头层级）；该翻 / 不翻判对的比例；**数字保留 100%**；术语一致；放回各档比例；
  全表字号一致；最后用户人眼抽查前后对比。
- 回放：录下模型响应，离线重跑，改代码不花钱（复用翻译 agent 的测试系统）。

## 6. 不做什么

- 不改表格的结构语义（不增删行列），agent 只能修 OCR 认错的地方。
- 不翻图（图里的文字另做）；不做公式内部的翻译。
- 第一版不改 Rust 模型执行器（看图只在翻译 agent 包里）。

## 7. 分支（每步做完都有用，可以在任何一步停）

| 步 | 内容 | 行为变化 | 做完的标志 |
|---|---|---|---|
| T0 | 摸底统计 + 评测集 | 无 | 表格类型分布、OCR 结构错误率有数；评测集标注完 |
| T1 | 表格模型 `table.v1`：规则合 OCR 的 HTML 和文字层，角色、内容类型、几何、置信度 | 无（多一个产物） | 评测集上结构正确率、对不上的比例 |
| T2 | 表格 agent（文字版）：工具、循环、校验、术语记忆，译文挂到表格模型和翻译清单；`translation.tables` 开关默认 `keep` | 开关打开才有 | 该翻 / 不翻判对率、数字保留 100%、一致性 |
| T3 | 阅读页先用上：表格 block 带整表译文，悬浮框和复制能看到 | 开关打开才有 | 前端不用改就能看到（悬浮框读现有字段） |
| T4 | PDF 原位覆盖：全表统一字号、数字格不碰、对齐保留、整表兜底 | 开关打开才有 | 放回成功率、人眼抽查 |
| T5 | 看图：agent 用截图核对和修正结构；图片表的"重排整表" | 开关打开才有 | 图片表能翻的比例 |
| T6 | 长表分段、跨页续表合并译法、表下附译表 | 开关打开才有 | 对应评测类别达标 |
| T7 | 接口和前端：开关进契约、质量报告、前端交接；评测达标后默认 `translate` | 默认翻表格 | 用户看过评测结果点头 |

## 8. 要用户定的

2. 看图第一版只支持 anthropic 协议（别的协议只翻文字层表），可以接受吗？
3. 先让阅读页看到表格译文（T3），PDF 放回（T4）在后，这个顺序可以吗？
