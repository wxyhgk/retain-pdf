## 做了什么

- 新包 `backend/table-agent`（发行名 `retainpdf-table-agent`），照翻译 agent 包分两层：
  - 核心 `retainpdf_table_agent`：T3 的 `agent.py`、`cells.py`、`memory.py`、`validate.py`、`output.py` 用 `git mv` 原样搬来，只改 import；
    提示词 `table_translate_system.txt` 从翻译包的提示词目录搬到 `retainpdf_table_agent/prompts/`（带 `load_prompt`）；
    交接格式 `contract.py` 放 `ChatResult`（以前借精修的那个）；从模型回复取 JSON 的函数逐字抄进 `json_text.py`（核心不能 import 底座）。
    **只用标准库**，测试钉着。
  - 接线 `retainpdf_table_agent_engine`：T3 的 `llm.py`（`table_chat_fn`，接底座的 `request_chat_content`），装 `[engine]` 才有依赖。
- 调用方：流水线 `translate/tables_stage.py`、评测 `devtools/table_agent_eval.py` 改 import 新包；普通翻译包 `public.py` 去掉 9 个表格导出，
  `services/tables/` 删掉。
- 接线：后端 workspace（成员、依赖、`[test]`）、流水线依赖 `retainpdf-table-agent[engine]`、`uv.lock`；Docker 镜像（导出阶段的 pyproject、
  运行时 `COPY` 和 `pip install`）；开发脚本的 `PYTHONPATH`；源码包的必需文件；CI 的导入检查和新包测试一步；桌面 Python 包跟着 workspace
  成员自动带上（发布契约测试的必需名单加上它）；依赖清单重新生成。CLAUDE.md、后端贡献说明、翻译层说明跟着改。

## 行为不变

提示词（sha256 钉在测试里）、提示词版本 `table_translate.v1`、缓存键都没变，已有任务的表格缓存照样命中。核心抄的取 JSON 函数和底座的
对同一批回复结果一样（`tests/test_engine_wiring.py`）。T3 的 9 条离线测试原样搬到 `backend/table-agent/tests` 照样过。

方案里写的「`table_agent_eval.py --replay` 结果一字不差」这次没比：11-14 录的回复文件在当时的本机临时目录里，没进仓库、现在找不到了。
下次花钱实测（G5）时 `--record` 一份放进 `tests/fixtures/tables/`，以后搬动就能回放比对。

## 顺手修的

`tests/performance/pipeline/support/offline.py` 起子进程时 `PYTHONPATH` 只放流水线：在 worktree 里跑，子进程测的是主检出 venv 里装的那份
翻译代码，新包没装进 venv 时直接 `ModuleNotFoundError`（这次 27 条就是这么红的）。改成和 `run_translation_tests.py` 一样，本仓库所有
`retainpdf_*` 包排在最前；钉环境的测试跟着改。
