# 表格翻译 T0 摸底：更正

**日期：** 2026-11-12

[T0 摸底](./20261112-T0摸底.md) 里格子层面的数字算少了：`table_survey.py` 取表格 HTML 时只取了第一段，表格里有公式时 OCR
把 HTML 拆成好几段（文字段和公式段交替），后面的全丢了。标评测集时发现（两家 OCR 的 55 张表里，GLM-OCR 47 张、
PaddleOCR 51 张被截断），已改成取表格 block 的整段 `text`（公式写成 `$ … $`），加了测试。

重新跑的结果（表格来源三类、张数、续表、旋转页都不变）：

| 项 | 原来 | 更正后 |
|---|---|---|
| 格子 | 85310 | **110682** |
| 格子内容 | 文字 39715、数字类 30236、空 15359 | 文字 51960（47%）、数字类 40207（36%）、空 18515（17%） |
| 有合并单元格 | 873 张（28%） | **913 张（30%）** |
| 超过 150 格的长表 | 57 张 | **77 张** |

结论不变：比例几乎没动；长表比原来以为的多三成，成本和分段的考虑更要紧。

另外，评测集第一次生成时同样被截断，当时说"同一批表两家给的格子数差很多（957 对 545）"是错的；修好后是 GLM-OCR 7025 个、
PaddleOCR 6929 个，总数接近。两家结构的差别要逐表对着标准答案看。
