# 表格翻译 T1：表格模型实现记录

**日期：** 2026-11-12
**代码：** `backend/pipeline/retainpdf_pipeline/ocr/tables/`（说明见目录里的 README）
**打分：** `backend/pipeline/devtools/table_model_eval.py`，对着评测集 55 张表的标准答案

## 顺序调整（用户 2026-11-12 定）

先走"有文字层的表"这条线，尽早能用：T1 表格模型 → T3 表格 agent（先只看文字）→ T4 阅读页显示 → T5 放回 PDF；
看图（T2，所有协议都做）挪到这之后，再补图片表和字转曲线的表。原方案的决定不变，只是先后。

## 做法

结构用 OCR 的 HTML（两家行列数对的 89%–91%），每格的位置和原文从文字层取（OCR 的格子文字约四成不对）。
详细步骤见代码目录的 README。

## 一路改进的数字（格子原文和标准答案完全一致的比例）

| 改动 | GLM-OCR | PaddleOCR |
|---|---|---|
| 直接用 OCR 的格子文字（对照） | 63% | 61% |
| 第一版：按最大空隙切列 | 70% | 70% |
| 列界改成竖向空白通道（找不够退回按空隙切） | 82% | 80% |
| 符号字体错码对照表（Advent 字体：`\x04`→×、`1`→°、`D`→Δ…，逐个字形看图核对） | 94% | 92% |
| 斜着的水印不参与分行 | 96% | 94% |
| 按基线分行；抬高的零星片段并成上标 | **97.3%** | **94.7%** |

只比文字（不管上下标标记）是 98% 和 95%；角色（表头 / 行标签 / 数据 / 空）判对 97.6% 和 96.3%。

## 结构有错的表

OCR 结构本身就错了的表（行列数和标准答案不同）：GLM-OCR 5 张、PaddleOCR 5 张（规则修好一张：OCR 把表注当成了最后一行）。
规则修不了的打上 issues，交给后面看图裁决：

| | 结构真错的表被标出来 | 结构对的表被误标 |
|---|---|---|
| GLM-OCR | 3/5 | 4/50 |
| PaddleOCR | 5/5 | 5/50 |

GLM-OCR 漏标的两张：叠放的两层表头被并成一行、分组标题行整行漏掉——文字层上没有明显信号，要看图。

## 还没做

- "翻不翻"的规则建议只是粗分（判对约 80%，主要错在化合物名、反应条件被建议成翻）——T3 交给模型定，规则只挑明显不用翻的。
- 没有文字层的表（约两成）：看图之后做。
- 还没接进流水线（不写产物）：T3 接表格 agent 时一起接，免得先写一个没人读的文件。
