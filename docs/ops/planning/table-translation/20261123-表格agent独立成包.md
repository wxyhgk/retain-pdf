# 表格 agent 独立成包

**状态：** 方案，用户定了方向（见第 1 节），按第 6 节分步做，花钱的评测每次先问。
**日期：** 2026-11-23

## 1. 用户定的

用户：“我们的表格翻译得自己开发一个 agent 去处理”。问了三件事，答复：

1. **新包取代 T3**：照翻译 agent（`backend/translation-agent`）的样子单独做一个包；现在挂在普通翻译包里的文字版表格 agent（T3，
   `retainpdf_translation_classic/services/tables/`，约 700 行）的校验、术语记忆搬过去，新包稳定后删掉 T3，表格只剩一套。
2. **第一版就看图**：表格截图用来核对、修结构；排完的截图用来检查排版。
3. **评测和实测用 claude-haiku-5-5**；花钱的每次先问。

## 2. 现在到哪了、卡在哪

| 层 | 现在 | 问题 |
|---|---|---|
| T1 表格模型 | OCR 的 HTML + 文字层，每格原文对上 97.3% / 94.7% | 结构错的表只会标出来（`row_swallows_rows`、`columns_not_found`……），修不了；没有文字层的表（字转曲线 14%、图片 5%）没有格子原文 |
| T3 表格 agent | 只看文字，JSON 动作循环翻格子，Haiku 翻不翻判对 98.9%、数字全对 | 结构不可信的表整张跳过（评测集 55 张里 6 张）；看不到原表长什么样 |
| T5 放回 PDF | 规则量样式，引擎 `rpr-table.js` 按原表的框重排，排进了才换 | 没翻的格子丢上下标（LiFePO₄ → LiFePO4）；排不进就整张保留原表；排出来比原表矮留空白；自动列宽有时把空间都给一列 |

每一层各管一段，出了问题只能“跳过”或“保留原表”。缺的是一个从头管到尾、能看图、能改的人。

## 3. 一张表怎么走

一张表一个 agent 循环，四段，每段都是“规则先做、规则检查不过才问模型、模型只能用给定的工具改”（借表格排版 agent 方案的两条经验：
好坏以规则检查为准，模型看图为辅；每一步改动小而可检查）。

1. **读表**：表格模型（T1）、原表截图（裁到表格的框，长边约 1000 像素）、表题表注、这本书的术语记忆。
2. **定结构**：表格模型没标问题的直接用。标了结构不可信、或没有文字层的，把截图和当前结构给模型，它只能用结构工具改：
   - `set_header_rows`、`merge_cells` / `split_cell`、`move_row_to_caption`（被当成一行的表题表注）、`set_cell_source`（只给没文字层的表填原文，看图认字）。
   - 改完用文字层核对（有文字层时每格的字要对得上），对不上的退回；最多 3 轮，不行整张保留原文。
3. **翻格子**：T3 的循环搬过来（`lookup_terms` 查译法、`submit` 交格子、逐格校验数字 / 上下标 / 同表同译、长表分段、术语记忆），
   加一个 `search_book`（全书原文和已有译文里搜，翻译 agent 已有同名工具）。这一段不看图，和现在一样便宜。
4. **排版**：表格排版 agent 方案（[layout-agent](../layout-agent/20261122-表格排版agent方案.md)）的 A1–A5 并进来：
   规则排第一版 → 规则检查（排没排进框、每格的字和数字、上下标、字号不低于原文 0.8 倍、没有一个字一行的窄列）→ 过了就用；
   没过才给模型看原表截图、排好的截图和没过的检查项，它只能改排版描述（`set_columns`、`set_font`、`set_cell` 只许加回格式、
   `shorten` 请压短某格译文、`keep_original`），引擎重排再检查，最多 3 轮，按规则得分取最好的一版。

产物：

- `translated/tables.v1.json` 照旧（阅读页 T4 在读），只加字段：每张表多一个 `agent` 记录（每段用了几轮、改了什么）。
- `translated/table-layouts.v1.json`：每张表选中的排版描述和每一轮的检查结果。渲染只读它，重渲染不再调模型。

## 4. 包怎么分

照翻译 agent：

- `backend/table-agent`，发行名 `retainpdf-table-agent`：
  - 核心 `retainpdf_table_agent`：循环、工具、校验、规则检查、交接格式（`contract.py`，只加不改），**只用标准库**，测试钉着。
    模型调用、截图、引擎排版都由调用方传进来（函数），核心不认识哪家模型、不碰文件。
  - 接线 `retainpdf_table_agent_engine`：接翻译底座的模型调用（带图）、术语记忆、PyMuPDF 截图、调 `rpr-table.js`；extra `[engine]`。
- 流水线 `translate/tables_stage.py` 改成调新包；表格模型（T1）留在流水线的 `ocr/tables`，接线把它的结果转成核心的输入。
- 跑在哪：照旧在正文翻完之后（要正文的术语记忆）。截图要原文 PDF，排版要引擎，流水线这一步都有。

## 5. 带图请求的路

Python 模型调用层已经能带图（`model_wire.image_part`，三种协议），但 **Rust 模型执行器还只收文字**，带图请求在 Python 这边直接报错。
任务带“模型连接”时走执行器（`uses_model_executor`），界面建的任务多半是这样，所以要在执行器里加上图片片段（请求体、缓存键、
请求日志记图片哈希不记内容）。这一步不改翻译的行为。

## 6. 分几步

| 步 | 做什么 | 花钱吗 |
|---|---|---|
| G1 | 建包：核心骨架和交接格式；T3 的循环、校验、术语记忆搬进核心，行为不变（T3 的离线测试搬过来照样过，`table_agent_eval.py --replay` 结果一字不差）；流水线改调新包；删 T3 | 不花 |
| G2 | 排版的规则部分：规则检查（A1）、引擎旋钮 `columns` / `noWrap` 和 `table-layouts.v1.json`（A2）、规则能修的先修（A3：上下标从文字层补回、窄列不折行、排不进先压行距内边距） | 不花 |
| G3 | Rust 模型执行器收图片片段 | 不花 |
| G4 | 看图的两段：定结构（第 3 节第 2 段）和排版循环（第 4 段的模型部分）；离线测试用录好的回复 | 不花 |
| G5 | Haiku 实测：评测集 55 张 + 回归样本 7 张，量结构修对多少、排进比例、丢上下标的格子、花费；人眼抽查原表 / 规则版 / agent 版 | **要用户同意** |
| G6 | 评测达标后：前端开关的“翻译表格（试验）”去掉“试验”，再定默认要不要翻表格 | 用户点头 |

G1–G4 不调模型。G5 之前每一步都能单独合，合了也不改变默认行为（开关默认 `keep`）。

## 7. 评测

- 结构：评测集里结构不可信的表（现在跳过的 6 张）修对几张；没文字层的表看图认字的准确率（和标准答案逐格比）。
- 翻译：和 T3 同一套口径（翻不翻判对、数字原样），不能比 T3 差。
- 排版：排进原表框的比例、丢上下标的格子数、字号缩小程度、留白；看图请求数和 token。
- 规则检查本身要先对：评测集上人标一遍“排得好不好”，看规则检查和人的判断一致多少（不一致的先修规则，不让模型当裁判）。

## 8. 风险

- 看图认字（没文字层的表）错一个数字就是错的数据：数字格看图认出来的要和 OCR 的结果对上才用，对不上的格子标出来、保留原表。
- 模型改结构改坏：每次改完都和文字层核对；只有工具，没有“重写整张表”。
- 花费：大部分表规则就过，只给挑出来的表看图；每张表看图最多 3 + 3 次。G5 用评测集量出一本书大概多少钱再定默认。
