# 表格翻译 T4：阅读页用上表格译文

**日期：** 2026-11-22
**代码：** 任务包 `backend/packages/retainpdf-jobs/src/reader/reader_regions.rs`、`reader_regions/artifacts.rs`；
产物位置 `retainpdf-core` 的 `resolve_table_translations`（`StoredFile::TableTranslations`）

## 为什么现在做

T3（2026-11-14）把表格翻好写进 `translated/tables.v1.json`，但没有接口读它，前端也就没把开关放进界面。用户 11-22 说
「先让前端接入表格翻译」。方案第 7 节 T4 定的就是这一步：阅读页先用上整表译文，PDF 放回（T5）以后再做。

## 做了什么

- 区块接口 `reader/regions` 读 `tables.v1.json`：整表翻了（`result.status == "translated"`、有 `translated_html`）的表，
  对应的块（按 `block_id` 找，三位、四位编号都认）`translated.text`、`markdown` 换成整表译文 HTML，`status` 记成 `translated`。
  位置不动，用原文的。
- 只加内容，不加字段、不改契约结构：阅读页把 `translated.text` 当译文，表格块本来就是 HTML，前端预计不用改就能显示。
- 读不懂、还没写出来的 `tables.v1.json` 当没有（记一条 warn），表格照旧只有原文，不让整页区块读不出来。
- 缓存：区块指纹本来就看翻译目录里每个文件的大小和修改时间，表格翻完 ETag 自然变，不用另加。
- 文件名两边各写一份（Rust `TABLE_TRANSLATIONS_FILE_NAME`、Python `TABLES_FILE_NAME`），Python 的 `test_tables_stage.py` 钉着。

## 没做

- 译文 PDF 里放回表格（T5）。
- 表格译文的单格修改、重翻：翻译清单里没有表格的格子（T3 记录里说了原因），等阅读页用起来再定。
- 原文 Markdown 下载（`reader/markdown`）是 OCR 原文，不涉及译文；前端的 MD 打包下载取的是 `reader/regions`，会带上表格译文。
