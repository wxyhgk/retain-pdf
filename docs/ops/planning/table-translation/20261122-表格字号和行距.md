# 表格字号比正文小一号，空出来的地方先给行距

2026-11-22。

## 用户定的

- 「表格里面的文字我建议比正文小」：表格起始字号不超过译文正文字号的 0.9 倍。正文字号取 rpr 引擎全书统一的那个
  （报告 `body_font.shared`）；拿不到（Typst 退路）按原表字号 × 0.9。原表本来就更小的照原表。
- 「优先增加行间距，然后增加文字，更适合中文」：表格排进了原表的框还有空时，先把格内行距加到 1.6 倍，再把格子上下内边距
  加到字号的 0.6 倍，字号不动；再有空就留白。

为什么：论文、书里的表格本来就比正文小一两号；汉字满框，同字号看着比英文大，照原表字号排显得挤；中文从更长的英文
译过来，表格变矮（回归样本表 2 每格三五行英文，译成中文两行），空间给行距比给字号读着舒服。

## 做了什么

- 引擎（retain-pdf-rendering main 的 42f787b，分支 `feat/table-fill` 合进去的）：表格输入加 `fill: {lineHeightMax, paddingYMax}`，排进了还有空时按"行距 →
  内边距"二分找最大的；报告多给 `line_height`、`padding_y`。
- `render/output/tables/overlay.py`：`table_start_size`（起始字号封顶）；格子上下内边距按实际字号反推，字号变小时行和行的
  间距还是原表的；传 `fill`（1.6 倍、0.6 个字）。渲染流程把引擎的正文字号传进来。

## 效果

回归样本：正文 10.21 pt，表格从 10.5 / 9.5 pt 变成 9.19 pt（8.5 pt 的那张照原表缩到 8.25 排进）；7 张表正好填满原表高度，
表 2（每格几行说明文字）行距 1.6、内边距 0.6 个字后还矮于原表，下面留白。

## 下一步

正文也照这个顺序：先加行距、再加字号（引擎 `fit-model/passes/retain-body.js` 的 underfill 阶段现在是先加字号）。
用户要求先量清楚一两行的段落、中英文译后字数比，再定什么时候加行距、什么时候加字号。
