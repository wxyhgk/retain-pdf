## 做了什么

表格模型（T1）标了结构不可信的表以前整张跳过；现在先把原表截图和当前结构给模型，它只能用结构工具改，改完用文字层核对，
修好了接着进翻格子的循环。

- **核心** `retainpdf_table_agent/structure.py`（只用标准库）：`fix_structure(table_model, source=StructureSource(...), chat_fn=…)`。
  - 调用方给 `StructureSource`（`contract.py`，只加）：文字层每行的字、结构初稿、`rebuild(draft)`、`screenshot()`。
    截图是调用方做好的消息片段，核心原样放进第一条 user 消息，不看内容。
  - 初稿像 HTML 表格一样按行排格子（列号由占位算出来）：改了跨度、删了格子，同一行后面的格子跟着挪——OCR 跨度错一格、
    整行右移这类错就是这么来的，也就这么改回去。
  - 一轮一次请求，最多 3 轮。模型回 `edit`（一组改动 + `done`）或 `give_up`。编号（行号、格子编号、列号、L 编号）
    都按这一轮开头给它看的结构，同一轮先做哪条都行。
- **工具**（看了评测集里 12 张被标的表都错在哪才定的，每个都用上了）：

  | 工具 | 修什么 |
  |---|---|
  | `move_to_caption` | 表题、表注的文字框进了表格（只能移最上面或最下面连着的几行） |
  | `split_row` | 几行数据（或叠放两层的表头）被 OCR 并成了一行；切出来的新行每列一格 |
  | `confirm_rows` | 规则标了吞行，其实是格子里折行（只能确认规则标出来的行） |
  | `set_span` | OCR 跨行跨列错了，后面的格子错位 |
  | `delete_cell` / `delete_column` | OCR 多认了一格 / 一整列空列（跨过这一列的格子自动少跨一列） |
  | `merge_cells` | 横跨整行的分组标题被切成了几格（要拼成长方形） |
  | `set_header_rows` | 表头行数（切开叠放表头以后） |

- **核对**（每条改动做完就重建一次）：表格行里文字层的字一个都不能丢——每个字要落进某个格子，或者是移出去的表题表注；
  丢了字、把列撑多了（没有加列的工具）、参数不对的改动撤回，连原因退回给模型。一轮做完再看规则检查（`row_swallows_rows`、
  `columns_not_found`）。**过了检查、字一个没丢才算修好**；说了 `done` 但这一轮有改动被退回的不算完，再给它看一轮。
  到了上限还不行、或者模型 `give_up`，整张保留原表，不留半修的结构。
- **流水线一侧** `ocr/tables/structure.py`：`table_structure(block, page)` 出初稿（就是表格模型自己用的那份网格和行对应），
  `rebuild(draft)` 走和建表格模型同一个 `assemble_table_model`（从 `build_table_model` 里拆出来，输出不变）。初稿原样交回重建
  和表格模型一字不差，评测集两家 OCR 110 张钉在测试里。表题表注的行移出去以后，表格的框收到表格本体（T5 放回 PDF 时不会盖掉表题）。
- **接线**：`table_screenshot_part(page, bbox)` 截原表（裁到框、留 3pt 边，长边约 1000 像素，小表最多放大 4 倍，PNG 超过 3.5 MB
  换 JPEG），PyMuPDF 的页由调用方给、接线不 import fitz。一个请求只有一张图（执行器上限 4 张、每张 4 MB）。
  请求标签 `table-translate-structure`，用量台账照旧记在「表格翻译」下。
- **流水线** `translate/tables_stage.py`：表格模型标了这一版修得了的问题（`row_swallows_rows`、`columns_not_found`）才定结构；
  修好了用修好的结构翻，`tables.v1.json` 里 `model` 存修好的那份（格子编号对得上译文），结果多一个 `structure` 记录
  （状态、原因、轮数、收下的改动、退回几条、改前改后行列数）；文件顶上多 `structure_prompt_version`。都是只加字段。
- **缓存**：提示词版本 `table_structure.v1`。要定结构的表缓存键另带「提示词版本 + 初稿 + 文字层」的指纹；不定结构的表键和以前
  一字不差（T3 的提示词、`table_translate.v1` 照旧钉着）。以前因结构不可信跳过的表键变了，重跑会去修。定结构的请求失败照旧记
  `request_failed`、下次重试；Key 被拒照旧停整个任务。
- 评测脚本 `table_agent_eval.py`：`--provider` 可给两家、`--only-flagged` 只跑被标的表、`--structure-only` 只定结构、
  `--no-structure` 照 G4 以前；修好的表和标准答案比行列数、格子原文；用量按用途分开记。

## 评测（2026-11-25，claude-haiku-5-5，用户说不用考虑费用）

评测集（公开样例 PDF，`tests/fixtures/tables/`）里表格模型标了结构不可信的表：GLM-OCR 5 张（T3 记录里的 6 张，11-22 折行误判修好后
少了一张）、PaddleOCR 7 张，共 12 张，都是有文字层的，定结构以后接着翻格子。

先看 12 张都错在哪（工具照这个定）：表题、表注被框进表格的第一行（6 张，其中 2 张 GLM-OCR 的行列数本来是对的，只是表题让
规则以为吞了行）；几行数据或叠放两层的表头被 OCR 并成一行（6 张）；横跨整行的分组标题和下一行并在一起（1 张）；OCR 跨行
多跨了一行、某行多认一格（1 张，`columns_not_found`）；最右多认一整列空列（1 张，`columns_not_found`）。手写正确改动跑一遍，
7 张有代表性的都修回标准答案的行列数（工具够用、核对不误挡）。

最终代码和提示词跑一遍（`table_agent_eval.py --only-flagged --provider glm_ocr --provider paddle`）：

| | 结果 |
|---|---|
| 修好（过了规则检查、文字层的字一个没丢） | **12 / 12**，保留原表 0 |
| 修完行列数和标准答案一样 | 11 / 12（差的一张：PaddleOCR 那张叠放表头的表，第二组叠放表头没切开，规则查不出来） |
| 轮数 | 10 张 1 轮、2 张 2 轮，共 14 次请求；退回 5 条改动（其中 4 条是跨度把列撑多了，模型下一轮改对） |
| 修好的表格子原文和标准答案一样（只比文字） | 2961 / 3022（98.0%）；对不上的是表格模型取字的老问题（逗号后的空格、错位的上标）和标注口径（标准答案用跨两行的格子，这边是上一格空着） |
| 接着翻格子 | 12 / 12 整表翻了；翻不翻判对 98.7%（3010 格），翻了的 355 格数字全部原样 |
| 用量：定结构 | 14 次请求，输入 16.9 万 token（其中缓存命中 2.4 万）、输出 1.3 万；按 Haiku 5.5 $0.10 / $0.50 每百万算约 **$0.02**（一张表约 $0.002） |
| 用量：翻格子 | 24 次请求，输入 10.8 万、输出 3.9 万，约 $0.03 |

开发过程中前后跑了 5 遍（每改一次提示词、规则重跑），修好的张数 12、12、12、11、12：没修好的那次是模型把跨度改大、列数变多以后
自己放弃（保留原表，没有半修）——之后加了「改动不许把列撑多」的核对，同一张表第二轮就改对了。抽看了几张：表题移出去以后
表头一行、数据行一行一条；71 行的长表把并成 5 行、8 行的两处切开；13 列多一列空列的表删了空列、表头的跨列跟着少一列。

**本机任务里的表**（`data/jobs` 只读，书的内容不进仓库，只记数字）：现在的表格模型标了结构不可信的有 8 张，其中 2 张没有文字层
（这一版不修）。6 张里修好 3 张：一张一格里折行的说明表（确认折行）、一张左右两栏并排的对照表（切开 4 处并行、把左边该跨两行
的格子合并，3 轮、退回 22 条改动后过了检查）、一张例题框（按「题目 / 解答」切了一行，翻了）；另 3 张模型自己放弃、保留原表，
其中 2 张它说明了「是例题和解答框，不是数据表」——这类框是 OCR 当成表格的教材版式，第一版提示词时模型会按公式把解答切成很多行，
提示词加了「不是数据表就 give_up」以后不再切。10 次定结构请求、6 次翻格子请求。

## 没做 / 下一步

- **没有文字层的表**（字转曲线、图片表，`no_text_layer`）：要看图认字（`set_cell_source`，数字要和 OCR 对上才用），这一版没做，照旧跳过。
- **OCR 没给网格的表**（`ocr_html_missing`）：要从文字层从头搭结构（定列界），工具不一样，没做。
- 没有加列、切格子（`split_cell`）的工具：评测集和本机任务里没见到要用的；OCR 少认列的表会一直 `columns_not_found`。
- 规则检查过不了的才看图：表格模型没标出来的结构错（T1 记录里 GLM-OCR 漏标的两张）照旧发现不了。
- G4 的排版循环（看排好的截图、排版工具）。
- G5 在完整评测集 + 回归样本上量花费、人眼抽查放回 PDF 的效果；`--record` 的回放文件进 `tests/fixtures/tables/`。
