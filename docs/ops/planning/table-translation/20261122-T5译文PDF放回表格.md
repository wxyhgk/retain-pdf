# 表格翻译 T5：译文 PDF 里放回表格（整表按原表的框重排）

2026-11-22。

## 为什么现在做

用户 11-22：「表格翻译怎么还不能显示啊排版啊」。T4 之后阅读页的区块接口已经带出整表译文，但译文 PDF 里的表格还是原文：
正文渲染（rpr_fit 引擎和 Typst 两条路线）把表格当保留元素，不碰；表格译文只在 `tables.v1.json` 里。

## 试过、放弃的做法

1. **逐格原位换字**（方案第一档）：在原表每个格子的位置删字、写译文，全表统一字号。一行的格子还行，
   多行说明文字的表（回归样本表 2）很难看：折行位置不对、句号掉到行首、上下位置乱。用户：「直接用 html 渲染」。
2. **MuPDF 的 HTML 排版（`fitz.Story`）**：不支持跨行（rowspan）、不认表格宽度，表 3、表 4 排乱；还把整个思源宋体嵌进去，
   一张表 50 MB。
3. 字直接用 PyMuPDF 写：MuPDF 子集化这个 OTF 报错，5 页 PDF 从 400 KB 涨到 20 MB。

用户在「Typst 表格 / 真浏览器 / 自己写 / 放进 rpr 引擎」里选了**放进 rpr 引擎**。

## 做了什么

**引擎**（retain-pdf-rendering 分支 `feat/table-layout`，同步进 `backend/rendering-engine/engine`）：

- `src/table/layout.js`：像 HTML `<table>` 那样排——列宽按 min-/max-content 自动分，跨行跨列，格子里折行
  （测字、折行用正文同一套 `Text` 测量器，和 Typst 一致的中文折行）；从原文字号往下找排得进原表高度的最大字号
  （最多缩到 0.7 倍）；三线表 / 全框的线画成细长的实心矩形。
- `bin/rpr-table.js`：输入 `rpr_table_input_v1`，出 `overlay.pdf`（一张表一页，字嵌子集）、`layout.json`、`report.json`
  （每张表排没排进、字号、宽高、列宽）。

**retain-pdf**（`render/output/tables/overlay.py`，渲染流程排完正文、挪链接之前调用）：

- 核对：表格位置上读出来的字和格子原文一致的不到一半，整张不动。
- 量原表：字号（格子字号中位数）、表头几行（优先按三线表的表头下线；其次开头连续的粗体行；表格模型的 role 不准，
  全是文字的表会把前几行都标成 header）、表头粗体、每列左/中/右对齐、行距（反推格子上下内边距）、表格线、颜色。
- 拼引擎输入：翻了的格子用译文，没翻的（数字、代号）照抄原文；`<sup>`/`<sub>` 转成公式上下标。
- 排进了原表的框：擦掉原表框里的字和整条落在框里的线（不填底色，图片不动），叠上引擎画的那一层。
  排不进、引擎用不了：保留原表，记在 `render_diagnostics.table_overlay`。

## 效果

回归样本 editable-tables.pdf（8 张表；表 2 用修好 `row_swallows_rows` 误判后重翻的译文）：8 张全部换上；
表 4 的跨行、表 3 的跨列、表 2 的多行说明文字都排对；7 张保持原文字号，1 张缩了一点（8.5→8.25）。
5 页 PDF 0.8 MB。

## 还没做

- 没翻的格子会丢原文的格式：文字层没带上下标的（表 5 的 LiFePO₄ 变成 LiFePO4）重排后就是平的；
  译文本身漏了上标的（表 1 表头 `g−1`）也一样。
- 排完的表比原表矮时，下面留空白（不挪后面的正文）。
- 字转曲线的表、图片表、跨页续表（T6）。
- 排版 agent：排不进、排得不好的表，循环看图改排版描述，见 [layout-agent](../layout-agent/README.md)（用户 11-22 同意先写方案）。
