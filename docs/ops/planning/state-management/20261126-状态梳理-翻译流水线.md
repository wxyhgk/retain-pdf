
## 6. 设计建议

### 6.1 目标

1. 每块一个显式状态，所有判定只读它。
2. 结果和它依据的原文、分组绑在一起：依据没变，结果就不会丢。
3. 模型的决定第一次产生就冻结，跟断点一起走。
4. 读盘只读；所有改动（策略、分组、引擎 skip、清洗、迁移）从一个调和入口进，有报告。
5. 旧字段降为投影，供 Rust、渲染、前端过渡。

### 6.2 块状态：数据结构草案（页记录里新增 `state`，旧字段保留为投影）

```jsonc
{
  "item_id": "p028-b003",
  // …原有输入字段不动（原文、合同、版面）…
  "state": {
    "v": 1,
    "status": "pending",            // pending | translated | kept | dead_letter
    "kept": {                       // 只在 status=kept 时有
      "owner": "document",          // document（OCR policy.translate=false）| policy（页面策略规则）
                                    // | engine（agent 的 skip_no_prose 等、普通翻译的编号快路径）
                                    // | model（模型判 keep_origin）| user
      "reason": "skip_back_matter_index",
      "decided_at": "2026-11-26T…", "attempt_id": "…"
    },
    "result": {                     // translated / dead_letter（失败前若有旧结果）时有
      "unit": {
        "id": "__cg__:cg-12",       // 单块就是块号
        "members": ["p027-b011", "p028-b003"],
        "index": 1
      },
      "basis": {                    // 结果依据的东西；调和时逐项比
        "source_sha": "…",          // 本块 source_text（规范化空白后）的 sha256
        "unit_source_sha": "…",     // 当时整组受保护原文的 sha256
        "math_mode": "direct_typst",
        "engine": "legacy",         // legacy | agent
        "inferred": false           // 旧断点迁移来的：true（见 6.7）
      },
      "unit_text": "…",             // 受保护的整组译文（取代 translation_unit_protected_* 和 group_protected_*）
      "member_text": "…",           // 受保护的本块译文（取代 protected_translated_text）
      "quality": "ok",              // ok | partial（reasoning 泄漏、邻段裁剪）| suspect（$ 不成对等，调和时标，不删）
      "origin": "model",            // model | fixed:toc_agent | fixed:connective | dedupe:<代表块号> | repair:garbled
                                    // | repair:agent | final_recovery | revision:user|agent|refine
      "at": "…", "attempt_id": "…", "revision_id": null
    },
    "failure": {                    // 只在出过错时有；成功后清掉，不残留
      "count": 2, "last_code": "transport_timeout", "last_at": "…"
    }
  }
}
```

要点：

- 还原后的文字（`translated_text` 等）不再是真相，由 `project_legacy_fields(item)` 从 `state` 算出来写回旧字段。Rust、渲染、前端照旧能读，后端对前端只增不改。
- `blocked`（等同组的伙伴、流式里等下一页）不落盘，是从 `status=pending` + 分组现算的。
- 诊断（`translation_diagnostics`）只当日志：`final_status`、`dead_letter` 从诊断里移走，读方一律读 `state`。
- 存放位置：仍在页文件里（页文件已经有快照、哈希、发布协议，不另起一套）。页文件外面包一层版本：`{"schema":"translation_page_v2","items":[…]}`；读方看到数组就按 v1 读。

### 6.3 转换表（唯一的写入口 `transition(item, event)`）

| 从 | 事件 | 到 | 条件 | 顺带做的事 |
|---|---|---|---|---|
| pending | `result_applied(unit, text, origin)` | translated | 当前分组 = `unit` | 写 `result`（含 basis）、清 `failure` |
| pending | `attempt_failed(code)` | pending | — | `failure.count++` |
| pending | `exhausted(code)` | dead_letter | 重试和补救都用尽 | 保留 `failure` |
| dead_letter | `result_applied` | translated | 同上 | 清 `failure` |
| pending / dead_letter | `keep(owner, reason)` | kept | owner 的优先级 ≥ 当前（user > model > engine > policy > document） | 有 `result` 时挪进 `result_shelved`，不删 |
| kept(owner=policy\|document) | `policy_recomputed(translate=True)` | pending（有 `result_shelved` 且依据没变就直接回 translated） | 只有策略自己能撤销自己的决定 | — |
| kept(owner=model\|engine\|user) | 策略重算 | 不变 | **冻结**（解决上一份 #1：agent 的 skip 不再被打回） | — |
| translated | `revised(text, source)` | translated | — | 更新 `member_text`/`unit_text`、`origin=revision:*`、`revision_id` |
| translated | `invalidate(reason)` | pending | **只有调和入口能发**：依据不符，或用户明确要求重翻 | 旧结果挪进 `result_stale`，写调和报告 |
| translated | `attempt_failed` / `exhausted` | translated | — | **拒绝**并记违规（现在 `final_status.py` 只观测；这里改成拦截） |

所有现有写入点映射到事件：

- `mark_policy_skip` → `keep(policy|document|engine)`；
- `mark_keep_origin` → `keep(model)`；但编号快路径 → `keep(engine)`，最终补救的策略保留 → `keep(policy)`；
- 去重副本：代表块失败时**副本保持 pending**，不再伪造 keep（修 N1）；
- `apply_*_translated_entry` / `apply_reconstructed_unit_text` → `result_applied`；
- `mark_translation_failed*` / `_mark_dead_letter` → `attempt_failed` / `exhausted`；
- `apply_revised_*` → `revised`。

### 6.4 冻结的模型决定：`translated/decisions.v1.json`

```jsonc
{
  "schema": "translation_decisions_v1",
  "document": {"normalized_document_sha256": "…", "page_count": 1032},
  "domain":   {"status": "ok", "value": {"domain": "…", "summary": "…", "translation_guidance": "…"},
               "model": "…", "decided_at": "…"},          // 失败也记 status=failed；之后不再重试，除非用户要求
  "fixed_translations": {"status": "ok", "source": "toc_agent", "input_sha256": "…",
                         "complete_document": true,       // 流式前缀算的记 false，OCR 做完后补算一次再冻结（修 N3）
                         "items": {"p003-b004": "第1章 …"}},
  "continuation_review": {"pairs": [{"prev": "p027-b011", "next": "p028-b003",
                                     "digest": "…", "join": true, "decided_at": "…"}]},  // 每批判完就追加（修 N2）
  "frozen_units": {"__cg__:cg-12": {"members": ["p027-b011","p028-b003"], "reason": "translated"}},
  "artifacts": {"term_base_sha256": "…", "style_guide_sha256": "…", "agent_reading_sha256": "…"}
}
```

- 写法：追加式、原子替换，每个决定产生的当下就写（不等阶段结束）。
- 续跑：读到就用，不再问模型。
- 断点身份**不再包含**这些决定的哈希：它们不是输入，是冻结下来的中间结果。
- Rust 拷贝改成按清单：Python 维护 `translated/resume-set.v1.json`，列出「跨任务要带走的文件和目录」：`decisions.v1.json`、`agent/`、`tables.v1.json`、`job-memory.json`、`term-base.v1.json`、`style-guide.v1.json`、`toc-agent.v1.json`、`revisions.v1.jsonl`、memo、请求日志。Rust 照单拷，不再写死文件名（修 N4，也修上一份 #2 的跨任务部分）。

### 6.5 调和入口 `reconcile()`

在 `TranslationCheckpointSession.acquire` 之后、第一次 `update` 之前，整本扁平口径跑一次：

1. **读**：页文件只读加载，不清洗、不迁移、不按单页刷新（删掉 `translations.py:83,144` 的刷新和 `template_sync.py:171-174` 的重打 skip；JSON 坏的页先从快照恢复，恢复不了才重建，并进报告）。
2. **原文绑定**：每块算 `source_sha`。有 `result` 且 `basis.source_sha` 不符 → `invalidate("source_changed")`。这是唯一会让译文「消失」的路径，也顺手修了上一份 #12。
3. **分组**：先套 `frozen_units`（已译完的组按记下的成员，不再重分）；再跑规则 + memo，只对没有冻结的块分组；新分组碰到有 `result` 的块，照 #224 的规矩拆开。
4. **策略**：只重算 `kept.owner ∈ {policy, document}` 的块；冻结的 owner 不碰。
5. **质量标注**：`$` 不成对、JSON 壳之类只标 `quality=suspect`，进待办（低优先级重翻），**不删译文**（修上一份 #3 和本文 N11）。
6. **报告**：`reconcile-report.v1.json`，列出 invalidate、拆组、策略变化各多少块、哪几块；摘要打一行 stdout 事件，前端能显示「续跑时 12 块原文变了，已重新排队」。
7. **一次提交**：调和后的状态作为新的基线写进断点，守卫只在这之后生效。

页面策略阶段、agent 的 skip、流式每轮的重整理，都改成调用 `reconcile` 的对应步骤，不再各自改页。

### 6.6 守卫和指纹

- **守卫**：从比较「待办名单」改成检查不变量。
  - 断点每块存 `result_fp = sha(unit.id, basis, unit_text, member_text)`（现在的 `item_fingerprints` 扩一下）。
  - 不变量：上一代有 `result_fp` 的块，这一代要么 `result_fp` 相同，要么调和报告里有它的 invalidate 记录。
  - 待办名单只用于显示，现算，不进比较。
  - 投影函数必须是纯函数：`pending_translation_items` 拆成「建单元（会写）」和「列待办（只读）」（修 N6）。
- **指纹分层**：
  - 硬输入（不符就隔离旧译文并提示）：文档 sha（或按块的 source_sha）、目标语言、`mode`、`math_mode`、引擎及其身份、模型、术语表；
  - 软输入（只记录）：`batch_size`、`classify_batch_size`、并发、规则文本版本、领域识别、定译（已冻结）（修 N9）。
- **身份计算**只用 JSON 可序列化的字段，显式列白名单，不再 `vars(policy_config)`。

**兼容旧断点的办法**

- **旧页文件（没有 `state`）**：用固定的推断表从旧字段得出 `state`。
  - `should_translate=False` → kept，owner 按 label 映射：`skip_model_keep_origin` → model，agent 那三类 → engine，其余 → policy；
  - 有本块或单元层译文 → translated；
  - `final_status=failed` 且诊断有 `dead_letter`/`dlq` → dead_letter；
  - 其余 → pending。
  - 推断出的 `basis` 标 `inferred=true`，第一次调和时用当前原文认领。
- **旧断点 v1**：照旧读、照旧比较 `pending_item_ids` 一次。比较之前先跑调和，并把调和后的待办当成「上一份」，于是不会再因为口径变化报 regressed。之后写 v2。
- **旧指纹**：同时算旧指纹和分层指纹。
  - 旧指纹相同 → 续跑；
  - 旧指纹不同但硬输入相同 → 也续跑（这正是要修的情况），stdout 记一行软输入差异；
  - 硬输入不同 → 隔离旧译文（挪进 `result_stale`），不删页文件，提示用户。
- **agent 状态目录**：
  - 指纹改成「引擎身份 + 文档」，不再含每块的 `translate`/`group`；
  - 回放时只对 `state.status=pending` 的块写回，不覆盖 translated（也就不覆盖用户修订，修上一份 #11）；
  - 页键改成页号（旧的 `NNNN` 列表下标在 `fingerprint.json` 里记一个映射，读旧目录时换算）。
