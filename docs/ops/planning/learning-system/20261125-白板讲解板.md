# 白板讲解板（第一版）

2026-11-25，第一版已写（`frontend/packages/whiteboard`，演示页 `frontend/web/whiteboard.html`），见文末「第一版实际做成的样子」。学习系统的总设计见用户 2026-11-23 的《Agent 系统设计：会找卡点、会讲、会让人回来的学习系统》（v1）；
本文只管其中「代码讲知识」的那块板。

## 定下来的

- **放在 RetainPDF 仓库里**，新包 `frontend/packages/whiteboard`（`@retainpdf/whiteboard`），和 `@retainpdf/reader` 一样独立：
  不依赖 `frontend/web`、阅读器、后端接口，谁要用谁挂载。以后可以直接拿书里的页面、公式当素材。（用户 2026-11-25 选的）
- **第一版只做讲解板**：Teaching Agent 出一份 JSON 讲解脚本，板子一步一步播出来。学生手写 / 草稿层第二版再说。（用户 2026-11-25 选的）

## 为什么是「脚本 + 播放器」

总设计的第 8 条：数字、公式、步骤由代码渲染，逐帧可控。所以：

- **模型只写脚本，不画画**：LLM 输出 JSON（写哪个式子、画哪个箭头、圈哪一项、这一步说什么），板子按脚本渲染。
  公式、数字原样来自脚本，前端不改、不算、不补。
- **同一帧永远一样**：`render(脚本, 第几步, 这一步过了多少毫秒)` 是纯函数，不依赖时钟和随机数。
  这样能写快照测试，以后短剧的「代码渲染」那一段（Drama Agent）可以拿同一份脚本逐帧导出，不用另做一套。
- **脚本是数据，不是口令**：文字一律按文字显示，不当 HTML；TeX 交给 MathJax 渲染；脚本有大小上限；
  不认识的指令跳过并在板上标出来，不让整块板崩掉。

## 脚本格式 v1（草案）

```json
{
  "version": 1,
  "title": "因式分解解一元二次方程",
  "steps": [
    {
      "id": "s1",
      "say": "先把方程写出来。",
      "ops": [
        { "op": "write", "id": "eq", "math": "x^2 - 5x + 6 = 0" }
      ]
    },
    {
      "id": "s2",
      "say": "找两个数：相乘得 6，相加得 -5。",
      "ops": [
        { "op": "write", "id": "hint", "text": "? × ? = 6，? + ? = -5", "below": "eq" },
        { "op": "mark", "target": "eq", "tone": "focus" }
      ]
    },
    {
      "id": "s3",
      "say": "是 -2 和 -3，所以可以拆成两个括号相乘。",
      "ops": [
        { "op": "write", "id": "fact", "math": "(x - 2)(x - 3) = 0", "below": "hint" },
        { "op": "arrow", "from": "eq", "to": "fact", "label": "拆开" }
      ]
    }
  ]
}
```

每一步 `say` 是字幕（以后接配音），`ops` 是这一步板上发生的事，按顺序动画。第一版的指令：

| 指令 | 作用 |
|---|---|
| `write` | 写一行：`text`（普通文字）或 `math`（TeX）二选一，像手写一样从左到右显出来 |
| `mark` | 圈 / 划 / 高亮一个已有的东西：`style` 取 `box`、`underline`、`highlight`，`tone` 取 `focus`、`correct`、`wrong` |
| `arrow` | 从一个东西指到另一个，可带短标签 |
| `note` | 在一个东西旁边加批注（小字，带引线） |
| `erase` | 擦掉一个东西 |
| `focus` | 镜头移到某个东西（板子大了以后用） |
| `levels` | 轨道能级图：给每条能级的名字、能量、几个电子（0–2），能量由代码换算成高度，电子画成 ↑↓（题材换成 Hartree-Fock 后加的） |

**位置不让模型写坐标**。模型给的像素坐标经常重叠、出界，所以默认自动排版：`write` 依次往下排成一列；
需要时用 `below`、`right_of` 指着已有的 `id` 摆；绝对坐标 `at` 只留作最后的退路。板子按内容自己算大小、自己缩放。

脚本的结构写成契约 `contracts/whiteboard-script.v1.schema.json`，后端生成脚本后先过校验再给前端；
前端拿生成的 TS 类型，播放前也校验一遍（`id` 不重复、引用的 `id` 存在、长度上限）。

## 播放器

- 控制：上一步、下一步、自动播放、重播这一步；键盘 ← → 空格。字幕在板下方。
- 动画：写字用描边显出、标记用画出来的效果；尊重系统「减少动态效果」，那时直接显示每步终态。
- 主题：用现有主题变量（深色、朱砂都要好看）；公式用 MathJax 出 SVG（阅读器已经在用 `mathjax-full`，不新加依赖）。
- 对外只暴露一个组件和几个回调：`<Whiteboard script step onStepChange />`，学习系统的页面、以后的短剧导出都挂它。

## 第一版做到哪

1. 包骨架 + 渲染器 + 上面 6 个指令 + 自动排版 + 播放控制。
2. 契约 schema（只定格式，先不加接口）。
3. 在 web 里加一个演示页，用写死的两三份脚本（解方程、一个物理受力图、一个反例）跑起来；截图测试加进 `visual:check`。
4. 单测：校验、排版、`render` 纯函数的快照。

不在第一版：学生手写层、和 Orchestrator / Teaching Agent 的接线、后端接口、导出视频。

## 待定

- 图形（坐标系、函数图像、受力图）第一版要不要：要的话加 `plot` / `shape` 两个指令，工作量多一截。
- 配音：`say` 以后接 TTS，播放节奏跟着配音走还是跟着动画走。

## 第一版实际做成的样子（2026-11-25）

- **指令**：上面 7 个（6 个加 `levels`）。`mark` 只在它那一步里显示（指一下、圈一下）；箭头、批注一直留着；
  `erase` 把目标连同指着它的箭头、批注一起淡出。坐标系、函数图像这类图形没做。
- **契约**：脚本格式先不放进 `contracts/`（那边每份 schema 都要在 `backend/contracts/` 镜像一份，属于后端）。
  第一版的格式和校验在包里（`src/script/types.ts`、`validate.ts`）；后端开始生成脚本时再搬成 `whiteboard-script.v1.schema.json`。
- **排版**：默认往下排一列，`below` / `right_of` 指着已有的 `id`；有箭头指过来的东西会和上面隔开 64px，放得下箭头和标签；
  上下连的箭头在两个东西左右有重叠时竖直画。文字按字符估宽（不碰 DOM），公式尺寸由 MathJax 给。
- **大小**：板子按内容缩放，最多放大 1.25 倍、最少缩到 0.7 倍（再窄就在板子里横向滚，页面不横向滚）。
- **安全**：文字一律当文字；MathJax 不开 `html` 扩展，排出来的 SVG 再去掉链接、事件属性和外部引用。
- **演示页**：`whiteboard.html?script=energy|roothaan|koopmans&step=N&still=1`，三份 Szabo 第 3 章的草稿脚本
  （总能量 ≠ 轨道能之和、Roothaan 方程里的 S、STO-3G H₂ 能级与 Koopmans），物理内容等用户审。
  `visual:check` 加了两个状态（`whiteboard`、`whiteboard-levels`）；基准提交里还没有这一页时跳过不比。
- **配音**：没做，`say` 只当字幕。
