# 正文填充策略和加宽策略

2026-11-22。引擎 retain-pdf-rendering main 99ba91f（分支 `feat/body-leading-fill`），代码 `src/fit-model/fill-policy.js`、
`src/fit-model/widen-policy.js`，在 `passes/retain-body.js` 里调用。

## 量出来的

三本教材（电磁学、量子化学、计算化学）各三四千段正文：

- 中文排版宽度约为英文的 **0.57–0.63**（同字号），三本书很稳定；一行的短段落更散（中位 0.64–0.70）。
- 按原来的做法（全书统一字号、行高约 1.24）排，三行以上的段落只填满原框的 **67–83%**，空出来的全在段落底下。
- 原文一行的段落里 **1–6%** 译文反而更长（超出原宽度中位 1.12–1.45 倍，九成在 1.9 倍内）；原来靠缩字号或折行塞进去。

## 用户定的（11-22，按顺序）

1. 表格比正文小一号（见 table-translation 的 20261122-表格字号和行距）。
2. "中文优先加行距，再加字"——先做成"空出来就加行距、填满原框、上限 1.8"。
3. "呼吸感变弱了，行距被拉的太大"、"不要一味追求把边框填满"——改成上限 1.45、每段底下留半个字的白、按页统一行距。
4. "以行间距为主是错的，应该比原来增加快一些些，或者动态调整，动态算法很重要"、"填充率也得看中英文文字的对比"、
   "使用动态的长度比，用一些函数"——改成下面的填充策略；c = 0.3、字号占四成、字号最多 +6%、行高最多 1.5、页间 ±0.1。
5. "算法部分做成一个包，以后好调整"——做成 `fit-model/` 下的纯函数模块，参数可从外面覆盖，报告写出算出来的值。
6. 一行的段落译文更长时"把 bbox 拉长，不要用原始的 bbox"——加宽策略。

## 填充策略（fill-policy.js）

- 长度比 ρ：每段"译文 ÷ 原文"的排版宽度；全书按原文长度加权取中位数；每页 = (n × 本页中位数 + 3 × 全书) / (n + 3)。
- 目标填充率 F*(ρ) = 1 − 0.3 × (1 − min(ρ, 1))：译文越短留白越多。
- 放大倍数 k = F* / 实测填充率（不小于 1）；文字高度约和"字号² × 行高"成正比，ln k 的四成给全书字号、其余给每页行高，
  都用 S(x, m) = m·tanh(x/m) 平滑封顶（字号最多 ×1.06，行高最多 1.5，每页在全书行高 ±0.1 内）。
- 落实：字号照全书统一字号时的规则放大（不碰别的东西即可，可以伸进框下空白）；行高每段在墨迹下留半个字的白、不出框、
  不碰别的东西的范围内取；一行的段落、译文比原文长的段落不加行高。
- 参数：`rpr_fit_input_v1` 的 `fill_policy`（覆盖 `FillPolicy.DEFAULTS`）；retain-pdf 现在不传，用引擎默认值。
  报告 `fill_policy` 给全书和每页的 ρ、填充率、目标、k、字号倍数、行高。

效果（各 40 页）：电磁学 ρ 0.55、填充 0.84 → 字号 +0.5%、行高 1.26；计算化学 ρ 0.50、填充 0.74 → 字号 +2.5%、行高 1.34。
溢出段落 +3～4（伸进框下空白，不碰别的东西；严格不出框的话 22 段字号会比别的小一号，选了全书字号一致）。

## 加宽策略（widen-policy.js）

原文一行、按本身字号译文排不下一行的（正文、非正文文字、标题、图注；居中的先不管）：右边往外拉到刚好放得下（+2%），
不超过本栏右边（同栏上下邻居的最右边，没有邻居不加宽）、不碰旁边的东西（留 2pt）、不出页边；正文要算上段落的内边距
（左 2、右 4pt）。替换 retain-pdf 移植来的固定规则（上面有两段正文时最多加宽 30%）。参数 `widen_policy`，报告 `widened`。

效果（电磁学 200 页）：加宽 31 段（中位 11.7pt）；原文一行、译文更长的段落不再折行、不再溢出。

## 走过的弯路

- 填满原框、行高到 1.8：段落间的呼吸感没了（用户否决）。
- 固定上限 1.45、空出一行才加：同页长段 1.45、短段 1.24，一松一紧；而且是死规则（用户否决）。

## 已知没解决

- 有的小节标题加宽后一行放得下，仍因"文字带不超过框高 94%"缩了字号（框太矮）——标题高度余量，另做。
- 填充策略放大正文后，标题没跟着放大，个别小节标题比正文小（见排版细节清单第 4 类）。
