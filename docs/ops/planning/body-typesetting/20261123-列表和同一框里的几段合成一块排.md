# 列表和同一框里的几段合成一块排

2026-11-23。用户：“列表的合并，以及上下文关系……OCR 会将他们分成三块，实际上他们是一块，这个 bbox 应该是一块，
这样更好保证字体大小什么的一致”；“大部分 bbox 的长度差不多，那么字体大小应该差不多才对”。

## 现象

OCR 把一个列表切成每项一个框，把小一号的文字框（例题框 Example）切成每段一个框。引擎按框各自定字号：

- 电磁学（14e352）p80–279：找到 51 个被切开的列表（132 项）。大部分已经一样大（有文字层，按原书字号排），
  框装不下译文的那几项被各自缩小：p181 习题 3.13 的 (a)–(d) 排 9.3pt、(e) 排 10.5pt；计算化学 p72 一组 9.8–11pt。
- 原书 9pt 的段落（例题框、旁注，电磁学 154 段）被当成正文拉到正文字号，框装不下再各自往小缩：
  排出来 7.9–11.2pt 共 19 种，偏离中位数 3% 以上的 41 段。p272 例题框里两段原书一样大，排出来 7.9pt 和 10.1pt。

## 改法（引擎 `retain/list-groups.js`，建模型时）

1. **合成一块**：同一页里按块顺序连续、左边对齐（差 ≤ max(6pt, 1 个字)）、上下挨着（间距 −0.5～1.6 个字）、
   并集里没有别的东西（图、公式、别的文字）的几块，属于同一类就合成一个流：
   - 列表项：以 `(a)`、`1.`、`(iv)`、`-`、`•` 这类标记开头，原书字号和正文一样；
   - 原书字号相同、又和正文差得多（> max(0.4pt, 4%)）的几段：例题框、旁注里连着的几段（里面的列表也算）。

   框取并集，一项一段，项之间的间距取原书的中位数，擦原文的范围也取并集。一起定字号，长项能用短项空出来的地方。
2. **按原书字号另排**：原书字号和正文差得多的正文流（合成的和单独的）移出正文统一字号组，按“原书字号 × 正文放大的倍数”排，
   用正文定下来的行距（以前移出来走非正文的紧行距）。
3. 跨框接续的段落（`translations[].flow`）两样都不参与：接续切分要在正文流之间做，移出去切分就乱了（试跑时 p112 出过错）。

报告里合成的块用 `members` 列出各项 id（retain-pdf 的排版诊断按块记，一组记一条）；`adapter` 里有
`listGroups`、`listItemsGrouped`、`sourceSizeDetached`。

## 结果

| | main | 改后 |
|---|---|---|
| 电磁学：合成的组 | — | 列表 50 组、同字号段 26 组，共 192 项 |
| 电磁学：原书 9pt 的 154 段 | 7.90–11.18，19 种，偏离 3% 以上 41 段 | 8.90–11.18，7 种，偏离 14 段（剩下的是跨框接续的段落） |
| 电磁学：溢出 / 超过 3pt / 碰撞 | 176 / 92 / 0 | 140 / 62 / 0 |
| 计算化学：合成的组 | — | 列表 3 组 12 项 |
| 计算化学：溢出 / 超过 3pt / 碰撞 | 18 / 7 / 0 | 17 / 8 / 0 |

- 9pt 那批段落移出正文组以后，正文统一字号从 10.49 变成 10.58（它们以前把正文往下拉），新增的溢出大多是正文跟着大了 1% 的 1–4pt。
- 计算化学 p72 的列表合成一组后整组排 10.55pt（正文 11pt）：组内一样大，比正文小一点；末项伸出框 4.3pt，没碰到东西。
- 被 OCR 当成正文的脚注（电磁学 p86 “1 提醒读者注意……”）以前排 10pt，现在按原书 8pt 排小了。

## 没做的

- 跨框接续、原书字号又偏离正文的段落（例题框跨页）还留在正文组里，14 段。
- 一般的正文段落不合并：每段锚在原位置（见[排版细节清单](./20261122-排版细节清单.md)里“纵向留白不做”），只合并列表和偏离正文字号的框内段落。
- 没有文字层的书（扫描件）量不到原书字号，只有列表合并起作用，同字号段的合并和另排都不发生。
- 列表的悬挂缩进还没做（清单第 4 级）。
