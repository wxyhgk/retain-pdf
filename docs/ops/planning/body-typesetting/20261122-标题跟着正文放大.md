# 标题跟着正文放大（2026-11-22）

排版细节清单（[20261122-排版细节清单](./20261122-排版细节清单.md)）第 3 级“字号关系”的第一条：小节标题比放大后的正文小。
同一天顺带核实了第 1 级剩下的“两端对齐把字距拉得过开”，见文末。

## 问题

两本书量出来（同一份译文，rpr 引擎）：

| 书 | 原书文字层：正文 / 标题 | 排版后正文 | 排版后标题 |
|---|---|---|---|
| 电磁学 p80–279 | 9.96 / 9.96（225 个标题和正文一样大） | 10.52（放大 1.056） | 中位 9.95，230/295 个比正文小 |
| 计算化学 p40–79 | 10.00 / 11.00（标题是正文的 1.1 倍） | 11（放大 1.10） | 11，和正文一样大 |

原因：rpr 引擎把正文统一放大到全书字号（通常比原书大一点），标题却按自己的原书字号（`source_font_size_pt`，2026-11-09 起）封顶，
不跟着正文放大。原书里标题和正文的比例就丢了：一样大的变小，大一号的变成一样大。

## 做法

正文定了以后，有原书字号的标题放大到 **原书字号 ×（排定的正文 ÷ 原书正文）**，以不多折行为限，之后照旧做碰撞退让。

- 原书正文字号：retain-pdf 给正文条目也量文字层字号（`title_source_size.py`，和标题同一个量法：框里文字按字数取中位数，
  只认文字层、不反推），写进条目的 `source_font_size_pt` 随译文条目传给引擎；引擎取正文的中位数。只在为标题读过的页上量，
  不够 30 个再均匀补读至多 20 页。
- 引擎 `fit-model/passes/retain-titles.js` 的 `followBody`，在正文排定和碰撞退让之间；比例限在 0.8–1.4，只放大不缩小；
  没有文字层（扫描件）不动。报告 `report.json` 加 `title_follow`（原书正文、排定正文、比例、放大了几个）。
- 引擎在“按几何估初始字号”的预设下拿不到文字层，所以原书正文字号由宿主量，不在引擎里量。

## 效果

| 书 | 比正文小的标题 | 碰撞 | 溢出 |
|---|---|---|---|
| 电磁学 p80–279 | 230 → 13（294 个放大 5.3%） | 0 → 0 | 176 → 176 |
| 计算化学 p40–79 | 2 → 0（18 个放大 10%，小节标题 12.1、正文 11） | 0 → 0 | 17 → 18（新的一个是标题墨迹出框 0.6pt，没碰到东西） |

## 顺带核实：两端对齐把字距拉得过开（第 1 级）

断行规则改好以后量了两本书（计算化学 694 行、电磁学 3896 行两端对齐的行）：汉字之间拉开最多 0.15em，99% 的行在 0.13em 以内；
空格（连同本身）最宽 0.53em；汉字不超过 3 个的两端对齐行只有 2 行，是整行公式。现在没有这个问题，不用做。引擎的做法和 Typst 一样：
先拉空格（每个最多半个空格），剩下的平均分到汉字后面，中文行里汉字多，每处只分到一点。
