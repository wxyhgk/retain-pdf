# 放在笔记（Studio）里：嵌入模式和「摘到笔记」

2026-11-01。后端交接见 [backend-changes-handoff](../../../core/frontend/backend-changes-handoff.md)「放在笔记（Studio）里时和它说话」，
方案见 [书和笔记接在一起](../studio-workbench/20261101-书和笔记接在一起.md)，消息格式 `contracts/studio-bridge.v1.schema.json`。

## 做了什么

- **`?embed=studio`**：`app/bootstrap/studio-embed.ts`（三页启动时都走，`shell-boot` 引入）在有父窗口时给 `<html>` 打 `data-embed="studio"`，
  首页顶栏不出 logo（Studio 有自己的品牌）；图书馆 / 合集 / AI 问答的分栏留着，那是 RetainPDF 自己的内容。
- **握手**：只认 `event.source === window.parent`、origin 是本机回环地址（`http://localhost`、`127.0.0.1`、`[::1]`，任意端口）的消息；
  收到 `hello` 记下 origin、换亮暗、回 `ready`（`theme`、`navigate`、`quote`）。之后只认这个 origin，发消息也都指定它。
- **theme**：亮 → 本机主题是亮色就用它，否则默认亮色；暗 → 本机是深色就用它，否则「夜间」。只换 `<html data-theme>`（新加 `showTheme`），
  不写本机存的设置；阅读页自己的 bootTheme 晚一步盖回来时再换回 Studio 的。
- **navigate**：整页打开 `reader.html?job_id=&page_idx=&block_id=&embed=studio`。
- **摘到笔记**：阅读器包加可选的 `notesQuote` 适配（`available`、`send`）；网页宿主只在嵌入时给，握过手、地址里有任务才显示。
  悬停框在「复制」旁多一个「摘到笔记」，交出块编号、原文页（0 起）、原文、整段译文；宿主补任务、书编号和书名（按任务查一次）发 `quote`。

## 和交接不一样的地方

- **嵌入时不软开阅读层。** 从书库打开阅读页本来是首页里再套一层 iframe（软打开），那样阅读页的父窗口是 RetainPDF 首页，
  Studio 的 hello 到不了、摘录也发不出去。嵌入时（地址带 `embed=`）改成整页跳转，Studio 那层 iframe 本身换成阅读页，加载完重新握手。
  阅读页「关闭」也不再找父页软关闭（以前会把关闭消息发给 Studio，Studio 收不到，按钮没反应），直接回 `index.html?embed=studio`。
  `navigateTo` 跳本站页面时自动带上 `embed`（`carryEmbed`）。
- **顺手修的**：阅读页的加载进度消息以前用 `'*'` 发给父窗口（宿主误用了阅读器包的默认端口），放进 Studio 时会发到 Studio。
  改成只发给同源的父页（软阅读层），行为不变。
