# Studio 打开同一本书的另一段：原地翻过去

2026-11-02。改 [放在笔记里](./20261101-放在笔记里.md) 定的「navigate 整页打开阅读页」。契约 `contracts/studio-bridge.v1.schema.json` 不动，
Studio 不用改。

## 为什么

用户：每次点击都得重新加载 PDF。笔记里摘的段落点右上角的 RetainPDF 标志、顶栏「读原书」、AI 回答里的出处链接，Studio 都发
`navigate`；阅读页收到后不管是不是正在读的这本，都整页打开 `reader.html?job_id=&page_idx=&block_id=`，PDF 从头加载、页面从头排。

## 做了什么

- 阅读器包加可选适配 `hostNavigation`（`subscribe`）。阅读页打开好（PDF 和块的位置都有了）就登记：宿主给的是同一个任务时，
  用阅读页自己的 `jumpToAnchor` 翻过去（有 `block_id` 按块所在的页、标出这一块，没有按 `page_idx`），返回 true。
- `studio-embed` 收到 `navigate` 先问登记的阅读页，接了就到此为止；没人接（别的书、在书库或详情页、阅读页还在加载）照旧整页打开。
- 原地翻过去以后，阅读页自己把当前页写回地址（`replaceState`），刷新回到这一页；`reading` 照常报给 Studio。

## 验过的

隔离的 Studio（notes-studio main）放这个 worktree 的阅读页，开发栈上一本 89 页的书（只发 GET）：先打开第 3 页，再让 Studio 打开同一本书
第 41 页，阅读页没有重新载入（窗口上做的记号还在、没有新的文档请求、没有新的 PDF 请求），停在 41 / 89，地址写成 `page_idx=40`。
