# 选 GLM-OCR 时不限页数

2026-11-03。用户：GLM-OCR 能识别任意长度，把 999 页的限制对 GLM 放开。

## 以前

主页上传时，前端一律拦 999 页以上的 PDF（`FRONT_MAX_PAGE_COUNT`），不管设置里选的是哪家 OCR。后端只按 OCR 拦：
PaddleOCR 999 页（`RUST_API_PADDLE_MAX_PAGES`）、MinerU 600 页（`RUST_API_MINERU_MAX_PAGES`），GLM-OCR 不拦
（它的驱动按 ≤100 页一片切开识别，`glm_ocr_driver.py`）；上传本身不限页数（`RUST_API_UPLOAD_MAX_PAGES` 默认 0）。

## 现在

- 每家 OCR 的定义带上 `maxPages`（`platform/config/providers.ts`：PaddleOCR 999、MinerU 600、GLM-OCR 0 = 不限），
  说明文字里也写上；去掉 `FRONT_MAX_PAGE_COUNT`。
- 上传（单本和一次多本）的页数上限变成每次选文件时现问：按设置里选的 OCR 定。超了说上限，再补一句「GLM-OCR 不限页数，
  可以在设置里把 OCR 换成 GLM-OCR」。
- 上传后又把 OCR 换成 PaddleOCR / MinerU 的，建任务时后端照旧拒（原话说上限）。

## 没动

前端 50MB 的文件大小上限（`FRONT_MAX_BYTES`）照旧；后端上传上限 512MB，GLM 每片 ≤50MB。几百页以上的扫描书常超过 50MB，
要不要对 GLM 一起放开另说。
