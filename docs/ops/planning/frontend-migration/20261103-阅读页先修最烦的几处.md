# 阅读页先修最烦的几处

2026-11-03。

## 为什么

用户：「RetainPDF 的阅读页面得大改，目前非常不好用」。整屏用一本 89 页的书走了一遍，列出六条：功能藏在 Markdown 面板里
（目录、搜索、原文/译文切换），模式按钮只有图标，浮动竖条和底栏压在书上，缩放「50%」和看到的对不上，译文页排版乱，
两种视图不同步。提了一版新布局（一条顶栏、左边目录栏、「流式译文」当正式读法），用户选了**先修最烦的几处**，整体布局不动。

## 做了什么

- **模式页签写上字**：原文 / 对照 / 译文（以前是「源文件 / 翻译文件」，而且只露图标）；宽不到 640px 只剩图标，字留给读屏。
  快捷键说明跟着改名。
- **竖条、底栏不压书**：宽度 600px 起，阅读区右边给竖条、底下给页码缩放那一条各留出位置（`--reader-rail-room`、
  `--reader-hud-room`），页面排在留出来之外；缩放按阅读区算，对照照样两页铺满。手机上留不起，照旧浮在上面。
- **目录、搜索到 PDF 这边**：顶栏左边「目录」「搜索」，点开左边一栏（宽 900px 起阅读区让出这一栏，窄了盖在上面、跳过去就收起）。
  都从阅读页已经拿到的块来（`shared/content/reader-find.ts`），不靠 Markdown 面板：目录是标题块（标题里的公式读成字：H₂O、α），
  标出眼下在哪一节；搜索在每块的译文和原文里找，标出命中，最多列 200 处，回车跳第一处。点一条按块跳过去。
- 阅读器包第一次用上基础组件 `@retainpdf/ui`（Button、Input，不带 variant，样子在阅读器自己的 `styles/finder.css`）：
  新代码不许手写 `<button>`、`<input>`（基础组件棘轮门禁）。

## 验过的

开发栈 89 页的书：目录 46 条，点「开壳层态…」跳到第 6 页；搜「超共轭」2 处，点了到第 41 页；1440、667（Studio 书标签）、
400 三种宽度截图看过。前端测试 2447（新 4 个：目录、当前节、搜索、标题里的公式）、桌面端 60。

## 没做的

- 新布局（一条顶栏、左边常驻目录、「流式译文」当正式读法并和 PDF 同步）：用户这次没选，以后再说。
- 缩放数字的意思、译文页的排版（后端产物）。
