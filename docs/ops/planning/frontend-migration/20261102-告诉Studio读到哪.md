# 告诉 Studio 读到哪（reading）

2026-11-02。接着 [阅读页笔记按钮](./20261102-阅读页笔记按钮.md)。契约 `contracts/studio-bridge.v1.schema.json` 的
`ReadingMessage`（后端会话在 feat/studio-bridge-reading 加的，只加不改），交接见
[backend-changes-handoff](../../../core/frontend/backend-changes-handoff.md)「告诉 Studio 眼下读到哪」。

## 为什么

用户定了：笔记 Studio 里只用 Studio 自己的 AI，由它读 RetainPDF 的书（notes-studio 加了 `list_books`、`search_books`、
`read_book`、`read_passage` 这些操作，走 RetainPDF 的只读接口）。AI 缺的是作者眼下在读哪本、哪一页，「这一页讲了什么」答不了。

## 做了什么

- `ready` 的 features 加 `reading`。
- **发什么**：`{job_id, document_id, title, page_idx, page_count}`，页从 0 起；不在阅读页（主页、详情页）五项都是 null。
  任务从阅读页地址来，书编号、书名按任务查一次（和 quote、open-notes 同一套），查回来再报一次。页不在页数里时 `page_idx` 写 null。
- **什么时候发**：每次握手后发一次（Studio 重新加载过这一页也算；还没报页就是全 null 的那条）；阅读器翻页停下来 600ms 再发
  （`READING_DEBOUNCE_MS`），一样的不重发。只发给握手的那个 origin。
- 阅读器包加可选适配 `readingPosition`（`report(pageIdx, pageCount)`），控制器在当前页、页数变了时报；防抖、发不发由宿主管
  （`app/bootstrap/studio-embed.ts`）。不在 Studio 里时宿主不给，包里什么都不做。

## 验过的

假 Studio 页（另一个本机端口）放这个 worktree 的阅读页，开发栈上一本 620 页的书（只发了 GET）：进阅读页依次收到全 null、
只有任务、带书名、第 0 页 / 620 页；滚动几屏停下来只收到一条（第 6 页）；回主页收到全 null。
