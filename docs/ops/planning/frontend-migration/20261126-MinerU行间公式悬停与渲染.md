# MinerU 行间公式悬停与 Markdown 渲染故障

记录日期为 2026-11-26，负责模块为前端阅读器 `@retainpdf/reader`。工作区已出现公式分类与 Markdown 渲染的修复改动，待 Windows 打包验收。

## 复现

打开本机任务 20261126084948-f748c5 的对照阅读，在第 1 页右栏把鼠标移到公式（1）和（2）的正文上。用户反馈 Windows 10/11 桌面版不出悬停框。本机新版 Web 能出框，浮条上的普通「复制」会复制公式源码。打开 Markdown 面板，两条公式会显示「公式渲染失败」。[本机任务](http://127.0.0.1:40001/reader.html?job_id=20261126084948-f748c5)

该任务的 `/reader/regions` 响应包含 `p001-b0008` 和 `p001-b0010` 两条公式。两条公式的坐标依次为 `[321, 293, 534, 320]` 和 `[342, 384, 526, 415]`，在原文栏和译文栏一致。页面尺寸为 612 × 792 pt。

| 字段 | 值 |
| --- | --- |
| `region_type` | `unknown` |
| `sub_type` | `display_formula` |
| `asset_ids`、`asset_urls` | 各有一项公式图片资源 |
| `source.text` | 完整的裸 LaTeX，含空格、带参数的命令和末尾的 `\tag` |
| `translated.text` | 空，区块状态为 `kept_origin` |

## PDF 悬停与复制

旧版 `readerRegionKindForRegion()` 遇到 `unknown` 时，根据图片资源把两条公式归为 `figure`，漏读了明确标为 `display_formula` 的 `subType`。Windows 11 真机安装版 `2026.11.23` 的阅读器脚本哈希前缀为 `24734b7476`，与同名发布标签一致。该版本的悬停目标过滤器排除了 `figure`。新版 Web 支持图片悬停，因而也会给这两条被误判的公式画框。[区块分类](../../../../frontend/packages/reader/src/shared/data/reader-regions.ts#L182) [悬停目标过滤](../../../../frontend/packages/reader/src/pdf/ReaderTextHoverLayer.tsx#L18) [加入图片悬停的提交](https://github.com/wxyhgk/retain-pdf/commit/2947637e00355a0bdd472cb249849c925a0c1856)

浮条根据复制文本是否为空决定显示按钮。译文为空时取 `source.text`，所以两栏都能通过普通「复制」拿到原始 LaTeX。正确归类为公式后，按钮提示应显示「复制 LaTeX」。[复制文本的取值逻辑](../../../../frontend/packages/reader/src/shared/data/reader-regions.ts#L218)

## Markdown 渲染

Markdown 面板通过 `subType` 认出了公式块，但旧版 `readerMdBlockMarkdown()` 把裸 LaTeX 原样交给通用提取器。`bareLatex` 按连续字符提取片段，把带空格的命令与参数拆开，MathJax 收到不完整的表达式后回退到错误样式。两条原始公式分别用 `$$...$$` 包成完整块级表达式后，均能生成 SVG。[Markdown 块生成](../../../../frontend/packages/reader/src/shared/content/reader-blocks.ts#L118) [LaTeX 提取与渲染](../../../../frontend/packages/reader/src/shared/content/markdown-math.ts#L72)

## 修复与验收

1. 在共享区块分类函数中，让 display_formula 优先于图片资源推断。回归覆盖同时带图片资源与裸 LaTeX 的公式块，以及普通图片块。公式应在两栏都能悬停，复制值应为完整 LaTeX。
2. 按块渲染 Markdown 时，把已识别的公式整体交给 MathJax。用带空格和公式编号的裸 LaTeX 验证每块生成一个块级 SVG，并覆盖已有双美元符号定界的公式。
3. 用同一份任务数据对照 Web 和修复后的 Windows 安装包，检查原文栏与译文栏的公式悬停、复制，以及 Markdown 中的公式排版。

已用真实 API 响应对比两个版本的命中函数。旧版两栏均生成 0 个公式悬停目标，新版两栏均命中两条公式的中心。Windows 真机本地库对该任务 ID 返回 404，同一任务在 Windows 界面上的复现与修复验收仍待验证。
