# 阅读页的「AI」交给 Studio（ask-ai）

2026-11-02。接着 [告诉 Studio 读到哪](./20261102-告诉Studio读到哪.md)。契约 `contracts/studio-bridge.v1.schema.json` 的
`AskAiMessage`（后端会话在 feat/studio-bridge-ask-ai 加的，只加不改），交接见
[backend-changes-handoff](../../../core/frontend/backend-changes-handoff.md)「阅读页的「AI」打开 Studio 的 AI」。

## 为什么

用户在 Studio 里边读边记，觉得书和笔记接得别扭。走一遍看到：阅读页右边 dock 的「AI」打开的是 RetainPDF 自己的 agent 终端
（要先登录），Studio 的 AI 在右侧面板里、已经读得到书，两个 AI 互不相干。用户选了放在 Studio 里时只留 Studio 的 AI。

## 做了什么

- `hello.features` 里 Studio 列了 `ask-ai`（它有自己的 AI）时，点阅读页的「AI」不打开 dock 的终端面板，改发 `ask-ai`；
  发之前先把眼下读到哪（`reading`）立刻发出去，不等 600ms 的防抖，Studio 收到 `ask-ai` 时手上就是当前这一页。
- 上次存着开着的终端面板（阅读页会恢复面板），握手后也收起来，免得进来先看到另一个 AI。
- Studio 没列 `ask-ai`（旧版本）、不在 Studio 里时照旧打开终端。
- 阅读器包加可选适配 `hostAi`（`available`、`subscribe`、`ask`）和 hook `useReaderHostAi`；`selectAssistant` 选到「AI」时先问宿主，
  宿主接了就不开面板。宿主一侧在 `app/bootstrap/studio-embed.ts`（`askAi`）。

## 验过的

隔离的 Studio（notes-studio 的 feat/notes-and-book）放这个 worktree 的阅读页，开发栈上一本 89 页的书（只发 GET）：笔记开着时点「AI」，
阅读页里没有出现终端，Studio 右侧面板回来、停在 AI 上，服务器记着的读到哪是这本书第 2 页。
