# 基础组件与刻度（2026-10-31）

用户觉得前端的组件很乱。看下来，根子是**没有一套大家都用的基础组件**：每个功能自己写按钮、菜单、弹层和样式，
同一样东西有好几种写法。这份定下收拢的做法：一套不超过十个的基础组件、字号和圆角的刻度、按功能一块块迁、
用棘轮门禁防止回潮。

这也是迁进 Studio、让使用者通过 AI 改界面的地基（见 [studio-workbench](../studio-workbench/README.md)）：
零件少、名字统一、尺寸有刻度，AI 改一处才会全局生效，主题插件也只需要改变量。

## 不做的

- 不换视觉风格。这次只收拢写法，界面看上去应当和现在一样；刻度取整带来的 0.5px 级差别除外。
- 不一次全改。一个分支迁一块，每块单独能合。
- 不引入新的组件库。radix-ui 已经在用，照旧只用它的行为部分（焦点、Esc、可达性），样子自己写。

## 一、基础组件

只留一份，放在 `packages/ui`；`web/src/ui/components/` 里那几份复制品和 `web/src/ui/Button.tsx` 删掉，调用方改成从
`@retainpdf/ui` 引。

| 组件 | 管什么 | 接口要点 |
|---|---|---|
| `Button` | 所有带字的按钮 | `variant`：`primary` / `secondary` / `ghost` / `danger`；`size`：`sm` / `md`；`pending`（转圈、禁用）；默认 `type="button"` |
| `IconButton` | 只有图标的按钮 | 必须给 `label`（变成 `aria-label` 和悬停提示），否则类型报错 |
| `Select` | 原生下拉 | 包住原生 `<select>`，统一边框、箭头和禁用态；不做自绘下拉（手机上原生的最好用） |
| `Field` + `Input` / `Textarea` | 带标题的输入 | `Field` 管标题、说明、错误（`aria-describedby` 自动接好），`Input`、`Textarea` 只管框 |
| `Badge` | 状态小标签 | `tone`：`muted` / `active` / `done` / `warn` / `danger`，对应皮肤的语义色 |
| `Menu` | 点开的选项列表 | 基于 radix 的 DropdownMenu：键盘上下选、Esc 关、焦点回到按钮 |
| `Dialog` / `Sheet` | 弹窗、侧边抽屉 | 合并现有两份 `dialog`；`Sheet` 给阅读器的面板用 |
| `Panel` | 设置页、书详情里的一块卡片 | 标题、说明、操作区三个槽，圆角用 `--panel-radius` |
| `EmptyState` | 空状态 | 已有 `web/src/ui/icons/EmptyState.tsx`，挪进包里 |
| `StatusLine` | 表单下方的一行状态 | 已有 `form-status-line.tsx`，挪进包里 |

### 样式只用一种写法

- 基础组件各自一个 CSS 文件（带 `@owns`），变体用 `data-variant` / `data-size` 属性选择，颜色、尺寸只用变量。
- shadcn 默认的 `cva` 视觉（`bg-primary`、`rounded-md` 等）不再用：它和现有皮肤正面冲突，`web/src/ui/Button.tsx`
  的注释里已经说过。
- 功能里的 TSX 只许用 Tailwind 的**排版类**（`flex`、`grid`、`gap-*`、`min-w-0` 一类），不许用它定颜色、字号、圆角。
- 功能自己的 CSS 只管自己特有的版面，不再定义按钮、徽章、输入框的样子。

写进 `src/styles/tokens.css`，皮肤可以覆盖。

| 变量 | 值 | 现在的写法归到哪一档 |
|---|---|---|
| `--text-2xs` | 10px | 10px、10.5px |
| `--text-xs` | 11px | 11px、11.5px |
| `--text-sm` | 12px | 12px、12.5px |
| `--text-md` | 13px | 13px |
| `--text-base` | 14px | 14px、15px |
| `--text-lg` | 16px | 16px、18px |
| `--text-xl` | 20px | 20px 及以上（标题另说） |
| `--radius-sm` | 6px | 6px、8px |
| `--radius-md` | 10px | 9px、10px、12px |
| `--radius-lg` | 14px | 14px、16px、18px |

`--btn-radius`、`--panel-radius` 保留，默认值改成指向上面的刻度。半像素字号取整是唯一预期的视觉变化，每块迁的时候截图过目。

## 三、迁移顺序

每一步一个分支，做完照常跑 `typecheck`、`build`、`test`，再跑 `visual:check`，加上被迁那块的截图
（1440 和 390 宽，`classic` 和 `night` 两个皮肤）。

| 步 | 内容 | 为什么这个顺序 |
|---|---|---|
| 0 | 地基：合并 `packages/ui` 和应用里的复制品，删掉没人用的 `Tabs`；写上面十个组件和刻度变量；加门禁（见下） | 后面每一步都靠它 |
| 1 | 设置页：备份、同步、通知三个面板，加上设置对话框本身 | 最像复制粘贴，收益最直观，也最容易看出基础组件够不够用 |
| 2 | 书详情（含「进度」页流水线的站点按钮）和书架（工具栏、筛选菜单、批量操作菜单） | 用得最多的页面 |
| 3 | 问答、上传、凭据、术语表 | |
| 4 | 阅读器包：三个自己做的弹层换成 `Dialog` / `Sheet`；三个超大文件拆开，把这个包也放进 380 行门禁 | 最复杂，桌面壳也用，放在基础组件稳定之后 |
| 5 | 管理后台 | 多用户已冻结，最后做，或者不做 |

迁移期间的规矩：

- 元素的 `id`、`data-*` 属性不变（测试和门禁靠它们找元素，比如 `book-detail-station-*-btn`、`data-station-action`）。
- 旧类名可以在调用处先留着当别名，等那一块迁完再删，免得一次改太多测试。

## 四、门禁（棘轮）

和 `module-size`、`strict-ratchet` 一样按文件记数，存在 `tests/architecture/helpers/ui-primitives-baseline.json`：

- 每个文件里手写的 `<button`、`<select`、`<input`、`<textarea` 数：不在名单上的文件（含新文件）必须是 0；
  名单上的不许涨；降了就要更新名单，只减不增。
- CSS 里新写的 `font-size`、`border-radius` 字面量（不是 `var(--…)`）同样按文件计数，只减不增。
- 新造的 `*-btn`、`*-button` 类名：列出现有的，新的报错。
- 基础组件只许从 `@retainpdf/ui` 引；`web/src/ui/components/` 不许再出现组件文件。

基础组件自己的文件不算在内。

## 五、风险

- **看不出来的视觉回归**：基准截图只有 12 张，覆盖不到设置页的每个面板。每一步自己补被迁那块的截图，必要时把截图加进基准。
- **测试按类名找元素**：有的测试按类名找元素，类名一换就红。迁的时候先查 `tests/` 里有没有用到那个类名，用 `id` / `data-*` 的不受影响。
- **桌面壳**：桌面壳也用阅读器包，第 4 步要在桌面壳里也看一遍。

## 待定

- 第 5 步管理后台做不做。
- `Select` 要不要做自绘版（现在只做原生的）。
- 第 4 步拆阅读器大文件，要不要和 Studio 迁移一起考虑（阅读器可能变成 Studio 的块）。
