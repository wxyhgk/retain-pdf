# 没东西可翻的块算保留原文

2026-11-20，分支 `fix/nothing-to-translate`。用户定（前端转述）：没东西可翻的块不算「没翻成」。

## 起因

《The Interloper》当前版本（任务 20261119033954-b3f920）有 12 块 `final_status=failed`：11 块是书末注释里只有引注的条目
（"35. Brown-Saracino 2014, 43."、"9. Abend 2014; Khurana 2007; Schleef 2005."），只有 1 块是真没翻成的正文。
引注交给模型、原样交回判漏翻，重交几次后进死信。阅读页底栏「待处理」、书详情「没翻成」都读 `final_status=failed`，
于是把这 11 条当问题列出来。

## 做法

- 规则一处：agent 核心 `checks.nothing_to_translate(原文)`，有中文的原文不算；
  - `skip_citation_only`：只有引注（作者、年份、页码，或 Ibid.）。作者认一个、两个（A and B）、三个以上（A, B, and C）、et al.；
    三个以上是这次补的（以前 "31. Petriglieri, Ashford, and Wrzesniewski 2019." 判成要翻），检查规则版本升到 `translation-agent-checks-10`；
  - `skip_no_prose`：去掉公式、行内代码、角标、引用编号、网址以后一个英文词（大写或小写开头、三个字母以上）都没有：纯数字、符号、网址、代码、整块公式。
- 以后翻：agent 引擎交给模型之前就标成保留原文（`agent_flow.skip_nothing_to_translate`，和页眉、书后索引一样），写明原因；接续组的成员不管。
  这些块不再发请求。
- 以前翻好的书：`python -m retainpdf_translation_agent_engine.reclassify <任务目录>` 列出来，加 `--apply` 改写译文目录里的页记录，
  只改 `final_status=failed` 的块，不用重翻。没在读接口里现算：通用取数接口（`/data/translation_items`）和质量报告都直接读页记录，
  在 Rust 里再写一份规则会两边漂移。任务的完成说明（「有 N 个内容块保留原文未翻译」）是任务结束时写的，不跟着改。
- 质检：本来只查 `final_status=translated` 的块（`services/quality/qa/units.py`），失败、保留原文的块都不进 `qa_violations`，不用改。

## 没做

- 普通翻译引擎（legacy）不加这一步：它的引注由模型翻或模型判保留原文（`skip_model_keep_origin`），一般不会进失败。
- 整条书目（"Keenan, Marie. 2013. Child Sexual Abuse and the Catholic Church."）有书名，不算没东西可翻；参考文献区在 OCR 规范化时已标不翻。
