## 用户定：模型只管翻译，切分归程序

用户看了上面三条后定：跨栏、跨页的组交给模型时就是一段文字，模型只管翻成一段，程序自动回填、分配文字（"这样的好处是不会让模型
输出 json，有利于输出的稳定性"）。上面三个问题根上都出在让模型放断点：放到句末撑爆小框、个数不对整组重翻、按两块各自交回算没交。

做法（提示词版本 `translation-agent-14`，`CHECKS_VERSION` 3）：
- 请求里接续组的 `text` 是各块原文用空格接起来的整段，不再有 `[[BREAK]]`；提示词第 5 条改成"当成一段话翻通顺，用这条记录的 id
  交回一整段，不要按 members 分开交，分回各块由程序做"。
- 交回的整段一律由程序按原文各块的正文比例在附近的中文标点处切开（上面第 1、2 条的修法照用）；模型照老习惯写进来的 `[[BREAK]]` 删掉。
- 跟着删掉的：断点个数不对（`group_break`）整组重翻、断点放错时整段塞进第一块（`group_merged`）、程序切开的警告（`group_split_by_program`），
  以及按模型断点比例判断要不要重切的那一套。editorial.v1 里这三个代码以后不再出现（格式只加不改，代码表照留）。
- 重翻接续组时不再给"断点前后的原文几个词"，上次的译文直接接成一整段。

JSON 没去掉：一页十几块用严格模式的工具调用逐块交回，接口保证格式（加严格模式以后没再坏过）；改成纯文本要么一块一次请求（请求数
翻几倍），要么自己定分隔符再解析。去掉断点以后，交回的每一条都只是一段纯译文。要不要再试纯文本，另做对比，用户定。
