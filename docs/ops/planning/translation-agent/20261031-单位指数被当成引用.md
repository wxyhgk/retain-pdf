# 单位指数被当成引用

2026-10-31。用户："最新的 jobid 大量的段落没有翻译什么情况你看看"（一篇 18 页 ACS 论文，翻译 agent）。

## 查到的

- 正文、图注、标题 116 块都进了翻译（参考文献、页眉页脚本来就不翻），没翻的是 8 块退回原文的，其中 6 块是 Methods 的整段。
- 原因在正式流程交给 agent 之前那一步（`workflow/agent_flow.py` 的 `_agent_text`）：OCR 把引用角标写成 `$ ^{34} $`，程序换成脚注标记 `{{fn:34}}`
  （受保护、丢了查得出），写回时换回去。认角标的规则是"上标里只有数字、逗号、横线"，于是单位的指数 `ng mL $ ^{-1} $`、`mg kg $ ^{-1} $`
  也被换成了 `{{fn:-1}}`。模型把它写回 `$^{-1}$`（是对的），校验报"脚注标记丢了"，重翻两次一样，整段退回原文。Methods 里到处是这种单位。
- 另 2 块是图里的样品名（`PBS / BMS202 / M1 EV …`）和一个网址：没什么可翻，原样交回是对的，却被判"译文和原文一模一样"、标成失败。

## 改法

- 角标只认正整数、列表、范围（`34`、`2-6`、`40,52,53`）；负数（单位指数）不认；紧跟在数字、单位后面的（`10 $ ^{5} $`、`mm $ ^{3} $`）是乘方，也不认，留作公式。
  这篇和上一篇论文里的 28 个角标照样都认出来，18 个 `-1` 留作公式。
- 原文没有要翻的英文词（小写或首字母大写、三个字母以上；网址、邮箱不算）时，原样交回不算 `untranslated` / `no_chinese`。`CHECKS_VERSION` 升到 6。

## 同一篇里的另一处：接续组的角标（用户指出 p002-b0007 露出 `{{fn:13,33}}`）

`p002-b007` 和 `p002-b008` 是跨栏的一段话。两个问题叠在一起：

- **切点偏了**：引用角标在句号后面（"……至关重要。{{fn:28-32}} 由于……"），切分以前规定"角标跟着前面的词、不能切在它前面"，
  于是句号后面紧跟角标的地方都不能切，切点被推到下一个后面没有角标的句号：原文前一块占 35%，译文分到 45%。
  改成句号后面紧跟的角标（`{{fn:…}}` 或模型写成的 `$ ^{…} $`）一起留在前一句，切在角标后面；这段重切后前一块 34%，正好切在原文断开的那句后面。
- **角标没换回去**：脚注标记按块换回原写法，挪过切点的 `{{fn:28-32}}`、`{{fn:13,33}}` 在前一块的表里找不到，原样露了出来。
  改成接续组各块用整组的角标表；表里还是没有的写成上标公式 `$ ^{…} $`（交给 agent 的标记都是从引用角标换来的），不会再露出 `{{fn:…}}`。
