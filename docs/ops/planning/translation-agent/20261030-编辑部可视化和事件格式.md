# 编辑部可视化和事件格式（2026-10-30）

用户："让前端去做'编辑部'的组件，包括每一个部分的怎么动，怎么执行的，这样后续前端就能直接接入了，相当于让前端做一个可视化的组件，显示他们分工合作的画面，
如果必要的话可以绘制小人（可以网上找素材），我们的组件设计需要和我们的当前的前端的配色什么的设计风格一样"。

分工：前端做组件（先用模拟数据，带回放模式）；后端定事件格式，以后按它推真实进度。说明已发给前端会话（10-30）。

## 工位

| 工位 | 现在有没有 | 做什么 |
|---|---|---|
| 调度（程序） | 有 | 派活、计次数、记台账 |
| 通读员 | 有（`reader.py`） | 开翻前读全书一次：体裁、文风、术语表、人名、全部标题 |
| 译者 | 有（`agent.py`） | 一次一整页，逐块翻 |
| 质检裁判（程序） | 有（`checks.py`） | 每块查公式、编号、数字、标记、漏翻、术语：合格 / 警告 / 不合格；不合格退回重翻，还不行进"待人看" |
| 审校 | 有（`review.py`） | 每页翻完开问题单 |
| 修订（程序） | 有（`review.py`） | 按单只改被指出的片段，改完再过质检 |
| 术语表 | 有（`memory.py`） | 带版本号；新词、改词升版本；两种译法打架贴歧义单 |
| 目录 agent、重排 agent、表格 agent、原文核对员、一致性检查员 | 以后 | 先预留工位 |

流转：通读（全书一次）→ 第 N 页到译者 → 质检 →（不合格重翻，还不行进"待人看"）→ 审校 → 修订 → 再质检 → 定稿。第 N 页审校时第 N+1 页可以同时在翻。

## 事件格式 `editorial.v1`（只加不改）

每条：`{"v": "editorial.v1", "ts": 秒, "type": ..., ...}`

| type | 字段 |
|---|---|
| `run_started` | pages、model、doc_title |
| `reading_started` / `reading_done` | — / genre、name_policy、terms、headings |
| `page_started` | page、label、blocks |
| `translate_call` | page、attempt、blocks、role |
| `check_result` | page、attempt、ok、warn、error、codes（代码 → 次数） |
| `retry` | page、blocks |
| `fallback` | page、block、reason |
| `review_started` / `review_done` | page、blocks / page、tickets、applied、rejected |
| `glossary_changed` | version、action（add / promote / revise / widen / candidate）、source、target |
| `ticket_opened` | term、current、proposed、page |
| `page_done` | page、statuses（ok、warn、error、fallback_source） |
| `run_stopped` | reason（quota_exhausted / auth_failed / rate_limited），可以接着跑 |
| `run_done` | pages、glossary_version、tickets |

后端现在的台账 `state/ledger.jsonl` 有 start、read、call、glossary、review、page、stop、done，以后由调度在写台账时同时产出上面这套事件，
再接到任务事件流里给前端（接口只加不改，到时在 `docs/api/` 写清）。

## 设计要求（转给前端的）

配色、字体、圆角、动效按现有前端风格；能看出每个工位在做什么、手上是哪一页，以及累计数字（合格、警告、退回原文、审校改了几处、术语表第几版）；
小人素材只用 CC0 或允许商用和修改的（仓库公开），注明来源和许可，或者自己画 SVG；数据只从事件来，带回放模式。

## 取值全集（10-30 前端问，以代码为准，只加不改）

`reading_done.genre`：science_paper（理工论文）、textbook（教科书）、technical_manual（技术手册）、humanities（人文社科）、popular_book（通俗读物）、other（其他）。

`reading_done.name_policy`：keep（人名保留原文）、transliterate（中文译名，首次括注原文）。

`check_result.codes`（质检代码；严重程度 error 不合格、warn 警告、info 只算指标，前端可以只画 error 和 warn）：

| 代码 | 程度 | 中文 |
|---|---|---|
| missing | error | 漏交 |
| empty | error | 译文为空 |
| formula_unbalanced | error | 公式符号不成对 |
| formula_changed | error | 公式变了 |
| code_changed | error | 行内代码变了 |
| citation_lost | error | 引用标记丢了 |
| footnote_mark_lost | error | 脚注标记丢了 |
| footnote_number_changed | error | 脚注编号变了 |
| untranslated | error | 没翻 |
| no_chinese | error | 译文里没有中文 |
| stray_english | error | 中文里夹着没翻的英文 |
| too_short | error | 译文太短，可能截断 |
| group_break | error | 跨栏跨页段落的断点放错 |
| group_overlap | error | 跨栏跨页段落前后重复 |
| keep_original_lost | error（脚注里降为 warn） | 该保留原文的专名被翻了 |
| name_mismatch | error（脚注里降为 warn） | 人名译法不一致 |
| abbr_first_use | error | 缩写首次没写全称 |
| still_too_long | error（改稿两次后降为 warn） | 改稿后仍超长 |
| fallback_source | error | 退回原文、待人看 |
| number_lost | warn | 数字可能丢了 |
| english_residue | warn | 英文残留较多 |
| too_long | warn | 译文偏长 |
| group_share | warn | 断点位置可能挪了 |
| group_split_by_program | warn | 断点由程序切开 |
| group_merged | warn | 整段放进了第一块 |
| mark_moved | warn | 标记挪到了同一段的另一块 |
| duplicate | warn | 同一块交了两次 |
| term_mismatch | warn | 术语没照用 |
| abbr_lost | warn | 缩写没保留 |
| name_first_use | warn | 人名首次没括注原文 |
| hedge_lost | info | 保留语气丢了 |
| person_lost | info | 人称"我们"丢了 |
| review_mistranslation / review_omission / review_number_term / review_fluency / review_tone | info | 审校改了一处：错译 / 漏译添加 / 数字术语 / 不通顺 / 语气 |

`role`：translator（译者）、reviser（改稿）、reader（通读）、reviewer（审校）；现在每个角色只有一个，都用 claude-haiku-5-5。

事件从哪来、嵌在哪个页面：还没定。计划是调度在写台账时同时写 `events.jsonl`（editorial.v1），以后接到任务事件流；接口定了再通知前端。
