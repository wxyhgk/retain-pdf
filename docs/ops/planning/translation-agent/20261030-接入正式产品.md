# 翻译 agent 接入正式产品（2026-10-30）

用户："继续做，接入正式产品"。翻译 agent 在真实文档上已和现有流程（DeepSeek）大体持平、术语照用率更高（见[真实文档实测](./20261030-真实文档实测.md)），
下一步让真实任务能用上它。新旧两套并存，任务可以选，默认仍是旧流程，随时能切回。

## 现在的翻译阶段（查清的）

- Rust 写 `translate.stage.v1` spec（`retainpdf-data/src/worker_command/stage_specs.rs`），起 `python -m retainpdf_pipeline.translate --spec …`；
  翻译的 API key 由 Rust 从凭据库取出，经环境变量 `RETAIN_TRANSLATION_API_KEY` 传进去。
- Python：`translate_only_pipeline.main` → `execute_translation_request` → `execution_runner.run_translation_execution_plan`，
  其中 `book_flow.translate_book_with_global_continuations` 才是"逐页翻"那一步；前后的计划、断点（checkpoint，每页提交时往 stdout 打
  `pipeline_checkpoint`，Rust 落库供实时译文用）、清单、质检、进度事件、产物登记都是公用的。
- 正式产品现在是 Python 直接发模型请求（不走 Rust 模型执行器），用量台账也在 Python 侧（`usage_ledger.record_model_usage`）。
- `api_protocol` 已经有 `anthropic`（现有流程也能直连 Claude）；凭据种类统一是 `translation_api_key`，前端已有 Anthropic 选项。

## 做法

只在 `execution_runner` 里按引擎分支，替换"逐页翻"那一步；其余全部复用，渲染、阅读器、实时译文、改译文、导出都不用改。

| 部分 | 内容 |
|---|---|
| 任务字段 | `translation.engine`：`legacy`（默认，现有流程）/ `agent`（新 agent）。只加不改：`TranslationInput`、`PublicTranslationInput`、建任务契约 `contracts/create-job.v1.schema.json`、校验（agent 要求 `api_protocol=anthropic`）、spec 参数、黄金 fixture、Python spec 读取；jobs 领域读它用 `questions.rs` 新方法 |
| Python 适配（`retainpdf_translation` 里，agent 包保持只用标准库） | 每页模板记录 → `PageInput`（类别、位置、`$…$` 原文、接续组）；`DocumentRun` 式地逐页翻（通读、术语表、审校照开），译文用 `apply_translated_text_map` 写回；`fallback_source` 写成 keep_origin 并标原因（不卡发布门槛）；每页 `save_pages` + `checkpoint.update`（实时译文照常）；发 `translation_batches` 进度 |
| 模型请求 | agent 用自定义 transport：key 取 `RETAIN_TRANSLATION_API_KEY`（不读服务器的 `ANTHROPIC_API_KEY`），地址用任务的 `base_url`；每次请求记用量台账（Anthropic 的 usage 换成台账的形状） |
| 术语表 | 任务的 `glossary_entries` 快照 → agent 术语表（preserve → 保留原文、canonical → 锁定、preferred → 审定） |
| 公式 | agent 引擎强制 `math_mode=direct_typst`（原文带 `$…$`） |
| 续跑 | 引擎身份（`engine_identity.py`）记上 agent 的交接格式和提示词版本，换引擎不混用旧 checkpoint |
| 部署 | 运行时镜像装 agent 包（`Dockerfile.app`），流水线依赖加上 |
| 模型 | 默认 `claude-haiku-5-5`（用户定：全部用 Haiku） |

## 分步

1. 后端：字段、校验、spec、Python 分支和适配、用量台账、进度、续跑身份、部署；假模型测试 + 用用户本地的真实文档跑一个真任务（走 Rust 任务、看阅读器和实时译文）。
2. 前端：建任务的翻译选项里加"翻译引擎"下拉（前端会话做，后端写交接说明）。
3. 编辑部画面接真实事件（`editorial.v1`）。

先不做：模型执行器支持 Anthropic、agent 内部并发、编辑部的 preparation/refine 联动（agent 自带通读和审校）。

## 做了的（第 1 步，分支 feat/agent-translation-engine）

- 字段 `translation.engine`：`TranslationInput`（默认 `legacy`）、任务详情回显 `PublicTranslationInput`、契约 `create-job.v1` / `job-status.v1` /
  `library-documents.v1`（抄的那份）、校验（取值，以及 agent 要求 `api_protocol=anthropic`）、translate / provider 两种 spec、黄金 fixture、
  Python spec 读取一路传到 `TranslationExecutionRequest.engine`。多用户平台模型不是 Anthropic 时退回 `legacy`。
- Python：`workflow/agent_flow.py`（和 `book_flow.py` 同一层），`execution_runner` 按引擎分支；`book_flow` 的前半段拆成
  `prepare_book_payloads` 两边共用；接续组整组字段用 `apply.py` 的 `join_unit_text`（从 `revision.py` 挪过来，两边共用）。
- agent 包：`make_http_transport(密钥, url=…)`（正式流程用，不读环境变量）、`DocumentRun.run(pages, on_page=…)`、`glossary_from_entries`。
- 用量台账：`agent-translate` / `agent-revise` 记「翻译」，`agent-read` → `agent_reader`（通读），`agent-review` → `agent_review`（审校），
  Rust 用量报表加了这两个阶段的中文名。
- 部署：运行时镜像装 agent 包；`uv.lock` 更新。
- 测试：`devtools/tests/translation/test_agent_flow.py`（假模型整条跑通、死信、额度用完后续跑只补没翻的页、接续组写回、断点指纹、地址）；
  rust_api 建任务校验测试；提交快照 `submissions.txt` 只多了 `"engine":"legacy"`。

## 前端要改的（交接，前端会话做）

建任务的翻译选项里加「翻译引擎」：

| 文件 | 现在 | 改成 |
|---|---|---|
| `frontend/web/src/features/ingest/domain/workflow/payload.ts` `WorkflowDeveloperConfig` | 没有引擎字段 | 加 `engine?: TranslationInput["engine"]` |

## 论文实跑（10-30，用户："合，然后用论文实跑一次"）

几何优化那篇论文（20 页，138 块要翻），正式的翻译 worker + 渲染，`engine=agent`、Haiku 5.5、量子化学术语表；任务目录放在临时目录，
没走本地开发栈（那边的 rust_api 是 10-22 的老版本，不认 `engine`，重启会打断开发栈）。

| 轮次 | 结果 |
|---|---|
| 第 1 次（合进 main 的代码） | 第 4 页崩：模型把 `translations` 数组写成一段 JSON 字符串，而且那段 JSON 是坏的（引号写坏）；agent 包解析时直接异常，整个阶段失败 |
| 修解析后续跑 | 前 3 页从断点读回、没重发请求；第 4 页重翻时 7 块放在同一个请求里又坏了一次，7 块退回原文；全文 130 块译出、8 块死信 |
| 加 strict 工具后重跑 | 135 块译出、3 块死信（2 块接续段前后重复、1 块脚注标记丢了）；翻译 230 秒，约 0.04 美元（输入 25 万、输出 3.5 万 token）；渲染正常 |

跟着改的（分支 fix/agent-engine-skip-extras）：

- 工具定义加 `strict: true`（每层对象 `additionalProperties: false`），接口保证参数符合 schema；先发过一个小请求确认 Haiku 5.5 接受三个工具的 strict 写法。
  提示词版本升到 `translation-agent-13`（请求格式变了，断点和缓存不混用）。
- 数组字段被写成字符串时：能解析就照用，解析不了当没交、重翻，不再整页崩。
- 新检查 `foreign_script`（error）：译文里冒出原文没有的西里尔、韩文、日文假名、阿拉伯、希伯来、泰文（实跑看到 "…优化 должна 大致平行于…"）；希腊字母不算。
- 前端问起才发现：agent 模式下译前准备、翻译后自动精修会照跑、重复花钱；现在一个按 off、一个不自动跑（手动精修照旧）。

顺带看到：共用前半段的接续段检查给 Haiku 5.5 发了 `temperature`，被 400 拒一次后现有逻辑自动去掉重发、成功了，只多一次请求，不用改。
