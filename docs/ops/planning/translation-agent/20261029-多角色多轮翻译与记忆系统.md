# 多角色、多轮翻译与记忆系统（2026-10-29）

## 起因和用户的决定

翻译 agent 包（`backend/translation-agent/`）现在是单轮：一页一次请求、程序逐块校验、不合格重翻一次。用户提出：

- 要**多轮翻译**才能翻好；
- **上下文的链接关系**非常重要；
- **文章超长**、超出模型上下文时，没法一次通读，要有办法；
- 要有**记忆系统**和配套的其它系统；
- **必要时直接看原文**，不只看 OCR；
- 让多个 Sonnet 讨论还要注意什么。

讨论分两轮：第一轮四个 Sonnet 各看一面（记忆与超长文档、看原文与工具、多轮质量、工程与产品），第二轮一个反方合并、反驳、分档。
反方主张砍掉或推后的几条，用户逐条定了：

| 条目 | 反方 | 用户定的 |
|---|---|---|
| 章节摘要 | 不做（会丢细节、模型可能照着摘要改数字） | **做**：通读时每章出短摘要进上下文包，标明只作参考，数字和术语以原文和术语表为准 |
| agent 主动看原文 | 不做，只靠程序分诊 | **保留但有上限**：每页最多 2 次、写明理由、记账 |
| 译文记忆 | 不做（论文书重复句少） | **做**：一字不差的重复直接沿用，相近句子作参考译法 |
| 审校、多轮 | 排在很后 | **做**，第二版就上 |
| 角色 | 只留四个 | **要多角色**（见下表） |
| 同词异义 | 先不做识别 | **要考虑**：术语按"词 + 作用域"记，通读发现语境不同交术语专员定 |

同意反方的：编辑部的"主编"用规则代替（不再加一个模型）；精细限流、熔断、隐私分级、Rust 执行器扩协议放到接正式流程时；
不让模型随手无限调工具。

## 角色

7 个模型角色 + 2 个程序角色。**每个角色只能改自己管的那一样**，这是"数据不出错"的主要保障。

| 角色 | 做什么 | 能改什么 | 模型 |
|---|---|---|---|
| 通读员 | 按章节通读：抽术语候选（附原句和页码）、缩写和定义、人名机构、符号定义、本章依赖前面哪些章；写章节摘要；标出同一个词在不同章的不同用法 | 只产出抽取结果 | 中档以上 |
| 术语专员 | 审定术语：定译法、哪些保留原文（人名、机构、期刊、参考文献）、同词异义是统一还是分章；处理改术语的申请 | **术语表**（唯一能改的角色） | 中档以上 |
| 译者 | 逐页初译（现在的 `translate_page`），带上下文包 | 自己那一页的译文 | Haiku |
| 原文核对员 | 处理程序分诊标出的可疑块和译者的"申请看原文"：读 PDF 文字层、看局部截图，写 OCR 问题报告 | 只能上报 | 看图能力强的模型 |
| 审校 | 逐页审，只开问题单；每条必须逐字引用原文和译文 | 只能开单 | 比初译强的模型，只审程序预筛的嫌疑块 |
| 修订 | 处理问题单：局部改 / 整块重翻 / 说明不改的理由；接续组整组处理 | 被指到的块的译文 | Haiku |
| 一致性检查员 | 全书收尾：术语统一、目录和标题一致、交叉引用和编号格式统一 | 只能开单 | 程序为主、模型补充 |
| 调度（程序） | 按规则派活、计次数、到上限交给人、管预算 | 任务分配 | — |
| 质检裁判（程序） | 每次改动后查公式、数字、标记、术语、漏译、接续组重复；**改完违规只许减少不许增加**，增加就回滚 | 只判 | — |

## 记忆系统

| 记忆 | 存什么 | 谁写 | 说明 |
|---|---|---|---|
| 术语表 | 原文、译法、类别、作用域（全书或某几章）、首次出处原句和页码、状态（候选 / 审定 / 锁定）、版本 | 术语专员（人可以改，优先级最高） | 按版本存、旧版本不改；候选要"出现两次以上且译法一致"或经术语专员审定才晋升；找不到原句的条目丢弃 |
| 保留原文表 | 人名、机构、期刊、参考文献书名 | 程序规则 + 术语专员 | 任何角色不得译成中文（10 月 9 日编辑部实测吃过亏：J. Chem. Phys. 被改成《化学物理杂志》） |
| 缩写与定义表 | 全称、缩写、定义位置；符号定义（"其中 $E$ 为能量"） | 程序抓"全称 (ABBR)"句式，模型确认 | 第 1 章定义、第 5 章只用缩写时照样认得 |
| 风格说明 | 语气、编号标签格式（Figure → 图、Theorem → 定理） | 第 0 轮生成后冻结，人可以改 | 不超过 300 字；编号格式由程序套用，不让模型自创 |
| 章节摘要 | 每章三五句 | 通读员 | 只作参考，不是事实来源 |
| 译文记忆 | 已通过质检、没被开单的块的原文和译文，记着用的术语表版本 | 程序 | 一字不差的重复直接沿用；相近句子（字符 n-gram 相似）作参考附上 |
| 关系表 | 正文"见图 3""式 (2)""第 4 节""[12]"指向哪个块；同一实体的不同写法（Smith et al. / Smith (2019) / [12]） | 程序一遍扫描产出，带证据和置信度 | 低置信度的不进上下文包；每章各自编号的参考文献不能全书混用 |
| 台账 | 每次动作一行：块、轮次、角色、模型、提示词版本、token、结果、校验问题 | 所有角色（只追加） | 履历、记账、可观测性都从这一份来 |

**改错的办法**：每块译文记下用到的术语和版本（`used_terms`）。第 20 页发现第 3 页定的术语错了：术语专员升版本并写原因 →
程序只找出真正用到这个术语、原文里确实有这个词的块 → 字面替换的走规则，语境相关的开单给修订 → 已定稿的先列清单给人确认 →
动手前给出要改多少块、多少 token 的预估。同一个术语一轮最多改一次，防止来回改。

## 上下文包

每页请求带一个**固定大小**（约 6–8k token）的上下文包，大小不随文章变长而变大：

| 部分 | 预算 |
|---|---|
| 风格说明 | ≤ 0.3k |
| 本页出现的术语（按作用域取） | ≤ 1.5k |
| 本页用到的缩写、保留原文 | ≤ 0.7k |
| 全书一句话 + 本章摘要 + 上一章摘要 | ≤ 1k |
| 上一页结尾、下一页开头（原文和已定译文） | ≤ 1k |
| 本页引用到的目标（图注、表题、公式、参考文献条目）原文和已定译文 | ≤ 1.5k |
| 译文记忆里的相近句子 | ≤ 1k |

超了按 引用目标 > 术语 > 缩写 > 译文记忆 > 摘要 的顺序截断。检索不用向量库：术语和缩写用词表最长匹配，译文记忆用字符 5-gram 相似度，
"某词在哪出现过"用预先建好的倒排索引——都能只用标准库做。

## 超长文档

- **通读分而治之**：按章节切段（每段不超过模型上下文的一半，切在标题处，段与段重叠一两页免得定义被切断），
  每段由通读员做**结构化抽取**（不是写总结），程序合并成全书的术语候选、缩写表、实体表，再由术语专员审定；书很长就节 → 章 → 全书多层。
- **并行前先冻结**：术语表冻结成一个版本再分章并行翻译；翻译中发现的新词只进候选，一章译完再批量升版本，不让并行的章各自改表。
- **续跑**：按"页 × 轮次"记进度文件（缓存不算进度）；缓存的键里带上下文包的内容哈希，术语表升版本后不会误用旧译文。

## 看原文

1. **程序分诊为主**（信号由 OCR 归一化层产出，不放进 agent 包）：公式不是合法 LaTeX、替换字符和私用区字符、大量孤立单字符、
   框的大小和字数对不上、整页 OCR 字数远少于 PDF 文字层（漏行）、表格行列不一致、上下标丢失 → 给块打"可疑"标签和原因。
2. **先读 PDF 文字层**（文字、字体、字号、上下标），便宜且不会看错；公式字体常是乱序字符、扫描件没有文字层，才看**局部截图**
   （块外扩 8–10%，150–220 dpi，长边不超过 1500 像素）。渲染和裁剪在调用方做，agent 包只收图片字节。
3. **译者可以申请看原文**：每页最多 2 次、必须写明理由，由原文核对员处理，每次记账。
4. **发现 OCR 错了只上报**：结果里加 `ocr_findings`（类型、证据、建议的原文、置信度）；译文仍按 OCR 文本、标"待人看"；
   修 OCR 由归一化层决定，修完再重翻。模型看图也会看错，文字层和图冲突时以文字层为准。
5. 隐私：默认只发局部截图，整页图要显式开启并记录发过哪些页。

## 多轮流程

```text
第 0 轮  通读员按章节抽取 → 术语专员审定 → 冻结术语表、风格说明、章节摘要
第 1 轮  译者逐页初译（带上下文包）→ 质检裁判
         ├─ 可疑块：原文核对员 → OCR 问题报告
第 2 轮  审校（只审程序预筛的嫌疑块）→ 问题单
第 3 轮  修订 → 质检裁判（违规只许减少）→ 不过就回滚
         ↺ 第 2、3 轮最多来回 2 次；第二次只复核上一次改过的块
收尾     一致性检查员 → 问题单 → 修订 → 质检裁判 → 定稿
```

- **问题单**：必须带原文片段和译文片段，在原文和译文里逐字找不到就作废；只收四类——漏译、错译（附正确译法）、数字或术语、不通顺；
  "更自然""更学术"不收。
- **修订**只许改被引用的片段，程序比对改动范围，越界拒收；接续组是最小单位，改完重查整组，失败整组回滚。
- **分流**：规则能改的（术语不符）不调模型；漏译、数字公式丢失整块重翻；错译先局部改；和术语表冲突的转术语专员；超次数交给人，全书跑完一起列出。
- **次数上限**：每块修改最多 2 次、重翻最多 1 次；和以后重排 agent 要短版本共用一个计数，总数封顶。
  到顶时用**过了校验的最好一版**；一版都没有，就**保留原文、标红、待人看**——绝不输出没过校验的译文。
- **停的条件**（用程序指标，不用模型自评）：没有严重问题、本轮采纳的修订少于 2%、到轮数上限；某块被改回两轮前的样子立刻停、转人。
- **用户改过的块锁住**：任何角色都不许改，只能开单。

## 交接格式要加的字段（只加不改，仍是 `translation_agent.v1`）

| 对象 | 加的字段 | 用途 |
|---|---|---|
| `BlockInput` | `locked_by_user` | 用户改过的块，agent 只能开单 |
| `BlockInput` | `suspect`（原因列表） | 程序分诊的可疑标签 |
| `PageInput` | `context`（上下文包） | 术语、摘要、引用目标、相邻页、译文记忆 |
| `BlockResult` | `meta`：模型、提示词版本、分类版本、交接格式版本、轮次、角色、`used_terms` | 分清是哪个版本翻的；改术语时反查 |
| `BlockResult` | `ocr_findings` | 原文核对员上报的 OCR 问题 |
| `BlockResult.status` | 新值 `fallback_source`（保留原文、待人看） | 到上限都没合格时的退路 |
| 台账 | 每行：块、轮次、角色、模型、提示词版本、输入输出缓存 token、结果、问题 | 只追加 |

## 怎么评测

- **长样例**：在测试系统里造 30–50 页人造长文，故意埋坑——跨章同一术语、同词异义（两章意思不同）、缩写先定义后使用、
  同一实体多种写法、跨章引用、每章各自编号的参考文献、人名期刊、后面才出现的更正、故意写错一个数的摘要（看译者是否仍忠于原文）、
  OCR 公式乱码和漏行、扫描页。
- **指标**：术语一致率（章内、跨章）、保留原文正确率、缩写首次括注率、交叉引用正确率、改术语后的回改召回和误改、OCR 可疑块的分诊召回和误报、
  每页 token 和费用、缓存命中率；多轮和单轮做**成对盲评**，看胜率，更要看**变差率**。
- **防过拟合**：样例分开发集和封存集，封存集只在发版前跑；尽早加 2–3 篇真实文档；线上坏例子都加进样例。
- 硬指标（公式、数字、漏译）不许下降；改提示词要附评测报告和上次的对比。

## 分版

| 版 | 内容 |
|---|---|
| 1 | 地基：术语表（版本、作用域字段、`used_terms`）和保留原文表；固定大小的上下文包；台账、`meta`、`fallback_source`；30–50 页长样例和一致率指标；最基本的保护（429 按等待时间退避、额度用完整体停下保留进度） |
| 2 | 审校 + 修订 + 质检裁判的"违规只许减少"；一致性检查员（程序部分） |
| 3 | 通读员（结构化抽取 + 章节摘要）、术语专员（模型审定、同词异义）、分层通读和并行 |
| 4 | 译文记忆、关系表（"见图 3""[12]"、同一实体多写法） |
| 5 | 原文核对员：程序分诊、PDF 文字层、局部截图、译者申请看原文 |
| 以后 | Rust 模型执行器支持 Anthropic 接口和提示词缓存；块状态（初译 / 审过 / 定稿）给实时覆盖用；和重排 agent 共用改稿计数 |

每一版一个分支，用长样例量出前后对比再合。

## 不做

七个角色之外再加"主编"模型；让模型无限制地调工具；多模型自动选择；在线学习；跨文档共享记忆；BLEU 之类按参考译文打分的指标。

## 待定

- 文档标题、关键词、算法块翻不翻（块分类草案里的三个待定项）。
- 改稿规则：先精简措辞，还超就删次要的修饰和举例，核心意思、公式、标记、编号必须保留——用户还没确认。
- 各角色具体用哪个模型。
- 数字版 PDF 里文字层能精确证明的纯文字错误（断词、乱码），要不要由程序直接替换 OCR 文本再翻。
