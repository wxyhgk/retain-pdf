# 译文质量问题和修法（2026-10-30）

第 1 版合进 main 后，用户："下一步我们的 agent 翻译部分，针对目前的问题得修复一下，看看怎么搞更好"。

## 怎么查的

- 程序统计：6 份样例（21 页小书 + 4 份 7–8 页新样例，共 513 块要翻）第一次就全对的比例、重翻原因、token。
- 3 个 Sonnet 当审校逐块读译文（只读，不改），找程序校验抓不到的问题，按错译、漏译添加、术语专名、语气、翻译腔、结构、重翻变差分类，
  每类带原文和译文例子，并推测是 agent 哪一环造成的。

## 程序统计

| 样例 | 块 | 第一次全对 | 重翻块 | 主要重翻原因 |
|---|---|---|---|---|
| 小书 | 121 | 99% | 1 | 缩写首次没括注 |
| 会议论文 | 110 | 96% | 4 | 接续组断点 |
| 教科书 | 81 | 100% | 0 | — |
| 技术手册 | 137 | 99% | 1 | 专名保留被判"没翻" |
| 人文文章 | 64 | 80% | 13 | 接续组断点 6、短脚注漏交 4、脚注标记 2 |

15 个接续组里 4 个第一次没放断点，全是断点落在词组中间（"the first of the ‖ eight parts"、"'Kept ‖ it four days too long'"）；
重翻有一次和第一次逐字相同，说明原样再问一遍没用。

## 审校打分（5 = 可直接出版）

小书 4、教科书 4、技术手册 4、会议论文 3.5、3 页论文 3.5、人文文章 3。单句大多通顺，**机械层面基本干净，问题都在程序查不到的地方**。

## 问题，按出现多少排

1. **术语、专名全文漂移（三份审读都排第一）**
   - 会议论文：fitting 译成适配 / 拟合 / 排入 / 填回，rewrite 重写 / 改写，fallback 三种译法，box 四种。
   - 教科书：均值 / 平均数 / 平均值，样本量 / 容量；技术手册：agent 代理 / 代理程序，还和 proxy（代理服务器）撞车，"您""你"混用。
   - 人文文章：Agnes Pellew 四种写法（两种音译、一种别字、一种英文原样），ledger 账簿 / 账本各一半。
   - 根源：术语表只收译者自己报的"专业术语"，开头是空的；核心概念词（fitting、ledger、mean）模型不认为是"术语"所以不报；
     人名规则"一律不翻"是按理工论文写的，人文类模型自己去音译，又没登记。
2. **目录和正文标题各译各的**：技术手册 24 条里 6 条对不上（还原 / 恢复、故障排除 / 故障排查），小书 3 条。
   目录页先翻，那时还没有正文标题；提示词又说"不报标题"。
3. **词义判断错（程序查不到）**：set（排版）译成"设置"、points（磅 / 百分点）译成"点"、"a hundred times as much"译成"多一百倍"、
   "could not afford to let lapse"（舍不得断）译成"负担不起"、题记的 sorry（惋惜）译成"懊悔"、"not because it settles anything"译成"不是因为能解决问题"。
4. **语气被抹平**：前言"像喝咖啡时聊天"被译得书面；教科书 "Proportions are means in disguise" 译成"比例实质上是均值"；suggest 被加强成"表明"。
   上下文包里其实没有风格说明（第 3 版才有通读员写），语气全靠提示词一句笼统的规则。
5. **中文体例**：要"式 (3.2)"、"图 3.1(a)"、"子图"、pt 译"磅"、"百分点"；节标题编号体例一、二、IV. 混用；接续块以句号开头；
   双关语加了英文括注；中文里夹着孤立英文词（"实际上those崩溃"，校验没抓到）。
6. **机械问题**：接续组断点（见上）；专名本该原样，被判"没翻"逼着重翻成"Tidewater 备份代理"。
7. **需要产品决定的**：表格整块不翻（技术手册的说明列整段英文）；外文引文块（法文、德文）被译成中文后，正文作者自己的英译又被译一遍，读者看到两遍。

## 修法（按收益排）

| # | 改什么 | 修哪类问题 | 代价 |
|---|---|---|---|
| 1 | **翻译前通读一遍**（把第 3 版的通读员和术语专员提前做轻量版）：整篇（长书按章）送一次，产出 ① 体裁和领域（理工论文、教科书、技术手册、人文……）；② 文风说明（300 字内，带 2–3 句示范）；③ 概念词和专名表（含人名译法、书名、反复出现的普通概念词），直接登记成审定、全书照用；④ 全部标题的译法（标题表） | 1、2、4 | 每本多一次（长书每章一次）长请求，约多 10–20% 输入 token；定错会扩散——人可以改、译者可以声明例外 |
| 2 | **目录照搬标题表**：目录条目指向的标题已经有译法，程序直接用，不再让模型翻 | 2 | 省请求 |
| 3 | **翻完做一致性检查**（程序）：同一原文短语出现几种译法、和术语表不符的块，挑出少数派，一次请求只改这几块 | 1 | 少量请求 |
| 4 | **审校**（第 2 版提前）：只审程序挑出的高风险块（有数字、单位、否定、比较、倍数、题记、引语的），换强模型（Sonnet）对照原文只开问题单，修订只改被指出的片段 | 3 | Sonnet 只看一小部分块，估计多 20–40% 费用 |
| 5 | **提示词补中文体例**：式 (3.2)、图 3.1(a)、子图、pt 译磅、百分点、编号体例一致、双关用中文等效说法不加英文括注、"你 / 您"按文风说明定；可能 / 表明 分清 | 4、5 | 提示词变长 |
| 6 | **校验补几条**：中文里夹孤立英文单词、接续块不许以标点开头、节标题编号体例混用；专名（保留原文表里的）原样出现不算"没翻" | 5、6 | 无 |
| 7 | **断点**：模型没放断点就不再原样重问，程序在原文长度比例附近找最近的中文标点切开；放错数量的重翻时给出断点前后的原文锚点 | 6 | 省请求 |

先做 1、2、5、6、7（都是翻译之前或程序侧的，便宜），用 6 份样例量前后对比；再做 3、4（翻译之后的轮次）。
评测：程序指标（术语一致率按样例里所有反复出现的名词短语算，不只预设的几个）+ 再请 Sonnet 按同一套标准盲评打分，看分数和各类问题数。

## 用户定的（10-30）

- **人名按体裁定**：理工论文、技术文档保留原文；人文、通俗书首次写"中文译名（原文）"，之后全书用同一个中文译名。
- **表格以后单独建一个 agent 处理，现在先不管**（表格照旧整块不翻）。
- **外文引文块保留原文，不翻**（作者通常紧跟着给了译文，正文照常翻）。
- **审校先用 Haiku**（不先上 Sonnet）。

据此修法第 4 条的审校模型用 Haiku；表格不在这次范围里。
