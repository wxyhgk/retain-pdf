# 翻译 agent 测试系统（2026-10-29）

用户：先不做字数上限，直接建一个测试系统测翻译 agent，额度够用。代码在 `backend/pipeline/devtools/agent_lab/`（说明见那里的 README），
不碰现在的正式翻译流程。输入是 OCR 分类查看器的 3 页样例（目录页 + 2 页双栏正文，41 块要翻），模型 `claude-haiku-5-5`。

## 测试系统

- 一次送一整页：每块给类别、大概位置、原文、要不要翻、接续组和关系；整页附文档标题和章节路径。
- 模型通过固定格式的工具调用交回译文（不会出现 JSON 写坏）。
- 逐块校验，不合格的重翻一次（单块的合成一次请求，接续组整组）。
- 离线报告：原文页上按框叠译文，浏览器里缩字号，缩到 5.5pt 还放不下的标紫。
- 每个请求和回答缓存，结果可复现；假模型的离线测试 7 个。

## 四轮实测

| 提示词 | 结果 | 发现 |
|---|---|---|
| v1 | 39/41 合格，4 次请求 | 跨页段落前半段把整段话都翻了，后半段又翻一遍结尾——**内容重复**，校验没抓到；短标题"致谢"被误判截断，"level-2 → 二级"被误判数字丢失 |
| v2：加接续组重复检查、整组重翻、提示词写明"只翻自己那部分" | 40/41，5 次请求 | 光靠提示词不够：前半段停在半句话上，模型总想把它补完，重翻后后半段只剩 9 个字 |
| v3：接续组合成一条，原文用 `[[BREAK]]` 标断点，译文在对应位置放同样的标记再切回 | 41/41，7 次请求 | 跨页、跨栏都切对了（"前置部分（从标题到 / 关键词）与正文分开处理"）；但每页会漏交一两块（图注、短标题），多了 4 次重翻 |
| v4：请求里附 `required_ids` 要求交卷前核对；漏交的合成一次重翻 | **41/41，3 次请求，无重翻**；不用缓存连跑两次结果一样；每次 24–30 秒，约 1.5 万输入 token、3500 输出 token | — |

报告截图看：41 块都排进原框（没有放不下的），引用、脚注标记、"图 1""表 1""算法 1"的编号都保住。

## 结论

- 接续段落"按块分别翻"不可靠，**合成一条、用断点标记切回**可靠——这和现在正式流程"合成一段翻、按原文长度比例切回"相比，切点由模型按语义定。
- 一次一页的请求要附"必须交回的编号清单"，否则模型会漏交。
- 校验要查接续组内的重复，单看每块抓不到。

## 还没做

- 输入换成真实 OCR 的 `document.v1`（现在只吃样例的标准答案）。
- 放不下时让 agent 缩写的那一圈（报告已经能测出哪些块放不下）。
- 表格、图片翻译（要看图）；算法块翻不翻还没定，测试时按不翻。
- 跨页术语一致：把前面页的译法带给后面页；更长的文档（书）。
- 和现在的正式翻译流程并排对比同一篇。
- 报告里的公式渲染（现在显示 `$…$` 原文）。
