# 公式不再判对错

2026-10-31。用户重试论文翻译以后指出第 12、13 页跨页那段（`p012-b012`、`p013-b003`）还是没翻，问是不是缺一个先划分、检测跨栏跨页的 agent。

## 查到的

- **跨页切分这次是对的**。接续组整段翻完，程序按正文比例切回两块：前一页那块分到"相对于表 V 所给的参数值……或许可以进一步提高搜索效率。"，后一页那块从"然而……"开始，断在句末，位置和原文一致。
- **两块退回原文是公式检查判的**。原文里的参数写成 `$ n_{\mathrm{L}}^{\mathrm{max}} $`、`$ \delta F_{\mathrm{D}} $`，模型两次都写成普通文字 `n_L^max`、`δF_D`（第二次还是一样），
  `formula_changed` 判错 → 重翻 → 仍判错 → 两块都退回原文。看起来像跨页出错，其实是公式检查太严。
- 同一页另外两块（`p012-b005`、`p012-b010`）也是这样退回的：一块把 `$\Delta x^{ran}$` 写成 `Δx^ran`，一块把数字 `0.001` 挪进了公式。
  全文 147 块里退回原文 6 块，4 块是这个原因（另 2 块是作者姓名，原样保留，结果一样）。

所以不是缺一个检测跨栏跨页的 agent：接续组由 OCR 和程序认出来，模型只翻整段，切分归程序，这一套这次是好的。

## 用户定

"公式判断不好，太严格了，没有必要去判断公式。"

## 改法

- `checks.check_block` 不再拿译文的公式和原文逐个比：去掉 `formula_changed`（错）和 `formula_merged`（警告）。公式写成普通文字、改了、多了、少了都不重翻、不退回原文。
- 只留 `formula_unbalanced`：`$` 不成对还是错——不成对的话后面整段都会被当成公式排，渲染会坏。
- 模型把公式改了一点点（相似度 ≥ 0.85）的，程序照旧换回原文写法（`restore_formulas`），记的 `formula_restored` 从警告降成 info，不再让块显示成"有警告"。
- 接续组"挪过断点"的宽免名单 `MOVABLE` 去掉公式；审校重算的检查代码 `BLOCK_CHECK_CODES` 去掉 `formula_changed`。
- 提示词不改（仍要求公式原样保留），请求缓存照用；`CHECKS_VERSION` 升到 4，正式流程不再沿用旧进度。

## 代价

公式写成普通文字的块，阅读器里显示的是 `n_L^max` 这样的文字，不是排好的公式。比整段英文好，以后要的话可以在程序里把这种文字换回原文公式（不靠模型）。

## 验证

本次任务（`translation-agent-checks-3` 跑的）4 块退回原文的第一次译文用新规则重查：都没有错。`p012-b012`、`p013-b003` 的第一次译文就会直接收下，不再重翻。
