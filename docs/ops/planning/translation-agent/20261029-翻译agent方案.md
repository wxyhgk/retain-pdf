# 翻译 agent 方案（2026-10-29）

## 起因和用户的决定

用户：下一步做翻译 agent，做法要像人一样——**看大概区域 + 看文字 + 看上下文**，大模型才能翻得准、排得下。讨论中定下：

1. **平时不看图**。OCR 已经替大模型"看"过页面，把分类、大概位置、文字、上下文给它，它就能联想；只有翻译**图片和表格**时才看图。
2. **不再在 Typst 排版上投入**，译文显示用 HTML（阅读器的"实时覆盖"），以后看能不能用 HTML-in-Canvas（浏览器把 HTML 画进 canvas，目前只有 Chrome 实验开关）。
   Typst 这条路先不删：下载译文 PDF、导出 Word 还在用，删要单独开分支查清谁在用。

## 现状（2026-10-29 的代码）

路径相对 `backend/translation/retainpdf_translation/`，另有说明的除外。

| 方面 | 现在怎么做 | 问题 |
|---|---|---|
| 请求粒度 | 每块一次请求：`llm/shared/control_context.py` 的 `plain_batch_size = 1`（注释：带标签的批量会把 `<<<END>>>` 弄坏） | 一页几十次请求；模型看不到一页的全貌 |
| 模型看到什么 | 当前原文、按需附 ±2 块邻居各 360 字（`services/context/windows.py`，默认只在接续、图注、半句时附）、匹配到的术语（`core/terms/injection.py`） | **不知道块的类别、在页面哪里、属于哪个章节、框有多大** |
| 输出 | 纯文本（`translation_client.py`，`response_format=None`） | 只能一块一块对 |
| 校验 | `llm/validation/quality.py` 的 `review_translation_item`：空、`$` 不配对、协议外壳、英文残留、截断（译文不到原文 15%）、占位符 | 只查"太短"，不查"太长" |
| 接续 | 先合成一段整体翻（`core/payload/parts/units.py`），再按**原文长度比例**拆回各框（`core/payload/parts/group_split.py` 的 `split_group_protected_translation`） | **拆的时候不看框能放多少字**，跨栏、跨页段落是溢出的来源之一 |
| 放不下 | 网页覆盖（`frontend/packages/reader/src/pdf/LiveTranslationOverlay.tsx` 的 `computeLiveTranslationFit`）二分找字号，放不下就**悄悄用最小字号**；没有任何回报给后端 | 字小到看不清也没人知道 |
| 改稿 | `workflow/refine.py` 只限制"不许变长"（`length_budget` = 现长 × 1.10）；没有"缩短"这件事 | — |
| 容量估算 | 已有：`backend/pipeline/retainpdf_pipeline/render/layout/payload/capacity.py` 的 `box_capacity_units`（框能放多少字）、`font_size_fit.py`、`chinese_body_fit.py` | 在流水线包的渲染里，翻译包按架构规则不能跨阶段导入 |
| 看图 | 没有：Rust 模型执行器的 `Message { role, content: String }` 带 `deny_unknown_fields`（`backend/packages/retainpdf-providers/src/model_executor/policy.rs`），Python 的请求体也强制成字符串（`model_wire.py`） | 图片、表格翻译要先补 |

已经有、可以直接用的：

- **单块写回**：`workflow/revision.py` 的 `revise_translation_item`（带原因、代次检查、同一套质量校验、写 `revisions.v1.jsonl`）。
- **单块重翻带指令**：`POST /api/v1/jobs/:job_id/translations/:item_id/replay`（`backend/packages/retainpdf-jobs/src/translations/replay.rs`），已经能带"缩短到 N 字"这类指令。
- **带字数上限的修改**：`services/refine/fix.py` 给模型传 `max_chars`、`may_grow`；编辑部模式的整块重写（`services/editorial/rewrite.py`）也有字数上限。
- **离线测试**：`devtools/run_translation_tests.py`，假模型（替换 `request_chat_content`、`chat_fn` 注入、`SingleItemFlowDeps`），提示词快照守卫。

## 目标形态

一次请求送**一页**（太长时按章节切开，设上限），大模型一次看到这一页所有要翻的块和它们的位置关系，逐块交回译文。

### 大模型收到什么

每块一条记录：

```json
{
  "id": "p002-b014",
  "class": "figure_caption",
  "where": "第 2 页，右栏，图 2 下方",
  "text": "Figure 2: (a) Recall by column gap. (b) Recall by line spacing.",
  "max_chars": 46,
  "keep_lines": false,
  "group": {"id": "cg-3", "index": 1, "of": 2},
  "relations": {"caption_of": ["p002-b012", "p002-b013"]}
}
```

- `class`：OCR 块分类草案（`docs/ops/planning/ocr-normalization/20261029-块分类草案和查看器.md`）的类别。分类落进 `document.v1` 之前，先用现有字段换算。
- `where`：从框坐标换算的大概位置（第几页、左栏右栏、上中下、挨着哪个图表），**不给精确坐标**。
- `max_chars`：按框大小、原文字号算出的字数上限（见下面"放不下"）。
- 不翻的块（参考文献、页眉页脚、公式……）只作为上下文给出，标明"不用翻"，不要求交回。

整页还附：文档标题、这一页所在的章节标题路径、匹配到的术语、前一页同类块的译法（保持一致）。

### 大模型交回什么

```json
[{"id": "p002-b014", "translation": "图 2：(a) 召回率随栏间距的变化。(b) 召回率随行距的变化。"}]
```

要求 JSON 输出，每个要翻的块恰好一条。

### 校验（数据不出错的关键）

1. 块编号对得上：不多、不少、不重复。
2. 行内公式原样保留（`$…$` 成对，公式集合和原文一致）；数字、引用标记 `[3]`、脚注标记不丢。
3. 长度不超过 `max_chars` 的 1.15 倍。
4. 再过一遍现有的 `review_translation_item`。

某一块不合格，**只有这一块**退回现在的单块流程重翻；整页的 JSON 解析不了，整页退回。agent 只写译文，**不改框、不改分类、不改翻不翻**。

### 接续段落

agent 看到同一接续组的几块和各自的 `max_chars`，**自己决定每个框放哪一部分**，代替现在按原文长度比例的机械拆分。这是一个明确能减少溢出的点。

### 放不下怎么办

1. **翻之前估上限**：把 `capacity.py` 这类估算挪到三个阶段都能用的底座包（`retainpdf-base`），渲染和翻译共用，算出每块的 `max_chars` 交给模型。大部分块一次就放得下。
2. **网页先缩字号**：覆盖层照现在的二分找字号。
3. **缩到下限还放不下才缩写**：
   - 前端把这些块报给后端（新接口，只加不改，放在 `/jobs` 的 translations 类下）；
   - 后端把这些块连同"现在放得下的字数"交回 agent 缩写，用 `revise_translation_item` 写回，原因记 `layout_overflow`。
   - 前端怎么报写进给前端的整理记录，由前端会话做。

先缩字号再缩写：能不改译文就不改。

### 图片和表格（后做，要看图）

- 表格：看清单元格结构，逐格翻，按格子放回。
- 图里的文字：要知道每段字在图上的位置，翻完画回图上。
- 前提：模型执行器的消息支持图片（Rust 的 `Message` 加内容分段，Python 请求体跟着改，缓存键和请求记录也要带上），按"只加不改"做。

## 怎么评测

- **离线**：假模型 + 录好的回答，测校验和退回逻辑（块编号对不上、公式丢了、超长、JSON 坏了）。
- **样例文档**：用 OCR 块分类查看器的 3 页复杂论文（`backend/pipeline/devtools/ocr_viewer/`）。要先写一个小工具把它的标准答案转成 `document.v1`，不跑 OCR 就能直接拿来翻译。
- **指标**：放不下的块占比（按容量估算，以后加浏览器实测）、公式保留率、块编号出错率、每页请求次数和用量（和现在比）。
- **真模型对比**：要用户另外授权（会花钱、会发请求），小范围跑几篇，和现在的流程并排看。

## 分步

| 步 | 做什么 | 改不改现在的翻译结果 |
|---|---|---|
| 1 | 容量估算挪到底座包；每块算 `max_chars` 记在条目上；统计现在的译文有多少超了 | 不改，只多记一个数 |
| 2 | agent 原型：输入输出格式、校验、退回；开关默认关，只用假模型测 | 不改（开关关着） |
| 3 | 接续组由 agent 分配各框的译文 | 开关打开时才改 |
| 4 | 放不下回报：后端接口 + 前端回报 + 缩写循环 | 只改放不下的块 |
| 5 | 真模型小范围对比（用户授权后） | — |
| 6 | 表格、图片翻译（补看图能力） | — |

每步一个分支；动到翻译包就跑 `run_translation_tests.py` 正反两遍；动接口就同一分支改文档、重新生成接口快照。

## 要定的

1. **一次送多少**：按页（推荐，章节太长再切），还是按章节？
2. **用哪个模型**：agent 一次看一整页，对模型的长上下文和 JSON 输出要求更高，要不要换模型或单独配。
3. **翻不翻谁说了算**：推荐规则（类别默认值 + 现有策略）说了算，agent 只能"建议"，不能自己决定跳过。
4. **放不下时**：推荐先缩字号、缩到下限才缩写；还是宁可缩写也保持字号统一？
5. **真模型对比**什么时候跑、用哪几篇。
