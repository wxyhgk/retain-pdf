# 编辑部事件接口（2026-10-30）

前端会话转来：用户要在书详情「进度」面板里看到翻译 agent（原话"可以,你让后端补"）。前端要两样，都只加不改：
翻译覆盖的任务带上翻译引擎；agent 跑的时候按 editorial.v1 写事件，给一个只读接口让前端增量取、翻完全量回放。

[编辑部可视化和事件格式](./20261030-编辑部可视化和事件格式.md) 当时没定事件从哪来、嵌在哪个页面，这里定下来。

## 定了什么

- **谁写**：翻译 agent 包的调度（`runner.py` 的 `DocumentRun`）和台账同时写 `events.jsonl`，在它的状态目录里。正式流程的状态目录是
  翻译目录下的 `agent/run/`，所以文件是 `<任务>/translated/agent/run/events.jsonl`。测试系统（agent_lab）也有这份文件。
  路径在 Python（`agent_flow.EDITORIAL_EVENTS_RELATIVE_PATH`）和 Rust（`storage_paths::AGENT_EDITORIAL_EVENTS_RELATIVE_PATH`）各写一次，
  `test_agent_flow` 钉着两边一样。
- **翻译、质检、重翻、退回原文**发生在 `TranslationAgent.translate_page` 里面，调度看不到。agent 加了一个出口 `on_event`：调度接上，
  agent 报事件，调度补上页号写进文件；agent 单独用（没接）时什么都不产出。请求体没变，缓存键、提示词版本都不变。
- **页号**：`page` 是这次跑的第几页（1 起），通读是 0；`page_started.label` 是页码标签。前端格式里 `page` 是数字，标签可能不是数字
  （"iv"），所以不用标签当页号。
- **续跑**：额度用完后重试接着往后写，再有一条 `run_started`（多了 `resumed`：已经做完的页数），做完的页不再出现。换了文档或引擎版本，
  状态目录整个清掉，事件文件也跟着重开。
- **接口**：`GET /api/v1/jobs/:job_id/progress/editorial?after=&limit=`，归 `progress` 类（跑到哪了）。按条数续读：`after` 是上次的
  `next_after`；正在写的最后一行不完整就先不给；坏行跳过但算条数，游标不错位；`next_after` 比请求的 `after` 小表示文件重开了。
  legacy 任务、还没开翻的任务回空列表。读权限和任务的其它读接口一样（`signed`）。契约放进 `job-events.v2`（同是进度事件）。
- **哪些任务有**：翻译覆盖的 `CoverageJobView` 加 `engine`（读请求的 `translation.engine`，老任务、纯 OCR 任务是 `legacy`）和
  `has_editorial_events`（事件文件在不在）。前端两种都能用：看 `has_editorial_events` 决定显不显示，对 legacy 任务调接口也只是空列表。
- **书名**：`run_started.doc_title` 是文档里第一个标题块的原文（规范化文档的 `title`）。书库里改过的书名在前端那边本来就有，用不用由前端定。
- **`check_result`**：初译后报一次（`attempt` 1），有重翻再报一次（`attempt` 2），都是整页各几块；前端按页卡片显示最近一次，不累加。
  审校按单改稿是程序做的，不另报质检，`page_done` 是最终状态。
- **`fallback.reason`**：退回原文那块第一个不合格的问题代码（如 `formula_changed`）。

## 没做

- 不接进任务事件流（`/progress/events`、SSE）：编辑部事件量大（每页十几条），混进去会挤掉阶段进度。前端轮询这个接口就够。
- 阅读器、任务列表不显示编辑部。只在书详情的「进度」面板、agent 任务上出现（前端定）。
