# 剩余错误怎么解决：多 Sonnet 讨论（2026-10-30）

用户："不用考虑费用的事情，剩下的错误，让多个 Sonnet 讨论一下怎么搞能解决"；又补充："目录部分我们得专门的 agent 去处理，因为目录会很麻烦"。

剩下的错误（见[译文质量问题和修法](./20261030-译文质量问题和修法.md)的盲评）：通读定错全书跟错（token 定成"令牌"）、词义逻辑错审校查不出（"should not be surprised if it does not"译反、
女性的 Luise Brandt 写成"他"、"good ruled paper"丢了"划线"）、漏译添加（"约""随机""会尽量"）、人称和语气漂移（we 译成"我"）、体例不一（94% 和"百分之四"、"图1.1"和"图 2.1"、
"注1"）、断点偶尔挪半句或落在引号中间、书目性质的脚注整条没翻。

## 怎么讨论的

第一轮五个 Sonnet 各看一个方向（只读代码和实测数据）：A 通读和术语、B 审校、C 初译、D 结构类（断点、体例、脚注）、E 目录 agent。
第二轮一个 Sonnet 当反方：核实五份的说法、合并去重、反驳、分版、列出要用户定的。我核实了涉及模型接口的说法（Claude API 参考资料）。

## 核实出来的关键事实

- **初译和审校都没有思考**：`agent.py` 写死强制工具调用（`tool_choice: tool`），实测思考 token 全是 0，模型一上来就往 JSON 里写译文。
- **新的强模型不支持强制工具调用**：Sonnet 5.5、Opus 5.5、Fable 5.1 用 `tool_choice` any / tool 返回 400，要改成 `auto` + 工具 `strict: true` + 提示词写明用哪个工具，没调工具就重问。
  这些模型也不能调温度（多候选只能靠不同模型或不同提示词）。思考用 `thinking: {type: "adaptive"}`，深浅用 `output_config.effort`。
- **审校 62 张单子拒了 44 张**，其中 43 张是"占位、无需修改、撤回"（改法和原文一字不差）——没有思考，只能边写单子边推理边撤回；收下的 18 张有一部分是润色。真错一个没抓到。
- **文风说明在制造错误**：通读写的"probably、it seems 要译出来：大概、看起来"让译者给"as one generally does"加了"大概"，审校还照这句加"大概"；"作者以 I 叙述，偶尔用 we"让几处 We 译成"我"；
  示范句被原样照抄；`reader.py` 把文风说明截在 600 字，示范句断在"译为"。文风说明和提示词规则打架（"注1"：说明写"脚注用注1"，规则 6 写"不要写成注1"）。
- **token 那条错的根子是行话知识**：通读的说明里写着"视觉编码后的 patch 单元，不是访问凭证"，却定成"令牌"（应为"词元"）；指标还把"令牌"算对了（指标的可接受译法要修）。
- **人名条目没有说明**：`context.py` 的人名条目不带性别，Brandt 的性别传不到译者。
- **断点基本够用**：18 个接续组模型自己放对 16 个，残留英文是引文没有统一政策（断点恰好落在引号中间）；程序切的组会出假警告（数字和术语逐块查）。
- **目录"一致"是样例太干净**：现有样例里目录条目都和正文标题原文一字不差；真实书籍的难点（措辞不同、缩写截短、无指向、罗马数字页码、跨页、图表目录、"第一章"体例、译文变长放不下）都还没处理。

## 合并后的做法

- **体例**：通读给一组固定选项（`conventions`：你/您、I、we、图 N、第 N 章、百分数、脚注前缀、中英文间空格、附录写法；默认按 GB/T 15834、15835），
  程序后处理 `typeset.py` 统一执行（跳过公式、脚注标记、行内代码、URL；幂等；数字不变；先在样例上看 diff），不再写进散文式文风说明，提示词规则去重、提示词只许变短。
- **先想后写**：所有角色的请求改成"自动工具调用 + strict + adaptive 思考 + effort"，检查 stop_reason，没调工具就重问——这是换强模型的前提。
- **审校**：逐句对读出表（每句 ok / problem 加理由），只有 problem 才许开单；回译只在修订裁判里用（另起一次请求、不给原文），同一请求里的回译会被原文带偏。
- **人名**：术语表加性别、说明、证据句；程序先在人名出现处前后两句数 she/her/Mrs 和 he/his/Mr 给通读作提示；女名同块出现"他"且原文无 he 记警告。
- **通读拆三个请求**：元信息（体裁、人名规则、体例选项、3–5 句文风，不写词映射和示范句，人称写死 I→我、we→我们）；分章术语专员（强模型）；标题（术语定稿后、剥掉编号前缀只译正文再拼回）。
  分歧词用两个不同模型各自定，不一致由最强模型裁决（不用调温度投票）。
- **目录**：新包 `retainpdf-toc-agent`，负责目录的解析、和正文标题对齐、译法、体例、校验；翻译包只把它定的标题和目录译文当"已定好的译文"。

反方否掉或推后的：术语人工确认先只出文件不阻塞（改状态机和前端代价大）；翻译中回改术语（术语庭）推后；按风险特征路由深审不做（费用不计，全审），代词、否定、限定词对账改成程序警告和指标；
多候选推后（不同模型混用会让文风忽强忽弱）；脚注分段格式推后，先用程序检查整条英文重翻；目录一次做满推后，先做程序层。

## 用户定的（10-30）

1. **模型先对照实测再定**：审校和术语专员用 Opus 5.5，修订和目录用 Sonnet 5.5；初译先跑四臂对照（Haiku / Haiku+思考 / Sonnet 5.5+思考 / Opus 5.5+思考），
   哪个最好用哪个；慢一点可以。
2. **英文引文译成中文**：日记、批注、书信里的英文照常翻；法文、德文等外文引文仍保留原文；作者当作"词"讨论的词首次写"中文（原文）"。
3. **模型自加的英文括注可以由程序删**：只删小写普通词、不在术语表和人名里的；缩写、人名、术语首次出现的括注保留；每处记录可查。
4. **标题和目录的译法归目录 agent**：目录 agent 负责标题和目录条目的译法、对齐、体例；翻译 agent 只把它定的当"已定好的译文"。先做目录 agent 的程序层。

评测按反方建议：评委不用和翻译同一族的模型（用 Opus 评），另造 2 份新样例当留出集；术语表人工确认先只出文件、不阻塞；书目串不加《中文题名》。

## 用户后来改的决定（10-30）："以后全部用 haiku 就行了，测试的使用 haiku，不然我们扛不起"

**所有角色、所有实测都只用 `claude-haiku-5-5`**，上面"模型先对照实测再定"作废。分版跟着改：

- 第 2 版不换模型：只把请求改成让 Haiku 能思考（自动工具调用 + strict + adaptive 思考，按角色调 effort），四臂对照改成 Haiku 内部对照：
  不思考 / 思考 effort medium / 思考 effort high。
- 审校、修订、术语专员、目录 agent 都用 Haiku。审校靠思考、逐句对读和不同的提示词来和初译拉开，不靠换模型；
  回译裁判仍另起一次请求、不给原文。
- 第 3 版的"分歧词两个模型各自定"改成同一个 Haiku 用两种不同提示词各自定，不一致的进术语人工确认文件。

## 不是所有角色都思考（用户 10-30："不能所有角色都思考啊，不然我感觉会很慢吧"）

只在值得的地方思考，大部分请求保持现在的速度：

| 角色 | 思考 | 理由 |
|---|---|---|
| 初译 | 不思考 | 量最大；现在绝大多数块一次就合格 |
| 重翻没过的块 | 思考 | 量少 |
| 程序标出的高风险块 | 思考，只重看这几块 | 程序先对账代词（her ↔ 他）、否定（not ↔ 不/没）、数字、限定词（only、most、约），对不上的才复查 |
| 审校 | 思考，effort low–medium | 不想抓不到逻辑错；每页一次，和下一页的初译并行，不拖总时间 |
| 通读 | 思考 | 一本书一次，定错全书跟错 |
| 目录 agent | 不思考 | 主要靠程序对齐 |

第 2 版的对照同时量质量和耗时：现状 / 只审校思考 / 审校 + 高风险块思考，看每种多花多少时间、多改对几处。调度要支持审校和下一页初译并行。
