# 接续组跨独立公式：公式放进整段，切在公式处

2026-10-31，看普通翻译（legacy）最近三个任务时发现，用户同意按此做。两个引擎都改（接续组的拼接、切分两边各有一份）。

## 现象

legacy 三个任务（Jensen 第 12 章 41 页、Geometry optimization 20 页、量子化学-14 34 页，claude-haiku-5-5）没有退回原文、
漏标记、`$` 不成对的块，问题集中在接续组：

| 任务 | 块 | 现象 |
|---|---|---|
| 量子化学-14 | p003-b022 / p004-b004 | 原文 "whose $ x $ component is [独立公式] with similar expressions"。模型看不到公式，自己编了 `$ \mu_x = \sum_i q_i x_i $` 写进正文（原式 `\mu_{x,cl}=\sum Q_i x_i`），页面上一个公式出现两次 |
| 量子化学-14 | p002-b013 / p003-b002 | 公式后面的 "where φ is the spatial factor" 被按比例切到公式前面那块，读起来顺序反了 |
| 量子化学-14 | p029-b019 / p030-b004 | 模型把后半句的行内公式当成中间那个公式写成多行 `$$`，切点落在 `$$\n\` 后面，两块都渲染坏 |
| Jensen 第 12 章 | p035-b008 / p036-b002 | `。$^{55}$` 被切到下一页那块开头 |

量子化学-14 的 17 个接续组有 10 个两块之间夹着独立公式块，Geometry optimization 22 个里有 2 个。

## 原因

- 拼组只把两块原文用空格连起来，中间的公式块不在里面。
- legacy 切分认公式的正则不跨行，多行 `$$…$$` 没被当成一个整体。
- legacy 切分不认句末角标；agent 那边 2026-10-31 修过（`breaks.TRAILING_MARKS_RE`），legacy 没有。

## 改法

- 两块之间（阅读顺序）夹着的独立公式块，原文写成 `$$ … $$` 单独一行放在两块中间（`core/payload/parts/formula_gaps.py`，
  legacy 在 `pending_translation_items` 里算、记在成员的 `translation_unit_formula_before`；agent 由 `agent_flow` 填 `BlockInput.formula_before`）。
  只在公式直写（direct_typst）时放：占位符模式的公式是 `<f1-abc/>`。
- 提示：legacy 只在原文里有 `$$` 时给这块的请求加一句（`DISPLAY_FORMULA_IN_TEXT_HINT`），别的块请求不变、缓存照用；
  agent 写进系统提示第 5 条（`translation-agent-16`）。
- 切回各块：先在译文里找这几个公式（按内容，空白不算，`$$` 写成 `$` 也认；内容改过但独立公式个数对得上就按位置），
  在公式处切开、公式删掉（它在版面上单独一块），公式后面那段开头的标点删掉；公式之间夹着几块的再按比例切。
  认不出就删掉独立公式、整段按比例切。
- legacy 切分：`$$…$$` 当一个记号；原文各块都没有 `$$`、译文却写成独立公式的改回行内 `$…$`；句末标点后面紧跟的角标跟着前一句。
- agent：`$$…$$` 在检查和切分里都当一个公式（`translation-agent-checks-7`）。

没选新造一种占位符：要动整套受保护记号（`<[futnvc]N-xxx/>`，渲染也认），而且模型看到公式原文才知道 "where φ is" 说的是哪个式子。

## 顺带

每个 legacy 任务开头都有 4—9 个请求因为带了 `temperature` 先挨 400（`` `temperature` is deprecated for this model``）再重发：
进程里会记住，但开头几路请求是同时发的。文档写明不收 temperature 的 Claude 模型（Opus 5.5 / 5、Fable 5 / 5.1、Opus 4.8 / 4.7、
Haiku 5.5）现在一开始就不带（`model_wire._NO_TEMPERATURE_MODEL_RE`），别的模型照旧挨一次再记住。

## 验证

- 离线：三个任务的 payload 重算，量子化学-14 认出 10 组、Geometry optimization 2 组、Jensen 0 组，和人工统计一致。
- 单测：legacy `test_group_split_formula_gaps.py`、agent `test_translation_agent.py` 新加的三条、`test_model_protocol.py` 预先不带 temperature。
- 付费重跑量子化学-14（legacy，claude-haiku-5-5，没变的块走共用缓存，112 次请求成功、4 次 429 重试后成功、没有一次因为
  temperature 挨 400）：10 组都切在公式处，没有编出来的公式，`where` 子句留在公式后面那块，p029-b019 / p030-b004 不再被 `$$` 切坏；
  旧版本里几组残留的英文半句（p017-b028 "which was verified"、p018-b002 "for the ground state in"、p021-b019 "and 式 (14.93)"）也没了。
  整本 `$` 不成对 0、正文里漏出 `$$` 从 2 到 0、公式外露从 1 到 0。
- 重跑里两处和这次改动无关的模型失误：p003-b022 开头留了一个英文 "where"（这块在组头，前面不夹公式）；p014-b022
  "which has the same form as Eq. (8.94)." 模型交回原文被当成保留原文（旧版本译了）。legacy 对普通英文句子原样交回不重翻，
  agent 那边会判 untranslated 重翻，另做。
