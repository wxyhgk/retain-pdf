# 翻译 agent 第 1 版：术语记忆、上下文包、台账和长样例（2026-10-30）

按[多角色、多轮翻译与记忆系统](./20261029-多角色多轮翻译与记忆系统.md)的分版，第 1 版打地基。用户 10-30 说"合"后开工。

## 做什么

| 部分 | 内容 |
|---|---|
| 术语表 `memory.py` | 每条：原文、译法、类别（术语 / 保留原文 / 缩写）、作用域（全书或某几章）、状态（候选 / 审定 / 锁定）、首次出处（页、原句）。表有版本号，每次变动升版本、记原因，旧版本存成不改的快照。译者每页报上自己定的译法（候选），**同一译法出现两次、没有别的译法和它争**才升成审定；两种译法打架记一张"歧义单"，不自动统一（等第 3 版的术语专员或人）。用户给的术语是锁定。缩写由程序抓"全称 (ABBR)"句式 |
| 上下文包 `context.py` | 每页固定预算（默认约 7000 token），分几块：风格说明、本页出现的术语、保留原文、缩写、上一页结尾和下一页开头、章节摘要（调用方给，第 3 版才有通读员写）。超了按 术语 > 缩写 > 保留原文 > 相邻页 > 摘要 的顺序截。包的内容哈希记进台账 |
| 术语检查 | 审定、锁定的术语（译者报出来升审定的只管报过它的章，见下面实测）在块的原文里出现，译文就得用定好的译法；保留原文的词得原样出现。不符是错误，重翻时告诉模型。真是同词异义时，模型可以在交卷时声明"这里不用这个译法"并写理由，不算错，记一张歧义单 |
| 语气检查 | 原文有 may、might、suggest、appear、likely、perhaps 这类词，译文里得有可能、或许、似乎、表明之类；原文用 we，译文里得有"我们"。只记成"提示"（info），不影响状态，用来算指标 |
| 调度 `runner.py` | 整篇按页顺序翻：每页建上下文包 → 翻 → 更新术语表 → 写这一页的结果、台账、进度。中断后接着跑，已经做完的页不再请求。额度用完、密钥失效、一直限流时停下，保留进度 |
| 台账 | `ledger.jsonl` 只追加：每次请求一行（页、角色、模型、提示词版本、术语表版本、上下文包哈希、token、耗时、是否走缓存、结果），术语表每次变动一行 |
| 交接格式（只加字段） | `PageInput.context`、`PageInput.chapter`；`BlockResult.meta`（模型、提示词版本、交接格式版本、角色、轮次、术语表版本、`used_terms`、上下文包哈希）；状态加 `fallback_source`：重翻后还不合格就不交译文，保留原文、待人看 |
| 按角色选模型 | `TranslationAgent(models={"reviser": ...})`，没写的角色用默认模型 |
| 限流和停 | 429、5xx 按 `Retry-After` 等，指数退避加抖动；401、403 和额度用完直接停（`StopRun`），调度保存进度后退出 |
| 长样例 | 测试系统加一本 21 页（A5）的人造小书：前言（口语、第一人称）+ 7 章（文风各不同）+ 每章参考文献。埋的坑：跨章同一术语、同词异义（kernel 在模型一章是"卷积核"、在系统一章是"内核"；token 是"词元"还是"令牌"）、缩写先定义后使用、同一人和工具的多种写法、跨章引用（见图 2.1）、期刊名和人名保留原文、措辞很保留的讨论、后面才出现的更正 |
| 指标 | 术语一致率（章内、跨章）、同词异义按章正确率、保留原文正确率、缩写首次括注率、语气词保留率、人称保留率、每页 token、请求数。开记忆和不开记忆各跑一遍对比 |

## 不做（留给后面几版）

审校和修订（第 2 版）；通读员、术语专员、章节摘要由模型写（第 3 版）；译文记忆、关系表（第 4 版）；看原文（第 5 版）。

## 实测（Haiku 5.5，长样例 21 页、121 块要翻）

第一轮（提示词 `translation-agent-8`）带记忆**反而变差**：

- 译者报上来的 token = 词元 在第 2 章报了两次，升成审定、全书必须照用；第 3 章的 access token 被校验逼着改成"访问词元"，
  不带记忆时这几处都译对了（"访问令牌"）；有一块两次都按"令牌"译，被判不合格退回了原文。
- 一个跨页段落的断点落在英文从句中间（"the one I | wish someone had handed me"），中文语序倒过来，两次都没放断点，整段退回原文。
- 术语表里混进标题、书名、带括号缩写的条目（"光学字符识别（OCR）"）。

改了五处（提示词升到 `translation-agent-9`）：

1. 译者报上来升成审定的术语**只管报过它的章**，在两章里都这样用了才全书必须照用；别的章只作参考（显示成候选）。
   用户给的（锁定）照旧全书必须照用。
2. 校验先在包里全部条目里按最长匹配找，候选的 "access token" 盖住的 "token" 不查。
3. 重翻后只剩术语没照用（或保留原文、缩写首次没括注）：译文本身没坏，降成警告保留译文、交给术语专员或人，不退回原文。
   公式、标记丢了这类真错照旧退回原文。
4. 接续组断点两次都没放对：整段放进第一块，其余块留空、标警告，内容不丢；提示词加"放不到对应位置就放最近的分句边界"。
5. 报上来的术语去掉括号里的缩写，已登记的缩写不再记；提示词说明不报标题、书名、缩写。

另加一条检查：全书第一次用到的缩写（上下文包标了 `first_use`），这一页第一个用到它的块要写成"中文全称（缩写）"，不符合就重翻。

第二轮以后（同一个提示词，带记忆和不带记忆各跑一遍）：

| 指标 | 带记忆 | 不带记忆 |
|---|---|---|
| 术语一致率 | 98.2% | 92.9% |
| 同词异义按章正确率（kernel、token 在第 2、3 章） | 100% | 100% |
| 保留原文正确率 | 100% | 100% |
| 缩写首次括注率 | 100%（加了首次检查后；之前 50%） | 50% |
| 语气词保留率 | 92.9% | 85.7% |
| 人称保留率 | 96.7% | 93.3% |
| 跨章引用正确率 | 100% | 100% |
| 合格 / 退回原文 | 120 + 1 警告 / 0 | 120 + 1 警告 / 0 |
| 请求、输入 token | 22 次、约 9.8 万 | 22 次、约 8.6 万 |

结论：

- 这本样例对 Haiku 偏容易，不带记忆也大多一致，所以差距不大；记忆的好处主要在术语一致和缩写，代价是输入 token 多 8%–13%。
- **自动定下的术语强制全书照用是危险的**（第一轮的教训），所以按章约束；真正要全书照用的应该是用户给的或术语专员审过的（第 3 版）。
- 下一步要更难的样例（更长、术语更多、真的会翻乱的），以及多跑几次看波动。

## 4 份新样例（用户 10-30："让 Sonnet 再去多造几个 pdf，最好 5 页以上"）

4 个 Sonnet 各写一份，都在 `backend/pipeline/devtools/agent_lab/`，登记在测试系统的样例表里（`--sample <名字>`），各带离线测试：

| 样例 | 页数、块数 | 埋的坑 |
|---|---|---|
| `conference` 会议论文 | A4 双栏 7 页、194 块 | 段落跨栏又跨页、图表浮动到引用之后的页、通栏大表、两张子图共用图注、两段伪代码、带编号的行间公式和 Eq. (3) 引用、参考文献跨栏跨页且有一条被拆开、附录编号 A.1 |
| `textbook` 教科书一章 | B5 8 页、114 块 | 奇偶页镜像的页边注、例题跨页且中间夹浮动图、习题 3.1–3.12 跨页、定义定理例题编号、92 处行内公式、术语首次加粗 |
| `manual` 技术手册 | A4 8 页、181 块 | 约 65 处行内代码、目录页码要和标题实际页一致、参数表跨页重复表头、嵌套步骤列表、代码块和题注、跟着代码块或表的警告框、正文里像警告框的 Note 段落 |
| `essay` 人文期刊文章 | Letter 8 页、108 块 | 27 条脚注（每页 2–4 条，一条跨页接续）、题记、法文德文整块引文（标了语言）、罗马数字小节、长句在页边断开、书名人名保留 |

接这些样例时补的：

- 行内代码登记进分类（`inline_code`，不翻），交给 agent 时用反引号包住，校验要求原样保留（提示词 `translation-agent-10`）。
- 页边注的位置描述写成"页边"（原来按坐标会写成左栏、右栏）。

Haiku 5.5 实测（带记忆）第一遍暴露三处校验太死，译文本身没错却被退回原文：

1. 译文把原文已有的公式多提一次（"当 $b$ 为 0.002 时"）被判"公式变了"——原文已有的公式多出现不算错，原文没有的才算。
2. 行内代码里的 `$` 提示符被当成公式的半个美元符号——先去掉行内代码再查公式。
3. 中文语序把脚注标记挪过了接续组的断点，按块查是"丢了"——公式、引用、脚注标记、行内代码按整组合起来查，整组还在就只记警告（`mark_moved`）。

另外"英文残留"不再数书名号、引号、括号里的词和大写开头的专名（人文文章的脚注大量保留原文书名人名，是对的）。

改完后：

| 样例 | 要翻的块 | 合格 | 警告 | 退回原文 | 重翻过 | 请求 | 输入 / 输出 token |
|---|---|---|---|---|---|---|---|
| conference | 110 | 110 | 0 | 0 | 4 | 9 | 7.1 万 / 1.3 万 |
| textbook | 81 | 80 | 1 | 0 | 0 | 8 | 4.3 万 / 0.8 万 |
| manual | 137 | 137 | 0 | 0 | 1 | 9 | 5.2 万 / 0.8 万 |
| essay | 64 | 58 | 6 | 0 | 13 | 13 | 8.5 万 / 1.6 万 |

人文文章重翻多：6 块是长句在页中间断开、模型没放断点（重翻后大多放对，两组放不对走"整段放进第一块"），4 块是一页上的短脚注漏交（重翻补齐）。
文学类长句的断点是这套做法在这类文本上的主要额外开销，以后可以考虑在重翻时把断点前后的原词直接告诉模型。
