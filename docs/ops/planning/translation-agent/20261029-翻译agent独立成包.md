# 翻译 agent 独立成包（2026-10-29）

用户：翻译部分只管翻译 agent，要持续优化，先建一个包；以后重排部分再建一个 agent，两边打配合。包名用户定：
`retainpdf-translation-agent`（这一步）和 `retainpdf-layout-agent`（以后）。

## 包

`backend/translation-agent/`（`retainpdf_translation_agent`），说明见包里的 README。

- **交接格式** `contract.py`（`translation_agent.v1`，只加不改）：`PageInput`（一页的块）→ `BlockResult`（每块的译文、校验问题、请求次数、状态）；
  `RevisionRequest`（重排 agent 发来的改稿要求：哪块、现在的译文、原因、最多显示多少字）。
- **翻译** `translate_page`：测试系统里调好的那套搬过来（一页一次、工具调用交回、必交编号清单、接续组 `[[BREAK]]`、不合格合并重翻）。
- **改稿** `revise`（新）：只改列出的块，同页其它块作上下文；替模型算好现在多少字、至少删多少（模型自己数不准）；
  字数按显示算（脚注标记算 1 个字，公式按源码一半）；还超就再改一次；要求缩短时不再按"太短"报错。
- **只用标准库**（调模型用 `urllib`），测试钉着：翻译、重排、正式流程哪一边都能放心装。
- 测试 11 个（假模型）；测试系统 `devtools/agent_lab/` 改成调这个包。

## 实测（Haiku 5.5）

- 整份样例通过包跑：41/41 一次合格，3 次请求。
- 改稿 5 块（上限是现在字数的 50%–90%）：4 块达标（41→20、151→83、26→13、55→49），摘要 154 字要求 ≤107 只改到 121。
  信息密的段落砍三成以上，不丢内容做不到——这种情况交给重排 agent 改用缩字号。
- 改稿规则（用户待确认）：先精简措辞，还超就删次要的修饰语和举例，核心意思、公式、标记、编号必须保留。

## 和重排 agent 怎么配合（下一步）

重排 agent 量出放不下的块 → 先缩字号 → 缩到下限还放不下才发 `RevisionRequest`（附能放下的字数）→ 翻译 agent `revise` →
达标就用新译文，没达标（`still_too_long`）就保留较短的那版、再缩字号。缩短幅度太大的（比如超过三成）应先考虑版面办法。
