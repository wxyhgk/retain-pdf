# 接续组当一块翻

2026-10-31。用户："此外还得考虑一下跨栏跨页部分如何更优雅"；看了方案后："可以，按这个方案做"。

## 以前的问题

跨栏、跨页拆开的同一段话（接续组）一路分三段：OCR 和规则认出是同一段 → 模型整段翻 → 程序按原文比例在标点处切回各块。
问题在切开以后，各块被当成互不相干的块：

- **逐块校验**：中文语序会把内容挪过切点，一块"太短"、脚注标记"丢了"。为此加了一串补丁：整组不短的"太短"降成 `group_share` 警告、
  整组里还在的标记降成 `mark_moved` 警告、占比偏了记 `group_share`、相邻两块重复记 `group_overlap`（还得排除原文本来就重复的话）。
  这几次修的跨页问题，大半是在修这些补丁。
- **逐块退回原文**：一组里一块判错就只退回那一块，一段话前半中文、后半英文。
- 渲染阶段有一套按框容量切整段的代码（`render/layout/payload/prepare.py`、`continuation_split.py`），但各块已有译文时就跳过，
  两种翻译流程都写各块译文，所以一直没用上；阅读器实时译文也是逐块显示。

## 做法

- 新模块 `units.py`：`merge_groups` 把这一页要翻的接续组各合成一块（id 用组号、原文接成一整段、位置放在组里第一块、`members` 记原来的各块），
  组里只有一块要翻的当普通块；`split_units` 把合成那块的结果按原文正文比例切回各块（还是 `breaks.split_by_ratio`，不切开公式和标记），
  问题、状态、历史各块照抄整段的，`meta.unit_id` 记组号；整组退回原文时各块都退回。
- `TranslationAgent.translate_units` 翻合好的页：合成那块就是普通的一块，校验、重翻、挽救、退回原文都按整段；不合格的块（含合成的）合成一次请求重翻。
  `translate_page` 照旧对外（合 → 翻 → 切），调度 `DocumentRun` 分开调，**审校在切开以前**，审校看到的是整段。
- 编辑部事件照旧报原来各块的 id、按块数算（`translate_call`、`retry` 的 blocks 展开成各块，整组退回原文每块一条 `fallback`），前端不用改。
- 删掉：`check_group`（`group_overlap`、`group_share`）、`_apply_group_checks`、`_forgive_moved_marks`（`mark_moved`、太短降警告）、
  按组分开重翻、`expand_translations` 里的切分（改成 `clean_translations`，只去空白和老习惯的 `[[BREAK]]`）。
- 交接格式只加字段：`BlockInput.members`（agent 内部填）、`BlockResult.meta.unit_id`。请求里合成那块的记录和以前一样（`members`、接起来的 `text`）。
- `CHECKS_VERSION` 升到 5；提示词不变。

## 没做

- 不启用渲染那套按框容量切：两个框的容量比基本就是原文长度比，启用了 PDF 和阅读器切得会不一样。以后要改切法，只改 `split_units` 一处。
- 阅读器里鼠标停在一组的一半时另一半一起高亮——前端的事，可以另提。
