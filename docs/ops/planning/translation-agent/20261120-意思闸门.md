# 意思闸门

2026-11-20。第二批的另一半（前一半是跨节记忆）。

## 起因

按节翻之后，程序只查标记、数字、长度，漏一个分句、多一句评价、推测语气丢了都查不出；审校整节通读，输入 token 是节译的 1.7 倍，
Haiku 对细的语气错只抓到约三分之一（Sonnet 审读的第 1、13 条）。原来的想法：程序先筛可疑段，译者也能报「拿不准」，审校只看这些段。

## 做了什么

- `checks.meaning_flags`：按个数比，原文的推测词（perhaps、probably、seem、I suspect……）、否定（not、never、n't……）、句子比译文多就标，
  数字找不到也标；`checks.short_outliers`：一节里「汉字数 / 英文词数」低于中位数七成的段标「可能漏了句子」。
- 节译者可以附「@@ 拿不准」（每行「¶编号 原因」），`split_tail` 解析。
- `section.section_flags` 把三种标记合起来；`review_page` 加 `hints`（照审全部，带标记的段附上提示）和 `only`（只审带标记的段，
  一段都没有就不发请求）；审校提示词加「逐条核对 flags」。
- 按节翻默认用 `hints`。版本 `agent-section-7`、`translation-agent-21`。

## 埋错评测（Haiku，第 60–100 页那次的译文，40 段，10 段埋错）

5 类各 2 处：删推测词、删否定、改数字、删一句、加一句原文没有的评价。每种审法跑 3 次：

| 审法 | 抓到（共 10） | 误改 | 审校输入 token |
|---|---|---|---|
| A 整页全审（原来的提示词） | 2、4、0 | 0 | 约 2 万 |
| A 整页全审（加了「逐条核对」） | 4、3、4 | 1、0、0 | 约 2 万 |
| B 只审带标记的段 | 2、2、2 | 0 | 约 5,500 |
| C 整页全审 + 标记当提示 | 4、3、3 | 1、0、0 | 约 2 万 |

- 程序标记只标出 4 处（第一版按「有没有」、第二版按个数比都一样）：一段里删掉一个「不」，「不仅」「无论」之类把否定词个数撑高了，查不出；
  推测词同理。
- 只审带标记的段，上限就是那 4 处，审校又只改了一半；整页审抓得多，标记当提示没多抓。
- Haiku 当审校的上限大约是 10 处抓 3–4 处，怎么提示都差不多。

所以默认整页照审、标记当提示（花费不变），「只审带标记的段」留着给以后换更强的审校模型时用。

## 下一步要用户定

审校换更强的模型：按价格表 Sonnet 5.5 每百万输入 2 美元，是 Haiku 的 20 倍；《The Interloper》审校输入约 27.5 万 token，
整本全审约 5 元，只审带标记的段约 1.5 元（全书翻译本身约 1 元）。先拿同一组埋错样例试一次，再定。
