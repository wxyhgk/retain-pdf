# 书页区和右边一个停靠位

2026-11-27。重新设计阅读页外壳的第一步。

## 为什么

用户贴来一份阅读页重新设计的意见（三区工作台：左导航、中间书页、右边学习工作台）。对着代码看，其中三条是真的：

1. **右边两套停靠互相压。** Markdown 面板（`ReaderAssistantDock`，宽 `--reader-ai-split-width`）和贴右边的提问窗（`AskWindow` 自己用
   react-rnd 摆，靠贡献表 `reserveRight` 让书页）都从 `right: 0` 往左排。书页按宽的那个让，两个面板却叠在一起。
2. **开着面板就把对照砍成单栏原文。** `pane-composition.ts` 里 `assistantOpen && mode === "compare" ? "source"`（11-03 删 AI 时留下的），
   `ReaderCompareGrid` 的 `resolveReaderGridPresentation` 里还有一份。宽屏上右边开个 Markdown，书页那边也只剩一栏。
3. **位置靠 `position: fixed` 加视口算式互相躲。** 滚动壳、底栏、小球、两条提示各自写一条 `calc((100dvw - 面板宽) / 2)`，
   加了提问窗贴右边以后每条又多一份 `max(面板宽, 提问窗宽)`。再加一个左栏或别的面板，就得全部重写。

意见里另外几条和用户以前定的冲突，这一步不动：入口挪回顶栏、去掉小球（11-20 用户定的「顶栏只留目录、模式、下载、关闭」）；
右边做成停靠的学习工作台（11-25 用户定白板、笔记是浮窗）；悬停块上出「提问」（读书时选字、悬停都不弹东西）。
左栏收拢目录、搜索、书签、待处理，等这一步做完再看。

用户 11-27 说「开始做」，做的是下面三件，不动任何入口的位置。

## 做了什么

### 书页区（`.reader-stage`）

`ReaderAppReactPdf` 里多一层 `<div className="reader-stage">`，装滚动壳（`ReaderCompareGrid`）、底栏（`ReaderZoomHud`）、小球（`ReaderToolBall`）：

```
.reader-react-root { --reader-stage-right: 0px; }
.reader-react-root.is-assistant-open { --reader-stage-right: var(--reader-ai-split-width); }   /* 停着面板 */
.reader-react-root[data-right-inset] { --reader-stage-right: var(--reader-right-inset); }     /* 扩展贴右边 */
.reader-stage { position: absolute; inset: 60px var(--reader-stage-right) 0 0; }
```

滚动壳 `inset: 0` 铺满书页区；底栏、小球改成 `position: absolute`，按书页区居中、靠右下，不再各自减面板宽。
书页区不设 `z-index`、不裁剪，里面各块的层级照旧和根节点下的别的浮层比，底栏、小球弹出来的东西不被裁。
两条提示（加载失败、可选产物失败）是启动层画的、在书页区外，仍是 `fixed`，按 `--reader-stage-right` 居中、收宽度。
以后左边加栏，只改 `.reader-stage` 的 `inset` 和一个 `--reader-stage-left`。

窄屏（< 900px）面板铺满时照旧只藏滚动壳和底栏，小球留着（它在书页区里，书页区右边让到面板那么宽，位置和以前一样）。

### 右边只停一个，后来的留下

- 扩展贴右边（`reserveRight` 从 0 变成正数）时，阅读页关掉停着的面板：`useRightDockSlot`（`app/use-reader-extension-host.ts`）。
- 面板后开（`activePanel` 从 null 变成有）时，扩展自己挪开：提问窗多一个通用的 `dockTaken` 属性（`@retainpdf/ask`），
  变成 true 的那一下贴右边的窗口变回浮动，记住的摆法不改（下次打开照旧贴右边，再按「后来的留下」把面板关掉）。
- 两边都只看「刚变」的那一下：自己刚贴右边、宿主正要关面板的那一帧，`dockTaken` 还是 true，不能把自己挪走。

贡献表要在排台面之前知道 `reserveRight`，所以 `useReaderExtensionHost` 拆出 `useReaderContributionTable`（表和 `reserveRight`），
先调它，再排台面，再给扩展建接口。

### 对照按宽度收

`resolveReaderPaneComposition` 的输入加 `compareFits`；阅读页按 `compareFitsStage(书页区宽, 右边停着东西)` 算：右边停着东西、书页区不到
`COMPARE_MIN_STAGE_PX`（720，每栏 360）才收成单栏原文。右边没停东西时不在这里收（窄屏对照原来就不收）；宽度还没量出来时不收，免得闪一帧单栏。
`resolveReaderGridPresentation` 不再因为 `markdownSplit` 自己收栏，照 `paneComposition` 排。

页宽基准跟着改：单栏读时右边停着东西（面板或提问窗贴右边）按两倍书页区算，50% 正好铺满剩下的那一栏（Markdown 原来就是这样，
提问窗贴右边以前没有，书页只占书页区一半）；对照时按书页区算，50% 是一栏。

顺手：浏览器窗口变小时，浮动的提问窗挪回屏幕里（不改记住的位置）。
