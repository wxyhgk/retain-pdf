# HTML 页照排版引擎的结果画：后端要做的

2026-11-28。接着 [HTML 页](./20261128-HTML页.md)。

## 为什么要后端出东西

第一版 HTML 页用 OCR 的框和阅读页已有的块数据，在原文页上用 HTML 画字。用户问：

> 为什么这里的 html 渲染和我们自己的 html 排版不一样？能不能一样？

不一样的原因：第一版借的是「边翻译边看」那层的简易塞字。它每块单独二分找字号、让浏览器换行、用原始 OCR 框、字体看本机装了什么。我们的排版引擎 `retain-pdf-rendering`（`backend/rendering-engine`，译文 PDF 就是它排的）不是这样：

- 全书正文字号统一定；
- 按思源宋体的字宽表逐字算换行，带中文禁则和两端对齐；
- 避开矢量图形，平衡跨页、跨栏续段；
- 公式用 MathJax 3.2.1。

要一样，用户同意走这条：**前端照引擎排好的结果画**。引擎每次排完写一份 `layout.json`（`rpr_layout_v1`），译文 PDF 就是从这份文件画出来的（`src/output/pdf/layout.js`："The PDF is written from this file only"）。文件里有：

- 每页要盖掉原字的块（`covers`，含填色）；
- 每块的字号、粗细、颜色；
- 每一行每个字簇的 x 和基线；
- 每个公式的 LaTeX 和盒子（`w/h/d`，按字号的 em 算）。

前端拿原文页做底，先画白块，再把字簇摆到坐标上，字体和公式用同一份。这样画出来就是译文 PDF 本身，而每个字都是可以加动效的 DOM。

以后若要实时重排（改一句译文马上重排、动画重排），再考虑把引擎放进浏览器里跑（引擎是不依赖宿主的写法，字宽表是确定的数据），这次不做。

## 现状（本地看到的）

- `layout.json` 只在引擎的输出目录里：`data/jobs/<任务>/rendered/typst/rpr-fit-engine/out/layout.json`，旁边是 `overlay.pdf`、`report.json`。
  - 不是任务产物，没有接口。
  - 不是每个任务都有：`20261119144813-c8bcf5` 有；`20261124051239-e2c0a1`（VP ≠ VNP Over Every Field）的 `rendered/typst/` 下只有 `background-book`，没有。
- 公式 SVG：`MathStore` 每个公式用 MathJax 画一次（按内容哈希）。PDF 输出时只在内存里用 `entry.svg`，没落盘（输出目录里没有 `math/`）。
- `layout.json` 里的块 id 形如 `p001-b0014`，看起来和阅读页 `/reader/regions` 的 `item_id` 是同一套，**要确认**。
- 字簇只有 `t`，有的带 `mode: "dflt"`（只有标点、数字的一段，按西文整形），没写用哪个字体文件。前端不知道该用思源宋体还是后备字体。

## 要后端做的（按优先级）

### 1. 把 `layout.json` 存成任务产物，从接口给出（必须）

- 每次走引擎排版（`render.engine = "rpr_fit"`，输出 PDF 或 Typst 都算）都把 `layout.json` 存成任务产物（经 `stored_path(任务, data_root, StoredFile::…)` 读，不要别处拼路径）。
  - 一起记下：`schema`、引擎提交号（`UPSTREAM` 的 commit）、对应的译文 PDF 是哪一份。
- 接口（`/jobs` 的「阅读」类，`by(web)`）：
  - `GET /api/v1/jobs/:job_id/reader/layout`：清单。
    ```json
    { "schema": "rpr_layout_v1", "engine_commit": "417a441…", "available": true,
      "page_count": 70,
      "pages": [{ "index": 0, "width": 612, "height": 792, "etag": "…" }],
      "fonts": [{ "key": "serif-regular", "family": "Source Han Serif SC", "weight": 400, "url": "…" }] }
    ```
    没有时给 `available: false` 和原因（`not_engine_route` / `not_kept` / `job_too_old`），不要 404 当错误。
  - `GET /api/v1/jobs/:job_id/reader/layout/pages/:index`：一页，结构照 `rpr_layout_v1` 里的一页（`{ index, width, height, covers, blocks }`），带 ETag。
    - 一本书的整份 `layout.json` 有几百 KB 到几 MB（`c8bcf5` 10 页 526 KB），前端按页取。
- 契约写进 `docs/api/12-阅读`，前端用的类型放 `contracts/`（照现有做法生成）。

### 2. 老任务补出 `layout.json`（必须）

不重新翻译、不花模型的钱，只重跑排版，把 `layout.json` 补出来。可以是现有「重新渲染」的一种，或单独的阶段操作，后端定。前端在 `available: false` 且能补时给一个「生成 HTML 排版」的按钮。

### 3. 字体（必须）

- 前端要和引擎用**同一份字体文件**：思源宋体常规和粗体（仓库 `resources/fonts` 那份），加上引擎自带的后备字体（`engine/data/fonts/fallback`，授权见它的 NOTICE）。
- 给 woff2。思源宋体完整一份二三十 MB，建议**按书子集化**（只留这本书 `layout.json` 里用到的字），放进第 1 条的 `fonts` 清单。
  - 子集按任务缓存，带长缓存头。
- **字体对应要写进版面**：给每个字簇（或每段连续的同一字体）加一个 `font` 字段，取清单里的 `key`；`mode: "dflt"` 那种到底画在哪个字体上，前端不猜。
  - 这是在 `rpr_layout_v1` 上加字段，旧字段不动。要不要升到 `v2` 后端定，字段旧的不改，只加新的。

### 4. 公式 SVG（建议）

- 排版时把每个公式的 MathJax SVG 存下来（`MathStore` 已经按哈希画了，只是没落盘），版面里公式那一项加 `svg` 字段（哈希）。
- 接口 `GET /api/v1/jobs/:job_id/reader/layout/math/:hash`，返回 SVG，长缓存。
- 前端照盒子（`w/h/d`）摆。这样和 PDF 里的公式完全一样，不用两边对 MathJax 的版本和配置。

### 5. 确认几件事（回个话就行）

- 版面块 `id` 和 `/reader/regions` 的 `item_id` 是不是同一套，跨页续段每一截是不是各一块。
- `covers` 的填色是不是就是原页那块的底色（彩色底上也对）。
- 「重新排版」（改了译文后重排进 PDF）以后，`layout.json` 跟着换，接口的 ETag 跟着变。
- 表格（`rpr-table`）的结果在不在 `layout.json` 里。不在的话，表格先留原页像素，以后再说。

## 前端怎么接（这边做）

- HTML 页「画译文」时先看 `/reader/layout`：
  - 有就照版面画：底是原文页，上面是白块、字簇按 pt 坐标绝对定位、公式贴 SVG；
  - 没有就退回现在的按 OCR 框塞字，并提示可以生成。
- 每块仍是一个带块 id 的元素，动效、选字照旧挂在上面。
- 验收：同一页，HTML 页的截图和 pdf.js 画的译文 PDF 逐像素比，差别在阈值以内。放进前端测试，用 `c8bcf5` 那本先做。
- 后端接口出来之前，前端先用本地 `c8bcf5` 的 `layout.json` 做渲染器原型（从临时目录读，不改后端）。

## 分工

- 后端在固定的后端 worktree（`../retain-pdf-backend`）开分支做第 1 到第 4 条，接口只增不改，契约和 `docs/api/` 同一个分支改。
- 做完一条就告诉前端会话（接口地址、字段、哪本书能试），前端接上、跑像素对比。
