# 译文栏用 HTML 画（实现）

2026-11-28。接 [阅读页只加载原文 PDF](./20261128-阅读页只加载原文PDF.md) 的第 3 步：后端 #246（erase、tables）、#248（PDF 正文 300 细体）合进来以后，
用户说「开始做」。分支 `feat/reader-translated-html`。

## 怎么定用不用

- 打开书时，原文 PDF 照常立刻开始下载；同时要版面清单（`GET /api/v1/jobs/:id/reader/layout`），装上清单里的字体。
- 版面「完整」才替掉译文 PDF：`available`，`features` 有 `erase`（要抹掉的原字写明了，不用底图）和 `tables`（表格也是译文），
  清单里有字体、主字体每个字重都装上了。
- 不完整（Typst 路线、以前存的版面、后端还在补、字体没装上、清单 3 秒没回来）照旧下载译文 PDF，和以前一模一样。
- 阅读页地址带 `?translated=pdf`，或者 HTML 页菜单里勾「译文栏用 PDF」（这次打开里有效），照旧用译文 PDF。
- 下载按钮、改译文判断「有没有译文」照旧看译文 PDF 的地址，不受影响。

代码：`hooks/reader-session/translated-layout.ts`（要清单、判定、装字体），`session-assets.ts` 把译文那份下载改成等它的结果
（`downloadJobPdfs` 的 `translatedFinal` 可以是 Promise，原文不等）。

## 怎么画

- 译文栏挂原文 PDF（session 里已经下好的那份字节），版面里有的页盖上版面（`PdfPageSlot` → `LayoutPageHost`），
  画法和 HTML 页一样：原文页 → erase → covers → 表格 cover → 表格线 → 字。版面里没有的页（整页图、不翻的参考文献）就是原文页，和译文 PDF 一样。
- 一页的版面还在取时整页盖纸色（`.reader-layout-loading`），不让原文先露出来。
- 版面盖住的页不挂 pdf.js 的文字层：选字、复制、提问都走版面的 SVG 字（`page-selection.ts` 早就认版面层）。
- 搜索：版面上命中的字簇底下画一块和 PDF 文字层一样颜色的底（`layoutFindSpans`，一行里拼起来找，不跨行，公式不参与）。
- 悬停框、改过的竖线、改译文的框都按块的 bbox 画，不看底下是什么，照旧。
- 放大看：译文那一块用原文页裁出来，再把整页版面按同样比例放大、挪到这一块的位置盖上（`ZoomLayoutBlock`）；字是矢量的，放大也清楚。
- 原文 PDF 不登记成「译文 PDF」（书签、提问截图、引用预览不会把英文当译文）。

## 实测（本机开发栈，828df8，8 张表，后端已补好版面）

- 只下载了原文 PDF（`source.pdf`）；`?translated=pdf` 时照旧两份。
- 译文栏第 1 页和译文 PDF 逐像素比：差 > 64 的像素 3.42%，全在字的笔画边上（下载的 PDF 现在是 300 细体，HTML 用常规体，本来就该有差）。
- 搜「包覆」第 1 页标出 42 处；拖选出浮条；悬停框出来；放大看是中文、清楚。

## 还没做

- 书里的引用标记（「图 2.1」点了跳）挂在 pdf.js 文字层上，版面页上没有；要在版面上另接。
- 提问截图、引用预览要画译文那一块时，没有译文 PDF 就拿不到译文的图（用原文页加版面画，同放大看的做法）。
- 跨行的搜索词标不出来（PDF 文字层也只在一个 span 里找，一样）。
- 改译文以后重新排版：任务跑完 session 会重新加载，清单跟着重新要；还没在真书上走一遍。
