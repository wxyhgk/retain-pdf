# HTML 页（先用 OCR 的框和结果）

2026-11-28。用户：「我现在想做 PDF 的重排，我们纯 html 渲染整个 pdf，这样我们后续就能增加更多的功能，比如在文字里面增加动效，以及增加 3d 的场景，以及让 pdf 动起来」。

我给了两条路：
- 照原样摆（每页一个 div，字块按 PDF 坐标）；
- 流式重排（像网页、电子书）。

用户选了成本高的「照原样摆」，问第一性原理怎么做、后端要做什么。我的答复：
- 一份显示列表（每个东西：id、在哪、什么字体、画什么），PDF 和 HTML 都是它的渲染器。
- 排版引擎的 `layout.json`（`rpr_layout_v1`，每个字簇的位置、每个公式的 LaTeX 和盒子、盖原文的白块）已经是译文这一边的显示列表。
- 后端要做：存下并给出 `layout.json`、去字的底图、公式 SVG、字体接口、原文字形段和内嵌字体、行内公式框、契约。

用户接着说：「我们开始不用做的特别完美，我们不是有 ocr 的框以及 ocr 的结果吗？应该可以做一些事情了」。所以先不动后端，用阅读页已经有的块数据做第一版。

## 做法

- **画在哪**：原文栏的每一页上叠一层（扩展的 `pageLayer`，内置扩展 `html-page`）。
  - 底下照旧是 pdf.js 画的原文页，缩放、翻页、目录、当前页都不用动。
  - 只画在原文栏。对照时左边是 HTML 页、右边是译文 PDF，正好对着看。
  - 对比版本时左栏是另一份译文，不画。
- **画什么**：`pdf/HtmlPageLayer.tsx` 的 `htmlBlockContent`。
  - 正文类的块（正文、标题、图注……）：先用纸色盖住原字（往外多盖 1.5px），再按 OCR 的框画字。
    - 「画译文」取 `translatedBlockText`，没有就取 `markdown`。块里的 `markdown` 是译文的 Markdown，带 `$…$` 公式。
    - 「画原文」取 `source.text`。
  - 行间公式画 LaTeX。
  - 图、表、认不出的块不画，留原页的像素。
- **塞字**：沿用边翻译边看的叠层的 `LiveTranslationTextItem`。
  - 按框二分找字号，行内、行间公式用 MathJax 画成 SVG。
  - 原文用西文衬线字体（Times / Tinos / Liberation Serif），中文落到思源宋体。
- **动效的地基**：每块是一个带块 id 的元素（`data-html-block`、`data-html-kind`）。
  - 第一个动效是沿用实时译文「到达」那一下（模糊到清楚、轻轻一闪）。
  - 刚打开或换了画什么时，按阅读顺序每块晚 18ms 浮出来，最多 0.6 秒。
- **入口**：书页区右缘竖条上一颗 `</>`（CodeXml），点开往左弹「关 / 画译文 / 画原文」。
  - 开着时如果在看译文就切到原文。
  - 只在这次打开里有效，不写本机。
- **踩到的坑**：
  - 纸色、墨色变量（`--reader-overlay-paper / ink`）只定义在实时译文那一层里，新的一层要自己定义，不然盖不住；深色文档跟着换。
  - 块里的 `markdown` 是译文，不能拿来当原文。

## 量过的（VP ≠ VNP 那篇，第 2 页）

- 画译文：3 页、30 块（title、paragraph、heading、display_formula），134 处公式 SVG。原字全盖住，中文和公式排得开。
- 画原文：英文段落、上下标、`VNP ⊈ VP`、`k((ε))` 都画出来了。
- 对照：左 HTML 原文、右译文 PDF。
- 页面没有报错。

## 不准的地方（以后换显示列表就没了）

- 字号是按框推的，同一段里一样大；粗体、斜体、字体和原书不一样；个别块挤，最后一行会被框裁一点。
- 图、表还是像素，动不了；行内公式只是重新排，不是原来的字形。
- HTML 字不在 pdf.js 的文字层里，今天做的选字（清洗、色带、整个选公式）还没接上，选的是浏览器自己的选区。
