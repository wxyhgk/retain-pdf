## 2. 新契约和端点

契约按领域分文件，名字照现有习惯（按功能起名，`.v1`）：

| 契约 | 端点 | `client_name` |
|---|---|---|
| `credentials.v1`（新） | 凭据 5 条 | `listCredentials`、`createCredential`、`getCredential`、`updateCredential`、`deleteCredential` |
| `provider-probes.v1`（新） | 校验 3 条、余额 1 条 | `validateMineruToken`、`validatePaddleToken`、`validateDeepSeekToken`、`queryDeepSeekBalance` |
| `platform-settings.v1`（新） | 字体 1、同步 4、备份 4、健康检查 1 | `listFonts`；`getSyncStatus`、`updateSyncSettings`、`runSyncNow`、`testSyncTarget`；`getBackupStatus`、`createBackup`、`deleteBackup`、`restoreBackup`；`/health` 没有 |
| `auth-session.v1`（新） | `GET /auth/session` | `getAuthSession` |
| `uploads.v1`（新） | `POST /uploads` | 没有 |
| `reader-data.v1`（加一条） | `GET /jobs/:job_id/files/output/*name`，`transport: binary` | 没有 |
| `library-documents.v1`（加一条） | `GET /documents/:document_id/files/:name`，`transport: binary` | 没有 |

- **名字**照前端手写的（`frontend/packages/api/src/credentials.ts`、`providers.ts`、`fonts.ts`、`sync.ts`、`backups.ts`、`auth.ts`）。
  手写的叫 `fetchXxx` 的照术语表的先例改成 `getXxx`：`fetchSyncStatus` → `getSyncStatus`、`fetchBackupStatus` → `getBackupStatus`、
  `fetchAuthSession` → `getAuthSession`。`getCredential`、`deleteCredential` 前端还没有调用方（`deleteCredential` 第 2 期删了没人调的封装），
  名字照同一个规则起。
- **不写 `client_name` 的**：`/health` 不在 `/api/v1` 下，前端生成器只生成 `/api/v1/` 开头的地址（写了会让生成器报错）；
  `/uploads` 是 multipart，生成器只会发 JSON，网页要上传进度也是用 XHR 自己发；两个文件下载是 `binary`，生成器不生成，
  前端用地址（`jobOutputFilePath`、`documentSourcePdfPath`）打开。这几条照样有返回 schema（文件下载除外），前端可以用类型。
- **请求一侧** `additionalProperties: false`（都是 `deny_unknown_fields`）；空值照 serde 写：`Option` 的字段类型带 `null`，
  `String` 加 `#[serde(default)]` 的不带 `null`（写 null 会 400）。返回一侧每个键都写（serde 都会写出来），`required` 是全部键。
- **校验接口的 `status`** 照代码写全（含 2026-11-23 加的 `quota_exceeded`），但写成字符串加说明、不写 `enum`：
  文档约定「以后可能加值，界面按 `ok` 判断」，写死枚举以后加值就成了破坏性改动。`http_status`、`provider_code` 照
  `ProviderProbeView` / `DeepSeekBalanceView` 现在的含义写（2026-11-23 起分开放）。
- **`/health` 的 `version`、`build`**：分支 `feat/api-response-headers` 同时在加。这里写成可选属性（不在 `required` 里），
  rust_api 的测试允许它们不出现；那边合进来以后测试照样过，到时可以改成必填。

照 `library_documents_contract.rs` 的写法，在 rust_api 测试里起应用打真实请求，返回对着 `backend/contracts/` 的定义核对类型和键集合；
请求类型的字段从 serde 的 `deny_unknown_fields` 报错里取出来和契约比：

| 测试 | 钉什么 |
|---|---|
| `api_tests::credentials_contract` | 凭据 5 条返回；`CreateCredentialInput`、`UpdateCredentialInput`、`DeleteCredentialQuery` |
| `api_tests::provider_probes_contract` | 对本机假服务商（单机放开回环地址）打 3 个校验和余额（不是 DeepSeek 官方地址时 `unsupported_provider`；配置的余额地址指向假服务时带金额）；3 个请求类型。不碰真服务商 |
| `api_tests::platform_settings_contract` | 字体列表；同步（两个后端共用一个文件夹，`peers`、`last_run` 都有值）；备份（备份、恢复、删）；健康检查；`SyncSettingsInput` |
| `api_tests::settings_misc_contract` | 登录状态（单机、多用户登录前后）；真实上传一份 PDF |

审计还发现有契约却没钉的，这次在原来的接口测试里加上核对：

- `reader-data.v1` 7 条里的 6 条（以前只钉了 `JobFilesView`）：Markdown（`jobs_markdown.rs`）、区域（`jobs_reader/regions.rs`）、
  页面元数据（`jobs_reader/metadata.rs`）、实时译文布局、单页快照、SSE 推送的 `data` 行（`live_translation.rs`）。
- `library-documents.v1` 的译文版本 3 条返回（`translation_versions.rs`）。

新的 `job_view_contract::assert_contract_view`：契约里不是 `required` 的键（Rust 用 `skip_serializing_if` 整个省掉的，比如区域的
`reading_order`、`sub_type`）可以不出现，其余键集合要和契约一样；任何一层多出契约没有的键都红。

## 4. 「在用但没契约」冻结名单

`backend/api/src/api_tests/route_manifest.rs` 的 `IN_USE_WITHOUT_CONTRACT`（方法、地址、理由）和测试
`in_use_endpoints_without_contract_only_shrink`：

- 登记表里 `by(web)` 或 `by(desktop)` 的现用地址（旧地址 `old` 不算，契约里本来就只许写现用地址），要么在某份契约的端点表里，
  要么在名单里（带理由），否则红：前端要调的新接口先写进契约，不许加进名单。
- 名单里的接口已经有契约了（或删了、改成旧地址、不再是前端在用）也红：防忘删。
- 放在 `route_manifest.rs`：契约↔登记表的一致性检查（`contract_endpoints_are_registered`）也在这里，读契约端点表的函数共用。

补完第 1 节以后**名单是空的**：文件下载登记了 `transport: binary` 也算在契约里。以后真有不该进契约的接口（比如只给桌面壳用的内部探针），
写进名单并写明理由。

反向检查：删掉 `uploads.v1` 的端点表，测试红并列出 `POST /api/v1/uploads`；名单里加一条已有契约的 `GET /api/v1/fonts`，红并列出它。
