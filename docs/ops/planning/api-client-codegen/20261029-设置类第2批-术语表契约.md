## 术语表这一组

前端说 6 个，实际调的是 7 个（`frontend/packages/api/src/glossaries.ts`）：列表、新建、读一张、整份保存、删除、导出 CSV、解析 CSV。导出
那条直接是文件（`text/csv`、`attachment`），所以契约里写 `transport: binary`、没有 `output`；7 条都给了 `client_name`。

新契约 `glossaries.v1.schema.json`：

| 端点 | `client_name` | 请求 | 返回 |
|---|---|---|---|
| `GET /api/v1/glossaries` | `listGlossaries` | 查询 `ListGlossariesQuery` | `GlossaryListView` |
| `POST /api/v1/glossaries` | `createGlossary` | `GlossaryUpsertInput` | `GlossaryDetailView` |
| `GET /api/v1/glossaries/:glossary_id` | `getGlossary` | | `GlossaryDetailView` |
| `PUT /api/v1/glossaries/:glossary_id` | `updateGlossary` | `GlossaryUpsertInput` | `GlossaryDetailView` |
| `DELETE /api/v1/glossaries/:glossary_id` | `deleteGlossary` | | `GlossaryDetailView`（删掉的那张） |
| `GET /api/v1/glossaries/:glossary_id/export.csv` | `exportGlossaryCsv` | | 文件（`binary`） |
| `POST /api/v1/glossaries/parse-csv` | `parseGlossaryCsv` | `GlossaryCsvParseInput` | `GlossaryCsvParseView` |

- 词条 `GlossaryEntryInput` 从 `create-job.v1` 原样抄（建任务的 `translation.glossary_entries` 用的也是它），
  `tests/glossaries-shared-definitions.test.mjs` 锁成一致。
- 说明文字按代码写：列表按 `updated_at` 从新到旧；`q` 查名字、说明、编号（不分大小写）；`level` 认 preserve、canonical、preferred，
  `match_mode` 认 exact、case_insensitive、regex（都认别名，空的取默认值）；PUT 带 `expected_updated_at` 不一致时 409 `glossary_changed`。
