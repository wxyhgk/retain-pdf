# 表格排版 agent 方案

**状态：** 方案，待用户看过再动手。
**日期：** 2026-11-22

## 1. 为什么

表格翻译 T5（`docs/ops/planning/table-translation/20261122-T5译文PDF放回表格.md`，分支 feat/table-pdf-overlay）已经能把整张表按原表的框重排：
规则量出原表的样式，rpr 引擎（`rpr-table.js`）像 HTML 表格那样自动分列宽、折行，从原文字号往下缩到排得进。
规则排一遍解决了大部分表，剩下的问题规则不好修：

- **排不进**：最多缩到原文 0.7 倍还超出原表高度的表，现在整张保留原文。
- **丢格式**：没翻的格子原文有上下标、文字层没带出来（LiFePO₄ 变成 LiFePO4）；译文漏了上标（`g−1`）。
- **排得难看**：自动列宽把空间都给了最长的一列；列很窄的地方一个字一行；该对齐的没对齐。

用户 11-22 的想法：设计一个 agent，**循环绘制表格，相当于直接写代码**——画出来、看效果、改、再画。

## 2. 有没有人做过（11-22 搜过）

"渲染 → 和目标对比 → 改代码"的循环在研究里很常见，但没找到用在"把译好的表格画回 PDF 原位"上的：

- [LATTE](https://arxiv.org/pdf/2409.14201)（AAAI 2025）：表格图片转 LaTeX，渲染后和原图做差异图，迭代修正，表格修对 25.51%。
- [ChartIR](https://arxiv.org/html/2506.14837v1)、[RRVF](https://arxiv.org/html/2507.20766v4)、[VisRefiner](https://arxiv.org/html/2602.05998v1)：
  图表 / 网页截图转代码，渲染对比再改；趋势是把循环放进训练（[Visual-SDPO](https://arxiv.org/pdf/2606.10334)：推理时每多一轮
  就多一次渲染加一次看图的钱）。
- [闭环表格识别里，大模型当裁判的分数不能当优化信号](https://arxiv.org/pdf/2607.13347)：只靠模型打分会越改越偏。
- 翻译产品里最近的是 [BabelDOC](https://arxiv.org/html/2605.10845v1)：中间表示 + 排版引擎，没有看图修正的循环。

所以自己做，借两条经验：**判断好坏以规则检查为主、模型看图为辅**；**改动要小而可检查**（只动描述的字段，不重写整张表）。

## 3. 思路：agent 写的"代码"是表格的排版描述

agent 不写任意代码，改的是交给引擎的那份描述（`rpr_table_input_v1` 里的一张表）。它就是这张表的"源码"，
引擎是"编译器"：

```json
{ "fontSize": 9.5, "minFontSize": 6.65, "lineHeight": 1.2,
  "padding": { "x": 3.8, "y": 2.0 },
  "columns": [0.18, 0.42, 0.2, 0.2],            // 新增：列宽比例，不给就自动
  "headerRows": 1, "rules": { "kind": "booktabs", "top": 0.9, "mid": 0.5, "bottom": 0.9 },
  "cells": [{ "row": 1, "col": 0, "text": "LiFePO$_{4}$", "align": "left", "bold": false, "noWrap": true }, ...] }
```

能复现（同一份描述画出同一张表）、能比对（改了哪几个字段一目了然）、能撤销（存每一版）。
引擎要补的旋钮：`columns`（列宽比例）、格子 `noWrap`、`valign`（已有）、`lineHeight`（已有）。

可以改的地方（agent 的"工具"），每一步都是对描述的一个小改动：

| 工具 | 改什么 | 例子 |
|---|---|---|
| `set_columns` | 列宽比例 | 说明文字列给宽一点，数字列收窄 |
| `set_font` | 字号、最小字号、行距、内边距 | 排不进时先压行距和内边距，再缩字 |
| `set_cell` | 一格的文字（只许加回上下标、改标点）、对齐、不折行 | `LiFePO4` → `LiFePO$_{4}$`；`g−1` → `g$^{-1}$` |
| `shorten` | 请翻译把某格译文压短（复用精修的改写，有字数上限） | 窄列里的长译文 |
| `keep_original` | 放弃，保留原表 | 怎么改都不行 |

`set_cell` 不许改文字内容，只许加回格式：改完和原文 / 译文按核对规则比，字对不上就拒绝这一步。

## 4. 一轮怎么走

1. **规则排第一版**（现在的 T5，不花模型的钱）。
2. **规则检查**（每一版都跑，便宜、确定）：
   - 排没排进原表的框（引擎报告 `fits`、高度、宽度）；
   - 原表每格的字都在、数字没变（排好的那层读回文字，和格子原文 / 译文逐格比）；
   - 上下标没丢（原文 PDF 文字层里比基线高 / 低、字号小的字，排好的版本里也要是公式上下标）；
   - 字号没缩到原文 0.8 倍以下；没有一格一个字一行的窄列；表头对齐。
3. **都过了**：用规则这一版，不调模型。大部分表应该停在这里。
4. **没过才叫 agent**：给它原表截图、当前排好的截图（同一个框、同样分辨率）、当前描述、规则检查没过的项，
   它只能回一组工具调用（第 3 节的表）。引擎重排，再跑规则检查。
5. **最多 3 轮**，取规则检查得分最高的一版（得分只看规则，不看模型自己说好不好）；比第一版还差或都没过，`keep_original`。
6. 每一轮的描述、截图、检查结果、工具调用写进 `table-layout-fixes.v1.json`（每张表一条），渲染读它，
   重跑渲染直接用最后选中的那版，不再调模型。

## 5. 前提和成本

- **模型请求要能带图**：现在翻译用的模型客户端只发文字（11-22 查过，`retainpdf_translation/llm` 没有图片输入）。
  这是表格看图（方案里的 T2）和整页排版 agent 共用的一步，先做。
- **模型**：测试只用 Haiku（用户定的）；看表格截图准不准要实测。
- **只看挑出来的表**：规则检查过了的不看图；一本书几百张表也只有排不进、丢格式的那些花钱。
  每张表最多 3 次看图请求，两张截图（裁到表格的框，长边 1000 像素左右）。
- **在哪跑**：渲染阶段（要引擎排版、要截图），开关跟着表格翻译走；默认关，评测达标后再开。

## 6. 评测

- 用表格评测集（55 张表）加回归样本 8 张：每张跑"只用规则"和"规则 + agent"两种，量
  排进的比例、丢上下标的格子数、字号缩小程度、看图请求数和花费。
- 人眼抽查：原表、规则版、agent 版三张并排。
- 规则检查本身要先对：在评测集上标一遍"这张排得好不好"，看规则检查和人的判断一致多少。

## 7. 分几步

| 步 | 做什么 | 花钱吗 |
|---|---|---|
| A1 | 规则检查（第 4 节第 2 步）+ 检查报告，进 T5 的诊断；评测集上量现状 | 不花 |
| A2 | 引擎加旋钮（`columns`、`noWrap`），描述存档格式 `table-layout-fixes.v1.json` | 不花 |
| A3 | 规则能修的先用规则修：上下标从原文文字层补回、窄列合并成不折行、排不进先压行距内边距 | 不花 |
| A4 | 模型请求带图（和表格看图 T2 共用） | 不花 |
| A5 | agent 循环（第 4 节第 4、5 步），Haiku 实测 | 要用户同意再跑 |

A1–A3 不用模型就能把一部分问题修掉，也给 A5 打底（检查是 agent 的打分，旋钮是 agent 的工具）。

## 8. 要用户定的

1. 先做 A1–A3（不花钱的规则部分），还是直接做到 A5？
2. agent 跑在渲染阶段（每次渲染都可能看图），还是翻译完单独一步（结果存档，渲染只读）？方案里倾向后者：
   存档以后重渲染不花钱，也能在阅读页给用户看"这张表改过"。
