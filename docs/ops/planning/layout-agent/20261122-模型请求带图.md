# 模型请求带图（表格排版 agent 的 A4）

2026-11-22。用户：「后端增加一个 api，最好可以发图片」，选了"两者都做"：模型调用层能带图，再开一个 HTTP 接口。

## 做了什么

1. **Python 模型调用层**（翻译、精修、表格 agent 都走的 `request_chat_content`）：消息的 `content` 可以是片段列表，
   写法照 OpenAI Chat（`text` + `image_url` 的 data URL），用 `model_wire.text_part` / `image_part` 拼。
   - OpenAI Chat 原样发；Responses 换成 `input_text` / `input_image`；Anthropic 换成 `text` / `image`（base64 或网址），
     相邻同角色消息带图时并成块列表。system 消息只取文字。
   - 纯文字的请求和以前完全一样（内容还是字符串），已有的协议测试照旧过（加上新的 7 个，共 74 个）。
   - Rust 模型执行器还只收文字：带图的请求在 Python 这边直接报错，不悄悄丢图。
2. **HTTP 接口** `POST /api/v1/providers/translation/ask`（admin）：用翻译接口的配置（Key、地址、协议、模型）问一次模型，
   最多 4 张图、每张 4 MB，回答和用量带回。实现在 `retainpdf-providers` 的 `provider_probe/ask.rs`，和校验 Key、拉模型列表
   同一套地址检查、不跟随重定向，超时 180 秒。请求体上限 24 MB：接口登记加了 `large_body` 选项（别的 JSON 接口还是 2 MB）。
   契约 `translation-providers.v1` 加了这个接口，细节见 `docs/core/rust_api/08-Provider 校验接口.md` 第 9 节。

## 没做

- 没有真调过看图模型（要花钱，等表格 agent A5 实测时一起跑，用户同意再跑）。
- Rust 模型执行器带图。
- 前端界面：要不要用这个接口由前端定，交接见 `docs/core/frontend/backend-changes-handoff.md`。
