# 排版 agent 方案（暂缓）

**状态：** 暂缓。用户 2026-11-12 定：先写计划放着，先做表格翻译（[table-translation](../table-translation/README.md)）。
**日期：** 2026-11-12

## 1. 想解决什么

用户的想法：先用现有的排版排一遍，再让 agent 一页页看字的大小、排版、间距，改到满意。

现在没有任何环节"看"排出来的页面：

- `rpr_fit` 引擎给每块算字号，排不下就缩字、进应急档，记下溢出和缩放（`fit_report.v1.json`）。
- 精修（翻译后的审校、改写）只看译文，不看排版效果。
- 翻译质量报告里有"排版 fit"一项（`retainpdf_translation/services/quality/qa/fit.py`），但翻译阶段渲染还没跑，这一项
  一直是 skipped。

## 2. 思路：规则先挑页，agent 只看挑出来的页，只能动几个旋钮

1. **规则挑问题页**（不花模型的钱）：溢出、字缩得太小、同页正文字号忽大忽小、标题比原文大、行距不一致、译文比原文长很多。
   顺带让排版检查从 skipped 变成真的在查（渲染之后重算）。
2. **agent 看问题页**：原文页和排好的页两张图对比。它只能在固定的选项里选：某块的字号、行距、允许不允许缩字、让翻译把这段
   压短（复用精修的改写）。决定写进一份"排版修正"文件，渲染读它。能复现、能撤销、能审计。
3. **只重排改过的页**，再检查一遍，最多两轮；改坏了保留原来那版。
4. **先建评测集**：几十页已知有问题的真实页面，量改前改后的溢出数、字号一致性，用户人眼抽查。

## 3. 前提和成本

- 要看图：模型请求要支持图片（和表格翻译"以后"那一项是同一件事，先做的那个顺手补）。
- 看图比读文字贵得多，600 页的书不能每页都看，所以必须先挑页。模型先只测 Haiku，要实测它看排版图准不准。

## 4. 什么时候再拿起来

表格翻译 T3（渲染放回）做完以后：那时排版条目会多一种 `table_cell`，"排版修正"文件的格式可以一起定。
