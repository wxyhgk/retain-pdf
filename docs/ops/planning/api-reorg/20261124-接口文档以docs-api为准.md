# 接口文档以 docs/api 为准

2026-11-24。分支 `docs/api-doc-entry`。

## 问题

接口文档有三套，都自称入口：`docs/api/`（中文 Wiki，接口目录从接口登记表生成到这里）、`docs/core/api/`（`index.md` 写着「对外 API 总入口」）、
`backend/api/docs/api-spec/`（英文分领域实现契约，`backend/api/API_SPEC.md` 是它的索引）。同一件事三处各写一遍，改接口时常常只改了一处，
越改越对不上：比如任务详情顶层的阶段字段早就禁止回流了，`docs/api` 和 `index.md` 还写在顶层；事件的 `display_stage` 在 `index.md`
写成 `stage`；凭据、元数据建议、书库的用法只在 `api-spec` 和 `index.md` 里有。

## 决定

- **`docs/api/` 为准，是唯一的对外接口说明。** 字段、请求响应、错误码、地址、前端该怎么读，都写在这里；改了接口行为就改这里对应的篇。
- **`docs/core/api/` 只留内部设计**：架构、实现思路、配置、存储、事件怎么存、为什么这样设计。README 开头写明「对外接口用法看 docs/api/」。
- **`backend/api/docs/api-spec/` 不再写内容**，只留一个指向 `docs/api/` 的 README。`backend/api/API_SPEC.md` 也改成指路的短页
  （文件留着，因为 `backend/api/scripts/check_architecture.py` 的 `check_protocol_docs` 读它）。
- `CLAUDE.md` 里「改接口要同步改的文档」那句跟着改成以 `docs/api/` 为准。

## 合并时按代码纠正的旧说法

- 任务详情没有顶层的 `display_stage`/`stage`/`substage`/`lane`/`stage_detail`/`progress`/`background_stages`（测试钉着不许回流），
  只在 `stage_snapshot` 里；终态任务 `stage_snapshot` 为空，完成说明在 `completion_note`；后台阶段叫 `background_snapshots`。
- `display_stage` 在事件里只有 `ocr`/`translation`/`render`，算不出来时没有这个键，`done` 哪儿都不会出现；事件的 `stage` 是内部阶段
  （`index.md` 写成了公共大阶段）。
- 事件的 `event_type` 只有 `progress`/`artifact`/`terminal`/`error`/`diagnostic`，`stage_transition`、`artifact_published` 是
  `raw_event_type`；`lane` 还有 `artifact`、`diagnostic` 两种。
- 阶段操作的 409 `reason` 没有 `ambiguous_request`，实际是 `ambiguous_translation_request`、`ambiguous_ocr_dispatch`；`actions`
  示例的请求体不带 `mode`、`create_new_job`（只有精修带）。
- 书库：收藏（`/favorites`）早删了；标签 2026-11-21 回来了（按 `tag_id` 筛）；术语表列表只回摘要不带词条；元数据建议的候选来源有 5 种。
- 编辑部事件的 `limit` 越界 2026-11-24 起也是 400，`00-约定/04-限制.md` 还写着「夹到范围内」，一起改了。
- API key 是环境变量 `RUST_API_KEYS` 优先、没设才读 `auth.local.json`（`runtime-and-events.md` 写反了）。
