# 第二批删接口：单个任务的用量、质量问题清单、单个阅读区块

2026-11-14。用户定：「继续删」。

## 删了哪三个

| 接口 | 契约里的函数名 | 原来给谁用 | 现在 |
|---|---|---|---|
| `GET /api/v1/jobs/:job_id/reports/usage` | `getJobUsage`（`token-usage.v1`） | 单个任务的模型用量 | 界面只看书（`GET /documents/:id/usage`）和全部（`GET /usage`） |
| `GET /api/v1/jobs/:job_id/reports/quality/items` | `listQualityItems`（`job-reports.v1`） | 阅读页标出有问题的块 | 前端从来没接上；同样的数据从 `data/{dataset}` 取（比如 `qa_violations`） |
| `GET /api/v1/jobs/:job_id/reader/regions/:item_id` | `getReaderRegion`（`reader-data.v1`） | Studio 笔记引用一段（AI 的 `read_passage`） | Studio 2026-11-06 起不再接 RetainPDF；要一块就从 `reader/regions` 里找 |

## 凭什么能删

- **代码里没有调用方**：前端（`frontend/web`、`frontend/desktop`、`frontend/packages`）只有生成的请求函数，没有地方调；
  命令行、流水线、Studio 的仓库都搜不到。`frontend/packages/api/src/quality.ts` 里手写的 `QualityItem` 类型
  也没人用。
- **路由计数**（`data/diagnostics/route-usage.json`，从 2026-10-18 开始累计，重启不清零）：
  - `reports/usage`、`reports/quality/items`：27 天都是 0 次。
  - `reader/regions/:item_id`：9 次。来源只可能是 Studio 的 `read_passage`，它在 2026-11-06 删了，
    而且从 11-12 到 11-14 这个数没有动。
- 原来定的流程是计数清零、观察 14 天再删（11-12 跟前端说的）。前两个已经观察了 27 天；第三个的调用方已经确认删掉了，
  就不再另等 14 天，三个在一个分支里一起删，前端只用重新生成一次。

## 改了什么

- 接口登记表去掉三条（`app/router/jobs/reports.rs`、`reader.rs`），处理函数、任务包里只给它们用的
  `job_usage_view`、`quality_items_view` / `quality_items` / `QualityItemsView` / `QualityItemsQuery`、
  `reader_region_item_view` / `load_reader_region_item` 一起删。`ReaderRegionItemView` 留着（`reader/regions` 的每一项）。
- 契约两份副本：三条端点删掉；`job-reports.v1` 删 `QualityItem`、`QualityItemsQuery`、`QualityItemsView` 三个定义；
  `token-usage.v1` 的 `scope` 取值里先留着 `job`（不会再出现，但前端 `features/usage/domain/usage-view-model.ts` 判断
  `scope === "job"`，去掉的话前端类型检查会报两边没有交集），前端删了这个判断再去掉。重新生成 `contracts/src`、`contracts/dist`。
- 快照：`routes.txt` 和接口目录从 121 个接口变成 118 个。
- 测试：只测这三个接口的删掉（单个区块、并发取单个区块、单个任务用量的加载规则、质量清单）；还在测别的东西的改用别的接口
  （用量汇总改看 `GET /usage`，小响应不压缩改用 `reader/metadata`）。契约测试钉住三个函数名不再出现。
- 文档：任务接口分类、错误约定、分页、模型用量、阅读接口说明、契约 README、前端交接。
