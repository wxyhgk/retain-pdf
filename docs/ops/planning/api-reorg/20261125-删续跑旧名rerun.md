# 删续跑旧名 rerun

> 日期：2026-11-25
> 分支：`chore/drop-rerun-alias`
> 起因：用户 2026-11-25「继续做 api 部分的」。接口登记表里唯一还挂着的旧地址；[任务接口规矩和删留](./20261019-任务接口规矩和删留.md)
> 定过「前端改读 resume 以后再删」。

## 核对

- 路由计数（`route_usage_report.py`，主开发库从 2026-10-18 起）：`POST /jobs/:job_id/actions/rerun` 0 次，`actions/resume` 6 次。
- 调用方：前端 `@retainpdf/api` 没有 rerun 的请求函数，续跑一律 `resumeJob`（`actions/resume`）；桌面壳、命令行、Python 都不调。
- 任务视图的按钮链接 `actions.rerun` 以前指着旧地址。前端 `frontend/packages/domain/src/job/actions.ts` 只在 `actions.resume` 缺失时
  读它的 `enabled` 兜底，不用它的地址。

## 改了什么

- 登记表删掉 `POST /api/v1/jobs/:job_id/actions/rerun`（同一个处理函数 `resume_job`，只删这条登记）；现在是统一的「没有这个地址」404。
  接受 `Idempotency-Key` 的接口从 7 个变成 6 个。
- 任务视图的 `actions.rerun` 字段**留着**（契约里是必填，前端还读），值和 `actions.resume` 完全一样，地址也改成 `actions/resume`。
  前端去掉兜底以后再删字段。
- 原来走 `actions/rerun` 的测试改走 `actions/resume`；加一条旧地址 404 的测试。
- 接口清单、接口目录重新生成；契约三处 `JobActionsView` 副本的说明、`job-actions.v1` 续跑的说明跟着改；`docs/api/` 里提到旧名的地方删掉。

## 剩下

- `actions.rerun` 字段：等前端把 `domain/job/actions.ts` 的兜底去掉再删（已写进前端交接）。

## 后续（同日）

前端 #201（`chore/drop-rerun-fallback`）去掉了 `domain/job/actions.ts` 读 `actions.rerun` 的兜底，后端 `chore/drop-actions-rerun-field` 删了这个字段：
`JobActionsView` 去掉 `rerun`，契约 `job-status.v1`、`job-actions.v1`、`library-documents.v1` 两份副本的必填和属性一起删，重新生成。
