# 接口写明负责和调用方（2026-11-22）

用户 11-22：“我们现在后端的 api 太多了，我都看不过来了”；问大厂怎么做以后，定先做“每个接口写明谁负责、谁在用”（“这个太重要了”）。

## 做法

接口登记表（`backend/api/src/app/endpoints.rs` 的 `endpoints!`）加两样，接口清单快照 `routes.txt` 和接口目录 `docs/api/00-接口目录.md`
跟着生成：

- **谁负责**：表头 `owner: <领域>;`，8 个领域之一（`accounts`、`providers`、`ingest`、`files`、`jobs`、`library`、`glossaries`、`platform`），
  就是业务逻辑所在的领域包；表里个别条目归别的领域，行尾 `owner(…)` 另写（健康检查归 `platform`、用量归 `jobs`）。写错名字编译不过。
- **谁在用**：每条必写 `by(…)`，可以写几个：`web` 前端页面、`desktop` 桌面壳主进程、`worker` Python 流水线、`cli` 命令行、
  `ops` 运维调试、`multiuser` 只有已停的多用户网站版、`none` 还没有调用方。不写编译不过；`none`、`multiuser` 不能和别的写在一起。
- 接口目录开头加统计：按调用方、按领域各多少个；`none` 和 `multiuser` 的单独列出来。
- `ops/development/route_usage_report.py` 认新写法，并拿登记的“谁在用”和 rust_api 的按接口计数对账：写了 `none` 却有调用的、
  写了调用方却零调用的，各列一张单子。

## 第一次登记的依据

134 个接口逐个看了三样：前端代码里的调用（生成的客户端函数名、`frontend/packages/api/src` 里拼出来的地址）、命令行和桌面壳主进程里写死的地址、
rust_api 的按接口计数（主开发环境 2026-10-18 到 11-22，另有多用户、单机检查两个环境）。结果：

| 谁在用 | 个数 |
|---|---|
| `web` | 85 |
| `multiuser` | 24 |
| `none` | 19 |
| `cli` | 14 |
| `ops` | 3 |
| `worker` | 3 |
| `desktop` | 1 |

（一个接口可以有几个调用方。）`none` 的 19 个：标签 4 个、书的标签、书的文件列表、书和任务的按页取图、字体上传、运行资源 2 个、
OCR 服务商列表、查单价、问模型（`translation/ask`）、三份报告（翻译质检、排版、精修）、任务数据集列表、旧地址 `actions/rerun`。
有几个计数里有零星调用（个位数），是开发时手动调的。

判断不准的地方：前端调用是按代码找的，界面上有没有入口没逐个点；桌面安装包的计数在它自己的数据目录里，不在这次的计数里。
`credentials`、合集的增删改在主开发环境计数是 0，但前端代码在调，记成 `web`。
