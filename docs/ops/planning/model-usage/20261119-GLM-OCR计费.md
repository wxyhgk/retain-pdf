# GLM-OCR 记进用量台账、按智谱价估算花费

2026-11-19。接着 [用量估算花费](./20261119-用量估算花费.md)。

## 起因

用户问 GLM-OCR 的价格能不能也统计。查下来：
- 智谱 layout_parsing 每次返回都带 `usage`（prompt / completion / total tokens），驱动早就在逐片累加，写进
  `ocr/glm_ocr_result.json`，但没进模型用量台账，汇总里看不到。
- OCR 进程本来就拿到台账路径（`RETAIN_USAGE_LEDGER`，jobsd 给每个 worker 都设）。
- models.dev 里没有智谱 GLM-OCR。官方文档页（docs.bigmodel.cn 的 GLM-OCR 页）写「API输入输出同价，仅需 0.2 元/百万Tokens」；
  价格页是脚本渲染的，抓不到。用户说「开始做」。

## 做了什么

- **记账**：`glm_ocr_driver.py` 每真请求一片（含整片 5xx 后逐页、半页重试，各页用量已合进 `usage`）调一次
  `record_model_usage`，标签 `ocr glm-ocr pages <起>-<止>`，协议 `glm_ocr`。命中断点、共用缓存的片不记：没请求，不收钱。
  OCR 经翻译包的公开入口 `retainpdf_translation.public` 拿这个函数（流水线不许直接引翻译包内部）。
- **阶段**：`usage_stage` 认 `ocr ` 前缀 → `ocr`；汇总里叫「OCR 识别」，归 `preparation` 组。
  「台账里有翻译侧的行就不再折算旧诊断」的判断排除 `ocr`：OCR 在翻译之前，有它不说明翻译逐条记了。
- **价格**：服务商包 `pricing` 加 `LOCAL_PRICES`（models.dev 里没有、我们自己补的价，写明出处和核对日期），
  人民币按 1 美元 = 7.16 元换算（和 models.dev 换国内站价用的汇率一致）。读价格时并进去，不写进同步下来的价格历史；
  models.dev 以后收录了同一个模型，以它为准。现在只有 `zhipuai / glm-ocr`。

## 没做的

- **旧任务不补**：旧任务的 `glm_ocr_result.json` 里的用量把从共用缓存取来的片也算进去了（那些片这个任务没付钱），补出来偏高。
  只从这次以后开始记。
- **PaddleOCR、MinerU**：不按 token 计费，返回里也没有用量，不记。
- 汇率写死在代码里；人民币价变了或者汇率差得多了再改。

## 验证

- OCR 驱动：5 页分 3 片各记一行（阶段、模型、域名、协议、任务号都对）；中断后重跑只记补请求的那片；
  别的任务做同一份原文全走共用缓存，一行不记。
- 台账阶段：`ocr glm-ocr pages 1-10` → `ocr`。
- 价格：内置快照能给 `open.bigmodel.cn / glm-ocr` 定价（按域名、`zhipuai`），80 万 token 约 0.16 元；
  同步下来的历史不带补充价、读的时候并上；models.dev 收录了以它为准。
- 汇总：OCR 那行显示「OCR 识别」、归译前准备、有花费；只有 OCR 行的任务照样折算旧翻译诊断。
