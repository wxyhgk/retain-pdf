# 换模型之前估价：查单价、按书的历史或书库平均估

2026-11-19。接着 [用量估算花费](./20261119-用量估算花费.md)、[GLM-OCR 计费](./20261119-GLM-OCR计费.md)。

## 起因

前端要做「存多个 key、重新翻译时换模型、换之前看估价」（用户同意），要后端给价目。前端原想自己用书上次的 token 乘新模型单价；
问用户两件事：
- 估价放哪算：用户选**后端算**。缓存分开算、分档价、DeepSeek 忙闲时的规则只在后端一处，前端抄一遍容易错。
- 汇率：用户选**固定值**。写死 1 美元 = 7.16 元（和 models.dev 换算国内站价格用的一致），不另接汇率源。

另一半（凭据带连接信息、换连接时拦住地址和凭据对不上）在 feat/credential-connection。

## 做了什么

- `POST /api/v1/usage/prices`：按（接口地址，模型）批量查每百万 token 单价，带分档、`peak_multiplier`（DeepSeek 2）。
- `GET /api/v1/documents/{id}/usage/estimate`：这本书最近一次翻译（翻译部分最后一条用量最晚的任务）的逐条用量按新模型重算，
  翻译（含译前准备、不含 OCR）和精修分开；下限按上次的缓存命中，上限当缓存全没命中、按忙时。没翻译过退回书库平均。
- `GET /api/v1/usage/estimate`：书库里每本有页数、有翻译记录的书取最近一次翻译，合起来按页平均乘 `pages`；
  分档按平均一次请求的大小判断。
- 用量汇总、单价、估价的 `pricing` 加 `usd_cny`。契约 `token-usage.v1` 同步加了接口和类型。

## 取舍

- 「最近一次翻译」而不是全部任务：重试、换模型重译过的书，全部加起来会算成两三倍。
- 书库平均按页加权（合起来除总页数），不是每本书的平均再平均：薄书一页的固定开销（通读、术语预扫）大，平均再平均会估高。
- 页数用书的 `page_count`。只翻了部分页（选页）的任务会让每页平均偏高；量不大，先不管。

## 验证

- 任务包单测：查单价（按域名、官方标价兜底、查不到给 null、和契约字段一致）；按书的历史估（取最近一次、OCR 不算、
  上下限算法、查不到价照样给 token）；书库平均（没页数、没翻译记录的书不算，按页缩放请求数和 token，空书库是 none）。
- 接口测试：三个路由的 400、404，空书库、没翻译过的书。
