# 用量汇总估算花费：价格每天从 models.dev 同步

2026-11-19。

## 起因

用户想知道每家 API token 的费用，问有没有开源的、每天更新的价格库，并让我把几个候选都测一下。测完说「可以」，接进用量台账。

## 选型

同一天测了五个开源价格库（数据和脚本没进仓库）：

| 项目 | 近 30 天价格有更新的天数 | 我们用的模型 | 结论 |
|---|---|---|---|
| models.dev | 31/31 | Claude 5 系列、qwen3.8、deepseek-flash、glm-5.3-flash 全有，带分档价、缓存写入价，国内站、国际站分开 | 用它 |
| LiteLLM 价格表 | 30/31 | 全有 | 可以拿来对照，没接 |
| Portkey | 18/31 | 没有 qwen3.8、glm-5.3 | 不用 |
| genai-prices | 18/31 | 没有 Claude 5.5，拿 `claude-sonnet-5` 之类的前缀顶上，价格错 25%–50% | 不用 |
| Helicone | 0/31 | 都没有 | 不用 |

核对过的：Claude 四个型号和 Anthropic 官方价一致；DeepSeek 官网分忙闲时，models.dev 只记闲时价、LiteLLM 只记忙时价，
所以忙时规则写在我们代码里。

## 做了什么

- **服务商包 `retainpdf-providers` 的 `pricing`**：
  - `PriceBook::from_models_dev` 把 api.json 换成「服务商 → 模型 → 价格历史」，只留认得出接口域名的服务商
    （models.dev 的 `api` 字段；Anthropic、OpenAI、Google、xAI、Mistral 没写，在 `HOST_OVERRIDES` 里补）。
  - `merge` 价格变了才追加，日期只往后；`quote` 取那天生效的价，域名对不上按 `OFFICIAL_PROVIDERS` 的顺序找官方标价。
  - `Price::cost_usd`：缓存命中、缓存写入、其余输入分开算，超过门槛按分档；DeepSeek 忙时乘 2。
  - `spawn_daily_price_sync`：服务启动 30 秒后开始，每小时看一眼，超过 20 小时没同步就拉；失败只记日志。
  - 内置快照 `src/pricing/models-dev-snapshot.json`（17 家官方服务商、约 75KB），`ops/development/update_model_prices.py` 生成，
    没同步过时用。第一次同步不并快照，直接用拉到的数据起步，免得快照日期比同步日期晚、历史倒序。
- **用量汇总（任务包 `reports/usage`）**：每个桶加 `estimated_cost_usd`、`priced_requests`、`list_priced_requests`、
  `unpriced_requests`；`by_model` 加 `price_provider`、`price_basis`；汇总加 `pricing`。契约 `token-usage.v1` 同步改了，只增不改。
- **rust_api 启动**：`server.rs` 起每天同步（单测进程不起）。

## 验证

- 价格模块：域名匹配和退回官方价、包月套餐不抢官方价、缓存和分档算法、DeepSeek 忙闲时、价格变了追加且旧账按旧价、
  源坏了不覆盖历史、内置快照能给我们用的四家模型定价。
- 真的从 models.dev 拉了一次：291 家服务商、8122 个模型，价格历史约 850KB；马上再拉一次没有追加。
- 本机台账里出现过的「域名 + 模型」组合都对上了官方服务商（Claude、DeepSeek、qwen、智谱），用 IP 访问的自建模型算未定价。

## 没做的

- 中国法定节假日（DeepSeek 整天闲时价）判断不了，节假日忙时段估高。
- 人民币显示：models.dev 的国内站价格已经换成美元，原始人民币价看不到；要显示人民币得另找汇率。
- 前端显示花费是前端的事，接口字段已经有了。
