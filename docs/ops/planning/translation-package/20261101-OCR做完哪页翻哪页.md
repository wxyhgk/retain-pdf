# OCR 做完哪页翻哪页

2026-11-01。接 [Paddle 按片并行提交](./20261101-Paddle按片并行.md)。用户："可以,按照你说的来干"。

## 起因

开发栈 Paddle 端到端（34 页论文，翻译 glm-5.3-flash）共 75 秒，比同一篇用 GLM-OCR 的 39 秒还慢：

| 时间 | 发生了什么 |
|---|---|
| 0 秒 | 4 份同时提交 |
| 7 秒 | 第 21–34 页两份做完 |
| 15 秒 | 第 1–10、11–20 页两份还在排队，各再交一份，再交的也在排队 |
| 37 秒 | 第 11–20 页做完 |
| 46 秒 | 第 1–10 页做完，OCR 结束 |
| 46–69 秒 | 翻译 34 页 |

流式公布只公布前面连着做完的页，第 1 份一排队，翻译一页都拿不到，干等到 46 秒。再交一份防卡住这次没用（服务端整体在排队）。

## 决定

- **契约**（`retainpdf_base/ocr_stream.py`，仍是 `ocr_stream_v1`，只加字段）：清单加 `ready_page_indices`（就绪的页，从 0 数），
  `ready_pages` 改成就绪的页数；流里的文档页按原位置放，没做完的页是空页占位。没有这个字段的清单按前 `ready_pages` 页算，
  GLM 不传，照旧是前几页。Rust 标失败时原样留着，补 done 时写全部页。
- **Paddle**（`paddle_chunked.py`）：每做完一份就公布：做完的份放真结果，没做完的放同样页数、原文 PDF 尺寸的空页。
  全局编号偏移从「前面各份的最大编号」改成「起始页 × 1000」：前面的份没到时也算得出来，先公布的页和最后整份的编号一致。
- **翻译**（`streaming_flow.py`）：读就绪的页，不再按前缀；页范围里的页都到了（或 `done`）那一轮全部翻完。
  扣住的块从「最新一页页末能接下一页的那段」推广成「挨着没到的页的那一边」：下一页没到扣页末最后一个能接的块，上一页没到扣页首第一个，
  连同它们的拼接组。按顺序到时和以前一样。
- **跨页拼接**：规则本来就只连相邻两页（`continuation.rules` 查页号差 1），不用改。
- **上下文窗口**（`services/context/windows.py`）：以前把所有页摊平取前后两块，页不连着时第 21 页开头会拿第 10 页末尾当上文。
  改成只在连着的页里取；页连着时和以前逐字一样（提示词快照没变）。

## 验证

- 翻译：乱序到页（第 3 页先到、再第 1 页、最后第 2 页）跟着翻，译文、拼接和整本一次翻的逐块一样，没有块翻两次，判过的拼接对不再送模型；
  页缺口两边扣哪些块、上下文不跨过没到的页的单测；翻译单测 1920 个正着、倒着都过，集成测试（含提示词快照）指向本分支的代码跑过。
- Paddle：假接口跑完整驱动，第 2 份先做完：流里的文档 25 页、只有第 11–20 页有块，清单只列这些页，先公布的页和最后整份逐页一样。
- 拿开发栈那次的 4 份真实结果核对：只有第 3、4 份 / 第 2–4 份 / 第 1、3 份时，就绪的页和整份文档逐页一致（14/14、24/24、20/20），
  占位页全空；整份 243 块，文字和那次运行的结果一样。
- 开发栈端到端：见合并说明。
