# OCR 等待期间提速

2026-10-31，「普通翻译提速」之后四个 Sonnet 子代理调研，用户定"按你说的做"。这里是其中两条：
在 OCR 的那半分钟里先把识别领域做掉，以及 OCR 快完时查得勤一点。另一条"渲染准备提前做"验证后不做（见文末）。

## 识别领域挪到 OCR 期间

Jensen 第 12 章（41 页）：OCR 提交到结果约 37 秒，翻译开始后又串行等了 6.6 秒识别领域（修 temperature 前 8.6 秒）。
识别领域只读源 PDF 前两页的文本层（`llm/domain_context.extract_pdf_preview_text`），不依赖 OCR；结果按（模型, 预览文本）存进各任务
共用的缓存 `_domain_context_cache/`。

- Rust（`job_runner/domain_prewarm.rs`）：`run_job_with_ocr` 建好 OCR 子任务后拉起
  `python -m retainpdf_pipeline.translate.entrypoints.domain_prewarm`，spec 是 `specs/domain-prewarm.spec.json`（源 PDF 用上传文件，和翻译阶段
  复制进任务目录的是同一份；模型参数和翻译 spec 同源，有测试钉着）。只在学术模式（识别领域只在 sci 下做）、走 Python 请求
  （Rust 模型执行器的任务不拉起）、有翻译 key 的任务；只注入翻译 key。OCR 结束后最多再等 30 秒，进入翻译阶段。
  它只是缓存预热：不改任务状态、不写事件流；起不来、失败、超时只记日志，翻译阶段照常自己问。任务取消时 `kill_on_drop`。
- Python（`retainpdf_pipeline/translate/entrypoints/domain_prewarm.py`）：读 spec、登记连接、调 `infer_domain_context(output_dir=None)`，
  只写共享缓存；扫描件没有文本层时什么也不做。

验证：付费端到端，预热 5.8 秒写进共享缓存，随后翻译阶段日志 "domain-infer: shared cache hit"、不再发这个请求。

## OCR 快完时查得勤一点

Paddle 轮询按配置每 5 秒一次：:00 看到 40/41，:06 才看到 done，平均白等 2.5 秒。已提取页数到总页数九成以后每秒查一次，
其余照配置（`ocr_flow/polling.rs::near_done_poll_interval`）；多出来的查询只有几次。MinerU 没动。

## 渲染准备提前做：验证后不做

子代理建议在"哪些块要翻"定下来以后先算去文字层和底色 / 字色采样（渲染阶段约 2.3 秒）。离线拿 Jensen 第 12 章算指纹：
不带译文时块不标"要采底色"，整份指纹对不上；给要翻的块填占位译文后，覆盖框坐标仍然变了——覆盖框按译文排版算，
译文长短一变就变。提前算的结果渲染阶段一定命中不了，不做。
