# 本机 agent 改从 ACP 官方登记表来；pi 做我们自己的 agent（提案）

2026-11-26。用户：「我建议把 pi 什么的都接入进来，pi 有利于我们自己修改」。

第一部分（本机 agent 从官方登记表来）已经做了，分支 `feat/acp-registry`。第二部分（用 pi 做我们自己的 agent）**只是提案，没定**。

## 一、本机 agent 从 ACP 官方登记表来（已做）

以前登记表在 `registry.rs` 里写死三个（Claude Code、Codex、Gemini CLI）。ACP 有官方登记表
`https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`：2026-11-26 有 46 个 agent，每个写了发行方式（`distribution`）：

- `binary`：每个平台一个压缩包，加上里面的命令（`cmd`）、参数、环境变量；
- `npx`：npm 包、参数、环境变量；
- `uvx`：Python 包、参数、环境变量。

### 快照，运行时不联网

- 快照 `backend/packages/retainpdf-providers/src/acp/registry-snapshot.json`，编译时 `include_str!`。
  后端运行时**不去取**登记表，只认快照：起什么命令是仓库里审过的，断网也一样。
- 刷新用 `python3 ops/development/update_acp_registry.py`，写法固定：agent 按 id 排序、键排序、两格缩进，同一份数据重跑没有 diff。
  - `--from <文件>`：用已经下载好的文件。
  - `--check`：只比较不写，有变化时退出码 1。
  - 只能 npx 装、名单里又没有命令名的 agent，脚本会列出来，并顺带查出 npm 上的 `bin`。
  - 测试在 `ops/development/tests/test_update_acp_registry.py`，钉住仓库里的快照就是脚本写出来的样子。
- 人工名单 `acp/agents.json`。快照只照搬上游，我们自己的决定都写在这里：
  - `aliases`：登记表 id 换成对外 id。
  - `names`：改写显示名（`claude-acp` 显示成 Claude Code）。
  - `featured`：推荐顺序。
  - `hidden`：不列的 agent 和原因。
  - `bins`：npx 装好后的命令名。
  - `requires`：还要 PATH 上另有的命令。
  - 测试会核对名单里写的 id 都在快照里，刷新快照后上游删了某个 agent 会红。

### 怎么算「装了」

PATH 上有那个命令就算装了，查找不经 shell。依次找下面三种起法，找到哪个用哪个：

| 发行方式 | 命令名从哪来 |
|---|---|
| binary（这个平台的压缩包） | `cmd` 的文件名：`./dist-package/cursor-agent` → `cursor-agent` |
| npx | 名单 `bins`。登记表没写命令名，2026-11-26 按 npm 的 `bin` 逐个核过，22 个；有几个包装了多个命令，按 npx 的选法取和包同名的那个，比如 `@qwen-code/qwen-code` → `qwen`、`droid` → `droid`、`@github/copilot` → `copilot` |
| uvx | 包名，uvx 起的就是同名命令 |

- 平台写法照登记表：`darwin-aarch64`、`linux-x86_64`、`linux-x86_64-musl`、`windows-x86_64`……
- 这个平台没有压缩包、npx 的命令名也没核过的 agent，不列出来。
- 参数、环境变量照快照写死，不收客户端给的。例如 Factory Droid 带 `DROID_DISABLE_AUTO_UPDATE=true`，Qwen Code 是 `qwen --acp --experimental-skills`。
- pi-acp 自己不带 pi，要 PATH 上还有 `pi`（`@earendil-works/pi-coding-agent`）。没有 `pi` 时显示不能用，`reason` 说缺什么。
- **仍然不现场 npx / uvx 下载**。理由同 2026-11-25：下载到一半被断开，会留下坏缓存，之后每次都 `spawn -88`。
- 没装时怎么提示：
  - npm、uv 能装的，`install` 给一条命令：`npm install -g <包>`、`uv tool install <包>`，包名去掉版本号，装最新的。pi-acp 没装 pi 时，命令里连 pi 一起装。
  - 只有压缩包的，没有 `install`；`install_url` 给这个平台的下载地址，`reason` 写「下载……解压，把 X 放进 PATH（说明见官网）」。

### 旧 id 照旧能用

前端 2026-11-25 就在用 `claude-code`、`codex`、`gemini`，对外 id 不变：

| 对外 id | 登记表 id |
|---|---|
| `claude-code` | `claude-acp` |
| `codex` | `codex-acp` |
| `gemini` | `gemini`（两边一样） |

- 其余 agent 直接用登记表 id：`pi-acp`、`opencode`、`qwen-code`……
- 握手时登记表 id 也认，`/ai/agents/claude-acp/acp` 和 `/ai/agents/claude-code/acp` 起的是同一个；列表里只出一行，带 `registry_id`。
- 别名不能和别的 id 撞，也不能叫 `retainpdf`，有测试守着。

### 列哪些

46 个里列出 42 个（darwin-aarch64 上），全是 `kind: "local"`。排序是装了的在前，然后按推荐顺序，其余按名字。

推荐的 10 个带 `featured: true`：Claude Code、Codex、Gemini CLI、pi、OpenCode、Qwen Code、Kimi Code、goose、GitHub Copilot、Cursor。
前端可以只展开推荐的和装了的，其余折起来。

不列的 4 个（`hidden`）：

| id | 原因 |
|---|---|
| `agoragentic-acp` | 付费 agent 市场，用 USDC 结算，不是读书、写代码的 agent，点了会花钱 |
| `opencode-v2` | OpenCode 的旧 id，和 `opencode` 是同一个 |
| `kimi` | Kimi CLI 旧版（Legacy）。新版 `kimi-code` 装好后命令也叫 `kimi`，两个都列会一装两亮 |
| `antigravity-acp` | 压缩包里是 `agy_acp_server.par` 服务文件，不是装进 PATH 的命令，认不出装没装 |

为什么不只列推荐的几个：用户装了哪个就该能用哪个，名单越短越要人维护。全列再折叠，前端就能决定展示多少。

### 返回多了什么（只增）

`AgentView` 多了这些字段，自带的都没有：

- `registry_id`
- `description`
- `version`：快照里的版本
- `homepage`：官网，没有官网就是代码仓库
- `license`
- `distribution`：`binary` / `npx` / `uvx`
- `install_url`
- `featured`

契约 `ai-agents.v1` 两份同步，`client_name` 没动。

### 安全

闸门不变，本机 agent 只在下面这些条件都满足时才起：

- 单机模式；
- 后端只在本机监听；
- 握手的 `Host` 是本机地址；
- 没经过代理；
- 没设 `RUST_API_LOCAL_AGENTS=0`。

只起快照里有、又没被 `hidden` 的 agent，客户端改不了命令和参数。

有一个新风险要说明：登记表里有几个命令名很普通（`bob`、`nova`、`kimi`）。PATH 上恰好有同名的别的程序时，会被当成装了。
但只在用户点了那个 agent 时才起，起的也是用户自己 PATH 上的程序，所以不另加限制。

### 本机实测（2026-11-26，只做 initialize 和 session/new，不发问题、不调模型）

| agent | 本机版本 | initialize | session/new |
|---|---|---|---|
| pi-acp 0.0.35 + pi 1.1.0 | pi-acp 没全局装，装在临时目录里试 | 2.2 秒，`loadSession: true`，图片可以，MCP 的 http/sse 都不支持 | 成功，1.6 秒；6 个思考档位（modes）、59 个模型 |
| Claude Code（`claude-agent-acp` 0.112.0） | 已装 | 0.4 秒 | 成功，2.3 秒 |
| Qwen Code 0.26.1（`qwen --acp`） | 已装（Homebrew） | 1.4 秒 | 成功 |
| OpenCode 2.0.16（`opencode acp`） | 已装 | 1.0 秒 | 成功 |
| Kimi Code 0.34.0（`kimi acp`） | 已装 | 1.0 秒 | 成功 |
| Gemini CLI 0.63.0（`gemini --acp`） | 已装 | 7.3 秒 | **失败**：Google 说这个客户端不再支持个人版 Gemini Code Assist，要换 API key 登录，或者迁到 Antigravity |
| Grok（`grok agent stdio`） | 已装 | 3.8 秒 | **失败**：要先登录（`authMethods: grok.com`）。桥原样转 ACP 的 `authenticate`，要前端支持登录才能用 |

pi-acp 有一个要注意的地方：`session/new` 收下 `mcpServers` 但不交给 pi。所以桥补的 `retainpdf mcp` 对 pi 不起作用，
pi 作为本机 agent 读不了书。要让它读书，见下面第二部分。

## 二、pi 做我们自己的 agent（提案，没定）

### pi 是什么（2026-11-26 查的，来源是 npm 包里的文档和 pi-acp 的源码）

- **包和环境**
  - 本体是 `@earendil-works/pi-coding-agent` 1.6.1，MIT 许可，要 Node ≥ 22.19，命令名 `pi`。
  - 仓库在 `github.com/earendil-works/pi`，原来的 `badlogic/pi-mono` 会跳转过去。旧包 `@mariozechner/pi-coding-agent` 已弃用。
  - 适配器 `pi-acp` 0.0.35，MIT，Node ≥ 20，仓库 `github.com/svkozak/pi-acp`。它要 PATH 上有 `pi`，用 `PI_ACP_PI_COMMAND` 可以换成别的可执行文件。
- **设计取向**
  - 很小的 agent 骨架，默认只有 `read` / `bash` / `edit` / `write` 四个工具。
  - 能力靠扩展、skill 和包加；没有子 agent，没有 plan mode。
  - 0.99 起 MCP 以内置扩展的形式提供。
  - **没有沙箱，也不逐次要许可**。
- **扩展**
  - 写法：一个 TS 模块 `export default function (pi) { … }`，用 jiti 直接加载，不用编译。
  - 用 `-e <路径>` 指定，或放在 `~/.pi/agent/extensions/`、项目的 `.pi/extensions/` 下。
  - 注册工具：`pi.registerTool({name, label, description, parameters: Type.Object(...), execute(id, params, signal, onUpdate, ctx)})`，返回 `{content: [{type: "text", text}], details}`。
  - 事件钩子：`tool_call`（可以拦下）、`before_agent_start`、`context`、`before_provider_request`……
  - 其他：`registerCommand`；`ctx.ui.confirm/select`，在 RPC 模式下会变成发给宿主的请求。
  - skill（`SKILL.md`）、提示词模板、`--system-prompt` / `--append-system-prompt` 都有。
- **工具开关**
  - `--tools a,b` 白名单；`--exclude-tools`；`-nbt` 关掉内置工具；`--no-mcp`。
  - `-ne` 不加载自动发现的扩展，但 `-e` 指定的照样加载。
  - `-nc` 不读 `AGENTS.md` / `CLAUDE.md`。
- **模型**
  - 内置 Anthropic、OpenAI、DeepSeek、OpenRouter、Moonshot、MiniMax、ZAI、Qwen Token Plan 等很多家。
  - 自定义接口写在 `<配置目录>/models.json`：`baseUrl`、`api`（`openai-completions` / `openai-responses` / `anthropic-messages` / …）、`apiKey`（可以写 `$环境变量`）、`models`。
  - `PI_CODING_AGENT_DIR` 能把整个配置目录换掉，不碰用户的 `~/.pi`。
  - 命令行有 `--model provider/id`、`--thinking`。
  - 注意：`auth.json` 的优先级比 `models.json` 和环境变量都高，私有目录里不要放它。
- **运行方式**
  - 交互、`-p` 单次、`--mode json` 事件流、`--mode rpc`（stdin/stdout JSONL：prompt、steer、abort、set_model、compact……），还有 SDK（`createAgentSession`）。
  - 会话是 JSONL 树，默认放 `~/.pi/agent/sessions/`；可以用 `--session-dir` 换位置，`--no-session` 只在内存里。
- **pi-acp 怎么接上 ACP**
  - 每个会话起一个 `pi --mode rpc --no-themes [--session 文件]`，环境变量原样继承。
  - 思考 → `agent_thought_chunk`；工具 → `tool_call` / `tool_call_update`，`edit` 带 diff；另发 `usage_update`、`available_commands_update`。
  - 思考档位映射成 modes，模型映射成 configOptions。
  - 支持 `session/load`：靠 `~/.pi/pi-acp/session-map.json` 对上 pi 的会话文件。
  - **不把 `mcpServers` 交给 pi**；没有 `fs/*`、`terminal/*` 委托。
  - 只有扩展调 `ctx.ui.confirm/select` 时，才转成 `session/request_permission`。

### 「RetainPDF + pi」可以怎么做

**要发的东西**：`backend/pi-agent/` 下一个 pi 扩展，TS，不用编译。

- `retainpdf-book.ts` 注册三个工具 `read_pages` / `search_book` / `view_page`。
  - 读的接口和 Python 自带 agent 一样：`GET /jobs/{job_id}/reader/regions` 和两个页图地址。
  - 书、后端地址、读书密钥照旧由桥经环境变量给：`RETAIN_ASK_JOB_ID`、`RETAIN_ASK_DOCUMENT_ID`、`RETAIN_ASK_BACKEND_URL`、`RETAIN_ASK_BACKEND_KEY`。
  - 模型看不到这些，也挑不了地址。
- 「材料先给」用 `before_agent_start` / `context` 钩子，把附近的块放进这一问最前面。
- 系统提示词沿用 `backend/ask-agent` 的提示词文件，用 `--append-system-prompt` 加进去。
- 另有一个 `models.json` 模板（下面「模型」一条）。用户想改 agent，就改这个目录下的 TS，或者往里加 skill，这正是用户看重 pi 的地方。

**桥怎么起它**：新 agent id 比如 `retainpdf-pi`，归自带那一类，用设置里的模型。

1. 桥给每次连接建一个私有配置目录 `<数据目录>/ask-pi/agent`（`PI_CODING_AGENT_DIR`）。
   - 里面写一份 `models.json`：provider 是 `retainpdf`。
   - `baseUrl` 用设置里的 `base_url`。
   - `api` 按 `api_protocol` 对应：`openai` → `openai-completions`，`openai_responses` → `openai-responses`，`anthropic` → `anthropic-messages`。
   - `apiKey` 写 `$RETAIN_ASK_API_KEY`，密钥只在环境变量里，不落盘。
   - 不放 `auth.json`，不碰用户的 `~/.pi`。
2. 起 pi-acp，用 `PI_ACP_PI_COMMAND` 指向我们的小包装脚本。脚本在 pi-acp 给的参数后面加上：
   `--model retainpdf/<模型> --thinking <档位> -e <扩展> --tools read_pages,search_book,view_page -nbt --no-mcp -ne -nc --session-dir <数据目录>/ask-pi/sessions`。
   效果是只读，没有 bash，不读用户目录里的 `AGENTS.md`。
3. 以后想多控制一些，再把 pi-acp 换成自己的 Node 入口：用 pi 的 SDK 加 `@agentclientprotocol/sdk` 直接说 ACP。这样能自己发 `_meta.retainpdf.usage`、自己管会话，不再依赖 pi-acp（0.0.x，一个人维护）。

**拿到 / 失去**（和现在的 Python 自带 agent `backend/ask-agent` 比）：

| | pi | Python 自带 agent |
|---|---|---|
| 改起来 | 扩展、skill、提示词模板、钩子都是现成的，用户自己就能加工具 | 改要动我们的包，要重钉提示词快照 |
| 会话 | 有压缩（compaction）、`session/load`、分叉；问答记录重新打开能续上 | 现在只带最近 20 条，`loadSession: false` |
| 模型 | 很多家，思考档位、切模型都有 ACP 映射 | 三种协议，够用 |
| 运行环境 | **要 Node ≥ 22.19** 和 npm 包；桌面版要带 Node 或要求用户装；服务器、Docker 镜像变大 | 和翻译 worker 同一个 Python 环境，服务器上也能用 |
| 控制 | 「材料先给」和防失控上限（4 轮）要在扩展里重写；`_meta.retainpdf.usage`（花费、轮数、上下文）pi-acp 不发，前端用量行会变；行为跟着上游版本走 | 每一处都是我们写的、测试钉着 |
| 安全 | 默认能跑 bash、改文件，而且不要许可；必须靠 `--tools` 和 `-nbt` 锁住，升级时要复查默认行为；bash 子进程会继承环境变量里的密钥（锁了 bash 就没有这个问题） | 只有三个只读工具 |
| 许可 | MIT，和我们一致 | 我们的 |

**建议**（供用户定）：

1. 先不换掉 Python 自带 agent。它服务器上也能用、不要 Node，作为默认。
2. pi 先作为**本机 agent** 用。用户在终端 `npm install -g pi-acp`（本机已经有 pi 1.1.0），列表里的 `pi-acp` 就能用。
   这时 pi 读不了书（pi-acp 不传 MCP），只能靠问题里附的上下文。
3. 要「我们自己改的 pi」，就照上面做 `backend/pi-agent` 扩展加包装脚本，id 用 `retainpdf-pi`，先只在单机、本机闸门后面开。
   跑一轮和自带 agent 同样的实测（带字问、问别处、整本书，Haiku 和 Qwen），比较工具次数、首字时间和花费，再定要不要当默认。

### 等用户定的

- 要不要做第二部分；做的话，先走 pi-acp 加包装脚本，还是直接写自己的 Node 入口。
- 本机全局装 `pi-acp`（`npm install -g pi-acp`）要用户同意，这次没装。
- 桌面版带不带 Node。不带的话，pi 版只给自己装了 Node 的用户。
- Gemini CLI 个人版已经被 Google 停了（实测 `session/new` 报错），推荐名单里要不要留它。
