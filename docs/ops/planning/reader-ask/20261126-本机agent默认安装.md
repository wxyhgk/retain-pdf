# 本机 agent 默认安装（后端代装进自己的安装目录）

2026-11-26。分支 `feat/acp-agent-install`（后端部分；桌面壳、前端页面要做的写在
[后端改动交接](../../../core/frontend/backend-changes-handoff.md) 的「后端代装本机 agent」一节）。

接着 [ACP 官方登记表](./20261126-ACP官方登记表.md)：那一版只认 PATH 上装好的 agent，没装的给一条终端命令。

## 用户的决定（2026-11-26）

1. 本机 agent 要「默认给所有的桌面版都装上」：至少 pi（`@earendil-works/pi-coding-agent`，命令 `pi`）加适配器 `pi-acp`，
   以及 Claude Code 的适配器 `@agentclientprotocol/claude-agent-acp`（命令 `claude-agent-acp`）。
2. 推荐名单里 Gemini CLI 换成 Google Antigravity（登记表 id `antigravity-acp`）。Gemini 照旧列出，只是不在推荐里。

## 做法

### 安装目录

`<数据目录>/acp-agents/`（数据目录就是 `RUST_API_DATA_ROOT`，桌面版是用户数据目录下的那个）：

```
acp-agents/
  npm/<登记表 id>/<版本>/            npm install --prefix 的私有 prefix
    node_modules/.bin/<命令>
  binary/<登记表 id>/<版本>/<cmd>    压缩包解开的样子，cmd 照快照（./agy_acp_server.par）
  .staging/<登记表 id>.<随机>/       装的过程中用，装好了改名挪走
```

- **npm 包**：`npm install --prefix <临时目录>/prefix --no-audit --no-fund --no-update-notifier --loglevel=error <包@快照里的版本>`，
  不碰用户的全局 prefix。npm 缓存用用户默认的（`~/.npm`，内容按哈希校验，断了不会留下能被当成装好的东西；
  以前出事的是 npx 的 `~/.npm/_npx` 安装目录，不是缓存）。
  - npm、node 从哪来：先看 `RUST_API_NODE_DIR`（桌面版自带的 Node：放 `node`、`npm` 的那一层；给 Node 发行包的根也行，下面有 `bin/node` 就用 `bin/`），
    没有就用 PATH 上的 npm。起 npm 时 Node 目录放在 PATH 最前面（npm 本身是 `#!/usr/bin/env node`）。
  - 起托管的 npm 包时，子进程 PATH 前面是 Node 目录、再是这个 prefix 的 `node_modules/.bin`，后面才是原来的 PATH。
    `.bin` 放进去是给 pi-acp 找 `pi` 的（它在 PATH 上找 `pi`），所以托管的 pi-acp 一定用同一个目录里的 pi，不会用到用户自己装的旧版。
  - `requires`（pi-acp 要 pi）一起装进同一个 prefix。代装时的版本钉在 `agents.json`：`requires.pi-acp.version = 1.6.1`
    （2026-11-26 npm 上的最新版，要 Node ≥ 22.19）。终端安装命令（`install` 字段）照旧不带版本。
  - npm 建的 `.bin` 是相对符号链接，整个 prefix 改名挪位置以后照样能用（实测）。
- **压缩包**：按这个平台从快照取 `archive`，边下边算 sha256，和快照里的对不上就失败；解到临时目录（zip 拒绝 `..` 和绝对路径的条目，
  tar.gz 用 `tar` 包的 `unpack`，同样不会写到目录外面），`cmd` 必须在、Unix 上改成 755；参数、环境变量照快照。
  - 只认 `.zip`、`.tar.gz` / `.tgz`。登记表里还有 `.tar.bz2`（goose 的 6 个平台）、`.exe` 和不带扩展名的裸可执行文件，这些不代装，`install_status.reason` 写原因。
  - **快照里没给 sha256 的不代装**（cortex-code、corust-agent、cursor、devin、junie、stakpak、vtcode 这几个）。
  - 单个文件最大 2 GB；连接 15 秒、每段数据 60 秒超时。
- **一个 agent 有几种装法时**：有 npm 包、又找得到 npm 就用 npm；否则用这个平台的压缩包；Python（uv）包不代装（照旧给 `uv tool install` 命令）。
  Claude Code 的适配器两种都有：桌面版带了 Node 走 npm，没带 Node 又没有系统 npm 时走压缩包（快照里有 darwin / linux 的 sha256）。

### 不留半成品

- 都先装进 `.staging/<登记表 id>.<随机>/`，装好了（npm 退出码 0 且要的命令都在 `.bin` 里；压缩包 sha256 对、`cmd` 在）才一次 `rename`
  到 `npm|binary/<id>/<版本>`。同一个版本重装时旧目录先改名挪开、新的到位后再删。
- 装到一半断了（后端被杀、断网）只留下 `.staging` 下的目录，**不会被认成装好了**；下次装同一个 agent 时先清掉它的临时目录。
- 装好新版本后删掉同一个 agent 的其他版本、另一种装法装的那份。
- 同一个 agent 同时只有一个安装在跑：进程里登记（`install::begin`），在装的再要装直接返回「在装」。数据目录只有 rust_api 一个进程会装，不另加文件锁。

### 装了没

先看安装目录，再看 PATH（ACP 官方登记表那一版的逻辑）：

1. 安装目录：压缩包装的 `binary/<id>/<版本>/<cmd>` 能执行；npm 装的 `npm/<id>/<版本>/node_modules/.bin/<命令>` 能执行，有 `requires` 的另一个命令也在
   （同目录或 PATH）。快照的版本优先，旧版本也认（下面的默认安装会把它换成快照的版本）。
2. PATH 上有命令（和以前一样）。

### 接口（只增）

- `GET /ai/agents` 每个本机 agent 多一个 `install_status`：`state`（`missing` / `installing` / `installed` / `failed`）、`managed`、`installable`、
  `method`（`npm` / `binary`）、`installed_version`、`error`（失败原因）、`reason`（不能代装的原因）。自带的、本机 agent 关着时没有。
  状态只在内存里：重启后按目录重新算，失败原因没了。
- `POST /ai/agents/:agent_id/install`：后台装，马上返回这个 agent 的样子；开始装了或在装 202，安装目录里已经是快照的版本 200。
  登记 `signed by(none)`（桌面版、阅读页还没接）。`agent_id` 已经在 `classify_param` 里归成 `Nested`（不属于哪个用户），不用改；
  路由进了 `route_access.rs` 的复核名单（多用户模式下闸门一律关）。
- 闸门和起本机 agent 一样（`acp/gate.rs`）：单机、后端只在本机监听、没设 `RUST_API_LOCAL_AGENTS=0`、`Host` 是本机地址、没经过代理；
  浏览器带的 `Origin` 照 CORS 那套查。不认识 404，自带的 400，不能代装 409（`error.details.reason = agent_not_installable`）。
- 契约 `ai-agents.v1` 两份同步：加 `AgentInstallView`、`InstallState`、`InstallMethod`，`AgentView.install_status`，新接口不写 `client_name`
  （前端生成客户端时自己加）。

### 默认装

- `agents.json` 加 `default_install: ["pi-acp", "claude-acp"]`（测试钉着：都在快照里、不在 `hidden`、都有 npm 包）。
- 后端启动时，设了 `RUST_API_ACP_DEFAULT_INSTALL=1`（`true` / `on` / `yes` 也算）、本机 agent 开着，就 `tokio::spawn` 一个后台任务，
  按名单一个一个装：安装目录里已经是快照的版本的跳过；**用户自己装在 PATH 上的跳过**（不替用户装第二份）；安装目录里是旧版本的换成快照的版本；
  不能代装的（比如找不到 npm）只记日志。不挡启动，失败只记日志和 `install_status`。单测不起它。
- 服务器、Docker 不设这个开关；没设就和以前一样，什么都不装。

### Antigravity

- 从 `hidden` 拿掉，`featured` 里放在 Gemini 原来的位置（第 3 个）。
- 它在 PATH 上认不出来（压缩包里是 `agy_acp_server.par`），但后端代装进安装目录就认得出了：`binary/antigravity-acp/1.5.2/agy_acp_server.par`，
  Linux 上照快照带 `--uid=`。没装时 `reason` 写「RetainPDF 可以替你下载安装（地址）」。
- 测试只用本机造的假 zip / tar.gz 和本机 HTTP 服务，**没下载、没运行真的 Antigravity**（权限系统拒过运行下载来的可执行文件）。
  真机装 Antigravity、握手要用户自己点一次看。

## 本机实测（2026-11-26）

临时安装目录（测完删了），PATH 上的 npm 11.19.1 / node 26.8.2：

- 后端代码 `install_agent` 装 pi-acp：75 秒装好（`pi-acp@0.0.35` + `@earendil-works/pi-coding-agent@1.6.1`，170 MB），`.staging` 清空，
  `install_status` 是 `installed`、`managed: true`、`installed_version: 0.0.35`；`.bin/pi`、`.bin/pi-acp` 是相对符号链接。
- 照 `prepare_agent` 的起法（托管目录的 `pi-acp`，PATH 前面加 `.bin`）起来，ACP `initialize` 3.2 秒、`session/new` 2.2 秒成功（不发问题、不调模型）。
  用的是托管目录里的 pi 1.6.1，不是用户自己装的 pi 1.1.0。
- pi-acp 的 `session/new` 会写用户目录 `~/.pi/pi-acp/session-map.json`（pi-acp 自己的行为，和装在哪无关）。

## 待定（没问用户，先按下面的默认做）

- **桌面版带不带 Node、怎么带**：后端两种都支持，只认 `RUST_API_NODE_DIR`。建议带官方 Node（≥ 22.19，pi 要），macOS / Linux 约 40 MB 解压后；
  想省体积可以用 Electron 当 node（`ELECTRON_RUN_AS_NODE=1` 的小脚本叫 `node`，再带一份 npm 包），Windows 上 npm 的 `.cmd` 外壳找 `node` 的方式不同，不建议。
  没带 Node、用户也没装 Node 时，pi-acp 不能代装（`reason` 说找不到 npm），Claude Code 的适配器在有压缩包的平台走压缩包。
- **pi 的版本钉在 1.6.1**：刷新快照时顺手看一下 pi 的新版本，改 `agents.json`。
- **npm 缓存用用户的 `~/.npm`**：要完全不碰用户目录可以再加 `npm_config_cache=<安装目录>/.npm-cache`，代价是每台机器多一份缓存。
- **默认名单里用户已经装在 PATH 上的不再代装**：用户自己的版本可能很旧（比如 pi 1.1.0），但替用户装第二份会让「到底起的是哪个」更难说清；
  想要托管的可以在页面上点「安装」（`POST …/install` 不管 PATH 上有没有都会装，装好后优先用托管的）。
- **代装状态不落盘**：重启后失败原因没了；要显示历史失败再加文件。
