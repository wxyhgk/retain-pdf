# 回答里的互动块（OpenUI）和分层提示词

2026-11-26。用户要把 [Open Intelligent UI](https://github.com/thesysdev/open-intelligent-ui)（MIT）接进提问窗：回答里除了文字，
还能有能动手的小界面——拖滑块看结果怎么变、闪卡、对比表、图表、示意图、分步演示。用户定了三件事：

1. **一直开**：不加开关，每个会话都能写互动块。
2. **去掉会访问外网的组件**：任意网址的图片（`Image`）、YouTube 去掉；HtmlView（沙盒里跑模型写的小网页）留着。地图、搜图本来就不在组件库里。
3. **提示词分层**，不要一股脑塞进去（原来整份说明约 9–10k token，每个新会话都带太贵，也分散注意力）。由后端设计、实现。

## 它是什么、我们用哪部分

OpenUI 的模型输出一种小语言 OpenUI Lang（`root = Col([...])`、`$变量`、`@函数`），前端的渲染器边收边画成 React 组件。
Open Intelligent UI 是它的演示应用（Next.js，自带聊天界面）。我们**不用它的聊天界面**（换了就丢了 ACP、本机 agent、页码引用、问答记录），
只用三个包：

| 包 | 版本 | 谁用 | 干什么 |
|---|---|---|---|
| `@openuidev/react-lang` | 1.2.0 | 前端（提问窗包） | 渲染器 `Renderer`：把 OpenUI Lang 画出来，流式也能画 |
| `@openuidev/intelligent-ui-library` | 0.0.3 | 前端；生成说明 | 组件库（50 个组件、59 个 `@` 函数）、说明的规则和示例 |
| `@openuidev/lang-core` | 1.2.0 | 后端的 `openui_check` | 解析器：`createParser(组件库 JSON 规格, "Col")`，报出组件名不对、参数不对等错误 |

**遥测**：lang-core 在 Node 里有抽样遥测（生成说明、解析时 10% 抽样发到 PostHog，带一个 git 远程地址算出的项目哈希），
**默认关**——要设 `OPENUI_RUNTIME_TELEMETRY_ENABLED=1` 才发；浏览器里（有 `window` 和 `document`）一律不发。
我们在 Node 里跑它的地方（前端的生成脚本、后端的 `openui_check`）都再显式设 `OPENUI_TELEMETRY_DISABLED=1`、`DO_NOT_TRACK=1`。
它的命令行工具 `@openuidev/cli` 带 posthog，我们不用。

## 回答里怎么放

回答照常是 Markdown；需要互动的地方插一个代码块，语言写 `openui-lang`：

````markdown
Fock 方程每迭代一次，能量就往下走一点：

```openui-lang
root = Col([title, slider, chart])
$n = 3
...
```

拖滑块看前几次迭代的能量。
````

前端（`frontend/packages/ask`）把这种代码块画成界面，第一次出现时才加载渲染器；画不出来（写错了）显示原文和「让它修」，把解析错误发回给 agent。
互动块里的按钮 `@ToAssistant("…")` 当作用户的下一问发出去；`@OpenUrl` 只开 http(s)，新标签页、不带 opener。

## 分层

前端从组件库生成，放在 `contracts/openui/`（前后端共用；**前端生成、后端只读**）：

- **`ask-openui-prompt.v1.json`**：
  - `intro`：**L0 能力声明**（约 450 token）。什么时候值得插互动块、怎么包、「写之前先 `openui_spec` 取说明，写完 `openui_check` 检查」、可取的段的目录（每段一句话和大约多少 token）。**每个会话都带**。
  - `sections`：分层的说明，agent 按 `id` 取：

    | id | 内容 | 约 token |
    |---|---|---|
    | `core` | 语法、组件签名怎么读、按钮动作、书写顺序、写完的检查清单（**第一次写一定要取**） | 1100 |
    | `components:layout` / `text` / `inputs` / `data` / `play` / `drawing` | 六组组件的签名和用法 | 75–760 |
    | `functions:builtin` / `lists` / `numbers` / `text` / `dates` / `data` | 函数，按类分 | 330–550 |
    | `rules` | 风格规则（组件库的，去掉讲图片的两条，加我们的四条：可选、中文、不要外网图片和视频、`@ToAssistant` 写中文第一人称） | 1360 |
    | `examples:1` / `2` / `3` | 完整示例（小工具、组合页面、分步画图） | 260–850 |

  - 还有 `version`、`sources`（OpenUI 包的版本）、`fence`（`openui-lang`）、`root`（`Col`）、`removed_components`。
- **`ask-openui-library.v1.json`**：组件库的 JSON 规格（`library.toJSONSchema()`），`openui_check` 交给 `createParser` 用。

普通问答只多 L0；真要写一个互动块，大约取 `core` + 两三组组件 + 一两类函数，约 3k token（原来每次都是 9–10k）。
取过的段留在对话里，后面几轮走缓存，不用再取。

生成：`npm run generate:openui --workspace @retainpdf/ask`（`frontend/packages/ask/scripts/openui-spec.mjs`）。
前端测试会重新生成一遍和提交的比，组件库升级、改了去掉的组件忘了重新生成会红。

## 后端要做的

### 两个工具

| 工具 | 参数 | 返回 |
|---|---|---|
| `openui_spec` | `sections: string[]`（`sections` 里的 `id`；不认识的 id 回一句可取的列表） | 这几段的 `text` 拼起来 |
| `openui_check` | `program: string`（代码块里面的 OpenUI Lang，不带围栏） | 没错回「没问题」；有错按条回 `code`、`statementId`、`message`（parser 的 `meta.errors`） |

`openui_check` 要跑 JS 解析器：后端本来就跑 Node（`retainpdf2doc`、pi-agent），用一个小 Node 脚本加载
`@openuidev/lang-core` 和 `ask-openui-library.v1.json`，`createParser(schema, "Col").parse(program).meta.errors`。
（例：写错 `Titel(...)`、用了去掉的 `Image(...)`，回 `unknown-component`，消息里带可用组件列表，模型照着能改。）

### 三类 agent 怎么接

| agent | L0 放哪 | 两个工具放哪 |
|---|---|---|
| 自带 `retainpdf`（Python，`backend/ask-agent`） | 系统提示词（`ask_system.txt` 后面，固定不变，走缓存） | 和 `read_pages` 等并列；`openui_check` 起 Node 脚本 |
| 自带 `retainpdf-pi`（`backend/pi-agent`） | 同上（包装脚本给的系统提示词） | 扩展里注册，直接 import lang-core |
| 本机 Claude Code、Codex、pi…… | 桥给 `session/new` 补的 `retainpdf mcp`：MCP 的 `instructions` 和工具说明 | 同一个 MCP 加这两个工具 |

前端**不再**往第一问前面塞说明，提问窗只管画。

### 别的

- 说明文件只增不改：要改格式出 `v2`，`v1` 留着到前端换完。
- 后端打包（独立后端源码包、Docker）要带上 `contracts/openui/` 这两个文件和 lang-core。
- 工具的防失控上限：两个工具算进现有的「每轮最多几个工具」里，还是单独算，后端定。
- 测试：取段（认识的、不认识的 id）、检查（对的程序、错的组件名、用了 `Image`）、遥测环境变量设上了。

## 前端要做的（提问窗包）
