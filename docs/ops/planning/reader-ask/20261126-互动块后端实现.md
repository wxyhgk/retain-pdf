# 回答里的互动块：后端实现（分层提示词、两个工具）

2026-11-26，分支 `feat/ask-openui`。需求和方案以前端写的 [回答里的互动块（OpenUI）和分层提示词](./20261126-互动块分层提示词.md) 为准，
这里写后端怎么做、为什么这样定。用户定了三件事（经前端转达）：一直开、组件库去掉 Image 和 YouTube（留 HtmlView，前端生成说明时已经去掉）、
提示词分层由后端设计和实现。接口用法见 [阅读页提问](../../../api/16-AI/01-阅读页提问.md) 的「回答里的互动块」。

## 分层

| 层 | 内容 | 什么时候进上下文 |
|---|---|---|
| L0 | `ask-openui-prompt.v1.json` 的 `intro`（约 450 token）：什么时候值得写、怎么包、先 `openui_spec` 后 `openui_check`、可取的段的目录 | 每个会话都带，在系统提示词里，固定不变（走缓存） |
| L1 | `sections` 里的 17 段（`core`、六组组件、六类函数、`rules`、三个示例），模型用 `openui_spec` 按 id 取 | 模型要写互动块时，一次取齐要用的几段 |
| 检查 | `openui_check` 跑官方解析器 | 写完、放进回答之前 |

- **L0 从说明文件运行时读**，不复制进仓库的别处（免得和前端生成的漂移）：Python 自带 agent 读 `RETAIN_OPENUI_PROMPT` 指的文件；
  pi 由桥读出来写进这次连接的私有配置目录；`retainpdf mcp` 读同一个文件。说明文件读不到、`version` 不是 1 就整个不开（没有 L0、没有工具），回答照旧。
- **系统提示词的顺序**（自带的两个一样）：`ask_system.txt` → L0 → 有书时 `ask_tools.txt`（读书工具怎么用）→ 目录（单独一条系统消息）。
  前三段每个会话一样，Anthropic 的缓存、OpenAI 兼容服务商的前缀缓存都能命中。`ask_system.txt`、`ask_tools.txt` 没改，sha 钉住的快照不用重钉；
  L0 的内容由前端的测试钉（重新生成和提交的比）。
- 本机 agent：L0 接在 `retainpdf mcp` 的 `instructions` 后面（Claude Code、Codex 会把 MCP 的说明放进系统提示词）。

## 两个工具（三类 agent 同一套语义）

| 工具 | 参数 | 回什么 |
|---|---|---|
| `openui_spec` | `sections: string[]`（一个字符串也认） | 按给的顺序拼这几段的 `text`（去重，段之间空一行）。全不认识：工具出错，「不认识的段：`x`。可取的段：」加每段 id、简介、约多少 token；有认识的：照取，末尾一句「（不认识的段：…，没有取。可取的段：…。）」 |
| `openui_check` | `program: string`（不带围栏；带了替它去掉、提醒一句） | 「没问题。」，或「有 N 处问题，改完再用 openui_check 检查一次：」逐条 `序号. [code] statementId：message`（最多 20 条） |

- 检查器是后端自己的 Node 包 **`backend/openui-check/`**：`package.json` 钉 `@openuidev/lang-core` **1.2.0**（和说明文件 `sources` 一致，测试钉着），
  有 `package-lock.json`；`bin/openui-check.mjs` 是命令行入口（stdin 收程序、stdout 出一行 JSON，`--library` 给组件库，`root` 取组件库文件里的 `Col`），
  `lib/check.mjs` 是检查本身（`createParser(schema, "Col").parse(program).meta.errors`）。**回给模型的那段话在这里拼好**（JSON 的 `text`），
  三类 agent 原样转，说法一字不差；三处只各自写「检查器用不了 / 超时 / 输出不对」这几句兜底的话（也一样，测试各自钉）。
- `meta.errors` 之外，从同一次解析的 `meta` 补四种 parser 不算错、但画出来有问题的：`incomplete`（括号引号没闭合）、`unresolved-reference`
  （用了没定义的名字）、`orphaned-statement`（定义了没引用，不会画出来——说明里专门强调过）、`empty-program`（一条语句也没认出来，例如写成了自然语言）。
- **遥测**：lang-core 在 Node 里的抽样遥测默认关（要 `OPENUI_RUNTIME_TELEMETRY_ENABLED=1`）。起检查器的三处（Python、pi 扩展、`retainpdf mcp`）
  都显式设 `OPENUI_TELEMETRY_DISABLED=1`、`DO_NOT_TRACK=1`，去掉 `OPENUI_RUNTIME_TELEMETRY_ENABLED`；脚本加载 lang-core 之前自己也再设一遍
  （lang-core 是动态 import，测试钉了顺序和子进程里真看到的值）。**装依赖一律 `npm ci --ignore-scripts`**：lang-core 的 postinstall 是安装统计。
- **上限**：程序最多 4 万字符（调用方先查，不起进程）、等 15 秒（超时杀掉）、stdout 最多读 256 KB。Node 没有、依赖没装、组件库读不到、超时、输出不是 JSON，
  都回一段说明给模型（工具出错，「这次没法检查：照 openui_spec 取的说明仔细写，写简单些；或者不写互动块，用文字回答。」），整轮回答照常。
  **检查出了问题不算工具出错**（ACP 卡片是 `completed`），问题在结果里。

## 三类 agent 怎么接

| agent | L0 | 工具 | `openui_check` 怎么跑 |
|---|---|---|---|
| `retainpdf`（`backend/ask-agent`） | `server.py` 的 `_system_prompt`：`ask_system.txt` 后面 | `openui.py` 的 `OpenUiTools`，和 `BookTools` 并列（**没有书也有**） | 起子进程 `node openui-check.mjs`（标准库 `subprocess`，核心照旧只用标准库） |
| `retainpdf-pi`（`backend/pi-agent`） | 桥写 `<私有配置目录>/openui-intro.md`，包装脚本 `--append-system-prompt`（在 `ask_tools.txt` 前面） | `extension/openui.ts` 注册（没有书也有）；`--tools` 白名单、扩展的锁都加上这两个 | 起子进程，Node 是 `RETAIN_OPENUI_NODE`，没给用跑 pi 的那个 |
| 本机 agent | `retainpdf mcp` 的 `instructions` 后面 | 同一个 MCP 多两个工具（`backend/cli/src/cmd/mcp_openui.rs`），不调后端、不用密钥 | 起子进程 |

- **pi 为什么复用同一个 Node 包、不在扩展里直接 import lang-core**：pi-agent 没有 `node_modules`（pi 用 jiti 直接加载扩展的 TS），
  在那里 import 要另装一份依赖、另一个 lockfile；复用以后检查代码和给模型的话只有一份；遥测变量只设在子进程上，不改 pi 进程的环境；
  超时能直接杀掉。代价是每次检查起一个 Node（本机约 0.2 秒），和模型一轮的时间比可以忽略。
- **Python 核心只用标准库**：`openui.py` 只用 `json`、`subprocess`、`threading`、`shutil`，和 `tools.py` 用 `urllib` 一样放在核心；
  读环境变量在 `openui_tools_from_env`（入口 `__main__.py` 调）。核心的标准库测试照旧过。
- `retainpdf mcp` 只在桥给了 `RETAIN_OPENUI_*` 时开互动块：用户自己在终端里给 Claude Code 配的 `retainpdf mcp` 不在阅读页里，画不出来，不该带。

## 文件和 Node 怎么找到

- 桥（`retainpdf-providers` 的 `acp/openui.rs`）：说明文件目录 `RUST_API_OPENUI_DIR`，没设是 `<项目根>/contracts/openui`；检查器包
  `RUST_API_OPENUI_CHECK_DIR`，没设是 `<项目根>/backend/openui-check`（rust_api 建 `AcpConfig` 时定，目录不在就是没有）。
  Node 和代装那套一样：`RUST_API_NODE_DIR`（`bin/node` 或目录下的 `node`），没有就找 PATH；都没有就不给 `RETAIN_OPENUI_NODE`，
  Python 版、`retainpdf mcp` 自己再找 PATH，pi 用跑它自己的 node。
- 交给 agent 的环境变量：`RETAIN_OPENUI_PROMPT`、`RETAIN_OPENUI_LIBRARY`、`RETAIN_OPENUI_CHECK`、`RETAIN_OPENUI_NODE`；pi 另有 `RETAIN_PI_OPENUI_INTRO`。
  自带的两个在进程环境里；本机 agent 在补进 `session/new` 的 `retainpdf mcp` 的 `env` 数组里（在 AI 专用密钥后面）。
- 开发环境：仓库根的 `contracts/openui/`，检查器的依赖要先 `npm ci --ignore-scripts --prefix backend/openui-check`（不装时 `openui_check` 回「检查器用不了」）。
- 独立后端源码包：本来就带整个 `contracts/` 和 `backend/`；`build_source_archive.py` 的必需文件加上两个说明文件和检查器的 `package.json`、lockfile、入口。
  `node_modules` 不进源码包，构建时装。
- Docker（`Dockerfile.app`）：新阶段 `openuicheck`（构建机架构，`npm ci --omit=dev --ignore-scripts`，装完用组件库跑一遍冒烟），
  拷到 `/app/services/openui-check`；说明文件拷到 `/app/contracts/openui`；设 `RUST_API_OPENUI_DIR`、`RUST_API_OPENUI_CHECK_DIR`；Node 是镜像里本来就有的 `/usr/local/bin/node`。
  `release-docker.yml` 的触发路径加上 `contracts/openui/**`、`backend/openui-check/**`。
- 桌面版（`frontend/desktop`，后端不改）：要带两个说明文件和检查器（连 `node_modules`）、设两个环境变量，写进
  [交接记录](../../../core/frontend/backend-changes-handoff.md)。不做时桌面版没有互动块（找不到说明文件），不会出错。
- CI（`tests.yml`）：Node 提前装好，`npm ci --ignore-scripts` 装检查器的依赖、跑它的测试，再跑 ask-agent、pi-agent（真起检查器的几条不再跳过）。

## 防失控的上限

原来 Python 自带 agent 一问最多 4 轮调工具（每轮最多 4 个），到了就 `tool_choice = none`。互动块的两个工具**单独计数**：

| 工具 | 一问最多 | 怎么算 |
|---|---|---|
| 读书（`read_pages` / `search_book` / `view_page`） | 4 轮 | 一轮里调了读书的工具算一轮（和以前一样） |
| `openui_spec` | 2 次 | 按次 |
| `openui_check` | 3 次 | 按次 |
| 总轮数 | 9 轮（4 + 2 + 3） | 兜底 |

理由：

- 写一个互动块的正常路径是「取一次说明 → 检查 → 改一次再检查」，2 轮到 3 轮；要是算进读书的 4 轮，先读两轮书再写互动块就没额度改错了，
  反过来写互动块也会挤掉读书。分开算，两边都不受对方影响。
- 取说明给 2 次：一次取齐是 L0 里要求的，留一次补漏（写到一半发现要别的组件）。检查给 3 次：第一次大多能过（实测见下），留两次改。
- 某一样用完了，那一个调用不执行、回一句话（「这一问已经检查了 3 次，这次没有执行：还有错就把互动块改简单，或者不放互动块、用文字回答。」），
  别的照常；三样都用完或者到了 9 轮，下一轮 `tool_choice = none`，照已有的回答。每轮最多 4 个照旧。工具列表一直不变（缓存）。
- 到 `tool_choice = none` 那一轮，在最后一个工具结果后面接一句「这一问调工具的额度用完了，不能再调工具。现在直接给出最后的回答……
  互动块没通过检查就不要放进回答，用文字讲清楚。」（读书的 4 轮用完也一样）。实测 qwen3.8-flash 检查三次没过以后被 `none` 挡住，
  在正文里反复写「Emit. 发。Now.」想调工具，一直写到输出上限（130 秒）；加了这句以后见下面实测。接在工具结果里而不是另加一条用户消息，三种协议的消息顺序都不受影响。
- pi 扩展同样的额度（`RoundGuard`：读书按「调了读书工具的轮」计，取说明、检查按次），pi 不能强制 `tool_choice`，超了拦下回一句话，
  总轮数超过 9 + 2 轮就结束这一问。本机 agent 的轮数由它自己管。
- Python 自带 agent 带进下一问的历史不含工具来回（以前就这样），所以下一问要再写互动块得重新取说明；额度每一问重算，够用。
  这是和「取过的段留在对话里，后面几轮走缓存」不一样的地方（pi、本机 agent 是留着的）。

## 用量里看得到什么

`_meta.retainpdf.usage.openui`（这一问调过互动块的工具才有）：`spec_calls`、`sections`（取了哪几段）、`check_calls`、`check_problems`（几次没过）、
`refused`（超额度没执行的）。没有书、只调了互动块的工具时也有 `rounds`、`tool_calls`。

## 实测（2026-11-26，Python 自带 agent，真模型）

不带书（问题里附一小段自己写的原文，不用书的内容），每问一个新会话。4 个适合互动的问题（指数衰减公式加滑块、四个概念做闪卡、
牛顿迭代怎么收敛、三种排序的增长对比图），4 个普通问题（一句话什么意思、译文对不对、ħ 是什么、总结一段）。
第一轮每问开、关互动块各一次（看多花多少）；第二轮加了下面两处改动以后只开着跑，每问两次。模型 claude-haiku-5-5（Anthropic 协议）、
qwen3.8-flash（DashScope，OpenAI 兼容）。最后把回答里的代码块再用检查器过一遍。

**claude-haiku-5-5**（两轮共 24 问开着）：

- 适合互动的 12 问：**每次都先取说明、只取一次**，取 `core` 加相关的一到四组（闪卡取 `core`、`components:play`；滑块取 `core`、`components:inputs`、
  `components:text`、`functions:builtin`、`functions:numbers`），约 1.2k～3.4k token；然后检查，10 次第一次检查就过，2 次第一次有错（组件参数）、改一次就过；
  **12 个回答各一个互动块，全部过检查**。
- 普通的 12 问：**一次也没写互动块、没调工具**。
- 多花的：普通问题输入多约 1.8k token（L0 加两个工具的说明），第二次起几乎全部按缓存读（`cache_read` 2.1k～2.3k），用时多 0～1 秒；
  写互动块的问题输入 1.1 万～2.5 万 token（其中 0.9 万～1.9 万按缓存读），输出多 0～2.5k，用时 11～25 秒（关着 4～10 秒）。

**qwen3.8-flash**：

- 适合互动的：取说明取得多（一次 5～9 段，难的题两次额度用完、第三次被拒），检查常常不过：第二轮 8 问里闪卡 2/2 一次过、公式滑块 2/2 第三次过，
  牛顿迭代、排序对比 4/4 三次都没过（常见错误：用了不存在的 `@` 函数、名字没定义、定义了没引用）。
- 第一轮牛顿迭代那问：三次检查没过、被 `tool_choice = none` 挡住以后在正文里反复写「Emit. 发。Now.」想调工具，写到 130 秒；
  排序那问把没过检查的块放进了回答。于是加了**最后一轮的那句话**（见「防失控的上限」）：第二轮 4 问没过的都改成文字加表格回答，
  不再放坏块、不再打转，40～66 秒（有一次在回答里提了「工具额度用完了」，又给那句话加了「不用跟用户提工具或额度」）。
- 普通问题第一轮 4 问里 2 问（ħ、总结）也写了互动块。于是把 `openui_spec` 的工具说明加了一句「只在能动手的小界面明显比文字清楚时才写；
  解释一句话、看译文对不对、总结、概念问答这类问题用文字回答，不取说明」（三处一样）：第二轮 8 问里只有「译文对不对」两次都取了说明，
  其中一次写了块（过检查），别的 6 次没调工具。L0 是前端生成的，没改。
- 普通问题输入多约 1.3k token（缓存读 1k），用时基本不变；写互动块的问题输入 1.3 万～5.7 万 token、用时 11～66 秒（关着 5～22 秒）。

结论：Haiku 照分层的设计走（先取、只取要的段、检查、改对），普通问题不乱插；Qwen 写得吃力，靠检查和额度兜住，坏块不会进回答。
额度（取 2、查 3）对 Haiku 绰绰有余，对 Qwen 刚好是兜底。

## 没做的、以后再说

- 本机 agent 实测（Claude Code 经 `retainpdf mcp` 取说明、检查）没跑真模型；接线有单测（MCP 列工具、调用、instructions）。
- 桌面版要带文件、设环境变量（交接记录），桌面打包没改。
- 说明文件出 v2 时（前端改格式）：三处的读取都只认 `version: 1`，读到 v2 会整个关掉互动块，要跟着改。
