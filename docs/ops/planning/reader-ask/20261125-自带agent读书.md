# 阅读页提问：自带 agent 自己读书

2026-11-25（实测跨到 11-26），分支 `feat/ask-agent-tools`。接着 [第 2 步：自带 agent](./20261125-第2步：自带agent.md)：
那时书的上下文全靠前端放进 prompt（位置、选中的字、那一块的原文译文），问别的页、整章、全书就答不上。
接口用法见 [docs/api/16-AI/01-阅读页提问.md](../../../api/16-AI/01-阅读页提问.md) 的「自带 agent 读书」。

## 用户定的（几轮来回）

1. 自带 agent 经**我们的后端**读书，协议对前端照旧是 ACP。
2. 看了第一版（模型拿工具自己读，一问最多 6 轮）：「调用工具太多了，没有直达的，这个很影响使用」——常见的问题要直达：
   **代码先把材料放进第一问**，工具要粗（一次读几页、搜索结果带够上下文）。
3. 中间试过两种写死在代码里的规则：问题带着字就不给工具；后来改成带字只给 `search_book`、最多一次（因为「选中一个词问书里别处
   怎么用它」用户说「这个肯定得放开」）。
4. 最后用户否了写死的规则：「你规定死了也不好这样」。定稿是**材料先给，工具一直在，模型自己定**：
   - 材料：选中的字和那一块（前端已附）之外，代码补所在的节、同页前后的块；不带字的取那一页；没有文字层的页附页图；系统提示词带目录。
     常见的问题靠这些直接答。
   - 每一问都给同一套工具，代码不按问题的样子删工具；什么时候用只靠提示词引导（材料里有就直接答，答案明显在别处才调，找过就答）。
   - 只留一个宽的防失控上限（4 轮、每轮 4 个），到了就让模型照已有的回答——是保险，不是规则。
   - **控制靠实测**：典型问题还在调工具，就改提示词或材料，不加代码规则（下面「实测」写了改了什么）。
   为什么不写死：问题千变万化，「带不带字」管不住「这个词前面哪里定义过」「和第 30 页说的一样吗」这类问法，写死了要么挡住该查的、
   要么放进不该查的；模型看着材料和问题自己判断更准，代价是要靠实测盯着。

## 做法

### 哪本书、拿什么读

- 握手加查询参数 `job_id`（阅读页打开的任务；合并阅读的虚拟任务 `merged-…` 也行）。路由先查字符（`ask_job_id`，400），再用任务包的
  `ask_book_document_id`（和阅读页同一个加载函数 `load_supported_job`，没有就 404）取书编号；多用户下 `job_id` 在查询串里，
  `enforce_access` 本来就按它核归属（虚拟任务按书核）。本机 agent 不看它。
- 桥经环境变量给 agent：`RETAIN_ASK_JOB_ID`、`RETAIN_ASK_DOCUMENT_ID`、`RETAIN_ASK_BACKEND_URL`（`loopback_base_url`：后端配置的
  地址和端口，`0.0.0.0` 换成 `127.0.0.1`、`::` 换成 `[::1]`）、`RETAIN_ASK_BACKEND_KEY`。
- **密钥**：有 AI 专用密钥（`RUST_API_AGENT_KEYS`）就用排序后的第一把——只能调登记了 `agent` 的接口，正好是读书要的几个；
  没配（现在的桌面版就没配）用本机主密钥。理由：密钥只进 agent 子进程的环境变量，不进日志、不给模型；模型不能挑地址，
  请求是代码写死的几个 GET，书由桥定。和桥本身（后端进程里）同一个信任等级。一把都没有（认证都过不了，不该发生）就不给书。
- 读的接口：`GET /jobs/{job_id}/reader/regions`（阅读页那一份，页码、块号和阅读页一致，原文、译文、标题层级都在）——这次登记加上
  `agent`（AI 专用密钥能调的从 7 个变 8 个，`route_manifest` 的钉表跟着改）；页图用已经开给 `agent` 的两个页图接口。
  没有另加接口：搜索在 agent 进程里对这份块做（全文索引 `blocks_fts` 用任务自己的页号，合并阅读时和阅读页对不上）。
  70 页的书这一份 1.2 MB，会话一开就在后台取，留在进程里。

### 材料先给（`server.py` 的 `_plan`，`tools.py` 的 `background` / `prefetch` / `overview`）

| 这一问 | 代码先放进第一条用户消息最前面的材料 |
|---|---|
| 带字（`_meta.retainpdf.anchor` 有选中的字 / 原文 / 译文，或者问题前面有前端写的「我选中的这段：」「这一块的原文：」「这一块的译文：」） | 那段字前端已经附了；补所在的节、同页前后各一块（每块 ≤500 字）；问题写了「第 N 页」再带那一页（≤4000 字）。书没取到最多等 1.5 秒，不行就不带 |
| 不带字（点在空白处、扫描页、问整本书、追问） | 出处的那一页或问题里写的页（≤6000 字；有块号时是那一块和同页前后三块）；没有文字层就附页图 |

系统提示词另带页数和两级目录（≤3000 字，整个会话不变，能缓存）。「带不带字」只用来挑取哪种材料，不管工具。

- 位置从哪来：前端现在把出处写成一段字（`frontend/packages/reader/src/ask/acp-adapter.ts` 的 `anchorPromptBlocks`），最后一行
  「（RetainPDF 任务 <任务>，块 <块>，第 <页> 页）」。agent 先看 `session/prompt` 的 `_meta.retainpdf.anchor`（前端以后直接给，
  和问答记录同一个锚点写法），没有再认这行字。认字是权宜：前端改了出处的写法，这里的正则要跟着改（测试里钉着前端的写法）。
- 历史里存的是问连同材料，追问时模型还看得到。

### 工具和循环

- 每一问都给 `read_pages`（一次最多 5 页）、`search_book`（每条带页码、所在的节、整块原文译文）、`view_page`；防失控上限 4 轮、每轮 4 个，
  到了下一轮 `tool_choice = none`、多出的调用不执行并告诉模型。
- 三种协议原生的工具调用：Anthropic `tools` / `tool_use`（`input_json_delta` 拼参数；开了思考要把思考块连签名原样带回）、
  OpenAI Chat `tools` / `tool_calls`（按 `index` 拼；`reasoning_content` 跟着带回，DeepSeek 思考模式调工具要求带回）、
  Responses `function_call`（`strict: false`，带回时不带条目 id 和推理条目，`store: false` 查不到）。工具结果：Anthropic 的图放在
  `tool_result` 里；另两种工具结果只能是文字，图另起一条用户消息。
- 循环在只用标准库的核心里（`AskAgent`），接线只管流：产出 `tool_call`、`native`（这一轮要原样带回的东西）。
- ACP：每个工具一条 `tool_call`（`in_progress`，`title`、`kind`、`rawInput`）和一条 `tool_call_update`（`completed` / `failed`，一句摘要）。
  工具出错交回模型。叫停时不等工具（工具在旁边的线程跑）。
- 用量：`used` 是最后一轮占的上下文，`_meta.retainpdf.usage` 是各轮加起来，另有 `rounds`、`tool_calls`、`context`
  （代码取的哪种材料、哪些页、几块、几毫秒）。Anthropic 有工具时每轮在最后一条消息打缓存断点（加上历史和系统那两个，最多 3 个）。

## 实测

起一个临时后端（临时数据目录，只拷进一个真实任务：70 页的论文，DB 里只拷这一个任务、上传、书的几行，不碰开发者在 41000 端口的后端），
用 AI 专用密钥；直接起 agent（`python -m retainpdf_ask_agent`，环境变量照桥给的写；桥这一段由 `api_tests::acp_bridge` 起真后端测）。
带字的问题照前端 `anchorPromptBlocks` 的写法附出处。思考档 low。每个问题一个新会话（「追问」接上一问），会话开了等 1 秒再问（用户打字的时间）。

**第一版（只有工具、不先给材料，最多 6 轮）**，Haiku 4 问：每问都调了工具（1、3、3、1 个），首字 3.2–8.3 秒。用户嫌多。

**定稿（材料先给、工具一直在）**。「首字」是发问到第一段思考或正文（Haiku 先出思考摘要），「总」是到答完：

| 组 | 问题 | Haiku 工具 / 首字 / 总 | Qwen 工具 / 首字 / 总 |
|---|---|---|---|
| (a) 带字，问这段本身 | 这句译得对吗 | 0 / 5.6 / 7.5 秒 | 0 / 0.6 / 7.3 秒 |
| | 解释这段 | 0 / 2.1 / 6.1 秒 | 0 / 0.8 / 22.9 秒 |
| | 这个公式什么意思 | 0 / 3.5 / 8.4 秒 | 0 / 0.8 / 7.3 秒 |
| | 选中「tensors」问这个词在这里指什么 | 0 / 2.9 / 4.7 秒 | 1（读第 4、5 页：定义在第 4 页）/ 0.7 / 19.9 秒 |
| | 追问：再说细一点 | 0 / 3.5 / 8.2 秒 | 1（读第 4、5、18、19 页）/ 0.6 / 57.1 秒 |
| (b) 带字，问书里别处 | 选中「tensors」问书里别处怎么用 | 1 次搜索 / 2.7 / 10.0 秒 | 1 次搜索 / 1.1 / 11.2 秒 |
| | 选中「spectral point」问前面哪里定义过 | 1 次搜索 / 3.6 / 7.7 秒 | 1 次搜索 / 0.6 / 7.5 秒 |
| (c) 不带字 | 第 5 页讲了什么 | 0（代码取了第 5 页）/ 3.5 / 7.4 秒 | 0 / 0.6 / 14.4 秒 |
| | 书里哪里讲到 Poincaré 不等式 | 1 次搜索 / 4.2 / 12.5 秒 | 2 次搜索（同一轮）/ 0.7 / 23.1 秒 |
| | 主要结论、证明分几步 | 1（读第 1–5 页）/ 2.6 / 11.4 秒 | 2（读第 1–10 页，两轮）/ 0.5 / 22.1 秒 |

- 带字的材料取用 0–1 毫秒（书在会话一开就在后台取好了）；不带字的那一页同样。
- Haiku 的 (b) 第一次跑「前面哪里定义过」碰上一次 Anthropic 读超时（JSON-RPC 错误，会话照常），重跑那组得到上表。
- 回答质量：(a) 都答在点上；(b) 两家都找到定义 2.1（第 4 页）、别处的用法和页码；(c)「哪里讲到」都找到附录 F、定理 F.6（第 40 页），
  「主要结论」给出定理 1.1 的界和推论。
- 花费（按 `data/pricing` 的价）：这一轮 Haiku 10 问约 0.011 美元（输入 7.7 万、输出 0.85 万 token），Qwen 10 问约 0.017 美元。

**中间怎么调的（只改提示词，没加代码规则）**：第一次按定稿跑，(a) 里 Haiku 只有追问调了 1 次；Qwen 在「解释这段」「这个公式」
「这个词」都去读了页（1、1、1 次），追问读了 4 次。提示词加了两句：「每调一次工具，用户都要多等好几秒」；「段里的术语在书的别处
有正式定义，也先按材料和你的知识解释，不去查；觉得多读几页『会更全面』也不要读，先回答，末尾可以说『要的话我可以去读第几页』」，
并把「再说细一点」列进直接回答的例子。之后 Haiku (a) 全是 0；Qwen 降到 0、0、0、1、1——剩下的两次都是去第 4 页找「tensors」的
正式定义，算得上有理由。要再压只能继续改提示词或把材料给多一点（比如带字时同页前后两块），留着看用户实际用的情况。

## 已知的问题

- 出处是从前端那段字里认的，前端改写法要跟着改；前端在 `_meta.retainpdf.anchor` 里直接给就没这个问题（交接里写了）。
- 搜索是子串匹配（不分大小写、几个词都要在同一块里），没有词形变化、同义词；书大到几千页再看要不要改用全文索引。
- Qwen 比 Haiku 爱读页；靠提示词压，没有硬上限之外的拦法（用户的定稿就是这样）。

## 没做

- 前端：握手带 `job_id`（交接里写了）；可选在 `session/prompt` 的 `_meta.retainpdf.anchor` 里给锚点。
- 桌面版生成 AI 专用密钥（第 4 步，前端会话）；现在用本机主密钥读。
- 问答的用量进用量台账（台账按任务记）。
