# 书只放一个窗口

2026-11-04。用户说笔记快速上下滚动时还是卡，内容会晚出来。看过思源怎么处理长文档以后，用户说「做」。思源是在页面上只放一个窗口，往一头接、另一头卸。

## 卡在哪

在 WebKit 里，用真笔记的副本快速来回滚。

- **中等长度的长笔记**（几百个公式）
  - 原因：公式要等滚到附近才画，一到新地方就一口气画上下七屏，那一帧要 0.1–0.4 秒。
  - 改法：这类笔记打开后在后台画完公式。
- **书**（超过 1500 个公式或 40 万字，比如两本 OCR 的书）
  - 原因：3000 个块都在页面上，开头附近有一段变高或变矮，后面整本都要重排。试过的 CSS 都改不了。
  - 改法：编辑器里只放一个窗口。

## 做了什么

- Studio 的编辑器里只放书的一个窗口（`frontend/studio/src/studio/editor/book-window.ts`）。窗口前后的原文留在内存里。编辑器对外报的始终是整篇，所以保存、选中的行号、审阅都照旧。
- 滚动时一帧读下一段、下一帧放进去，等滚动停下后再放掉远的一段。动屏幕上方的内容，要等滚动停下来再做。
- 目录列出整本书的标题；「读到哪」记住窗口开在哪。
- 过程中修了两处滚动问题：
  - 位置被补了两遍：ProseMirror 连外层元素一起滚了，scroll-anchor 又补了一遍。
  - 不足 1 像素的零头会越攒越多。
- 后台画公式：每帧最多画 8 个，页面滚动时暂停。

详细的做法、数字、走不通的路，见 Studio 的开发记录 `frontend/studio/docs/long-articles.md`「第五轮：书只放一个窗口」。

## 结果

用 WebKit 测真书（190 万字节、6400 个公式）：

- 页面里的块：3054 → 一两百
- 最长一帧：1.6 秒 → 约 0.17 秒

600 多个公式的笔记，现在一帧都不超过 100 毫秒。

## 还没做的

- 书里 ⌘F 只在窗口里找。
- 换窗口以后，撤销只能撤销窗口里的修改。
