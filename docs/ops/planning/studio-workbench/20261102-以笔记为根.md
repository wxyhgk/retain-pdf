# 以笔记为根：书在笔记旁边打开

2026-11-02。接着 [搬进 RetainPDF](./20261102-搬进RetainPDF.md)。

## 为什么

搬家以后用户还是觉得阅读页和笔记没打通：书在「翻译」里，笔记在页面树里，中间靠按钮、跳转和消息来回。
我先提议「一本书就是一页」（书和它的笔记合成页面树里的一页），用户否了：

> 一本书就是一页的话，我们的笔记就没有办法整合在一起，因为很多时候我们要调研一个东西是需要多个 PDF 一起看的，
> 所以我们应该以笔记为根本。

## 定下的样子

笔记是页面，书是在笔记旁边打开的资料。

```
┌ 页面 ────────┬ 过渡态调研（笔记）────────────┬ 资料 ─────────────────────────┐
│ ▸ 过渡态调研 ◀│ # 什么是过渡态                │ [量子化学 41] [统计力学 12] [+] │
│ ▸ 读书笔记    │ 两本书说法不一样：            │ ┌───────────────────────────┐ │
│ ▸ 日志        │ 「…能量最高点…」 [↱量子化学]   │ │ …乙烷的构象…               │ │
│              │ 「…鞍点…」       [↱统计力学]   │ │ ▌← 这篇笔记摘过             │ │
│              │ 我的理解：…                    │ └───────────────────────────┘ │
└──────────────┴───────────────────────────────┴───────────────────────────────┘
```

- 任何一篇笔记旁边都能开几本书，一本一个标签，切换不重新加载。
- 点笔记里的出处，那本书在旁边翻到那一段；笔记不被换走。
- 摘录进当前开着的这篇笔记。
- 笔记记得自己开着哪几本书、各读到哪一页，再打开时资料原样回来。
- 书的页边标出这篇笔记摘过的段落，点它回到笔记里那一段。
- AI 看得到这篇笔记和旁边所有的书。
- 一本书一篇的「读书笔记」照旧能用：只开了一本书的笔记。

## 先做什么

上面每一条都要阅读器能在一页里开好几个。现在的 `@retainpdf/reader` 做不到：书从地址栏来、往地址栏写页码，
适配是全局一份，主题写在 `<html>` 上，快捷键挂在 window 上，样式不分范围。第一块是把它改成给书和位置的组件、
能同时开几个；RetainPDF 自己的阅读页改用它，行为不变。分几步合，每步阅读页和前端测试都照常过。
做完在 Studio 里放一个能开两本书的样子给用户看，再接摘录、标记、AI。
