# 以笔记为根：书在笔记旁边打开

2026-11-02。接着 [搬进 RetainPDF](./20261102-搬进RetainPDF.md)。

## 为什么

搬家以后用户还是觉得阅读页和笔记没打通：书在「翻译」里，笔记在页面树里，中间靠按钮、跳转和消息来回。
我先提议「一本书就是一页」（书和它的笔记合成页面树里的一页），用户否了：

> 一本书就是一页的话，我们的笔记就没有办法整合在一起，因为很多时候我们要调研一个东西是需要多个 PDF 一起看的，
> 所以我们应该以笔记为根本。

## 定下的样子

笔记是页面，书是在笔记旁边打开的资料。

```
┌ 页面 ────────┬ 过渡态调研（笔记）────────────┬ 资料 ─────────────────────────┐
│ ▸ 过渡态调研 ◀│ # 什么是过渡态                │ [量子化学 41] [统计力学 12] [+] │
│ ▸ 读书笔记    │ 两本书说法不一样：            │ ┌───────────────────────────┐ │
│ ▸ 日志        │ 「…能量最高点…」 [↱量子化学]   │ │ …乙烷的构象…               │ │
│              │ 「…鞍点…」       [↱统计力学]   │ │ ▌← 这篇笔记摘过             │ │
│              │ 我的理解：…                    │ └───────────────────────────┘ │
└──────────────┴───────────────────────────────┴───────────────────────────────┘
```

- 任何一篇笔记旁边都能开几本书，一本一个标签，切换不重新加载。
- 点笔记里的出处，那本书在旁边翻到那一段；笔记不被换走。
- 摘录进当前开着的这篇笔记。
- 笔记记得自己开着哪几本书、各读到哪一页，再打开时资料原样回来。
- 书的页边标出这篇笔记摘过的段落，点它回到笔记里那一段。
- AI 看得到这篇笔记和旁边所有的书。
- 一本书一篇的「读书笔记」照旧能用：只开了一本书的笔记。

## 顺序（用户定的）

规划过阅读器改成组件要分 11 步（适配跟着每个阅读器走、书和位置从参数来不读地址栏、快捷键只给看着的那个、
样式只管自己那块……），全部做完才看得到变化。用户选了先搭界面：每本书先是一个 RetainPDF 阅读页（iframe），
把「以笔记为根」的用法做出来用上；之后一步步把阅读器改成组件，换掉每个标签里的 iframe，界面和用法不变。

## 第一块做了什么（Studio）

- 每篇笔记顶栏多「书」（换掉原来书的笔记才有的「读原书」）：左边书、右边笔记，竖线能拖、能收起（和「翻译」里的笔记同一套）。
- 书的来源：这篇笔记摘过的书（编辑器里摘录的出处），「书」是一本书的笔记时那本书；＋ 从书库挑（Studio 的服务器问 RetainPDF
  的 `/api/v1/documents`，新路由 `GET /api/studio/retainpdf/books`）；× 关掉。按笔记记在浏览器里（`retainpdf-note-books`）。
- 每本书一个 iframe（`wiring/book-tabs.ts`），点到才加载、之后藏起来不卸，最多留 6 个；跨笔记同一本书共用。直接打开阅读页
  （不再先开书库再跳），不报自己的「笔记」能力（`hello.features` 只有 quote、ask-ai）。
- 点摘录的标志、AI 回答里的出处：在笔记上时书在旁边翻过去，笔记不动；在「翻译」里照旧。
- 旁边的书「摘到笔记」进当前这篇笔记；读到哪告诉 AI，带上这篇笔记。
- 契约、RetainPDF 都没改。

真书试过：开发栈两本书在一篇笔记旁边各开一个标签，书名从阅读页报来的换成书库里的，切回第一本不重新加载、停在 41 / 89。

## 接下来

- 书的页边标出这篇笔记摘过的段落，点它回到笔记：要 RetainPDF 的阅读页能画标记，契约加一条消息（后端会话）。
- 旁边的书里阅读页自己的「×」（回书库）在标签里没有意义，嵌在笔记旁边时藏起来。
- 阅读器改成组件（`@retainpdf/reader` 现在书从地址栏来、往地址栏写页码，适配是全局一份，主题写在 `<html>` 上，
  快捷键挂在 window 上，样式不分范围）：改成给书和位置、一页能开几个的组件，RetainPDF 自己的阅读页改用它，
  行为不变；分步合，每步阅读页和前端测试都照常过。做完把每个标签里的 iframe 换成它。
