# 书库进 Studio（2026-11-04）

## 为什么

作者说：「书库部分感觉还是没有融入我们的笔记软件里面来」。

那时左栏「书库」是在中间放 RetainPDF 自己的书库页（iframe）：样子、字号、按钮、底部悬浮栏都是另一个软件的；书卡只知道书，不知道笔记里摘了它什么。

作者选了：

- **做成 Studio 自己的一页**：像「全部页面」「资料库」一样用 Studio 的界面画，数据走 RetainPDF 的接口；
- **分工**：Studio 这头由 Studio 会话做，前端会话（商业版进展）配合接口；它手上改书库 iframe 的几件（书库点书、书库卡片的点法和文案）不用做了，「资料库里的 PDF 送去翻译」并进这里。

## 做了什么（studio/library-view）

- **服务器**（`server/retainpdf-library.mjs`）：
  - `shelf`：书列表，加上各书当前任务的状态（`GET /jobs?job_ids=`：排队、在跑的站名和百分比、失败的一句话原因）；
  - `cover`：封面（`/documents/:id/files/thumbnail.jpg`），由服务器带着密钥去取；
  - `bookDetail`：书、它的任务（`/documents/:id/jobs`）、翻了多少页（`translation-coverage`）、目录（阅读用的那个任务的标题块，照 RetainPDF 阅读器的 `readerOutline`）；
  - `jobAction`：停下（`actions/cancel`）、续跑（`actions/resume`）。
- **笔记里的摘录**（`ArticleRepository.bookQuotes`）：各篇笔记里的 `retainpdf:` 出处链接按书（没有书号的按任务）收起来，每段带页码、块号、开头几个字；笔记没改过就不重读。
- **接口**：`GET /api/studio/retainpdf/shelf`、`…/shelf/:document`、`…/shelf/:document/cover`、`POST /api/studio/retainpdf/jobs/:job/(cancel|resume)`。
- **页面**（`library/BookShelf.tsx`、`book-shelf.css`）：
  - 书卡上有封面、读到哪、摘了几段几篇笔记、翻译进度；
  - 筛选：全部、摘过的、翻译中、未翻译；
  - 右边的详情里有摘录（按笔记分开，点了打开笔记到那一段）、目录（点了书开在笔记旁边那一页）、翻译任务（停下、续跑）。
  - 点书 = `openBookBesideNote`。
- 左栏「书库」按钮（`#open-library`）打开这一页；从「上传 PDF」进到 RetainPDF 自己的页面时，按钮也还亮着。

## 还没定、要作者点头的

**在 Studio 里上传 PDF 并翻译**。接口是 `POST /uploads`，再 `POST /documents/:id/translate`。但请求体光给 `{}` 跑不起来（后端会话查过）：

- 模型、base_url、OCR 服务商、`credential_ref`，是 RetainPDF 网页用它浏览器里存的设置拼进去的（`frontend/web/src/features/ingest/domain/workflow/payload-assembly.ts`）；
- 密钥在服务器的凭据库里。

两条路：

1. Studio 自己存一份「翻译用哪个模型 / OCR / 凭据」（凭据从 `/credentials` 列出来挑）；
2. 请后端加「服务器端默认的翻译、OCR 设置」，网页和 Studio 都用它。后端会话说这是新功能，要作者点头。

定之前，「上传 PDF」先打开 RetainPDF 自己的页面去传。
