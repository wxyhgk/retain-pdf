# 阅读页唤出笔记（2026-11-01）

接着 [书和笔记接在一起](./20261101-书和笔记接在一起.md)。摘录 → 笔记 → 点回原文那一圈做完后，用户：真正要的是在阅读页里直接唤出笔记，
边读边记。

## 定下来的

- **并排，不另写编辑器。** 在 Studio 的「翻译」里，左边 RetainPDF 阅读页，右边这本书的笔记，用的是 Studio 自己的编辑器。
  不在 RetainPDF 里另做一个笔记编辑器（那样是两个编辑器、两份笔记，又分开了）。
- **唤出**：阅读页加「笔记」按钮，点了右边出来这本书的笔记，再点收起；中间的分隔条能拖。
- **一本书一页笔记，放在「读书笔记」下面**（用户选了 A：一个普通页面下面每本书一个子页面；以后要像书库那样有列，再升级成数据库）。
  第一次唤出时新建，标题是书名，属性里记下书的编号和任务编号；以后按书的编号找回这一页（没有书的编号时按任务编号）。
- **摘录当场可见**：笔记开着时，「摘到笔记」写进右边这一页。

## 消息（studio-bridge.v1，只加不改）

| 方向 | type | 什么时候 |
|---|---|---|
| Studio → RetainPDF | `hello` 多一个可选的 `features` | 写 Studio 会处理的：`quote`、`open-notes`。早先的 Studio 不发，RetainPDF 就不显示「笔记」 |
| RetainPDF → Studio | `open-notes`（任务、书、书名） | 点了「笔记」，笔记收着时 |
| RetainPDF → Studio | `close-notes` | 再点「笔记」，笔记开着时 |
| Studio → RetainPDF | `notes`（开着没有、哪一页） | 握手后一次，以后每次变了；RetainPDF 的 `ready` 里有 `notes` 才发 |

## 分工

| 谁 | 做什么 |
|---|---|
| 后端（本仓库） | 契约、契约测试、这份方案、前端交接 |
| 前端会话 | 阅读页「笔记」按钮：`hello` 的 `features` 有 `open-notes` 才显示；按 `notes` 显示开关；点了发 `open-notes` 或 `close-notes` |
| Studio | `hello` 带 `features`；「翻译」里左右并排、分隔条；按书找或新建笔记页（「读书笔记」下面）；收 `open-notes`、`close-notes`，发 `notes` |
