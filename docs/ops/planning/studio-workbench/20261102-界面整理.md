# Studio 里的界面整理：不挤、不重复、名字对得上

2026-11-02。接着 [以笔记为根](./20261102-以笔记为根.md)。

## 为什么

用户：「感觉目前的前端还是很奇怪」。走一遍（一篇笔记、打开「书」、＋ 挑两本、切到书库）列了四条，用户认了三条，另说
「RetainPDF 的阅读页面得大改，目前非常不好用」：

- 太挤：打开「书」时一屏四栏（页面树、书、笔记、右边的文件面板），书不到一半宽。
- 两套界面叠在一起：书的标签里是整个 RetainPDF 阅读页，带它自己的「关闭」；书库里还有 RetainPDF 自己的「AI 问答」，加上 Studio 的
  AI、阅读页的 AI，三个 AI 入口。
- 名字对不上：书在左栏的「翻译」里，「资料库」里却是文件。

## 做了什么

- 打开「书」时右边栏收起（和书库里开着书的笔记一样），收起「书」就回来；书和笔记各占一边。
- 左栏「翻译」改叫「书库」（图标换成书）；给 AI 的说明、设置、文档跟着改。「资料库」不改：右栏已有「文件」，「书库」和「资料库」
  已经分得开，改名会动到很多提示和给 AI 的工具说明。
- 放在 Studio 里时：
  - RetainPDF 图书馆顶上不出自己的「AI 问答」（`:root[data-embed="studio"]`）。
  - 笔记旁边的书标签，Studio 加载阅读页时地址多带 `embed_pane=beside`，阅读页据此不出「关闭」（标签自己能关）；书库里的阅读页照旧有。
  - 阅读页浮动的「AI」留着：打开「书」时右边栏收起，它就是打开 Studio 的 AI 的地方（它打开的就是 Studio 的 AI）。

## 还没做

- 阅读页大改：先在全宽下用一本书认真读一遍，把不好用的列出来、画个样子给用户定，再动；和「阅读器改成组件」一起做。
- ＋ 挑书的菜单太简陋（用户这次没选）。
