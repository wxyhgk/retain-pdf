# 书库点书在笔记旁边打开

2026-11-03。

## 用户定的

我把两种方式摆给用户看：

- **整页读**：书是主角。书宽、读得舒服，但笔记要另外打开，而且读书有两种样子。
- **在当前笔记旁边打开**：笔记是主角。书是这篇笔记的一个标签，但书只有半边宽；随手翻一本书时，这本书也会挂到当前笔记上。

我的建议是两者结合：点书在笔记旁边打开，书标签上另有「⤢ 整页读」。用户选了「两者结合」。

## 怎么做的

- **契约**（后端，`feat/studio-bridge-open-book`）：
  - 新消息 `open-book`，RetainPDF → Studio，带 `job_id`、`document_id`、`title`，可选 `page_idx`。
  - `StudioFeature` 加 `open-book`。Studio 在 `hello.features` 里写了它，RetainPDF 才发。
  - 同一个分支里把 `open-notes` 的说明改成「打开正在写的那篇」。
- **RetainPDF**：
  - 书库里所有「读这本书」都走 `ReaderNavigation`，包括卡片上的「对照阅读」和详情框里的阅读按钮。
  - 它算出该打开的任务以后，如果放在 Studio 里、Studio 又认 `open-book`，就把书交给 Studio，自己不开阅读页（`handOffBook`，由 `HomeApp` 接上 `studioEmbed.openBook`）。
  - 只读原文、还没有任务的书交不了，照旧自己开。
  - 点卡片本身还是弹详情框：翻译、删除这些管理都在里面，没去掉。
- **Studio**：
  - 书库那一页的 `hello.features` 带 `open-book`，笔记旁边的书标签不带，所以书标签里不会再往外交书。
  - 收到 `open-book` 就回到正在写的笔记（一篇都没开着时新建一篇），把书作为标签开在旁边，有页就到那一页，没有就从上次读到的地方开。
- **⤢ 整页读**：
  - 书标签栏最右边的按钮：书铺满中间，笔记先收起来；这时摘的段落照样进它，会提示进了哪篇。
  - 再点（⤡）回到并排；收起书时也回到并排。

## 验过的

- RetainPDF 测试：
  - `ReaderNavigation` 交给 Studio：交的是合并后的任务，带页的也交；Studio 不认、只读原文的照旧开。
  - `open-book` 对得上契约；没握手、Studio 不认都不交。
  - 能力清单是四项。
  - 全部 1946 条过。
- Studio 浏览器测试：书库点书 → 回到笔记、书在旁边、到那一页；书标签不往外交；⤢ 整页读。
- 真的 RetainPDF 上走了一遍：书库点「对照阅读」，书开在「Studio 测试夹具」旁边；⤢ 后铺满。
