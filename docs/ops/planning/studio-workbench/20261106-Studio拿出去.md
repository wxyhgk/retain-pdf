# Studio 拿出去、RetainPDF 放进 Studio

2026-11-06。改 [Studio 搬进 RetainPDF](./20261102-搬进RetainPDF.md) 的「Studio 放在 `frontend/studio/`」：反过来，Studio 回到自己的仓库，
RetainPDF 的阅读器和书库做成组件放进 Studio。那份里「阅读器改成组件、去掉 iframe 和握手」的方向不变，变的是谁装着谁。

## 用户定的

- 「我建议把 studio 拿出来，我们后续将我们的 retainpdf 放到我们的 studio 里面。」
- Studio 去**自己的仓库**，带着历史；retain-pdf 回到只放 RetainPDF。
- 放进 Studio 的是**阅读器和书库**：Studio 是外壳，直接放这两个组件，不再用 iframe。上传、翻译、后端照旧是 RetainPDF 的服务，
  Studio 去调。

## 几步

1. **拿出去**：把 `frontend/studio/` 带历史拆到 Studio 自己的仓库（只取这个文件夹的提交，路径改回仓库根），Studio 在那边照原样能跑、
   测试能过；作者的 RetainPDF.app（`tools/studio-app`）和 4321 的服务器改指新位置。之后 retain-pdf 删掉 `frontend/studio/`、
   根目录 `.gitmodules` 里的 milkdown 子模块，文档里的链接改成指向 Studio 仓库。retain-pdf 已推送的历史里照旧有 Studio，删不掉，也不用删。
2. **阅读器做成组件**（前端会话）：`@retainpdf/reader` 现在从地址栏读任务、往地址栏写页码，适配、主题、快捷键都是全局一份。
   改成给任务和位置、只管自己那块的组件；RetainPDF 自己的阅读页改用它，行为不变。这几天给嵌入加的（`hostChrome`、quoted、
   reader-state / reader-command 的那套状态和命令）就是组件的接口，换成直接调用。
3. **书库做成组件**（前端会话）：书库现在是 `frontend/web` 的整页应用，拆出书架、详情、上传几块给 Studio 放。
4. **Studio 直接放这两个组件**（Studio 会话）：去掉 iframe 和握手，摘录、读到哪、跳转都直接调用；浏览器里的组件经 Studio 的服务器
   去问 RetainPDF（密钥不进浏览器）。studio-bridge.v1 在两边都换完以前留着。

## 还没定的

- Studio 怎么拿到 `@retainpdf/reader` 和书库组件：发 npm 包、git 依赖，还是本机并排两个检出用路径接。第 2 步开始前定。
- 桌面版：[搬进 RetainPDF](./20261102-搬进RetainPDF.md) 第 4 步说合成一个 RetainPDF 的 Electron 桌面版；Studio 做外壳以后桌面版跟谁走，到时候再定。
- 拿出去以后 Studio 的规矩（推送、CLAUDE.md）照那边仓库的；本仓库 `CLAUDE.md` 里管 Studio 的几条跟着删。

## 分工

- Studio 会话：第 1 步的拆仓库、Studio 那边能跑、作者的 app 改指；第 4 步。
- 前端会话：第 1 步里 retain-pdf 这边删文件夹、子模块、改文档链接（等 Studio 那边能跑了再删）；第 2、3 步。
