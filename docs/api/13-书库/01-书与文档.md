# 书与文档

书（document）是一篇 PDF 的稳定身份：按原文内容的 sha256 去重，同一篇 PDF 不管上传几次、翻译几次，都是同一个
`document_id`；任务（job）是书名下的一次处理记录。后端是书、PDF、产物、封面的唯一真源，前端不在本地存真实文件，
只读接口返回的视图和链接。

接口清单见[接口目录 · 书](../00-接口目录/14-书.md)。字段以契约
[`library-documents.v1.schema.json`](../../../contracts/library-documents.v1.schema.json) 为准（2026-10-22 起，TS 类型
`@retainpdf/contracts/library-documents`；rust_api 的 `api_tests::library_documents_contract` 钉住真实返回的键集合）。
前端怎么接（书详情、合集页）的说明另见 [前端对接说明：图书馆数据层](../../core/frontend/library-api.md)。

## 书列表

```http
GET /api/v1/documents?limit=50&offset=0&reading_status=&collection_id=&tag_id=&q=
GET /api/v1/documents?job_id=<任意任务编号>
```

返回：

```json
{ "documents": [ … ], "total": 128, "limit": 50, "offset": 0, "has_more": true }
```

- 只认 `limit`、`offset`、`reading_status`、`collection_id`、`tag_id`、`job_id`、`q`，不认识的参数 `400`
  （例如很早就删了的 `tag`；按标签筛现在用 `tag_id`）。
- `limit` 默认 50，范围 1..=500，越界 `400`（2026-10-22 以前静默夹），规矩见 [分页](../00-约定/03-分页.md)。
  `limit`、`offset`、`has_more` 照回；`has_more` 就是 `offset + 这一页条数 < total`，页和 `total` 读自同一个快照。
- 排序 `added_at DESC, document_id DESC`：同一秒入库的书（批量上传）翻页不乱。
- `total` 是套用 `reading_status`、`collection_id`、`tag_id`、`q` 以后、分页以前的总数；没有上传记录的书不算、也不列。
- `reading_status`：`unread` / `reading` / `done`。
- `q` 只搜书自己的**书名和原始文件名**（任一包含就算命中，ASCII 不分大小写；`%`、`_` 按字面比；空白等于没给）。
  搜正文用 `GET /search`（见 [合集、标签与检索](02-合集标签与检索.md#全文检索)）。
- **带 `job_id` 是直查，不是翻页**：用任意任务编号（含历史任务）找它所属的书，其余筛选和 `offset` 不起作用，最多一条，
  命中 `total: 1`、没命中 `total: 0`；`limit` 照样校验，`limit`、`offset` 照请求回显，`has_more` 恒为 `false`。
  不要再扫列表反查 `active_job_id`。

### 一本书的字段（`DocumentRecord`）

列表项和 `GET /documents/{document_id}` 一样：

| 字段 | 说明 |
|---|---|
| `document_id` | 原文内容的 sha256（hex），稳定不变 |
| `title`、`title_source`、`title_locked` | 书名、书名来源（`filename` / `user` / `ocr` / `pdf_metadata`）、是否被用户锁定，见 [元数据建议](03-元数据建议.md) |
| `source_filename`、`page_count`、`bytes` | 原始文件名、页数、字节数 |
| `active_job_id` | 书卡当前对应的任务：在跑的优先，其次最好的成功任务，再次最近提交的。**打开阅读器不要用它**，用 `/reading` 给的 `job_id` |
| `reading_status` | `unread` / `reading` / `done` |
| `added_at`、`updated_at` | 入库、更新时间 |
| `source_pdf_url`、`cover_url`、`thumbnail_url` | 书的文件地址（`/documents/{document_id}/files/…`），见 [下载总览](../07-产物下载/01-下载总览.md#书的文件)；空的时候整个键不出现 |
| `has_translation` | 有没有**任何**成功的、不是纯 OCR 的任务，即「能不能对照阅读」。和 `active_job_id` 无关：重新翻译在跑或失败时，旧译文照样能读。只查任务表，不保证 PDF 还在磁盘上，真正能打开什么以 `/reading` 为准 |
| `tags` | 书上的标签 `[{tag_id, name, color}]`，按名字排，没有是 `[]`（2026-11-21 起） |
| `active_version_id` | 早已删掉的 AI 改写文档留下的，2026-11-21 起恒不出现，不要用 |
| `authors_json`、`year`、`doi`、`last_opened_at` | 没有写入点，恒为 `"[]"`、`null`、`""`、`null`；留着只为不破坏旧客户端，不要拿来显示 |

## 读、改、删一本书

```http
GET    /api/v1/documents/{document_id}
PATCH  /api/v1/documents/{document_id}          {"title": "…", "reading_status": "reading"}
DELETE /api/v1/documents/{document_id}?force=true
```

- `PATCH` 只认 `title`、`reading_status`，别的字段 `400`；`reading_status` 不是那三个值 `400`。
  手动改书名会把 `title_source` 设成 `user`、`title_locked` 设成 `true`，之后自动命名不会再覆盖。
- `DELETE` 删整本书：书名下所有任务（含每个任务的 `-ocr` 子任务）、上传、原文和书的记录。查询串只认 `force`，拼错 `400`
  （以前当成不强删）。名下有排队 / 运行中的任务时不带 `force` 返回 `409` + `error.details.reason = "job_active"`；
  带 `force=true` 先取消再删。依赖者在别的书里时也可能 `409 job_has_dependents`。原因表见
  [认证与错误 · 删除的 409 原因](../00-约定/02-认证与错误.md#删除的-409-原因)。
  返回 `{deleted, document_id, removed_jobs, removed_paths}`；`removed_paths` 是服务器路径，只用来排查。
- 只删一个任务、书留着：`DELETE /jobs/{job_id}`，见 [删除任务](../01-任务/05-删除任务.md)。
- 同一篇 PDF 再传一次不会多一本书：不要假设「上传成功 = 列表多一条」。

书不存在是普通 `404`（`document not found: …`）；书的记录在、库里读不出来是 `500`，不说成不存在。

## 书的任务列表

```http
GET /api/v1/documents/{document_id}/jobs?limit=20&offset=0
```

返回 `{items, invocation_summary, total, limit, offset, has_more}`，`items` 是和 `GET /jobs` 一样的任务列表项
（`JobListItemView`，契约 `job-status.v1`），失败的带精简的 `failure`。

- **刷新页面后恢复 OCR、翻译、渲染状态以它为准**，不要只记浏览器内存里最后一个 `job_id`。
- 排序 `updated_at DESC, job_id DESC`，同一时间戳的任务翻页不乱。
- 只认 `limit`（默认 20，1..=500，越界 `400`）和 `offset`，别的参数 `400`。
- `total` 是 `COUNT(*)`；`has_more` 多取一条判断（2026-10-22 起；读不出来的坏行会被列表跳过，以前拿 `total` 算会在最后一页误报还有）。
- 每项带 `attempt`（从 1 数）、`retry_count`、`last_retry_at`，客户端不要从事件条数或时间去推。
- 书名下任务的**活态**（状态、进度、阶段）也可以批量查：
  `GET /jobs?job_ids=a,b&limit=n&include_live_stage=true`（`n` ≤ 500，超了分批），见 [任务列表](../01-任务/03-任务列表.md)；
  标题读 `display_name`，阶段和进度读 `stage_snapshot`。

`GET /documents/{document_id}/agent-versions`（Agent 改写历史）2026-11-03 跟 RetainPDF 自己的 AI 一起删了。

## 翻译这本书、给这本书做 OCR

```http
POST /api/v1/documents/{document_id}/translate
POST /api/v1/documents/{document_id}/ocr
```

请求体是 `POST /jobs` 的同一个 `CreateJobInput`，返回 `JobSubmissionView`；原文由书自己的上传提供，`/translate`
能复用已有 OCR。规则（和入口矛盾的字段 400、复用 OCR 的校验、`runtime.job_id` 不能发）见
[创建任务](../01-任务/01-创建任务.md)。多用户模式下页数额度不够是 `402 PAGE_QUOTA_EXCEEDED`。

## 阅读入口与翻译覆盖

```http
GET /api/v1/documents/{document_id}/reading[?version=<version_id>|auto]
GET /api/v1/documents/{document_id}/translation-coverage
```

`/reading` 告诉阅读器该打开哪个任务：

```json
{ "job_id": "…", "merged": false, "contributing_job_ids": ["…"], "version_id": null }
```

- `job_id` 为 `null`：这本书还没有可读的译文。
- 一本书分几次、每次只翻几页时，返回合并后的虚拟任务 `merged-<document_id>-<指纹>`（`merged: true`），阅读器按普通任务读它
  （`/jobs/{job_id}`、`files/…`、`reader/…`，合并任务按整本书编页）。超过一天没人读、而这本书又生成了新合并的旧 id 会被清理，
  再读得 `404` + `error.details.reason = "merged_reading_expired"`，重新调一次 `/reading` 拿新 id，见
  [认证与错误 · 合并阅读过期](../00-约定/02-认证与错误.md#合并阅读过期404-merged_reading_expired)。
- 每页取最近翻译了它的那个任务；书的页数按原文 PDF 的实际页数，读不了 PDF 才用库里的 `page_count`。
- 查询串只认 `version`，见下一节。原文 PDF 不在磁盘上是普通 `404`。

`/translation-coverage` 给书详情的「进度」用：`{page_count, translated_pages, contributing_jobs, segments, jobs}`，
`segments` 是整本书按页的来源（连续同源的页并成 `{first, last, job_id}`，`job_id` 为 `null` 是原文没翻），`jobs` 是这本书的全部任务
（新到旧，带处理的页、当前合并里取自它的页数、失败原因一句话等）。只计算、不生成合并，和 `/reading` 用同一套「每页取最新」规则。

## 译文版本

2026-11-18 起，一本书的几份译文能切换（方案见 [译文版本第一期](../../ops/planning/translation-versions/20261118-译文版本第一期.md)）。

```http
GET   /api/v1/documents/{document_id}/translation-versions[?include_hidden=true]
PUT   /api/v1/documents/{document_id}/translation-version             {"version_id": "…" | null}
PATCH /api/v1/documents/{document_id}/translation-versions/{version_id}  {"label": "…", "hidden": true}
```

三个都返回 `TranslationVersionsView`：`{document_id, current_version_id, has_newer, versions}`，`versions` 从旧到新，每项有
`version_id`、`name`（显示名：用户起的，没起按翻译设置生成）、`label`、`origin`（`translate` / `retranslate` / `backfill`）、
`base_version_id`、`hidden`、`status`、`job_ids`、`page_ranges`（这个版本自己翻的页，1 起闭区间）、`whole_book`、`engine`、
`model`、`reviewer_model`、`edited_blocks`、`is_current`。

- 整本翻译开一个版本；重新翻译开一个以源任务版本为底的新版本；只翻一部分页时，以用户正在读的版本为底；续跑、OCR 恢复、单独的重渲染
  并进源任务的版本；纯 OCR 任务不是版本。
- `PUT …/translation-version` 的 `version_id: null` 回到自动（逐页取最新）。切到已隐藏的版本 `409`，`error.details.reason = "version_hidden"`
  （2026-11-24 起带），先 `PATCH` 带 `{"hidden": false}` 恢复。版本不存在 `404`。
- `PATCH` 的 `label` 空串是清掉、回到生成的名字，超过 80 字 `400`。
- `/reading?version=<id>` 读指定版本（它自己的页优先，其余沿底版本链往下找），`version=auto` 强制自动；不给读书的当前版本，
  当前版本还没有可读的页时退回自动。隐藏的版本不参与自动合并。回包的 `version_id` 是实际读的版本，`null` 是自动。
- 三个接口和 `/reading` 的请求体、查询串都不认识的字段 `400`。

## 书的文件

原文、封面、缩略图、原文页预览在 `/documents/{document_id}/files/…`，见 [下载总览 · 书的文件](../07-产物下载/01-下载总览.md#书的文件)。
任务列表、详情里的 `cover_url`、`thumbnail_url` 已经指向书的地址；查不到书编号时是 `null`，前端用本地占位封面。
