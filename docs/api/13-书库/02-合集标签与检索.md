# 合集、标签与检索

接口清单见 [接口目录 · 合集](../00-接口目录/15-合集.md)、[标签](../00-接口目录/16-标签.md)、[书](../00-接口目录/14-书.md)（`/search`）。
字段以契约 [`library-documents.v1.schema.json`](../../../contracts/library-documents.v1.schema.json) 为准。
这几组的请求体不认识的字段一律 `400`。查询和关系接口只返回持久化的编号和安全的投影，客户端不要把本地文件路径当资源编号。

## 合集

给书分组的文件夹，v1 只做扁平一层。

```http
POST   /api/v1/collections                       {"name": "…", "parent_id": null}
GET    /api/v1/collections
PATCH  /api/v1/collections/{collection_id}       {"name": "…", "sort_order": 3}
DELETE /api/v1/collections/{collection_id}
POST   /api/v1/collections/{collection_id}/documents               {"document_ids": ["…"]}
DELETE /api/v1/collections/{collection_id}/documents/{document_id}
```

- 列表 `{collections: [...]}` 不分页，按 `sort_order`、再按建立时间排；每项 `collection_id`、`name`、`parent_id`、`sort_order`、
  `created_at`、`document_count`。
- `name` 不能为空（`400`）。建的时候可以带 `parent_id`（前端不发）；`PATCH` 只认 `name`、`sort_order`，带 `parent_id` `400`
  （2026-10-22 起，以前 200 但不生效）。
- 删合集只删文件夹本身，书不动；同时清掉 `<数据目录>/collections/<id>/`，清不掉只记日志，删除照样成功。
- 加书：书不存在 `404`（书的记录在、库里读不出来是 `500`）；重复加同一本是幂等的，不报错、不重复计数。合集不存在 `404`。
- 某个合集里有哪些书：`GET /documents?collection_id=…`，见 [书与文档](01-书与文档.md#书列表)。
- 合集的 Agent 工作区 `POST /collections/{collection_id}/agent-workspace` 2026-11-03 跟 RetainPDF 自己的 AI 一起删了。

## 标签

2026-11-21 起（只增）。一个标签可以打在很多本书上，一本书可以有很多标签。同名（不分大小写、不看首尾空白）的标签只有一个，
编号由名字算出来，两台设备各自建的同名标签同步以后是同一个。

```http
GET    /api/v1/tags                                → {tags: [{tag_id, name, color, document_count, created_at, updated_at}]}，按名字排
POST   /api/v1/tags                {"name": "…", "color": "#RRGGBB"}   同名的已经有了就返回那个
PATCH  /api/v1/tags/{tag_id}       {"name": "…", "color": "…"}
DELETE /api/v1/tags/{tag_id}                       → {tag_id, deleted: true}，从打了它的书上一起去掉，书不动
PUT    /api/v1/documents/{document_id}/tags        {"tag_ids": ["…"]}   设成正好这几个，空数组 = 全去掉；返回改完的书
GET    /api/v1/documents?tag_id=…                  打了这个标签的书
```

- `name` 去掉首尾空白后 1–64 个字（空 `400`、太长 `400`）；`color` 是 `#RRGGBB`，空串或不给 = 不设颜色，别的写法 `400`。
- `PATCH` 改成别的标签已经在用的名字 `409`。书或任何一个标签不存在 `404`。

## 全文检索

```http
GET /api/v1/search?q=光学光谱&limit=20[&document_id=…]
```

搜的是**块级正文**（原文和译文），给阅读器的全文命中用；只搜书名、文件名用 `GET /documents?q=`。

返回 `{query, hits, limit, has_more}`，每个命中：

| 字段 | 说明 |
|---|---|
| `document_id`、`job_id`、`page_idx`、`block_id` | 锚点：`job_id + page_idx + block_id` 就是阅读器的定位坐标 |
| `source_snippet`、`translated_snippet` | 片段，命中词用 `[` `]` 包着，前端可换成高亮 |
| `document_page` | 这一块在整本书里的页号（1 起，2026-11-03 加）；任务记录读不到时是 `null` |

- `page_idx`（0 起）是建索引那个任务自己的本地页号。分段翻译的书两者不同：要跳到 `/documents/{id}/reading` 给的阅读任务
  （合并任务按整本书编页）用 `document_page - 1`；直接打开 `job_id` 那个任务才用 `page_idx`。
- 任意长度的 `q` 都能查（≥3 字走全文索引，更短退回模糊匹配）。
- 只认 `q`、`limit`、`document_id`，别的参数 `400`。`limit` 默认 20、1..=100，越界 `400`（2026-10-22 以前静默夹）；
  没有 `offset`，`has_more` 表示命中不止这些，要更多就加大 `limit`。
- 删任务时会清掉它在全文索引里的行，并按这本书剩下的成功任务重建。
- **索引里的译文是哪一份**（2026-11-24 起）：和阅读入口 `GET /documents/{id}/reading` 同一条规则——书选了译文版本就是那个版本
  （连同来源版本，上层的页盖住下层），没选过就自动（逐页取最新，隐藏版本的任务不算）。不在这份译文里的任务只提供原文，
  所以选了旧版本时搜不到新版本的译文；选的版本里没有能建索引的翻译任务时退回自动。以前不看版本，总是逐页取最新。
- **什么时候更新**：任务完成、删任务时立刻重建；改译文（`PATCH /jobs/{id}/translations/{item_id}`）、切换或隐藏译文版本、
  同步收进别的设备的改动以后，由书库的后台对账重建（改译文、切换版本会立刻叫醒它，几秒内；同步收进的按周期，默认 60 秒，
  见 [书文件夹 · 自动刷新](05-书文件夹.md#自动刷新)）。以前这三种情况索引不更新，搜到的还是旧译文。
