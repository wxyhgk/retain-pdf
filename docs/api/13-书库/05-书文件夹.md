# 书文件夹

把书库导出成 Markdown，放在 `<数据目录>/books/`，给 AI（Claude Code、Codex、Gemini CLI……）直接打开、读、grep。
接口清单见 [接口目录 · 书](../00-接口目录/14-书.md)。方案和后续步骤见规划目录
`docs/ops/planning/ai-data-access/`（「AI 怎么拿到书的数据」）。

这个文件夹是**派生的**：随时可以删掉重新导出；不同步、不备份，每台设备自己生成。文件夹里的东西只读，改了下次导出会被覆盖。

## 导出

```http
POST /api/v1/book-folder/export
{"document_ids": ["…"]}
```

- `document_ids` 不给或为空：导出整个书库，并删掉已经不在书库里的书的文件夹。给了就只导出这几本。
- 请求体不认识的字段 `400`。多用户版不开（`404`）。
- 命令行：`retainpdf books export [--document <书编号>]...`（后端要开着）。
- 返回：

```json
{
  "root": "/…/data/books",
  "documents": 12,
  "exported": 3,
  "unchanged": 8,
  "empty": 1,
  "removed": 0,
  "failed": [{ "document_id": "…", "message": "…" }]
}
```

| 字段 | 含义 |
|---|---|
| `exported` | 重新写了的书 |
| `unchanged` | 和上次导出一样、没动的书（按来源指纹判断，不读区块） |
| `empty` | 没有可导出内容的书（还没识别）；只在 `library.md` 里列出 |
| `removed` | 删掉的文件夹：书删了、书名改了留下的旧文件夹、书已经没有内容 |
| `failed` | 导出失败的书和原因；别的书照常导出 |

可能要生成合并阅读的目录（和阅读入口一样调流水线），书多时第一次会慢。

### 什么时候要重新导出

这一版**只在调接口时写**。识别、翻译完成，改了译文、换了译文版本、改了书名之后，再调一次就会刷新（没变的书不重写）。
自动刷新是后续的事。

## 目录结构

```text
books/
  README.md                  给 AI 的说明
  library.md                 全部书的书目：书名、作者、标签、合集、内容（原文 + 译文 / 只有原文 / 没有）、文件夹
  <书名>-<书编号前 8 位>/
    meta.json
    toc.md                   标题 → 页码 → text/文件:行号
    text/NN-<章名>.md        正文
    source.pdf               指向原文 PDF 的链接
```

- 文件夹名：书名里只留字母和数字（含中文），其余换成 `-`，最多 48 个字符，后面接书编号前 8 位。书名改了文件夹跟着改名，
  旧文件夹在下次导出时删掉。
- `source.pdf` 建不了链接（Windows 没有权限之类）时不放，`meta.json` 的 `source_pdf` 写原文路径、`source_pdf_linked: false`。
- 图片不复制：Markdown 图片的地址写成相对 `text/` 的路径（指向数据目录里 OCR 的图片），不在数据目录里的写绝对路径。

### 读哪份

和阅读入口 [`GET /documents/{id}/reading`](01-书与文档.md) 同一条规则：书的当前译文版本，没选过就自动（逐页取最新），
多次范围翻译读合并结果。合并阅读里没翻译的页、以及没有可读译文的书，从最近一次成功的 OCR 任务补原文。

### 正文

按顶层标题分文件（出现至少两次的最高一级标题；当前文件不到 16KB 时不换文件），每个文件不超过 200KB，超了从下一块起换文件。
没有标题的书按大小分，文件名用起始页号（`01-p1.md`）。每个文件第一行是 `# 书名 · 第 x–y 页`。

每块：

```markdown
<!-- p012-b0034 job=20261101093000-ab12cd page=12 -->
The entropy of an isolated system never decreases.

> 孤立系统的熵永不减少。
```

- 原文在前，译文是紧跟着的 `>` 引用块；没翻译的块只有原文。标题写成 `## 原文标题｜译文标题`。
- 页眉、页脚、页码（`sub_type` 是 `page_number`、`header`、`footer`、`page_header`、`page_footer`……）不导出。

### 锚点

`<!-- <item_id> job=<任务> page=<页码> -->`：

- `job` 是**真正有这一块的任务**，`item_id` 是这块在那个任务里的编号，前缀的页号是那个任务自己的本地页号——和全文检索
  （[`/search`](02-合集标签与检索.md)）的 `job_id`、`block_id` 同一规则。合并阅读的虚拟任务（`merged-…`）把页号改成了整本书的页号、
  而且只读，导出时按合并计划换回了源任务。
- `page` 是整本书的页码，给人看。
- 重新识别后块编号会变。引用一块时除了「书编号 + 任务 + 块编号」，再存一小段原文，对不上时按原文找回。
- 跳到阅读页：`reader.html?job_id=<阅读任务>&page_idx=<page - 1>&block_id=…`，阅读任务从 `GET /documents/{id}/reading` 取。

### meta.json

```json
{
  "format_version": 1,
  "document_id": "…",
  "title": "…",
  "authors": ["…"],
  "page_count": 320,
  "reading": { "job_id": "merged-…", "merged": true, "contributing_job_ids": ["…"], "version_id": null },
  "source_only_job_id": "…",
  "sources": [{ "job_id": "…", "regions_fingerprint": "…", "role": "reading" }],
  "fingerprint": "…",
  "generated_at": "…",
  "source_pdf": "/…/uploads/…/book.pdf",
  "source_pdf_linked": true,
  "files": [{ "path": "text/01-Introduction.md", "first_page": 1, "last_page": 18 }]
}
```

- `reading`：读的是哪个任务（和阅读入口一样，合并阅读是虚拟任务）；没有可读译文时是 `null`。
- `source_only_job_id`：补原文的任务，真的补了页才有。
- `fingerprint`：来源指纹（格式版本、书名、作者、页数、译文版本、原文路径、参与的任务和它们的区块指纹）。和上次一样就不重写。
