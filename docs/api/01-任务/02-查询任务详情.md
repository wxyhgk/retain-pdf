# 查询任务详情

## 接口

```http
GET /api/v1/jobs/{job_id}
```

用于获取任务当前快照。页面首屏应优先读取这个接口，再接入 events。

## 推荐读取字段

```json
{
  "job_id": "20260616120000-abcdef",
  "status": "running",
  "display_stage": "translation",
  "stage": "translating",
  "substage": "translation_batches",
  "lane": "main",
  "stage_detail": "正在翻译第 789 / 5216 批",
  "progress": {
    "unit": "batch",
    "current": 789,
    "total": 5216,
    "percent": 15.1
  },
  "background_stages": [
    {
      "display_stage": "render",
      "stage": "rendering",
      "substage": "render_prewarm",
      "lane": "background",
      "progress": {
        "unit": "step",
        "current": 2,
        "total": 3
      }
    }
  ]
}
```

字段说明：

- `status`: job 状态，例如 `queued`、`running`、`succeeded`、`failed`、`canceled`。
- `display_stage`: 前端展示大阶段，只能按约定理解为 `ocr | translation | render | done`。
- `stage`: 后端内部阶段名。
- `substage`: 机器可读子阶段。
- `lane`: `main` 或 `background`。
- `progress`: 当前最可信进度快照。
- `stage_detail`: 人类文案，不参与逻辑判断。
- `background_stages`: 同步进行的后台阶段，例如渲染预热。

## 前端规则

- 状态卡主阶段读 `display_stage + lane=main`。
- 进度条读 `progress.unit/current/total/percent`。
- `stage_detail` 只显示，不用于判断。
- 页面刷新后不要只依赖 events 重放，先用详情快照恢复状态。

## 服务商限流等待：`stage_snapshot.upstream_wait`

2026-11-23 起（只加不改）。翻译或 OCR 的请求被服务商限流（HTTP 429）、过载（529）、暂不可用（503），正在按 Retry-After
或退避等待时，`stage_snapshot` 多一个 `upstream_wait`；所有在等的请求都等完，字段消失。进度数字、`stage_detail` 不变。
任务列表（`include_live_stage` 时）的 `stage_snapshot` 同样带它。

```json
"stage_snapshot": {
  "display_stage": "translation",
  "stage": "translating",
  "substage": "translation_batches",
  "lane": "main",
  "stage_detail": "已翻译 96/408 块 · 已完成 9/48 页",
  "progress": {"unit": "block", "current": 96, "total": 408, "percent": 23.5},
  "upstream_wait": {
    "provider": "deepseek",
    "http_status": 429,
    "reason": "rate_limited",
    "code": "rate_limit_exceeded",
    "retry_after_s": 30.0,
    "wait_source": "retry_after",
    "attempt": 1,
    "max_attempts": 2,
    "started_at": "2026-11-23T00:00:00.000Z",
    "until": "2026-11-23T00:00:30.000Z"
  }
}
```

- `provider`：翻译 `openai` / `anthropic` / `deepseek` / `zhipu` / `qwen` / `opencode` / `custom`（按 base_url 的域名认），
  OCR `paddle` / `mineru` / `glm_ocr`。
- `reason`：`rate_limited`（429）、`overloaded`（529）、`unavailable`（503）。`code` 是上游错误码，没有为 `null`。
- `retry_after_s`、`wait_source`（`retry_after` 照响应头 / `backoff` 自己退避）、`attempt` / `max_attempts`、`until`（预计等到）。
  同一阶段好几个请求同时在等时是最近一次等待的信息。
- 别的 5xx、超时、连不上照旧重试，但不报等待。契约：`job-status.v1` 的 `UpstreamWaitView`。

前端规则：字段在就显示「服务商限流，等待中」（可以带服务商名和 `until` 倒计时），不在就照常显示进度；`until` 已过、字段还在
（下一次请求还没回来）时照样显示等待中，不要据此判断卡死。
