# 查询任务详情

## 接口

```http
GET /api/v1/jobs/{job_id}
```

用于获取任务当前快照。页面首屏应优先读取这个接口，再接入 events。

## 推荐读取字段

```json
{
  "job_id": "20260616120000-abcdef",
  "status": "running",
  "display_stage": "translation",
  "stage": "translating",
  "substage": "translation_batches",
  "lane": "main",
  "stage_detail": "正在翻译第 789 / 5216 批",
  "progress": {
    "unit": "batch",
    "current": 789,
    "total": 5216,
    "percent": 15.1
  },
  "background_stages": [
    {
      "display_stage": "render",
      "stage": "rendering",
      "substage": "render_prewarm",
      "lane": "background",
      "progress": {
        "unit": "step",
        "current": 2,
        "total": 3
      }
    }
  ]
}
```

字段说明：

- `status`: job 状态，例如 `queued`、`running`、`succeeded`、`failed`、`canceled`。
- `display_stage`: 前端展示大阶段，只能按约定理解为 `ocr | translation | render | done`。
- `stage`: 后端内部阶段名。
- `substage`: 机器可读子阶段。
- `lane`: `main` 或 `background`。
- `progress`: 当前最可信进度快照。
- `stage_detail`: 人类文案，不参与逻辑判断。
- `background_stages`: 同步进行的后台阶段，例如渲染预热。

## 前端规则

- 状态卡主阶段读 `display_stage + lane=main`。
- 进度条读 `progress.unit/current/total/percent`。
- `stage_detail` 只显示，不用于判断。
- 页面刷新后不要只依赖 events 重放，先用详情快照恢复状态。
