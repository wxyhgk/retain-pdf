# 任务接口分类

`/jobs/{job_id}` 下的接口按"回答什么问题"分成 9 类，每类一个固定前缀。下面表里的“旧地址”列只是对照：
这些旧地址都已于 2026-10-18 删除，请求返回 `404`，只能用新地址。

整理的来由见 [任务与文件接口整理](../../ops/planning/api-reorg/20261015-任务与文件接口整理.md)。
全部接口的清单钉在 `backend/api/docs/routes.txt`。

| 类 | 前缀 | 回答什么问题 |
|---|---|---|
| 任务 | `/jobs`、`/jobs/{job_id}` | 有哪些任务、建一个、看一个、删一个 |
| 操作 | `/jobs/{job_id}/actions/…` | 能对它做什么、去做 |
| 进度 | `/jobs/{job_id}/progress/…` | 跑到哪了（运行中） |
| 文件 | `/jobs/{job_id}/files/…` | 产出了哪些文件、取一个，见 [下载总览](../07-产物下载/01-下载总览.md) |
| 报告 | `/jobs/{job_id}/reports/…` | 跑完结果怎么样 |
| 阅读 | `/jobs/{job_id}/reader/…` | 阅读页要的东西 |
| 译文 | `/jobs/{job_id}/translations/…` | 逐条看、人工改、重翻一条 |
| 数据 | `/jobs/{job_id}/data/…` | 通用查询，按名字取一张表 |
| AI | `/jobs/{job_id}/ai/…` | AI 助手写在这本书里的东西 |

| 方法 | 地址 | 说明 |
|---|---|---|
| GET | `/jobs` | 任务列表 |

## 报告

| 方法 | 新地址 | 已删除的旧地址 | 说明 |
|---|---|---|---|
| GET | `/jobs/{job_id}/reports/quality` | `/quality-summary` | 质量体检卡 |
| GET | `/jobs/{job_id}/reports/quality/items` | `/quality-items` | 质量问题逐条清单，`?kind=layout\|untranslated\|qa\|escalated`，`limit` 1..=1000（默认 200，越界 400），回包带 `has_more` |
| GET | `/jobs/{job_id}/reports/translation-qa` | `/translation/qa` | 翻译质检 |
| GET | `/jobs/{job_id}/reports/translation` | `/translation/diagnostics` | 翻译诊断 |
| GET | `/jobs/{job_id}/reports/layout-fit` | `/render/fit-report` | 排版缩放情况 |
| GET | `/jobs/{job_id}/reports/refine` | `/translation/refine-report` | 精修报告 |
| GET | `/jobs/{job_id}/reports/failure` | `/diagnostics` | 失败原因，见 [失败结构](../08-调试诊断/01-失败结构.md) |
| GET | `/jobs/{job_id}/reports/usage` | `/usage` | 模型用量（token） |

还没产出时（2026-10-19 定，见 [错误约定](../00-约定/02-认证与错误.md#还没产出404)）：

- 原始报告 `translation-qa`、`translation`、`layout-fit`、`refine`：`404` + `error.details.reason = "not_ready"`，
  提示分别是 `translation-qa report not ready`、`translation report not ready`、`layout-fit report not ready`、`refine report not ready`。
- 摘要 `quality`、`quality/items`、`usage`、`failure`：`200`，没有的段给 `null`、空清单或 0。
- 任务不存在一律是普通 `404`，不带 `reason`。

## 数据

| 方法 | 地址 | 说明 |
|---|---|---|
| GET | `/jobs/{job_id}/data` | 有哪些数据表 |
| GET | `/jobs/{job_id}/data/{dataset}` | 按名字查一张表（字段、筛选、分组、分页） |

`data`、`reports/quality`、`reports/quality/items`、`reports/usage` 读任务的方式和其余读接口一致：认合并阅读的虚拟任务 id
（`merged-<文档>-<指纹>`，合并目录里没有的数据集 `available: false`，没有的报告给 null / 空清单，用量给空汇总），
旧目录格式的任务返回 `409`。`reports/usage` 有一条有意保留的例外：库里没有这个任务、但 `output/<任务>/` 目录还在时，
仍然返回 `200`（用量账本在任务目录里，删掉记录之后还查得到）。
任务还没有输出目录（排队中、还没开始跑）时，`data` 每个数据集 `available: false`、`data/{dataset}` 是空结果，
`reports/quality` 各段 `null`、`quality/items` 空清单，都是 `200`（2026-10-19 以前是 `404 job has no output directory`）。

## AI

AI 助手写的文件在任务目录的 `ai/board/` 下，不并进文件接口。还没放过东西时画板列表返回空列表。

读画板时，如果这个任务是重译出来的、`ai/` 里还是空的，会把同一本书上次的 AI 工作区复制过来（只复制一次，
之后的读取只多一次 stat；复制最多 500 个文件 / 64 MB，在阻塞线程里做）。所以这两个 GET 第一次读时可能写盘。

阅读路径 `ai/reading-path`、概念图 `ai/canvas` 已于 2026-10-19 删除（前端早已并进画板，没有调用方），
请求这两个地址现在返回 `404`。

| 方法 | 新地址 | 已删除的旧地址 | 说明 |
|---|---|---|---|
| GET | `/jobs/{job_id}/ai/board` | `/board` | 画板文件列表 |
| GET | `/jobs/{job_id}/ai/board/{name}` | `/board/{name}` | 画板里的一个文件 |

## 已删除的别名

- 返回里带的链接 2026-10-17 已换成新地址（字段不变）：`actions.cancel`、`actions.rerun`、`links.events_*`、`links.cancel_*`、操作列表里重试阶段的链接，以及文件、Markdown 的链接（见[下载总览](../07-产物下载/01-下载总览.md)）。产物列表 `/artifacts`、产物清单 `/artifacts-manifest` 的链接也已换成 `/files`（字段不变，返回的结构是 `/files` 的，见[产物清单链接换成文件清单](../../ops/planning/api-reorg/20261017-产物清单链接换成文件清单.md)）。
- `/ocr/jobs/…` 这组别名（只做 OCR 的任务）2026-10-18 已删除。建 OCR 任务改成先 `POST /uploads` 再 `POST /jobs`（`workflow: "ocr"`，`source.upload_id`），列表、详情、事件、取消、文件都用上面的 `/jobs/{job_id}/…`，见 [OCR-only 任务](../03-OCR/02-OCR-only任务.md)。
- 全部 58 个旧地址的删除记录见 [删掉旧地址](../../ops/planning/api-reorg/20261018-删掉旧地址.md)。
