# 通用取数

要读任务目录里已有的数据（质检问题、排版块、精修处理、修订记录、术语表、风格规则、事件、用量、编辑部台账……），
**先看这里，不要再为单个需求加接口**。2026-11-24 从 `docs/core/api/index.md` 第 7.5 节挪过来。

```http
GET /api/v1/jobs/{job_id}/data
GET /api/v1/jobs/{job_id}/data/{dataset}
```

- `GET /data`：这个任务有哪些数据集、文件在不在、有哪些字段（能不能筛选）。
- `GET /data/{dataset}`：按名字取。参数：
  - `fields=a,b`：只要这些字段；
  - `<字段>=值[,值…]`：等值筛选，逗号为「或」，只能用登记为可筛选的字段；
  - `group_by=字段`：按字段计数；`sort=字段` / `sort=-字段`；
  - `offset`、`limit`（1..=1000，默认 200，越界 400）。回包带 `has_more`；`group_by` 时 `offset` / `limit` 翻分组，
    分组个数在 `group_total`，`total` 仍是筛选后的行数（见 [分页](../00-约定/03-分页.md)）。
- 每条记录统一带 `item_id`（三位，改译文用）、`reader_item_id`（四位，阅读页跳转用）、`page`（从 1 起）。
- 文件不存在时 `available=false`、不报错（任务还没有输出目录时也是这样）；没登记的数据集 404，没登记 / 不能筛选的字段 400。

## 登记表

登记表是契约 [`contracts/job-data.v1.schema.json`](../../../contracts/job-data.v1.schema.json) 的 `datasets`：新的读需求在那里加一条
（文件位置、记录位置、字段），后端、前端类型、契约测试都照它走。只开放登记过的数据集，路径限定在任务目录里。

现有的数据集：`translation_items`（逐块译文和状态）、`revisions`（译文修订记录）、`qa_violations`（确定性质检问题）、
`layout_blocks`（排版结果：缩放、字号、是否溢出）、`refine_fixes`（最近一次精修对每块的处理）、`escalated`（编辑部留给人确认的块）、
`terms`、`term_conflicts`（术语表和多候选术语）、`agent_terms`、`agent_term_tickets`（翻译 agent 的术语表和歧义单）、`style_rules`、
`style_guide`（风格规则和概要）、`events`、`pipeline_events`（任务事件和流水线细粒度事件）、`token_usage`（模型用量台账）、
`editorial_ledger`（编辑部台账）、`domain_context`（领域判断）、`refine_summary`（最近一次精修的概要）。以契约里的为准。

## 例子

- 这次精修改了什么：`data/revisions?source=refine&sort=-ts`
- 阅读页标出改过的块：`data/revisions?group_by=item_id`
- 第 9 页溢出的块：`data/layout_blocks?page=9&overflow=true`
- 留给人确认的全部：`data/escalated`
- 锁定的术语：`data/terms?treatment=lock&sort=-frequency`
- 最新一条事件：`data/events?sort=-seq&limit=1`
