# 任务列表

## 接口

```http
GET /api/v1/jobs
```

用于展示最近任务、书库入口和任务卡片列表。

## 查询参数

| 参数 | 说明 |
|---|---|
| `limit` | 一页条数，默认 20，范围 1..=500，**越界返回 400**（不静默夹）。 |
| `offset` | 从第几条开始，默认 0。 |
| `status` | 任务状态过滤，例如 `running`、`succeeded`、`failed`。 |
| `workflow` | 任务类型过滤：`book`、`translate`、`render`、`ocr`。 |
| `provider` | OCR 服务商过滤（不分大小写）。 |
| `q` | 搜索，见下。 |
| `job_ids` | 逗号分隔的任务编号白名单，只列这些任务；仍然按 `limit` / `offset` 分页。 |
| `include_live_stage` | `false` 时只读已存的任务摘要，不去读事件流算实时阶段（首屏更快）。 |

排序是 `updated_at` 倒序，同一时间再按 `job_id` 倒序。过滤都在分页之前做，所以 `q`、`status` 等不会让一页变短。

### `q` 搜什么

不分大小写（ASCII）、子串匹配，前后空白会去掉，`%`、`_` 不是通配符。命中下面任意一项就算：

- 任务编号 `job_id`；
- 书名：所属文档当前的标题（`display_name` 优先用它，改过名的书搜新名字）；
- 上传的原文件名；没有上传记录时是来源地址 `source_url` 的最后一段（和 `source_file_name` 一致）；
- 来源地址 `source_url` 全文；
- 当前阶段 `stage`、阶段说明 `stage_detail`；
- 错误信息 `error`。

书卡、文件夹按 `job_ids` 批量取任务活态（以前走书架 `/library/books?job_ids=`，2026-10-22 删了）；`job_ids`
同样受 `limit` 校验（1..=500），名单超过 500 个要分批。

不认识的查询参数目前被忽略，以后核对完前端发送的参数再改成 400。

## 响应重点

`data` 里：`items`、`invocation_summary`，以及分页字段 `limit`（实际生效的条数上限）、`offset`、
`has_more`（这一页之后还有没有）。分页规矩见 [分页](../00-约定/03-分页.md)；前端用 `has_more` 判断
有没有下一页，不要用"这一页条数等于 `limit`"猜。

`invocation_summary` 是这一页里 worker 调用方式的计数：`stage_spec_count`、`unknown_count`。

列表项是给书库卡片用的稳定投影，前端不用再从 `request_payload`、产物或事件里推（形状见契约
[`job-status.v1.schema.json`](../../../contracts/job-status.v1.schema.json) 的 `JobListItemView`）：

- `job_id`、`workflow`、`status`
- `display_name`：书名（所属文档当前的标题），没有时是文件名
- `attempt`：第几次执行（从 1 起，等于 `retry_count + 1`）；`retry_count`：已记录的重试次数；`last_retry_at`：最近一次重试被接受的时间，没有为 `null`
- `trace_id`
- `completion_note`：终态任务的额外说明（例如「有 N 个内容块保留原文未翻译」），正常为 `null`
- `stage_snapshot`：当前阶段（`display_stage`、`stage`、`substage`、`lane`、`stage_detail`、`progress`，以及等限流时的 `upstream_wait` 都在里面，不再有同名的顶层字段）；终态任务为 `null`。`include_live_stage=false` 时取已存的摘要
- `background_snapshots`、`stages`：同 [任务详情](02-查询任务详情.md)
- `page_count`
- `source_file_name`
- `cover_url`
- `thumbnail_url`
- `output_pdf_ready`
- `markdown_ready`
- `bundle_ready`
- `invocation`：同任务详情
- `created_at`、`updated_at`
- `detail_path`、`detail_url`：任务详情的相对 / 绝对地址
- `source_artifact_job_id`：复用了哪个任务的产物（OCR / 译文），没有为 `null`。重新渲染、原地精修过的任务链顺着它能找到真正持有译文的任务，不用逐个打详情
- `failure`：只有失败的任务才有，成功和进行中的任务整个键不出现（不是 null）。是精简版：`category`、`stage`、`retryable`、`summary` 必有，`failure_code`（同任务详情 `failure.failure_code`，同一个 `category` 里要给不同说法时按它分，比如 `auth` 下的 `auth_failed`、`upstream_model_unavailable`、`upstream_region_unsupported`；2026-11-24 加，老任务没有时键不出现）、`root_cause`、`suggestion`、`provider`、`upstream`（上游服务商回的 `{provider, http_status, code}`，2026-11-23 加，见 [失败结构](../08-调试诊断/01-失败结构.md)）没有时键也不出现；不带 traceback，要完整错误去读任务详情的 `failure`。形状见契约 [`job-status.v1.schema.json`](../../../contracts/job-status.v1.schema.json) 的 `#/definitions/JobFailureBriefView`（`library-books.v1.schema.json` 里暂时还有同样一份，给前端契约测试读）。`GET /documents/{document_id}/jobs` 的列表项同此。

## 前端规则

- 列表卡片使用列表接口返回的快照即可，不需要立即拉每个 job detail。
- 图片使用 `cover_url` / `thumbnail_url`，为空时由前端使用占位图。
- 不要扫描本地文件系统或拼接 job 目录。
