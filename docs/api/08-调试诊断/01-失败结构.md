# 失败结构

> 地址已按 8 类整理（新地址如 `/jobs/{job_id}/reports/failure`）。对应的旧地址已于 2026-10-18 删除（返回 404）。新旧对照见 [任务接口分类](../01-任务/04-任务接口分类.md)。

任务失败时，优先读取 job detail 的 `failure` 和 diagnostics 接口。

## 任务诊断

契约：[`job-reports.v1`](../../../contracts/job-reports.v1.schema.json)（返回 `JobDiagnosticsView`，前端类型从 `@retainpdf/contracts/job-reports` 导入；质量体检卡、质量清单、翻译诊断也在这份契约里）。

```http
GET /api/v1/jobs/{job_id}/reports/failure
```

## 失败字段示例

```json
{
  "failed_stage": "translation",
  "failure_code": "python_unhandled_exception",
  "failure_category": "translation",
  "summary": "任务失败，但暂未识别出明确根因",
  "detail": "translation review gate blocked",
  "retryable": true,
  "provider": "translation",
  "raw_exception_type": "RuntimeError"
}
```

## 重启后的自动续跑与 `translation_request_ambiguous`

API / 任务服务重启时，停在翻译阶段的运行中任务默认自动续跑。但如果翻译请求日志里有「已发出、没有终态」的请求（结果不明，续跑会把它们原样再发一遍），不自动续跑：任务落成 `failed`，
`failure_code` 为 `translation_request_ambiguous`（`failure_category=translation`，`resume_from=translation`，`retryable=true`），
`reports/failure` 和任务详情里的 `translation_request_recovery.requires_confirmation` 为 `true`。
用户确认重复风险后，走 `retry-stage`（`stage=translation`，`ambiguous_request_policy=accept_duplicate_risk`）——这条路径和手动重试的歧义闸门完全一致，不需要新接口。
日志干净（每个请求都有终态）或还没有日志时，照旧自动续跑。渲染 / 精修阶段不看这份日志。

## 自动续跑次数上限与 `auto_resume_limit_exceeded`

（2026-10-19 新增）启动恢复和运行期巡检把「运行中却没人在跑」、又有可续断点的任务放回排队自动续跑。
同一次运行（同一个 pipeline attempt）**连续 3 次**自动续跑、每次都没有新进度（没有提交新的单元、没有完成新的阶段）
就又中断了，多半是这份输入每次都让任务运行时崩溃；第 4 次发现它中断时不再续跑，任务落成 `failed`：

- `failure_code` / `category`：`auto_resume_limit_exceeded`，`failure_category=internal`，`failed_stage=startup_recovery`，
  `retryable=true`，`resume_from=null`；
- `summary`：「自动续跑次数超过上限，疑似导致运行时崩溃」，`detail`（`root_cause`）写明连续续跑了几次、上限多少；
- `recovery_hint` 来自恢复目录：先看日志排查，再手动重试。

两次中断之间有新进度就从头数，正常的反复重启（桌面端关了又开）不会把长任务判死。
用户手动重试 / 续跑是新的一次运行（新 attempt），计数从 0 开始。数据库从备份恢复后的那次续跑也计入。
上限是 runner 里的常量 `MAX_AUTO_RESUMES_WITHOUT_PROGRESS`，计数存在 `pipeline_attempts.auto_resume_count`（迁移 v27）。
前端不用改：按已有规则显示 `summary`、`recovery_hint` 即可。

## 前端规则

- 错误标题优先用 `summary`。
- 展开详情使用 `detail`。
- 是否展示重试按钮参考 `retryable` 和 `GET /jobs/{job_id}/actions`。
- 不要直接把完整 traceback 默认展示给普通用户。
- `raw_excerpt`、`traceback`、诊断 payload 可能已做脱敏。

## 翻译调试

```http
GET /api/v1/jobs/{job_id}/reports/translation
GET /api/v1/jobs/{job_id}/translations
GET /api/v1/jobs/{job_id}/translations/{item_id}
POST /api/v1/jobs/{job_id}/translations/{item_id}/replay
```

这些接口用于排查翻译缺失、模型输出异常、批次失败和 replay，不应作为普通用户主流程依赖。
