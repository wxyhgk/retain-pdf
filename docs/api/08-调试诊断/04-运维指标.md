# 运维指标（Prometheus）

（2026-11-24 新增）`GET /metrics` 返回 Prometheus 文本格式（`Content-Type: text/plain; version=0.0.4; charset=utf-8`）的指标：
按接口的请求数、状态码分类、耗时直方图，以及 `GET /health` 里已有的几个运行时数。给 Prometheus、Grafana 这类监控抓取，
看错误率、P95 耗时；前端不用。

```http
GET /metrics
X-API-Key: <key>
```

- 地址在根上（和 `/health` 一样，不带 `/api/v1`），只在完整 API 端口上有，第二个端口（`42000`）没有。
- 要 `X-API-Key`，没带 401。多用户模式下只给管理员（`admin`）。
- 不是 JSON，没有 `{code, message, data}` 信封。

## 指标

| 指标 | 类型 | 标签 | 说明 |
|---|---|---|---|
| `retainpdf_http_requests_total` | counter | `method`、`route`、`status` | 请求数。`route` 是接口登记表里的路由模板（`/api/v1/jobs/:job_id`），不是具体地址；`status` 是 `1xx`…`5xx`，`unknown` 是 2026-11-24 以前只计了次数、没分状态码的部分 |
| `retainpdf_http_request_duration_seconds` | histogram | `method`、`route` | 拿到回应头的耗时，不含传正文（大文件下载只算到开始传）。分桶上界 `0.05`、`0.2`、`1`、`5` 秒和 `+Inf` |
| `retainpdf_http_streaming_requests_total` | counter | `method`、`route` | 事件流（`text/event-stream`）、WebSocket 这类长连接的次数。它们不进耗时直方图，免得算成快请求或慢请求 |
| `retainpdf_db_up` | gauge | | 任务库能不能用（1/0） |
| `retainpdf_jobs_queued` | gauge | | 排队中的任务数（库读不出来时不出这一项） |
| `retainpdf_jobs_running` | gauge | | 运行中的任务数（同上） |
| `retainpdf_jobsd_status` | gauge | `status` | 恒为 1，状态在标签里：`starting`、`healthy`、`unhealthy`、`unsupervised`（和 `/health` 的 `jobsd` 一样） |
| `retainpdf_disk_free_bytes` | gauge | | 数据目录所在磁盘的剩余空间（拿不到时不出这一项） |
| `retainpdf_disk_min_free_bytes` | gauge | | 剩余空间下限（`RUST_API_MIN_FREE_DISK_MB`，`0` 不查） |
| `retainpdf_disk_low` | gauge | | 低于下限（1 是；此时新上传、新任务 503） |

- 只列有过请求的接口。没匹配上路由的请求（404 兜底）不计。
- 计数和接口用量文件（`<data_root>/diagnostics/route-usage.json`，见 `ops/development/route_usage_report.py`）是同一份：
  从文件的 `since` 起累计，重启时读回来接着加，所以重启后计数不归零；清零（`route_usage_report.py --reset`）后会从小数重来，
  Prometheus 的 `rate()` 当作计数器重置处理。

```text
retainpdf_http_requests_total{method="GET",route="/api/v1/jobs/:job_id",status="2xx"} 1834
retainpdf_http_requests_total{method="GET",route="/api/v1/jobs/:job_id",status="4xx"} 12
retainpdf_http_request_duration_seconds_bucket{method="GET",route="/api/v1/jobs/:job_id",le="0.05"} 1790
retainpdf_http_request_duration_seconds_bucket{method="GET",route="/api/v1/jobs/:job_id",le="0.2"} 1840
...
retainpdf_http_request_duration_seconds_bucket{method="GET",route="/api/v1/jobs/:job_id",le="+Inf"} 1846
retainpdf_http_request_duration_seconds_sum{method="GET",route="/api/v1/jobs/:job_id"} 31.42
retainpdf_http_request_duration_seconds_count{method="GET",route="/api/v1/jobs/:job_id"} 1846
retainpdf_jobs_queued 0
retainpdf_jobs_running 1
```

## 接 Prometheus

在 `prometheus.yml` 里加一个抓取任务。后端只认 `X-API-Key` 头（不认 `Authorization: Bearer`），用抓取配置的 `http_headers`
带上（较新的 Prometheus 才有这一项；没有的话在前面的反向代理上给 `/metrics` 补 `X-API-Key` 头）：

```yaml
scrape_configs:
  - job_name: retainpdf
    scrape_interval: 30s
    metrics_path: /metrics
    static_configs:
      - targets: ["127.0.0.1:41000"]
    http_headers:
      X-API-Key:
        files: ["/etc/prometheus/retainpdf-api-key"]   # 文件里只放 key，别写进配置
```

常用查询：

```promql
# 各接口 5 分钟内的 5xx 比例
sum by (route) (rate(retainpdf_http_requests_total{status="5xx"}[5m]))
  / sum by (route) (rate(retainpdf_http_requests_total[5m]))

# 各接口的 P95 耗时（秒）
histogram_quantile(0.95, sum by (route, le) (rate(retainpdf_http_request_duration_seconds_bucket[5m])))
```

后端监听回环地址时，Prometheus 和后端不在同一台机器上，要么走反向代理（代理要在 `RUST_API_ALLOWED_HOSTS` 里，见
[本地开发配置](../../core/api/local-dev.md)），要么在本机放一个抓取代理。分桶只有 5 个，P95 是桶内插值，精度到“落在哪一档”。

## 日志相关的开关

看单个请求还是靠日志（见 [排错](../../core/api/troubleshooting.md#对上某个请求的后端日志)）：
`RUST_LOG_FORMAT=json` 让日志一行一个 JSON 对象，`RUST_API_ACCESS_LOG=1` 让每个请求按 info 记一行访问日志。
