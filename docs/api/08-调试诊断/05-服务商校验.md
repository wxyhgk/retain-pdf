# 服务商校验

2026-11-24 从 `docs/core/api/index.md` 第 11 节挪过来。请求体、各家 `status` 的全部取值、地址检查、超时和重定向的细节在
[Provider 校验接口](../../core/rust_api/08-Provider%20校验接口.md)（那篇还在 `docs/core/rust_api/` 下，没在这次挪）。

| 接口 | 说明 |
|---|---|
| `GET /api/v1/providers/ocr` | OCR 服务商清单，不分页，见 [OCR Provider 列表](../03-OCR/01-provider列表.md) |
| `GET /api/v1/providers/error-codes` | 服务商错误码目录（2026-11-23），见 [服务商错误码](03-服务商错误码.md) |
| `POST /api/v1/providers/mineru/validate-token` | 检测 MinerU token |
| `POST /api/v1/providers/paddle/validate-token` | 检测 Paddle token |
| `POST /api/v1/providers/deepseek/validate-token` | 检测翻译接口的 key（请求体可带 `base_url`、`model`、`api_protocol`，地址沿用旧名） |
| `POST /api/v1/providers/deepseek/balance` | DeepSeek 余额 |
| `POST /api/v1/providers/translation/models` | 从翻译接口拉模型列表（2026-11-19） |
| `POST /api/v1/providers/translation/ask` | 用翻译接口的配置问一次模型，可以带图片：最多 4 张、每张 4 MB，请求体上限 24 MB（2026-11-22） |

上面 4 条检测和余额 2026-11-24 起有契约 `contracts/provider-probes.v1.schema.json`。多用户模式下除了 `providers/ocr`、
`providers/error-codes`，这一组只给管理员。

要点（2026-10-22 起）：

- 请求体里不认识的字段 400；
- 界面看 `data.ok`；`status` 各家取值不同（MinerU 多一个 `expired`，翻译接口多 `rate_limited`、`model_unavailable`、
  `insufficient_balance`、`quota_exceeded`、`invalid_input`），三家都可能是 `redirected`（服务商回了 3xx，校验不跟随）；
- 2026-11-23 起 HTTP 状态码在 `http_status`（数字），`provider_code` 只放服务商自己的业务码；429 按业务码分清限流和欠费、额度用完
  （欠费的 Key 不再显示「可用（当前被限流）」）；
- 超时统一 `RUST_API_PROVIDER_PROBE_TIMEOUT_SECS`（默认 20 秒，比前端等的 30 秒短；没设时认旧名
  `RUST_API_DEEPSEEK_PROBE_TIMEOUT_SECS`），不重试；建任务后真正跑 OCR 时的 MinerU、Paddle 请求有自己的超时和重试；
- 地址检查：单机模式能校验本机和内网的模型服务（仍拦链路本地地址、云元数据地址），多用户模式拦回环、内网、链路本地；
  `RUST_API_ALLOW_PRIVATE_PROVIDER_URLS=1` 两种模式都放开；
- `provider_message`、`operator_hint` 最多 500 字。
