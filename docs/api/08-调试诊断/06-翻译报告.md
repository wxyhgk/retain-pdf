# 翻译报告

任务跑完后的四份原始报告：翻译诊断、翻译质检、精修、排版缩放。都在 `/jobs/{job_id}/reports/` 下，返回前和 debug 接口一样脱敏
（结构化密钥字段清空，夹带的密钥换成 `[REDACTED]`）。质量体检卡 `reports/quality`、失败原因 `reports/failure` 是摘要类，
见 [失败结构](01-失败结构.md)；逐条看译文见 [Translation Debug API](02-translation-debug.md)。

```http
GET /api/v1/jobs/{job_id}/reports/translation
GET /api/v1/jobs/{job_id}/reports/translation-qa
GET /api/v1/jobs/{job_id}/reports/refine
GET /api/v1/jobs/{job_id}/reports/layout-fit
```

还没产出（2026-10-19 定，规矩见 [错误约定](../00-约定/02-认证与错误.md#还没产出404)）：任务在、报告还没生成是 `404` +
`error.details.reason = "not_ready"`，提示分别是 `translation report not ready`、`translation-qa report not ready`、
`refine report not ready`、`layout-fit report not ready`；任务不存在是普通 `404`。

## 翻译诊断

`GET /api/v1/jobs/{job_id}/reports/translation` 读 `artifacts/translation_diagnostics.json`，返回 `{job_id, summary}`，
`summary` 是文件原样：翻译运行统计、服务商统计、重试统计等。

```json
{
  "job_id": "20260416034152-d12925",
  "summary": {
    "schema": "translation_diagnostics_v1",
    "counts": {"translated": 412, "kept_origin": 18, "skipped": 97},
    "provider_family": "deepseek",
    "final_status_counts": {"translated": 412, "kept_origin": 18, "skipped": 97}
  }
}
```

## 翻译质检

`GET /api/v1/jobs/{job_id}/reports/translation-qa` 返回 `{job_id, report}`，`report` 是 `artifacts/translation_qa.v1.json` 原样。
翻译阶段结束时内联生成一次（`generator.mode=inline`，这时还没排版，`checks.layout_fit` 是 skipped），渲染结束后带上排版报告重算并覆盖
（`generator.mode=post_render`）。

```json
{
  "job_id": "20261006023250-703433",
  "report": {
    "schema": "translation_qa.v1",
    "generator": {"mode": "post_render"},
    "checks": {"layout_fit": {"status": "ok", "violation_count": 17}},
    "summary": {"by_severity": {"critical": 0, "major": 17, "minor": 16}},
    "violations": [
      {
        "id": "qa-00015", "check": "omission", "type": "length_ratio_low", "severity": "major",
        "location": {"item_id": "p043-b006", "page_number": 43},
        "evidence": {"length_ratio": 0.0515, "source_excerpt": "…", "translation_excerpt": "…"}
      }
    ]
  }
}
```

要按条筛选、分组，用通用取数 `GET /jobs/{job_id}/data/qa_violations`。

## 精修报告

`GET /api/v1/jobs/{job_id}/reports/refine` 返回 `{job_id, report}`，`report` 是 `artifacts/refine_report.v1.json` 原样，结构见契约
[`refine-report.v1.schema.json`](../../../contracts/refine-report.v1.schema.json)（schema `refine_report_v1`）。

精修（挑错 + 定点修改）在渲染阶段、真正渲染之前跑：新任务由建任务时的 `translation.refine` 决定（默认 `off`，不生成报告）；
已完成的任务用 [retry-stage](../06-阶段操作/02-retry-stage.md) 的 `{"stage": "refine", "create_new_job": false}` 原地触发。

```json
{
  "job_id": "20261006023250-703433",
  "report": {
    "schema": "refine_report_v1",
    "mode": "review_and_fix",
    "trigger": "manual",
    "scope": {"start_page": 3, "end_page": 5},
    "review": {"findings": [{"item_id": "p043-b006", "category": "omission", "severity": "critical", "origin": "qa"}]},
    "fixes": [{"item_id": "p043-b006", "status": "applied", "revision_id": "rev-…"}]
  }
}
```

上次精修的摘要（中途停了从哪页接着）也在 [`GET /jobs/{job_id}/actions`](../06-阶段操作/01-stage-actions.md) 精修那一项的 `last_refine` 里。

## 排版缩放

`GET /api/v1/jobs/{job_id}/reports/layout-fit` 返回 `{job_id, report}`，`report` 是 `artifacts/fit_report.v1.json` 原样：
每块的最终字号、缩小比例、是否进了应急档、是否溢出，以及页级、全书汇总。`report.status` 是 `ok` / `failed` / `unavailable`
（逐页降级等不走整本 Typst 的渲染路径）。

```json
{
  "job_id": "20261006023250-703433",
  "report": {
    "schema": "fit_report_v1",
    "status": "ok",
    "summary": {"blocks": 396, "shrunk_blocks": 38, "emergency_blocks": 2, "overflow_blocks": 16},
    "blocks": [
      {"item_id": "p040-b004", "page": 40, "final_font_size": 11.08, "base_font_size": 11.08, "scale": 1.0,
       "tier": "base", "emergency_tier": false, "overflow": true, "overflow_pt": 11.73, "overflow_chars_estimate": 4}
    ]
  }
}
```
