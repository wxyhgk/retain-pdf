# 翻译事件

翻译事件通过统一 job events 暴露：

```http
GET /api/v1/jobs/{job_id}/progress/events
```

## 常见 substage

- `translation_prepare`
- `domain_inference`
- `page_policies`
- `continuation_review`
- `translation_batches`
- `garbled_repair`
- `translation_review`

## 事件示例

```json
{
  "seq": 120,
  "display_stage": "translation",
  "stage": "translating",
  "substage": "translation_batches",
  "lane": "main",
  "event_type": "progress",
  "progress": {
    "unit": "batch",
    "current": 789,
    "total": 5216,
    "percent": 15.1
  },
  "stage_detail": "正在翻译第 789 / 5216 批"
}
```

## 前端规则

- 主翻译进度读 `display_stage=translation` 且 `lane=main`。
- `progress.unit` 可能是 `batch`、`page`、`item` 或 `step`，按返回值展示。
- `stage_detail` 只做人类文案。
- 后台渲染预热事件会是 `display_stage=render`、`lane=background`，不要覆盖翻译主状态。

## 服务商限流等待

翻译请求被服务商限流（429 / 529 / 503）退避等待时，事件流里有一对「开始等 / 等完」的进度事件，任务详情
`stage_snapshot.upstream_wait` 在等待期间出现。四条请求路径都报：普通翻译（共用请求层 `request_chat_content`）、
翻译 agent 的 Anthropic 协议请求、OpenAI 协议的 agent（走共用请求层）、Rust 模型执行器（`RETAIN_MODEL_EXECUTOR_*`，
worker 轮询操作状态时看到 `upstream_wait` 再报）。说明见 [事件总览](../02-进度事件/01-事件总览.md#服务商限流等待事件2026-11-23)。
