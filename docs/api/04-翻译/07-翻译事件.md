# 翻译事件

翻译事件通过统一 job events 暴露：

```http
GET /api/v1/jobs/{job_id}/progress/events
```

## 常见 substage

- `translation_prepare`
- `domain_inference`
- `page_policies`
- `continuation_review`
- `translation_batches`
- `garbled_repair`
- `translation_review`

## 事件示例

```json
{
  "seq": 120,
  "display_stage": "translation",
  "stage": "translating",
  "substage": "translation_batches",
  "lane": "main",
  "event_type": "progress",
  "progress": {
    "unit": "batch",
    "current": 789,
    "total": 5216,
    "percent": 15.1
  },
  "stage_detail": "正在翻译第 789 / 5216 批"
}
```

## 前端规则

- 主翻译进度读 `display_stage=translation` 且 `lane=main`。
- `progress.unit` 可能是 `batch`、`page`、`item` 或 `step`，按返回值展示。
- `stage_detail` 只做人类文案。
- 后台渲染预热事件会是 `display_stage=render`、`lane=background`，不要覆盖翻译主状态。

## 服务商限流等待

翻译请求被服务商限流（429 / 529 / 503）退避等待时，事件流里有一对「开始等 / 等完」的进度事件，任务详情
`stage_snapshot.upstream_wait` 在等待期间出现。四条请求路径都报：普通翻译（共用请求层 `request_chat_content`）、
翻译 agent 的 Anthropic 协议请求、OpenAI 协议的 agent（走共用请求层）、Rust 模型执行器（`RETAIN_MODEL_EXECUTOR_*`，
worker 轮询操作状态时看到 `upstream_wait` 再报）。说明见 [事件总览](../02-进度事件/01-事件总览.md#服务商限流等待事件2026-11-23)。

## 断点不能接着用、已译的页作废（2026-11-26）

重试任务时，worker 会拿上一个任务的翻译断点接着翻。断点和这一次真的对不上（原文变了，或者模式、规则、术语表、模型、引擎、
页范围变了）时，已译的页作废、从头翻，事件流里多一条 `event_type=progress` 的事件（只加不改）：

- `stage=translating`、`substage=checkpoint_resume`，没有进度数字；
- `payload.observation.resume_checkpoint_discarded = {"source_attempt_id": "<上一个任务>", "reason": "<原因>"}`，
  `reason` 是 `document_changed`（规范化文档变了）、`source_pdf_changed`（跟着 OCR 翻的原文 PDF 变了）、
  `parameters_changed`（翻译参数变了）、`fingerprint_changed`（别的）之一；
- `message` 如「上一个任务的翻译断点不能接着用（翻译参数变了：模式、规则、术语表、模型、引擎或页范围），已译的页作废，这次从头翻」。

worker 的事件文件里这条的级别是 `warning`；判断时读 `payload.observation.resume_checkpoint_discarded`，不要看 `level` 或 `message`。
领域识别结果、目录 agent 的定译变了**不会**再让断点作废（以前会），见 `backend/translation/retainpdf_translation/workflow/checkpoint/identity.py`。
