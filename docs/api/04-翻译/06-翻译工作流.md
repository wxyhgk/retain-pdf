# 翻译工作流

## book workflow

`workflow=book` 的主链：

```text
OCR child -> normalize -> translate -> render
```

Rust 会先准备 OCR 结果，再启动翻译阶段。翻译成功后继续渲染。

## translate workflow

`workflow=translate` 的主链：

```text
OCR child -> normalize -> translate
```

翻译完成后任务结束，不生成最终 PDF。

## 复用已有 OCR artifact

如果请求带 `source.artifact_job_id`，后端可以复用已有 OCR artifacts，直接准备翻译输入，不必重新 OCR。

## 翻译阶段输入

- `source_json`: normalized `document.v1.json`
- `source_pdf`: 源 PDF
- `layout_json`: provider layout/result JSON，可用于诊断或补充信息

## 翻译阶段输出

- translation manifest
- page translation payloads
- diagnostics
- debug index
- review artifact

渲染阶段只应消费翻译产物和 source PDF，不应回头读取 OCR provider 私有字段。

## 翻译 agent 的结构（2026-11-19）

翻译引擎是 agent 时，通读判成人文社科、通俗读物的书按节翻（第二版，2026-11-19 起默认）：几页正文接成一份带段号的稿子
一次交给模型，按段号对回各块，再整节对照原文审一次意思；论文、教材等别的体裁照旧逐页翻（第一版）。服务端设环境变量
`RETAIN_AGENT_STRUCTURE=page` 时人文书也退回逐页。切换结构后同一任务的翻译从头做（不沿用另一种结构的断点）。
接口、产物、编辑部事件都不变；按节翻时一节几页的 `page_started` 连着来，这一节只有一次 `translate_call` 和一对审校事件。
方案见 [按节翻译](../../ops/planning/translation-agent/20261119-按节翻译.md)。
