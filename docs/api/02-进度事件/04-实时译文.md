# 边翻边看（实时译文）

任务还在翻译时，阅读页可以先显示已经提交的译文。2026-11-24 从 `backend/api/docs/api-spec/live-translation.md`、
`reader-read-model.md` 和 `docs/core/api/index.md` 第 6 节合并过来；worker 怎么提交页快照、为什么按这个顺序，
见 [运行时与实现备忘](../../core/api/runtime.md#边翻边看的生产方要求)。字段以
`backend/packages/retainpdf-jobs/src/views/live_translation.rs` 和契约 `contracts/reader-data.v1.schema.json` 为准。

```http
GET /api/v1/jobs/{job_id}/progress/layout
GET /api/v1/jobs/{job_id}/progress/pages/{page}
GET /api/v1/jobs/{job_id}/progress/stream?after_seq={seq}
```

都要 `X-API-Key`。旧地址（`/live-events` 等）2026-10-18 删了，对照见 [任务接口分类](../01-任务/04-任务接口分类.md)。

## 版面：`progress/layout`

从规范化的 OCR 文档投影出每页的尺寸和文字块：`{ "pages": [ { "page_idx", "width", "height", "blocks": [...] } ] }`。
版面可以比任何一页译文都先好。

- `page_idx` **从 0 起**（阅读区域 `reader/regions` 的页码从 1 起，见 [阅读接口](../12-阅读/01-阅读接口.md)；只在界面边界换算一次，不要混用）。
- 每块：`item_id`、`bbox`（PDF point，左上角原点）、`source_text`、`kind`，可选 `typography`。
  `item_id` 和译文条目用同一套规范化编号，可以直接对上。有可用的排版计划时，`bbox` 换成计划里的背景框，和 `padding_*` 在同一个坐标系。
- `typography`（有渲染预热清单、而且这一块参数齐全时才有；老任务、参数不全时不出现，客户端自己适配字号）：

```json
{
  "item_id": "p001-b0003",
  "bbox": [59, 176, 304, 445],
  "source_text": "Original text",
  "kind": "paragraph",
  "typography": {
    "font_family": "Source Han Serif SC",
    "font_size_pt": 9.82,
    "leading_em": 0.56,
    "font_weight": 400,
    "text_align": "justify",
    "padding_top_pt": 0,
    "padding_right_pt": 0,
    "padding_bottom_pt": 0,
    "padding_left_pt": 0,
    "fit_min_font_size_pt": 7,
    "fit_max_font_size_pt": 9.82
  }
}
```

  `bbox`、字号、内边距是 PDF point，`leading_em` 是 em。这是交给 Typst 的输入计划和字号范围，不代表最后编译选定的字号。
  客户端不用、也不该去取 `.typ` 文件。预热清单缺了或坏了，`layout` 照样成功，只是没有 `typography`。

## 一页译文：`progress/pages/{page}`

`{page}` 是从 0 起的页序号。返回 `attempt`、`generation`、`page_idx`、`page_hash`、`items`（每项 `item_id`、`translated_text`、`status`）。
只读已经提交、哈希对得上的页快照（不读还在改的工作文件），没有译文的块不出现。`translated_text` 原样返回，`$...$`、`$$...$$`
里的公式不转图、不去掉。

## 提交通知：`progress/stream`

SSE（`text/event-stream`），响应带 `X-Accel-Buffering: no`，nginx 这类反向代理不会缓冲，15 秒一次保活。

- 每提交一页发一条 `event: translation_units_committed`，SSE `id` 是这个任务在库里的权威序号，`data` 是
  `{event, seq, attempt, generation, page_idx, page_hash, changed_item_ids}`。**它只是「该刷新了」的提示，不带译文**，
  收到后去取那一页。
- 断线重连带 `after_seq` 或 `Last-Event-ID` 头，两个都有时取大的。查询串只认 `after_seq`，别的参数 400
  （``unknown field `<名字>`, expected `after_seq` in the query string``；2026-11-24 起，以前忽略）。
- 流开着时后端查询出错（任务被删了、库读不了……），先发一条 `event: error` 再关流（2026-11-24 起；以前直接断开）。
  这条没有 `id`，不推进续读位置；`data` 是和普通接口一样的错误信封，`500` 只带 `error.details.error_id`：

  ```text
  event: error
  data: {"code":40400,"message":"job not found: …","error":{"code":"NOT_FOUND","http_status":404,"details":{}}}
  ```

  不认 `error` 的客户端照旧当作流结束、重连即可。
- 认证照旧走请求头，浏览器原生 `EventSource` 带不了 `X-API-Key`，要用能带头的流式 `fetch`。
- 改一块译文（`PATCH /jobs/{job_id}/translations/{item_id}`，见 [Translation Debug API](../08-调试诊断/02-translation-debug.md)）登记好改过的页后
  也发同样的事件，成功、失败、取消的任务都会发；`attempt` 不变、`generation` 变大，已经在显示这一页的客户端重取就行。
  写了还没登记的修订，在任务不在排队、不在跑时读 `layout` 会顺带登记。

客户端处理每条 `translation_units_committed`：

1. 忽略重复或更旧的 `seq`；
2. 取 `progress/pages/{page}`；
3. 比较 `attempt`、`generation`、`page_hash`，新的才替换本地这一页；
4. 只显示这份已提交的快照。

这样断线、重连、服务重启都不会显示出后来又消失的译文。

## 错误

| `error.code` | 含义 |
|---|---|
| `LIVE_TRANSLATION_LAYOUT_NOT_READY` | OCR 版面还没好，带退避重试 |
| `LIVE_TRANSLATION_LAYOUT_INVALID` | 版面数据不合法 |
| `LIVE_TRANSLATION_PAGE_NOT_COMMITTED` | 这一页还没有提交的译文（`404`）——不是「空译文」，原文照常显示、等着 |
| `LIVE_TRANSLATION_SNAPSHOT_UNAVAILABLE` | 提交过的快照取不到 |
| `LIVE_TRANSLATION_SNAPSHOT_INVALID` | 快照和提交的哈希对不上 |
| `LIVE_TRANSLATION_EVENT_INVALID` | 提交事件不合法 |

这几个码同时出现在 `error.code` 和顶层 `code`（兼容期，没定删除日期）。按 `error.code` 区分「还没提交」和「快照坏了」，
不要匹配 `message` 决定要不要重试。错误里不带检查点路径、快照原文和没提交的译文。路径里的 `job_id`、页号不合法、`after_seq`
不是数字，是普通的参数错误（400，固定提示，见 [响应格式](../00-约定/01-响应格式.md)），不是上面这些码。

## 阅读页该怎么用

| 状态 | 做法 |
|---|---|
| 只有原文（纯 OCR、还没翻） | 原文 PDF、只有原文的区域可能已经有，译文 PDF、译文元数据是 `null`，不要造一个译文栏 |
| 在翻译、OCR 版面还没好 | 原文照常读；`layout` 可能回 `LIVE_TRANSLATION_LAYOUT_NOT_READY`，带退避重试 |
| 版面好了、这一页没提交 | 原文照常读，等 |
| 这一页提交了 | 只显示返回的、哈希对得上的快照 |
| 翻译结束 | 最终的原文 / 译文 PDF 以产物链接为准；留下的实时快照可以用来排查，不替代最终产物 |
| 翻译失败、取消 | 原文照常读，已经提交的页照常能看；不要因为翻译停了就说阅读页坏了 |
