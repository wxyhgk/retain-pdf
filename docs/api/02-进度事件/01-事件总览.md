# 事件总览

## 接口

```http
GET /api/v1/jobs/{job_id}/events
GET /api/v1/ocr/jobs/{job_id}/events
```

事件流用于展示任务历史、当前阶段和细分进度。

## 事件结构

```json
{
  "created_at": "2026-06-16T12:00:00Z",
  "seq": 1234,
  "display_stage": "translation",
  "stage": "translating",
  "substage": "translation_batches",
  "lane": "main",
  "event_type": "progress",
  "stage_detail": "正在翻译第 789 / 5216 批",
  "message": "translation batch progress",
  "progress": {
    "unit": "batch",
    "current": 789,
    "total": 5216,
    "percent": 15.1
  }
}
```

## 字段说明

- `seq`: 全局递增事件序号。前端用它判断新旧事件。
- `display_stage`: 用户看到的大阶段。
- `stage`: 后端内部阶段。
- `substage`: 机器可读小阶段。
- `lane`: `main` 或 `background`。
- `event_type`: `progress`、`stage_transition`、`artifact_published` 等。
- `progress`: 唯一正式进度对象。
- `message` / `stage_detail`: 人类文案。

## 前端规则

- 按 `seq` 排序。
- 同一个 `display_stage + substage + progress.unit` 内，优先使用最新事件。
- 主状态选择 `lane=main`。
- 后台预处理展示在辅助区域，不覆盖主阶段。
- 不要用 `message` 关键词判断阶段。
