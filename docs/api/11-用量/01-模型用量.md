# 模型用量

模型 token 用量的汇总，两个接口返回同一个结构，契约是
[`token-usage.v1`](../../../contracts/token-usage.v1.schema.json)（前端类型从 `@retainpdf/contracts/token-usage` 导入）。

| 接口 | 谁能用 | 范围 |
|---|---|---|
| `GET /api/v1/documents/{document_id}/usage` | signed | 一本书的全部任务，加上问这本书时 AI 助手花的 |
| `GET /api/v1/usage` | signed | 现存的全部任务，加上 AI 助手；删掉的书不再计入 |

都不分页，没有查询参数。单个任务的 `GET /jobs/{job_id}/reports/usage` 2026-11-14 删了（没有调用方，界面只看书和全部），
见 [第二批删接口](../../ops/planning/api-reorg/20261114-第二批删接口.md)。

## 返回

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "scope": "all",
    "totals": {
      "requests": 120, "requests_without_usage": 2,
      "input_tokens": 830000, "output_tokens": 210000, "total_tokens": 1040000,
      "cache_hit_tokens": 400000, "cache_reported_input_tokens": 790000,
      "cache_write_tokens": 0, "reasoning_tokens": 12000,
      "estimated_cost_usd": 0.4312, "priced_requests": 117, "list_priced_requests": 0, "unpriced_requests": 3
    },
    "by_stage": [{ "stage": "translation", "label": "翻译", "group": "translation", "requests": 100, "...": "同 totals" }],
    "by_model": [{ "model": "deepseek-flash", "host": "api.deepseek.com", "price_provider": "deepseek", "price_basis": "host", "requests": 100, "...": "同 totals" }],
    "by_month": [{ "month": "2026-10", "requests": 120, "...": "同 totals" }],
    "jobs_counted": 8,
    "jobs_estimated_from_reports": 1,
    "first_at": "2026-09-30T23:59:00Z",
    "last_at": "2026-10-22T08:00:00Z",
    "pricing": { "source": "https://models.dev/api.json", "synced_at": "2026-11-19T08:00:00Z", "snapshot_date": null, "currency": "USD" }
  }
}
```

- `scope`：`document` / `all`（`job` 是删掉的单任务接口用的，2026-11-14 从契约去掉）。
- 每一组（`totals`、`by_stage`、`by_model`、`by_month` 的每一项）都是同一套计数：
  - `requests_without_usage`：服务商没报用量的请求数，这些请求的 token 没算进来；
  - `cache_hit_tokens`、`cache_write_tokens` 包含在 `input_tokens` 里，`reasoning_tokens` 包含在 `output_tokens` 里；
  - 缓存命中率 = `cache_hit_tokens / cache_reported_input_tokens`，分母为 0 表示不知道（服务商没报缓存）。
- `by_stage` 按 `total_tokens` 从大到小；`group` 是 `translation` / `preparation` / `refine` / `assistant` / `other`，界面按它分组，`label` 是中文名。
  2026-11-19 起多了 `ocr`（「OCR 识别」，`preparation` 组）：GLM-OCR 真请求过的片，见 [GLM-OCR](../03-OCR/06-GLM-OCR.md#用量和花费2026-11-19)。
- `by_month` 按月份从早到晚，`month` 是 `YYYY-MM`（UTC）。
- `jobs_estimated_from_reports`：有台账之前的旧任务，从翻译诊断和精修报告折算，只算得出输入输出（没有缓存、思考明细），
  界面可以注明"早期任务按报告估算"。
- `first_at`、`last_at`：最早、最近一条用量的时间，没有用量时为 `null`。
- 花费（2026-11-19 起，只增不改）：每一组多了 `estimated_cost_usd`、`priced_requests`、`list_priced_requests`、
  `unpriced_requests`，`by_model` 每项多了 `price_provider`、`price_basis`，汇总多了 `pricing`，见下面「估算花费」。

## 估算花费

花费是**估算**，界面写「约 $0.43」。

- **价格从哪来**：[models.dev](https://models.dev)（github.com/anomalyco/models.dev，MIT），社区维护的各家标价，每天都在更新。
  - 服务端每天同步一次（启动 30 秒后开始，每小时看一眼，上次同步超过 20 小时才拉），存成价格历史
    `<data_root>/pricing/model-prices.v1.json`：价格变了追加一条，不覆盖。
  - 每条用量按它那天生效的价算，降价以后旧账不跟着变；比第一次同步还早的用量按最早那批价算。
  - 没同步过（第一次启动、断网）用程序里带的快照，只有官方服务商；`pricing.synced_at` 为 `null`、`snapshot_date` 是快照日期。
  - `RETAINPDF_MODEL_PRICES_URL` 换镜像地址，设成空字符串不同步。同步只发一个不带账号信息的 GET。
- **怎么对价**：
  - 台账每行记了接口域名和模型。域名对上 models.dev 里某家服务商的接口地址，在它那里按模型编号查价：`price_basis = "host"`；
  - 对不上（代理、自建网关）或那家没有这个模型，按模型的官方标价估算：`"official_list"`，数进 `list_priced_requests`；
  - 都查不到，不定价，数进 `unpriced_requests`，花费里不算（例如用 IP 访问的自建模型）。
  - `price_provider` 是 models.dev 的服务商编号（`anthropic`、`alibaba-cn`、`deepseek`、`zhipuai`……）。
- **怎么算**：
  - 输入分三份：缓存命中按缓存读价，缓存写入按缓存写价，其余按输入价；服务商没给缓存价的按输入价。
  - 一次请求的输入超过分档门槛（例如 Haiku 5.5 的 10 万 token），整次按那一档的价。
  - DeepSeek 分忙闲时：models.dev 记的是闲时价，工作日 UTC 01–04 点、06–10 点按 2 倍算。
    中国法定节假日整天是闲时，这里判断不了，按工作日算，节假日忙时段的请求会估高。
  - 不含折扣、包月套餐、代金券；国内站的价格在 models.dev 里是从人民币换算的美元。
  - models.dev 里没有的模型，服务端自己补价（官方页面核对过，按 1 美元 = 7.16 元换算；models.dev 以后收录了以它为准）：
    智谱 GLM-OCR `glm-ocr` 输入输出都是 0.2 元/百万 token（2026-11-19 核对）。
  - 金额保留 6 位小数。

## 数据从哪来

- 每个任务的台账 `artifacts/token-usage.v1.jsonl`：流水线每次模型返回追加一行；
- AI 助手的台账 `<data_root>/usage/assistant.v1.jsonl`；
- 有台账之前的旧任务：`translation_diagnostics.json` 和精修报告里的 `token_usage`。

台账是追加写的文本，坏行（写到一半断电之类）跳过，不让整份汇总失败。
时间戳取不出 `YYYY-MM`（被手改过、别的工具写的）的那一行照样计入总数和按阶段、按模型，只是不进 `by_month`，
也不当 `first_at` / `last_at`（2026-10-22 起；以前一行怪时间戳会让整个接口 500）。

## 报错

- `GET /documents/{document_id}/usage`：书不存在 404；有书没任务 200、全零。
- `GET /usage`：多用户模式下只算当前账号的任务（不含助手）。

每次请求都把涉及的任务目录读一遍，没有缓存；任务多了以后再加（见
[服务商探测与用量](../../ops/planning/api-reorg/20261022-服务商探测与用量.md)）。
