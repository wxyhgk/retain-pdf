# 模型用量

模型 token 用量的汇总，三个接口返回同一个结构，契约是
[`token-usage.v1`](../../../contracts/token-usage.v1.schema.json)（前端类型从 `@retainpdf/contracts/token-usage` 导入）。

| 接口 | 谁能用 | 范围 |
|---|---|---|
| `GET /api/v1/jobs/{job_id}/reports/usage` | signed | 一个任务自己的（含它的原地精修、重渲染），不含同一本书的其它任务；2026-11-20 加回 |
| `GET /api/v1/documents/{document_id}/usage` | signed | 一本书的全部任务，加上问这本书时 AI 助手花的 |
| `GET /api/v1/usage` | signed | 现存的全部任务，加上 AI 助手；删掉的书不再计入 |
| `POST /api/v1/usage/prices` | signed | 按接口地址和模型批量查单价（2026-11-19 起），见「查单价」 |
| `GET /api/v1/documents/{document_id}/usage/estimate` | signed | 这本书换个模型重新翻译大概多少钱（2026-11-19 起），见「估价」 |
| `GET /api/v1/usage/estimate` | signed | 还没有的书按书库每页平均估（2026-11-19 起），见「估价」 |

都不分页，没有查询参数。单个任务的 `GET /jobs/{job_id}/reports/usage` 2026-11-14 删过（当时没有调用方），2026-11-20 加回：
进度页拿书的合计当成这一次的花费，一本翻过多轮的书显示成十几倍，见 [加回单个任务的用量](../../ops/planning/api-reorg/20261120-加回单个任务的用量.md)。
任务不存在 `404`；合并阅读的虚拟任务给空汇总；旧目录格式的任务 `409`；库里没有记录但任务目录还在，照样给用量。

## 返回

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "scope": "all",
    "totals": {
      "requests": 120, "requests_without_usage": 2,
      "input_tokens": 830000, "output_tokens": 210000, "total_tokens": 1040000,
      "cache_hit_tokens": 400000, "cache_reported_input_tokens": 790000,
      "cache_write_tokens": 0, "reasoning_tokens": 12000,
      "estimated_cost_usd": 0.4312, "priced_requests": 117, "list_priced_requests": 0, "unpriced_requests": 3
    },
    "by_stage": [{ "stage": "translation", "label": "翻译", "group": "translation", "requests": 100, "...": "同 totals" }],
    "by_model": [{ "model": "deepseek-flash", "host": "api.deepseek.com", "price_provider": "deepseek", "price_basis": "host", "requests": 100, "...": "同 totals" }],
    "by_month": [{ "month": "2026-10", "requests": 120, "...": "同 totals" }],
    "jobs_counted": 8,
    "jobs_estimated_from_reports": 1,
    "first_at": "2026-09-30T23:59:00Z",
    "last_at": "2026-10-22T08:00:00Z",
    "pricing": { "source": "https://models.dev/api.json", "synced_at": "2026-11-19T08:00:00Z", "snapshot_date": null, "currency": "USD", "usd_cny": 7.16 }
  }
}
```

- `scope`：`job` / `document` / `all`（`job` 2026-11-14 随单任务接口从契约去掉，2026-11-20 加回）。
- 每一组（`totals`、`by_stage`、`by_model`、`by_month` 的每一项）都是同一套计数：
  - `requests_without_usage`：服务商没报用量的请求数，这些请求的 token 没算进来；
  - `cache_hit_tokens`、`cache_write_tokens` 包含在 `input_tokens` 里，`reasoning_tokens` 包含在 `output_tokens` 里；
  - 缓存命中率 = `cache_hit_tokens / cache_reported_input_tokens`，分母为 0 表示不知道（服务商没报缓存）。
- `by_stage` 按 `total_tokens` 从大到小；`group` 是 `translation` / `preparation` / `refine` / `assistant` / `other`，界面按它分组，`label` 是中文名。
  2026-11-19 起多了 `ocr`（「OCR 识别」，`preparation` 组）：GLM-OCR 真请求过的片，见 [GLM-OCR](../03-OCR/06-GLM-OCR.md#用量和花费2026-11-19)。
- `by_month` 按月份从早到晚，`month` 是 `YYYY-MM`（UTC）。
- `jobs_estimated_from_reports`：有台账之前的旧任务，从翻译诊断和精修报告折算，只算得出输入输出（没有缓存、思考明细），
  界面可以注明"早期任务按报告估算"。
- `first_at`、`last_at`：最早、最近一条用量的时间，没有用量时为 `null`。
- 花费（2026-11-19 起，只增不改）：每一组多了 `estimated_cost_usd`、`priced_requests`、`list_priced_requests`、
  `unpriced_requests`，`by_model` 每项多了 `price_provider`、`price_basis`，汇总多了 `pricing`，见下面「估算花费」。

## 估算花费

花费是**估算**，界面写「约 $0.43」。

- **价格从哪来**：[models.dev](https://models.dev)（github.com/anomalyco/models.dev，MIT），社区维护的各家标价，每天都在更新。
  - 服务端每天同步一次（启动 30 秒后开始，每小时看一眼，上次同步超过 20 小时才拉），存成价格历史
    `<data_root>/pricing/model-prices.v1.json`：价格变了追加一条，不覆盖。
  - 每条用量按它那天生效的价算，降价以后旧账不跟着变；比第一次同步还早的用量按最早那批价算。
  - 没同步过（第一次启动、断网）用程序里带的快照，只有官方服务商；`pricing.synced_at` 为 `null`、`snapshot_date` 是快照日期。
  - `RETAINPDF_MODEL_PRICES_URL` 换镜像地址，设成空字符串不同步。同步只发一个不带账号信息的 GET。
- **怎么对价**：
  - 台账每行记了接口域名和模型。域名对上 models.dev 里某家服务商的接口地址，在它那里按模型编号查价：`price_basis = "host"`；
  - 对不上（代理、自建网关）或那家没有这个模型，按模型的官方标价估算：`"official_list"`，数进 `list_priced_requests`；
  - 都查不到，不定价，数进 `unpriced_requests`，花费里不算（例如用 IP 访问的自建模型）。
  - `price_provider` 是 models.dev 的服务商编号（`anthropic`、`alibaba-cn`、`deepseek`、`zhipuai`……）。
- **怎么算**：
  - 输入分三份：缓存命中按缓存读价，缓存写入按缓存写价，其余按输入价；服务商没给缓存价的按输入价。
  - 一次请求的输入超过分档门槛（例如 Haiku 5.5 的 10 万 token），整次按那一档的价。
  - DeepSeek 分忙闲时：models.dev 记的是闲时价，工作日 UTC 01–04 点、06–10 点按 2 倍算。
    中国法定节假日整天是闲时，这里判断不了，按工作日算，节假日忙时段的请求会估高。
  - 不含折扣、包月套餐、代金券；国内站的价格在 models.dev 里是从人民币换算的美元。
  - models.dev 里没有的模型，服务端自己补价（官方页面核对过，按 1 美元 = 7.16 元换算；models.dev 以后收录了以它为准）：
    智谱 GLM-OCR `glm-ocr` 输入输出都是 0.2 元/百万 token（2026-11-19 核对）。
  - 金额保留 6 位小数。

## 查单价

`POST /api/v1/usage/prices`，请求 `{"items": [{"base_url": "https://api.deepseek.com/v1", "model": "deepseek-flash"}, …]}`（最多 100 条，多了 400）。
返回 `{pricing, items}`，`items` 和请求一一对应、同顺序：

```json
{ "base_url": "https://api.deepseek.com/v1", "model": "deepseek-flash", "price_provider": "deepseek", "price_basis": "host",
  "price": { "input": 0.15, "output": 0.6, "cache_read": 0.003, "cache_write": null, "tiers": [], "peak_multiplier": 2.0 } }
```

- 单价是每百万 token 的美元，对价规则和上面「估价花费」一样；查不到 `price_provider`、`price_basis`、`price` 都是 `null`。
- `cache_read`、`cache_write` 为 `null` 表示按输入价算；`tiers` 是输入超过门槛后整次请求的价（例如 Haiku 5.5 超过 10 万）；
  `peak_multiplier` 是一天里最贵时段的倍数（DeepSeek 忙时 2，别家 1）。
- `pricing.usd_cny`：1 美元换多少人民币，写死 7.16（和 models.dev 换算国内站价格用的一致），显示「约 ¥x」用。
- 下拉框显示单价用这个；估价用下面两个接口，不要在前端自己乘（缓存、分档、忙闲时的规则只在后端一处）。

## 估价

重新翻译换模型之前给个价。两个接口返回同一个结构 `UsageEstimateView`：

| 接口 | 查询参数 | 参照 |
|---|---|---|
| `GET /documents/{document_id}/usage/estimate` | `base_url`、`model` | 这本书最近一次翻译（`basis = "book_history"`）；没翻译过按书库每页平均乘这本书的页数（`"library_average"`） |
| `GET /usage/estimate` | `base_url`、`model`、`pages`（1–100000） | 书库每页平均乘 `pages`；多用户模式只算当前账号的任务 |

```json
{ "basis": "book_history", "base_url": "https://api.deepseek.com/v1", "model": "deepseek-flash",
  "price_provider": "deepseek", "price_basis": "host", "pages": 212, "source_job_id": "20261118103126-246003",
  "sample_documents": 0, "sample_pages": 0,
  "translation": { "requests": 240, "input_tokens": 1830000, "output_tokens": 410000, "cache_hit_tokens": 600000,
                   "low_usd": 0.43, "high_usd": 1.04, "low_cny": 3.0788, "high_cny": 7.4464 },
  "refine": null,
  "pricing": { "...": "同用量汇总的 pricing" } }
```

- **最近一次翻译**：这本书**成功完成**的任务里，翻译部分最后一条用量时间最晚的那个（`source_job_id`），用它的逐条用量按新模型的价重算。
  取消、失败、还在跑的任务不当参照（2026-11-19 起；以前刚建就取消的任务也算，估出来一排「约 ¥<0.01」）。那次选了页码范围、只翻了部分页的，
  按「整本页数 ÷ 翻的页数」放大；翻得不到 5 页的（书本身更短就整本）不当参照。一个都没有就退回书库平均。
- **翻译**（`translation`）含译前准备（术语预扫、通读……），**不含 OCR**：重新翻译复用 OCR 结果。**精修**（`refine`）另算，参照里没有精修是 `null`。
- **区间**：`low_*` 按参照里的缓存命中算；`high_*` 当缓存全没命中、按最贵时段（DeepSeek 忙时 2 倍）。界面写「约 ¥3.1–7.4」。
- **书库平均**：书库里每本书取最近一次能当参照的翻译（同上：成功完成、翻够页数），按那次实际翻的页数合起来平均（`sample_documents` 本、`sample_pages` 页），
  分档按平均一次请求的大小判断。书库里还没有翻译过的书时 `basis = "none"`，`translation`、`refine` 都是 `null`。
- 模型查不到价时照样给 token，四个金额是 `null`。
- 只是估：模型换了，输出长短、重试次数都会变。
- 报错：`base_url` 不是 http(s)、`model` 为空、`pages` 越界、参数不认识都是 400；书不存在 404。

## 数据从哪来

- 每个任务的台账 `artifacts/token-usage.v1.jsonl`：流水线每次模型返回追加一行；
- AI 助手的台账 `<data_root>/usage/assistant.v1.jsonl`；
- 有台账之前的旧任务：`translation_diagnostics.json` 和精修报告里的 `token_usage`。

台账是追加写的文本，坏行（写到一半断电之类）跳过，不让整份汇总失败。
时间戳取不出 `YYYY-MM`（被手改过、别的工具写的）的那一行照样计入总数和按阶段、按模型，只是不进 `by_month`，
也不当 `first_at` / `last_at`（2026-10-22 起；以前一行怪时间戳会让整个接口 500）。

## 报错

- `GET /documents/{document_id}/usage`：书不存在 404；有书没任务 200、全零。
- `GET /usage`：多用户模式下只算当前账号的任务（不含助手）。

**每个任务的汇总存在库里**（2026-11-21 起，库 v34 的 `job_usage_cache` / `job_usage_rollups`；以前每次请求都把全部任务目录读一遍，
本机「总用量」要几秒到几十秒）。按（阶段、模型、接口域名、月份）一组存，花费逐行估好再加。每次请求只看一眼台账和报告文件的
大小、修改时间（加上价格表的指纹）：对得上就用存着的，对不上（任务还在跑、精修又写了报告、价格表同步了新价）只重算那一个任务。
正本照旧是任务目录里的文件，库里这份随时可以删掉重算。返回结构不变；花费因为先按组再合计，和逐行相加在第 6 位小数上可能差 1。
真实数据（本机 debug 构建）：第一次 6.2 秒（算完存库），之后约 60 毫秒。
