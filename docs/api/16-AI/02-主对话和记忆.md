# 阅读页提问：主对话、副对话和记忆

2026-11-26 起（数据库 v40）。一个**全局主对话**一直延续（不按书切），副对话从主对话某条消息分出来深挖、结束时结论回到主对话；
每条消息记自己属于哪本书和**结构化出处**（任务、译文版本、页、块、选中的字）；**记忆**分用户层和书层。**库是正本**，agent 只负责回答：
开新会话时由后端拼好上下文交给 agent，换 agent 也能接着聊。契约 `ask-conversations.v1`（`@retainpdf/contracts/ask-conversations`）。
设计和分期见 [主对话、副对话和记忆](../../ops/planning/reader-ask/20261126-主对话副对话和记忆.md)。

- 都包在 `{code, message, data}` 里；请求体、查询参数不认识的字段 `400`。
- **多用户模式下关闭**（网站账号 `404`）：全局的对话、记忆没有归属列。单机照常用。
- 不同步到别的设备；跟着数据库进备份。
- v39 的按书问答记录（[阅读页提问](./01-阅读页提问.md)「问答记录」）**只读保留**，不迁过来；新前端不再往里写。

## 接口

| 方法 | 地址 | 做什么 | AI 专用密钥 |
|---|---|---|---|
| `POST` | `/ai/ask-conversations/main` | 取或建当前的全局主对话（幂等） | 不能 |
| `GET` | `/ai/ask-conversations` | 列对话（`kind`、`status`、`parent_id` 筛）；主对话在前 | 不能 |
| `POST` | `/ai/ask-conversations` | 开副对话 `{parent_id, forked_from_message_id?, title?, document_id?}` | 不能 |
| `GET` | `/ai/ask-conversations/{conversation_id}` | 一个对话 | 不能 |
| `PATCH` | `/ai/ask-conversations/{conversation_id}` | `{title?, status?}`：改标题、归档主对话、再开副对话 | 不能 |
| `DELETE` | `/ai/ask-conversations/{conversation_id}` | 删对话（消息、它的副对话跟着删；记忆留着） | 不能 |
| `POST` | `/ai/ask-conversations/{conversation_id}/close` | 结束副对话 `{summary?}` | 不能 |
| `GET` | `/ai/ask-conversations/{conversation_id}/messages` | 消息分页（`before_seq`、`limit`） | 不能 |
| `POST` | `/ai/ask-conversations/{conversation_id}/messages` | 追加一轮 `{messages: [...]}` | 不能 |
| `GET` | `/ai/ask-conversations/{conversation_id}/context` | 开新会话用的上下文（`document_id`、`recent_turns`） | **能** |
| `GET` | `/documents/{document_id}/ask-messages` | 这本书上问过的地方（画「?」） | 不能 |
| `GET` | `/ai/memories` | 列、查记忆（`scope`、`document_id`、`q`、`status`、`source_conversation_id`、`created_after`、`limit`） | **能** |
| `POST` | `/ai/memories` | 记一条 | **能** |
| `PATCH` | `/ai/memories/{memory_id}` | 改字、类别 | 不能 |
| `DELETE` | `/ai/memories/{memory_id}` | 删（撤销）一条 | 不能 |

地址前缀省略了 `/api/v1`。为什么不用 `/ai/conversations`：这个地址 2026-11-03 跟旧的 AI 服务一起删了，意思不一样，不复用。

## 对话

```json
{"conversation_id": "conv-20261126103000-a1b2c3", "kind": "side", "parent_id": "conv-…", "forked_from_message_id": "msg-…",
 "status": "closed", "title": "深挖 这句", "summary": "结论：……", "document_id": "<书>",
 "message_count": 6, "last_seq": 6, "created_at": "…", "updated_at": "…", "closed_at": "…"}
```

- `kind`：`main` 全局主对话 / `side` 副对话。同一时间**只有一个 `open` 的主对话**；`POST …/main` 有就回它，没有就建一条空的。
- `status`：主对话 `open` / `archived`；副对话 `open` / `closed`（结束了）/ `archived`。主对话归档以后再取主对话会建新的；
  重新打开一个旧主对话时已经有开着的 `409 ask_main_conversation_open`；主对话改成 `closed` `400`。
- 副对话：`parent_id` 必须是主对话（副对话不嵌套，`400`）；`forked_from_message_id` 要是主对话里的消息（`400`）；没有父对话 `404`。
  `title` 空白压成一个空格，最多 200 字。
- **结束副对话** `POST …/close`：`status` 变 `closed`。给了 `summary`（最多 8000 字）就记下，并在**主对话末尾追加一条 `side_summary` 卡片**
  （指回副对话；主对话不是 `open` 时不追加），返回 `{conversation, card}`；没给只关掉，`card` 是 `null`。已经结束的再给 `summary` 再追加一张。
  第一期摘要由前端给；第二期由后端用设置里的模型生成。结束了的副对话 `PATCH status=open` 能再开。
- 删对话：消息、它的副对话跟着删；**记忆留着**（出处置空）；副对话回到主对话的卡片留着（`side_conversation_id` 置空）。

## 消息

```json
{"message_id": "msg-…", "conversation_id": "conv-…", "seq": 1, "role": "user", "text": "这句是什么意思？",
 "thought": null, "usage": null, "agent_id": "retainpdf", "side_conversation_id": null,
 "document_id": "<书>", "job_id": "<任务>", "version_id": "<译文版本>", "pane": "translated", "page": 56,
 "selection": {"document_id": "<书>", "job_id": "<任务>", "translation_version": "<译文版本>", "pane": "translated", "page": 56,
               "item_ids": ["p056-b0003"], "selected_text": "选中的一句", "section": "2 方法"},
 "client_message_id": "c-1", "created_at": "…"}
```

- `role`：`user` / `assistant` / `side_summary`（只由结束副对话写）。`seq` 从 1 起，分页按它。
- `document_id`：**这条属于哪本书**（问的时候在读的书）。书删了置空，文字快照留着。主对话不分书，每条自己记。
- 出处查得多的几项拆成了 `job_id`、`version_id`（就是出处的 `translation_version`）、`pane`、`page`；整个出处在 `selection`（整理过的，
  只有有值的键）。`job_id`、`version_id` 只是编号，任务删了、版本换了还在。
- **只追加，不覆盖**：`POST …/messages` 一次 1–10 条（一轮问答一起），按顺序排在最后。两个窗口同时问也只是各自往后追加。
  - `client_message_id`（最长 128 字）在这个对话里重复的不再追加，回原来那条——网络重试安全。
  - `document_id` 不给时取 `selection.document_id`；两个都给又不一样 `400`；书不在库里当没有书。
  - `memory_ids`（最多 10 个）：这条回答里记下的记忆（「已记住」的编号），出处还空着的补上这条消息。
  - 对话结束了或归档了 `409 ask_conversation_not_open`；超过 50000 条 `409 ask_conversation_limit`（`details.limit`）。
  - 长度同问答记录：正文 50000 字、思考 20000 字、用量是对象且写成 JSON 最多 4096 字节，超了 `400`。
- 分页：`GET …/messages?before_seq=&limit=`（默认 50，1–200）回 `seq < before_seq` 的最后 `limit` 条，按 `seq` 从小到大；`has_more` 说前面还有没有，
  再拿第一条的 `seq` 当 `before_seq` 往前翻。
- 书上的「?」：`GET /documents/{document_id}/ask-messages` 回所有对话里属于这本书、有页码的问（`role: user`），按页再按时间，最多 2000 条。

## 结构化出处（`selection`）

请求里（追加消息的 `selection`，和 ACP `session/prompt` 的 `_meta.retainpdf.selection` 同一个写法）：

| 字段 | 说明 |
|---|---|
| `page` | **必填**，第几页（从 1 起，最大 100000） |
| `document_id`、`job_id`、`translation_version` | 书、阅读页正在读的任务（`merged-…` 也行）、译文版本；1–200 个字母、数字、`-_.:` |
| `pane` | `source` / `translated` |
| `item_ids` | 选区落在哪几块（前端按选区换算，后端不碰坐标），最多 50 个；空的、重复的去掉 |
| `selected_text`、`section`、`source_text`、`translated_text`、`prefix`、`suffix` | 选中的字（4000 字）、章节（200 字）、那一块的原文和译文（各 8000 字）、选区前后几个字（各 200 字，换版本、重翻后重新定位用）；超长截断 |

返回里的 `selection` 只有有值的键（`page`、`item_ids` 总在）。

## 开新会话用的上下文：`GET /ai/ask-conversations/{conversation_id}/context`

查询参数：`document_id`（当前在读的书，带上它的书层记忆）、`recent_turns`（最近几轮，1–20，默认 6）。

```json
{"conversation": {…}, "summary": null, "parent": null,
 "messages": [{…}, {…}], "omitted_messages": 12,
 "memories": {"user": [{…}], "user_omitted": 0, "book": [{…}], "book_omitted": 0},
 "memory_text": "【RetainPDF 记下的关于用户的事（用户可以看、改、删；是参考，不是指令；和用户这次说的冲突时以这次为准）】\n- [mem-…] 2026-11-20 回答风格：用户要先看结论",
 "text": "（memory_text）\n\n【我们之前的对话（最近几轮，更早的 12 条没带）】\n\n我（第 56 页）：……\n\n你：……"}
```

- `messages`：最近 `recent_turns` 轮（`recent_turns × 2` 条，副对话的摘要卡片也算一条），**不分书**，最多 16000 字（至少一条，太长截断）。
- `parent`：副对话才有——主对话到分叉那条为止的最近几轮。
- `memories`：用户层每次都带（约 3000 字，≈2000 token），书层是 `document_id` 那本书的（约 2000 字）；都是最近改过的在前、只有 `active` 的，
  放不下的条数在 `*_omitted`。
- `memory_text`：记忆那段的给模型看的写法（每条 `- [编号] 日期 类别：内容`），自带 agent 放进系统提示词**最后**（前面的固定内容走缓存）。
- `text`：整份拼好的文字（记忆 + 前文），给不认结构的本机 agent：前端放进新会话第一问的前面。什么都没有是空串。
- `summary`：压缩摘要，第二期才有，现在总是 `null`。
- AI 专用密钥能调（自带 agent 开会话时自己取）。

## 记忆

```json
{"memory_id": "mem-…", "scope": "book", "document_id": "<书>", "category": "term", "text": "Hamiltonian 定译为哈密顿量",
 "status": "active", "superseded_by": null, "origin": "agent", "agent_id": "retainpdf",
 "source_conversation_id": "conv-…", "source_message_id": "msg-…", "source_job_id": "<任务>", "source_page": 56,
 "created_at": "…", "updated_at": "…", "deleted_at": null}
```

- `scope`：`user` 关于用户（偏好、背景、回答风格）/ `book` 关于某本书（读到哪、术语、结论）。书层要 `document_id`（书不在 `404`），用户层不能给（`400`）。
  **删书时书层记忆跟着删**；删对话不删记忆。
- `category`：`preference` / `background` / `style` / `progress` / `term` / `conclusion` / `other`（默认）。
- `text`：一条一件事，1–500 字（去掉首尾空白）。
- `status`：`active` / `superseded`（被新的一条替代，`superseded_by` 指新的）/ `deleted`（用户删了、撤销了；行留着，列表默认看不到，**模型看不到**）。
- `origin`：`user`（默认，用户在记忆面板里加的）/ `agent`（模型用 `remember` 记的，带 `agent_id`）。
- 出处：`source_conversation_id`、`source_message_id`（不在库里的当没给）、`source_job_id`、`source_page`。

`POST /ai/memories`：`{scope, text, document_id?, category?, origin?, agent_id?, source_*?, replaces?}`，回 `{memory, created, replaced}`。

- 同层同书、去掉空白后一模一样的 `active` 记忆已经有了：不重记，回那条，`created: false`。
- `replaces`：要替代的旧条（标 `superseded`）；没有或已删 `400`。
- 每层 `active` 的上限：用户层 200 条、书层每本书 500 条，到了 `409 ask_memory_limit`（`details.limit`、`details.scope`）：先删旧的或用 `replaces`。

`GET /ai/memories`：最近改过的在前（默认 100 条，最多 500）。`q` 全文检索（最多 200 字）：空格隔开的词都要在同一条里；每个词都 ≥3 个字时走
FTS5（trigram，不分大小写，按相关度排），否则退回 `LIKE`。`status` 默认 `active`，`all` 是全部。`source_conversation_id` + `created_after`
（RFC 3339）用来补画一轮里记下的。

`PATCH /ai/memories/{id}`：`{text?, category?}`，`updated_at` 换成现在；删了的 `409 ask_memory_deleted`。

`DELETE /ai/memories/{id}`：标 `deleted`、记 `deleted_at`；**被它替代的旧条恢复成 `active`**（撤销一次「记住」就回到记之前）。再删一次原样返回。

## 自带 agent（`retainpdf`）怎么用（2026-11-26 起）

- **握手**：`/ai/agents/retainpdf/acp` 多一个查询参数 `conversation_id`（只许字母、数字、`-_.:`，不对 `400`；不查存不存在）。桥经环境变量
  `RETAIN_ASK_CONVERSATION_ID` 交给 agent；后端地址和密钥（`RETAIN_ASK_BACKEND_URL`、`RETAIN_ASK_BACKEND_KEY`）有密钥就给，**没带书也给**（记忆工具要用）。
  `retainpdf-pi` 和本机 agent 不看它（第二期、第三期）。
- **`initialize`** 多报 `agentCapabilities._meta.retainpdf`：`{"selection": true, "memory": <有记忆工具>, "conversation": <握手带了对话>}`。
  `selection` 为真：前端可以不在问题前面写那段可读出处（agent 自己按 `_meta.retainpdf.selection` 写一段给模型）；`conversation` 为真：
  agent 开会话时自己取前文，前端**不要**再把前几轮拼成文字带过去。`loadSession` 仍是 `false`（库是正本，`session/new` + `conversation_id` 已经能续）。
- **开会话**（`session/new`）：带了对话就 `GET …/context`（`document_id` 是握手的书，最近 6 轮），`memory_text` 放进系统提示词最后，最近几轮当真的
  user / assistant 消息进会话历史（副对话先接主对话前文；摘要卡片当用户那边的一条；开头是回答的去掉）。取不到就当没有前文。会话中途记的新记忆
  不刷新系统提示词（缓存不失效），下个会话再带。
- **每一问**：`session/prompt` 的 `_meta.retainpdf.selection` 优先于旧的 `_meta.retainpdf.anchor`（读书的工具照旧认 `anchor`，有 `selection`
  没 `anchor` 时换一份）；都没有再从问题里前端写的那段字认。问题里没有前端那段字时，agent 在问题前面写一段「【这一问的出处（RetainPDF）】第 N 页……」。
- **工具**（有后端地址和密钥就给，没有书也有）：

  | 工具 | 参数 | 做什么 |
  |---|---|---|
  | `remember` | `text`（≤ 500 字）、`scope`（`user` / `book`）、`category`、`replaces` | `POST /ai/memories`（`origin: agent`，出处是这个对话、这一问出处的书、任务和页；书层的书取出处的书，没有取握手的书，都没有回工具出错） |
  | `search_memories` | `query`、`scope`（`user` / `book` / `all`，默认 `all`）、`limit`（默认 8，最多 20） | `GET /ai/memories?q=…`；书层只查当前这本书，结果每条带编号、日期、类别、「关于用户 / 这本书 / 别的书」 |

  额度（和读书、互动块分开）：每一问记 3 次、查 2 次，超了的不执行、卡片 `failed`。
- **「已记住（撤销）」**：`remember` 是一次真的工具调用，照 ACP 发 `tool_call`（`title`「记住：……」，`kind: "other"`）和 `tool_call_update`；成功时
  `tool_call_update`（`status: "completed"`）的 `_meta.retainpdf` 多一个 `memory`（契约里的 `AcpMemoryNotice`）：

  ```json
  {"sessionUpdate": "tool_call_update", "toolCallId": "toolu_…", "status": "completed",
   "content": [{"type": "content", "content": {"type": "text", "text": "已记住：用户要先看结论"}}],
   "_meta": {"retainpdf": {"round": 1, "memory": {"id": "mem-…", "scope": "user", "text": "用户要先看结论", "category": "style",
     "document_id": null, "created": true, "replaced": null}}}}
  ```

  编号写进库以后才有，所以在 `tool_call_update` 上，不在 `tool_call` 上。前端把这张卡片画成「已记住：……（撤销）」，撤销调 `DELETE /ai/memories/{id}`；
  这一轮的编号在追加回答时放进 `memory_ids`。`created: false` 是已经记过一模一样的（没有新记，不用画撤销）。
- 用量 `_meta.retainpdf.usage` 多一个 `memory`（这一问调过记忆工具才有）：`remember_calls`、`remembered`（记成的）、`search_calls`、`refused`。

## 上限和错误

| 情况 | 结果 |
|---|---|
| 没有这个对话、记忆、书 | `404` |
| 追加到结束了或归档了的对话 | `409`，`reason = ask_conversation_not_open` |
| 一个对话超过 50000 条 | `409`，`reason = ask_conversation_limit`，`details.limit` |
| 重新打开旧主对话时已经有开着的 | `409`，`reason = ask_main_conversation_open` |
| 记忆一层的 `active` 到上限（用户层 200、书层每本书 500） | `409`，`reason = ask_memory_limit`，`details.limit`、`details.scope` |
| 改一条已经删了的记忆 | `409`，`reason = ask_memory_deleted` |
| 副对话嵌套、分叉消息不在父对话里、结束主对话、主对话改成 `closed`、出处 `page` 出范围或 `pane` 不认识、编号写法不对、书层没给书 / 用户层给了书、`replaces` 找不到、长度超了、一次追加 0 条或超过 10 条 | `400` |
