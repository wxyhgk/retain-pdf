- 自带的（`retainpdf`）总排第一，服务器上也能用。第二行是 `retainpdf-pi`（2026-11-26 加，也是 `kind: "builtin"`，用设置里的模型，
  但起的是本机装的 pi，只在本机 agent 的闸门里能用，见下面「RetainPDF + pi」）。
- 本机 agent（2026-11-26 起）来自 [ACP 官方登记表](https://agentclientprotocol.com/get-started/registry)
  （`cdn.agentclientprotocol.com/registry/v1/latest/registry.json`）：后端用仓库里的快照
  （`backend/packages/retainpdf-providers/src/acp/registry-snapshot.json`，`python3 ops/development/update_acp_registry.py` 刷新），
  **运行时不联网取**，只起快照里有的，命令名、参数、环境变量都照快照写死，不收客户端给的。现在列 40 来个（Claude Code、Codex、
  Google Antigravity、pi、OpenCode、Qwen Code、Kimi Code、goose、GitHub Copilot、Cursor……；2026-11-26 起推荐名单里 Antigravity
  换下 Gemini CLI，Gemini 照旧列出）。不列的：付费 agent 市场、旧 id、这个平台起不了的，名单和原因在同目录的 `agents.json`（`hidden`）。
- 排序：装了的在前，再按推荐顺序（`featured: true` 的那几个），其余按名字。前端可以只展开推荐的和装了的，其余折起来。
- 「装了」先看后端自己的安装目录（`<数据目录>/acp-agents/`，下面「代装」），再看 PATH 上有没有那个命令（不经 shell）：压缩包发行的（`distribution: "binary"`）是压缩包里的命令名；npm 包（`npx`）的是
  npm 的 `bin`（登记表没写，`agents.json` 的 `bins` 人工核过）；Python 包（`uvx`）的就是包名。装了几种的，按压缩包、npm、Python 的顺序找。
  pi-acp 还要 PATH 上有 `pi`（pi 本体，`@earendil-works/pi-coding-agent`），没有就 `available: false`，`reason` 说缺什么。
- 没装就 `available: false`，`reason` 写怎么装：有一条命令的（npm、uv）`install` 是安装命令（在终端跑一次，pi-acp 没装 pi 时连 pi 一起装）；
  只有压缩包的没有 `install`，`install_url` 是这个平台的下载地址。`launch` 是实际起法（命令名加登记表的参数，比如 `gemini --acp`、
  `qwen --acp --experimental-skills`、`goose acp`）。
- 2026-11-25 以前没装适配器时用 `npx -y` 现场下载：Claude Code 的适配器第一次要下约 384 MB，下到一半连接断了会在 `~/.npm/_npx`
  留下坏的可执行文件，之后每次都 `spawn ... -88`，所以不现场下载（npx、uvx 都不）。
- **id**：本机 agent 的 `id` 是登记表的 id（`pi-acp`、`opencode`、`qwen-code`……），只有 2026-11-25 就有的两个沿用旧写法：
  `claude-code`（登记表 `claude-acp`）、`codex`（登记表 `codex-acp`）；`gemini` 两边一样。`registry_id` 是登记表的 id，
  WebSocket 地址里写登记表 id 也认（`/ai/agents/claude-acp/acp` 和 `/ai/agents/claude-code/acp` 是同一个），列表里只出一行。
- 2026-11-26 加的字段（只增）：`registry_id`、`description`（登记表的一句英文介绍）、`version`（快照里登记的版本，不是本机装的）、
  `homepage`（官网，没有就是代码仓库）、`license`、`distribution`（`binary` / `npx` / `uvx`：装了的按找到的那种，没装的按推荐的装法）、
  `install_url`、`featured`（推荐的才有，`true`）。自带的这些都没有。
- `install_status`（2026-11-26 加，只增）：
  - `state`：`missing` 没装、`installing` 后端正在装、`installed` 装好了（安装目录里或 PATH 上）、`failed` 上一次代装失败（`error` 是原因，可以再装）；
  - `managed`：装在后端自己的安装目录里（`false` 是没装，或者用户自己装在 PATH 上）；`installed_version`：安装目录里的版本；
  - `installable`：后端能不能代装，不能时 `reason` 说为什么（只有 uv 包、压缩包没给 sha256 或不是 .zip / .tar.gz、找不到 npm）；
  - `method`：托管的是怎么装的，没装的是后端会怎么装（`npm` / `binary`）。
  - 自带的、本机 agent 关着时没有这个字段。
- `local_agents.enabled = false`（多用户模式、后端不是只在本机监听——服务器和 Docker、`RUST_API_LOCAL_AGENTS=0`）时本机 agent
  全是 `available: false`，`reason` 和 `local_agents.reason` 一样。

## 代装本机 agent：`POST /api/v1/ai/agents/{agent_id}/install`

2026-11-26 起。signed，没有请求体。把这个 agent 装进后端自己的安装目录 `<数据目录>/acp-agents/`，**后台装，马上返回**这个 agent
现在的样子（和列表里的一项一样）：开始装了或已经在装回 `202`（`install_status.state` 是 `installing`）；安装目录里已经是快照的版本回 `200`。
之后轮询 `GET /ai/agents` 看 `install_status`（装好了 `installed` 且 `available: true`；失败 `failed`，`error` 是原因，可以再调一次重装）。

- 怎么装（不碰用户全局）：
  - 有 npm 包、找得到 npm 的：`npm install --prefix <数据目录>/acp-agents/npm/<登记表 id>/<版本> <包@快照里的版本>`。
    npm、node 先用 `RUST_API_NODE_DIR`（桌面版自带的 Node 目录，放 `node`、`npm` 的那一层，给 Node 发行包的根也行），没有就用 PATH 上的。
    pi-acp 连 pi 一起装（`@earendil-works/pi-coding-agent@1.6.1`，版本钉在 `agents.json` 的 `requires`）。
  - 只有压缩包的（比如 Google Antigravity）：按这个平台从快照取地址下载，**核对快照里的 sha256**，解到
    `<数据目录>/acp-agents/binary/<登记表 id>/<版本>/`，命令和参数照快照。快照没给 sha256、不是 .zip / .tar.gz 的不代装。
  - 都先装进 `<数据目录>/acp-agents/.staging/` 下的临时目录，装好了一次改名到位；中途断了不会留下「装了一半」的 agent。
    同一个 agent 同时只有一个安装在跑。装好新版本后删掉旧版本。
  - Python（uv）包不代装，照旧给终端命令（`install`）。
- 起托管的 npm 包时，子进程 PATH 前面加上 Node 目录和那个 prefix 的 `node_modules/.bin`（npm 包的入口是 `#!/usr/bin/env node`；pi-acp 在那里找到 pi）。
- 闸门同起本机 agent：多用户模式、后端不是只在本机监听、`RUST_API_LOCAL_AGENTS=0`、`Host` 不是本机地址、经过代理都是 `403`；
  浏览器带的 `Origin` 照 CORS 那套查。不认识的 agent `404`；自带的（`retainpdf`）`400`；后端不能代装的 `409`，
  `error.details.reason` 是 `agent_not_installable`，`message` 是原因。
- 状态只在内存里：后端重启后正在装的不会接着装（临时目录下次装同一个时清掉），失败原因也没了，`state` 按目录重新算。

### 桌面版默认装

后端启动时设了 `RUST_API_ACP_DEFAULT_INSTALL=1`、本机 agent 开着，就在后台把 `agents.json` 的 `default_install`（现在是 `pi-acp`、
`claude-acp`）里没装的装上：不挡启动，一个一个装，失败只记日志和 `install_status`。用户自己已经装在 PATH 上的不装；
安装目录里是旧版本的换成快照的版本。服务器、Docker 不设这个开关。

## 连上一个 agent：`GET /api/v1/ai/agents/{agent_id}/acp`（WebSocket）

- 认证：`X-API-Key` 请求头，或者 `?api_key=`（浏览器的 WebSocket 带不了请求头；查询参数里的 key 只对 WebSocket 握手有效，
  请求日志不记查询串）。浏览器带的 `Origin` 照 CORS 那套查（单机：本机页面、同主机、`RUST_API_ALLOWED_ORIGINS`）。
- 自带 agent（`retainpdf`、`retainpdf-pi`，就是 `kind: "builtin"` 的）要带模型配置（查询参数）：`model`（必填）、`base_url`、`api_protocol`（`openai` 默认 / `openai_responses` /
  `anthropic`）、`thinking`、`credential_ref`（必填，凭据库里 `translation_api_key` 类的引用；不收明文 key）。
- 自带 agent 读书（2026-11-25 起）：再带 `job_id`——阅读页正在读的任务编号，就是打开阅读页用的那个（`/documents/{id}/reading`
  给的，合并阅读的虚拟任务 `merged-…` 也行）。带了，agent 自己从后端读这本书（附近的上下文由代码取好；问题不带字时才给模型工具，见下面「自带 agent 读书」）；
  不带和以前一样，只靠问题里附的上下文。只许字母、数字、`-_.:`，不对 `400`；没有这个任务 `404`；多用户模式下要是自己的（不是 `403`）。本机 agent 不看它；`retainpdf-pi` 和 `retainpdf` 一样用它。
- 自带 Python agent 接着哪个对话（2026-11-26 起）：再带 `conversation_id`（`/ai/ask-conversations` 的编号，只许字母、数字、`-_.:`，不对 `400`），
  agent 开会话时自己从后端取记忆和最近几轮，见 [主对话和记忆](./02-主对话和记忆.md)「自带 agent 怎么用」。`retainpdf-pi`、本机 agent 不看它。
- 本机 agent 另外要求：这次握手的 `Host` 是 `localhost` 或回环地址，没有 `Forwarded` / `X-Forwarded-*`。
  起的是安装目录里装的（2026-11-26 起，优先）或 PATH 上找到的那个命令，参数、环境变量照快照（比如 Factory Droid 带 `DROID_DISABLE_AUTO_UPDATE=true`），加在继承来的环境上。
- 握手前就不行的回 HTTP 错误、不升级：不认识的 agent（快照里没有、不列的、这个平台起不了的）、没装、`job_id` 的任务不存在 `404`；本机 agent 没开或没过上面的检查 `403`；
  模型配置、凭据、`job_id` 写法不对 `400`；没认证 `401`。

连上以后：

- 一条文字消息就是一条 ACP 消息（JSON-RPC 2.0），两头原样转，包括 agent 发来的 `session/request_permission`。
- 桥只改客户端发的 `session/new`、`session/load`（`retainpdf-pi` 另去掉 pi-acp 报的选模型那一项，见下面「RetainPDF + pi」的「思考强度」）：`cwd` 空着填书文件夹（`<数据目录>/books`，没有就是数据目录）；
  `mcpServers` 里没有名为 `retainpdf` 的就补一个——`retainpdf mcp`（[命令行文档](../../core/cli/README.md)的「MCP 服务」），
  环境变量带 AI 专用密钥（`RUST_API_AGENT_KEYS` 的第一把，没配就不带，`retainpdf mcp` 用本机主密钥），2026-11-26 起还带
  互动块的说明文件和检查器的位置（`RETAIN_OPENUI_*`，见下面「回答里的互动块」）。找不到 `retainpdf` 命令行就不补。
- 连接断开就结束 agent 进程；agent 退出就关连接，关闭码 `1011`，原因写退出码和 stderr 最后一行（最多 123 字节）。
- 一条消息最大 32 MB（带截图的 prompt）。

## 自带 agent

后端用 `python -m retainpdf_ask_agent`（`backend/ask-agent`，和翻译 worker 同一个 Python 环境）起，模型配置和密钥经环境变量交给它
（`RETAIN_ASK_MODEL`、`RETAIN_ASK_BASE_URL`、`RETAIN_ASK_API_PROTOCOL`、`RETAIN_ASK_THINKING`、`RETAIN_ASK_API_KEY`）。

- `initialize`：`promptCapabilities.image = true`（扫描页的截图）、`embeddedContext = true`；`loadSession = false`（库是正本，续接靠握手的 `conversation_id`）。
  2026-11-26 起另报 `agentCapabilities._meta.retainpdf = {selection, memory, conversation}`，见 [主对话和记忆](./02-主对话和记忆.md)。
- `session/prompt` 收的内容块：`text`、`image`（png / jpeg / webp / gif）、`resource`（嵌入的文字）、`resource_link`（只当文字提一下）。
- 回答边收边发：思考 `agent_thought_chunk`（模型给思考的话），正文 `agent_message_chunk`；结束发一条 `usage_update`：

  ```json
  {"sessionUpdate": "usage_update", "used": 1520, "size": 200000,
   "_meta": {"retainpdf": {"usage": {"model": "claude-haiku-5-5", "elapsed_ms": 3120, "first_token_ms": 640,
     "input_tokens": 1400, "output_tokens": 120, "cache_read_tokens": 1100, "cache_write_tokens": 0}}}}
  ```

  `used` 是输入加输出，`size` 是上下文窗口（Anthropic 按 20 万估，别的 12.8 万，`RETAIN_ASK_CONTEXT_WINDOW` 可改）。
  `input_tokens` 是这次请求的全部输入（含缓存命中的部分），`cache_read_tokens` 是按缓存读的；OpenAI 兼容的还有 `reasoning_tokens`。
  `session/prompt` 的结果 `{stopReason, _meta.retainpdf.usage}` 也带一份。
- 同一个会话的前几轮（最多 20 条消息，图片不带）跟着下一问发；Anthropic 在上一轮回答上打缓存断点。
- 出错回 JSON-RPC 错误 `-32603`（服务商的状态码和一句说明，不带 key），会话照常能接着问；`session/cancel` 叫停的回 `stopReason: cancelled`。
- 一个会话同时只答一个问题，没答完又问回 `-32602`。

### 思考强度：`configOptions` 和 `session/set_config_option`（2026-11-26 起）

按 ACP 的 [Session Config Options](https://agentclientprotocol.com/protocol/session-config-options) 报这个模型**实际有**的思考档位，
会话里能改。只有一项，`category` 是 `thought_level`；**不报 `category: "model"`**——模型是设置里存的连接，换模型照旧带新的握手参数重开会话。

`session/new` 的结果：

```json
{"sessionId": "ask-…",
 "configOptions": [{"id": "thought_level", "name": "思考", "category": "thought_level", "type": "select",
   "currentValue": "low",
   "options": [{"value": "low", "name": "low"}, {"value": "medium", "name": "medium"}, {"value": "high", "name": "high"},
               {"value": "xhigh", "name": "xhigh"}, {"value": "max", "name": "max"}]}]}
```

- `options` 从弱到强；`value` 和 `name` 都是模型那边的原名（不翻译）。档位表在翻译底座 `model_wire.thinking_menu`（翻译和问答共用）：

  | 模型（怎么认） | 档位 | 每档发的字段 |
  |---|---|---|
  | Claude（`api_protocol=anthropic`） | `low` / `medium` / `high` / `max`；Opus 4.7、4.8 和 5.x、Fable、Mythos、Sonnet 5.x、Haiku 5.5 多 `xhigh`；不发思考字段就不思考的（Opus 4.6—4.8、Sonnet 4.6、更老的和认不出的）最前面多 `off` | `thinking: {type: adaptive}` + `output_config.effort`（不认退到 `budget_tokens`，再退到不加）；`off` 什么都不加 |
  | Qwen（地址是 `dashscope.aliyuncs.com`，OpenAI 协议） | `off` / `on` | `enable_thinking: false / true` |
  | DeepSeek（地址是 `api.deepseek.com`，OpenAI 协议；没填地址也算） | `off` / `on` | `thinking: {type: disabled / enabled}` |
  | 别的地址上的 Qwen3（按模型名认：带 `qwen3`，大小写不管，名字带 `instruct`、`thinking`、`coder` 的不算；自己部署或中转的，比如自定义的 `Qwen3.8-27B-Uncensored`；2026-11-27） | `off` / `on` | 先一起发 `enable_thinking` 和 `chat_template_kwargs.enable_thinking`（vLLM、SGLang、llama.cpp 认后一种），回 400 再分开试，最后不加 |
  | 智谱（`open.bigmodel.cn`） | `off` / `low` / `medium` / `high` / `max` | `reasoning_effort`；`off` 是 `thinking: {type: disabled}`，关不掉的退到 `low` |
  | GPT（按模型名认，OpenAI Chat 和 Responses 都算，经中转的 `openai/gpt-5` 也认） | o1 / o3 / o4：`low` / `medium` / `high`；GPT-5：`minimal` / `low` / `medium` / `high`；GPT-5.1 起：`none` / `low` / `medium` / `high` / `xhigh` | Chat 是 `reasoning_effort`，Responses 是 `reasoning.effort` |
  | 别的（认不出的模型，地址不是 `api.openai.com`，OpenAI Chat 和 Responses 都算；Responses 上名字带 qwen3 的也是这个；2026-11-27 起） | `off` / `on`（通用开关） | `on`：先一起发 `enable_thinking` 和 `chat_template_kwargs: {enable_thinking, thinking}`，回 400 再少发几样，最后不加；`off` 最前面再多带 effort `none`（Chat 是 `reasoning_effort`，Responses 是 `reasoning.effort`，Responses 最后还单独试一次它）。服务一般忽略不认的字段，所以模型本身不思考、或服务不认这几种写法时开关不起作用 |
  | `api.openai.com` 上认不出的（`gpt-4o` 这类不推理的） | 不报 `configOptions`，前端不显示这一栏 | 照握手的 `thinking` 发 |

- `currentValue` 是握手的 `thinking`（设置里的 `auto` / `off` / `low` / `medium` / `high` / `max`）换成的档位，和第一问实际发的字段一致：
  设置那一档按顺序要试的字段里，第一个对得上某一档的就是它（Claude 的 `off` 发的是 effort `low`，所以报 `low`；GPT-5 的 `off` 先试
  `none`、不认再试 `minimal`，报 `minimal`；`max` 在没有 `xhigh` 的模型上是 `high`）。Qwen、DeepSeek 的 `off` 是 `off`、其余都是 `on`。
  `auto` 对实测过的模型照实测规则（claude-haiku-5-5 是 `low`，qwen3.8-flash 是 `off`，glm-5.3-flash 是 `low`），别的什么都不加，
  报的是服务商不加字段时的默认档：Claude Opus 5.5、Haiku 5.5 是 `medium`，别的不发也思考的 Claude 是 `high`，不发就不思考的 Claude 是 `off`；
  DashScope、别的地址上的 Qwen3 和通用开关按 `on`；DeepSeek 名字带 `reasoner` 的 `on`、其余 `off`；智谱 `max`；GPT-5 和 o 系列 `medium`，GPT-5.1 起 `none`。
- `session/set_config_option`：`{"sessionId", "configId": "thought_level", "value": "<options 里的一个>"}`。只改这个会话**下一问**的思考档位
  （正在答的那一问不变），不重开会话、历史照旧；结果是整份 `{"configOptions": [...]}`（`currentValue` 换成新的）。改过档位以后按档位表发
  那一档的字段（服务商回 400 就按表里的顺序退，最后不加思考字段；2026-11-26 起 OpenAI Chat、Responses 也和 Anthropic 一样逐个退）。
- 出错（JSON-RPC 错误）：`value` 不在 `options` 里、不是字符串 `-32602`；`configId` 不是 `thought_level`（包括 `model`）`-32602`；
  会话不存在 `-32002`。认不出的模型（没报 `configOptions`）改档位一律 `-32602`。
- 不发 `config_option_update` 通知（档位只在客户端改时变，结果里已经是整份）。`session/prompt` 的用量 `_meta.retainpdf.usage` 多一个
  `thinking_level`（这一问用的档位）。

### 自带 agent 读书（2026-11-25 起，握手带了 `job_id`）

桥核过任务以后，经环境变量多给 agent 四样：`RETAIN_ASK_JOB_ID`（书）、`RETAIN_ASK_DOCUMENT_ID`（书编号，原文页图用）、
`RETAIN_ASK_BACKEND_URL`（后端自己的回环地址，监听 `0.0.0.0` 时是 `127.0.0.1`）、`RETAIN_ASK_BACKEND_KEY`（读书用的密钥：
有 AI 专用密钥 `RUST_API_AGENT_KEYS` 就用排序后的第一把，没配用本机主密钥；模型看不到它，请求是代码写死的几个只读请求）。
书的块来自 `GET /jobs/{job_id}/reader/regions`（阅读页同一份，页码一致；2026-11-25 起也登记给 `agent`），会话一开就在后台取好。

**材料先给，工具一直在，用不用由模型定**：每一问都给同一套工具，代码不按问题的样子删工具；第一次问模型之前，代码先把材料
放进这一问最前面（一段「【RetainPDF 从书里取的……】」），常见的问题照材料直接答，不用调工具。

| 这一问 | 怎么认 | 代码先放进去的材料 |
|---|---|---|
| 带字：选中了一段或一个词，或者前端附了那一块的原文译文 | `_meta.retainpdf.anchor` 的 `selection` / `source_text` / `translated_text` 不空，或者问题前面有前端写的「我选中的这段：」「这一块的原文：」「这一块的译文：」 | 那段字前端已经附了；补所在的节、同页前后各一块（每块最多 500 字）；问题里写了「第 N 页」再带那一页。书还没取到最多等 1.5 秒，取不到就不带 |
| 不带字：点在空白处、扫描页、问整本书、追问 | 上面都没有 | 出处的那一页或问题里写的页（每页最多 6000 字；有块号时是那一块和同页前后三块）；那一页没有文字层就附**页图** |

系统提示词里另有这本书的页数和目录（两级以内）。提示词让模型：问的是这段字本身就照材料答；答案明显在别处（别的页、别的章、
别处的定义、这个词书里别处怎么用、整本书）才调工具；找过就答，不先「看看周围」。

前端以后可以在 `session/prompt` 的参数里直接给锚点（和问答记录同一个写法），后端就不用从出处那段字里认：

```json
{"sessionId": "…", "prompt": […], "_meta": {"retainpdf": {"anchor": {"page": 5, "item_id": "p005-b0002", "selection": "选中的字",
  "source_text": "…", "translated_text": "…"}}}}
```

没给时从前端写的出处最后一行「（RetainPDF 任务 <任务>，块 <块>，第 <页> 页）」认页码和块号。

工具（都只读、粗粒度，一次够用）：

| 工具 | 参数 | 做什么 | 读的接口 |
|---|---|---|---|
| `read_pages` | `pages`（原文页码列表，最多 5 页）、`side`（`both` 默认 / `source` / `translated`） | 这几页每块的块编号、类型、原文、译文（页眉页脚页码不算；一页最多 12000 字，合计 24000 字） | `reader/regions` |
| `search_book` | `query`、`limit`（默认 6，最多 12） | 全书原文和译文里找字（不分大小写，空格隔开的词都要在同一块里）；每条带页码、所在的节、整块原文译文（长块取命中处前后 600 / 500 字），一般不用再读 | `reader/regions` |
| `view_page` | `page`、`side`（`source` 默认 / `translated`） | 一页的图（JPEG，宽 1000，超过 3.5 MB 不给）；扫描页已经由代码附了图，这个只在公式图表读不清时用 | `GET /documents/{id}/files/pages/{page}.jpg`、`GET /jobs/{job_id}/files/pages/{page}.jpg`（译文页按任务自己的页号） |

- 模型调了工具就逐个跑，每个发两条 `session/update`，前端照 ACP 画工具卡片：

  ```json
  {"sessionUpdate": "tool_call", "toolCallId": "toolu_01…", "title": "读第 5、6 页", "kind": "read", "status": "in_progress",
   "rawInput": {"pages": [5, 6]}}
  {"sessionUpdate": "tool_call_update", "toolCallId": "toolu_01…", "status": "completed",
   "content": [{"type": "content", "content": {"type": "text", "text": "第 5 页 5 块，第 6 页 10 块"}}],
   "_meta": {"retainpdf": {"round": 1}}}
  ```

  `kind`：`read_pages` 是 `read`，`search_book` 是 `search`，`view_page` 是 `fetch`。`title` 是给人看的一句（「读第 5、6 页」
  「在书里找「Hamiltonian」」「看第 5 页的原文图」）。`content` 只是一句摘要，工具的全文只给模型。工具出错（页码不对、
  这一页还没排好、后端连不上）是 `status: failed`，错误说明交回模型，不是 JSON-RPC 错误。
- 调了工具，结果接在对话后面再问。防失控的上限：最多 4 轮、每轮 4 个（多的不执行，告诉模型）；到了就不许再调、照读到的回答。调工具前说的话和之后的回答之间空一行（都在 `agent_message_chunk` 里）。
- 叫停（`session/cancel`）在工具跑的时候也立刻生效：那个工具的卡片 `failed`（「取消了」），回 `stopReason: cancelled`。
- `usage_update`：`used` 是最后一轮占的上下文（输入加输出）；`_meta.retainpdf.usage` 的 token 是各轮加起来（花了多少），另有
  `rounds`（问了模型几轮）、`tool_calls`（调了几个工具）、`context`（代码取了什么：`kind` 是 `background`（带字）/
  `prefetch`（不带字），`pages`、`blocks`、`item_id`、`images`、用了几毫秒 `ms`）。Anthropic 每轮在最后一条消息上打缓存断点。
- 带进下一问的历史是问（连同代码取的材料）和最后的回答，工具来回不带。

## RetainPDF + pi（`retainpdf-pi`，2026-11-26 起）

第二个自带 agent：和 `retainpdf` 一样用设置里的模型、握手参数一样（`model`、`base_url`、`api_protocol`、`thinking`、`credential_ref`、
`job_id`），读书的接口、材料、工具、提示词、4 轮上限都一样；不同的是 agent 骨架换成本机装的 [pi](https://github.com/earendil-works/pi)，
用户可以改 `backend/pi-agent/` 下的扩展（TS，不用编译）。方案和实测见 [RetainPDF 加 pi](../../ops/planning/reader-ask/20261126-RetainPDF加pi.md)。

- **要装的**：本机的 `pi-acp` 和 `pi`（`npm install -g @earendil-works/pi-coding-agent pi-acp`，要 Node ≥ 22.19；pi 至少 1.1.0）。
  「装了没有」和本机 agent 列表里的 `pi-acp` 同一套判断。没装是 `available: false`，`reason` 说缺什么，`install` 给安装命令。
- **闸门**：起的是用户本机的 Node 程序，和本机 agent 同一道：单机模式、后端只在本机监听、握手的 `Host` 是本机地址、没经过代理、
  没设 `RUST_API_LOCAL_AGENTS=0`；不满足的列表里 `available: false`、握手 `403`。服务器、Docker 上只有 `retainpdf`。
  暂时只支持 macOS、Linux。安装包没带 `backend/pi-agent` 时 `reason` 说没找到扩展。
- **怎么起**：桥起 `pi-acp`，`PI_ACP_PI_COMMAND` 指向包装脚本 `backend/pi-agent/bin/retainpdf-pi`，脚本在 pi-acp 的参数后面加上
  `--model retainpdf/<模型> --thinking <档位> --system-prompt ask_system.txt [--append-system-prompt <互动块的 L0>] [--append-system-prompt ask_tools.txt]
  -e extension/index.ts -nbt --tools read_pages,search_book,view_page,openui_spec,openui_check --no-mcp -ne -ns -np -nc -na --offline
  --session-dir <数据目录>/ask-pi/sessions`。扩展另外拦下这五个以外的一切工具调用。没有 bash、不改文件、不读用户的 `~/.pi`、`AGENTS.md`、skill、MCP。
- **模型**：每次连接一个私有配置目录（`<数据目录>/ask-pi/connections/<编号>/`，连接结束删掉）：`models.json` 只有一家 `retainpdf`
  （`api_protocol` → `openai-completions` / `openai-responses` / `anthropic-messages`；Anthropic 地址去掉 `/v1`；`apiKey` 写
  `$RETAIN_ASK_API_KEY`，密钥只在环境变量里，不落盘），`settings.json` 关掉缓存保温、安装统计、项目信任；没有 `auth.json`。
  起会话时的思考档位（`--thinking`）：`low` / `medium` / `high` / `max` 照传，`off` 照传（Anthropic 的 `off` 按 `low`，和 `retainpdf` 一样），
  没给（「自动」）时 Anthropic 用 `low`、别的 `off`；模型在 pi 里没有的档，pi 起会话时就近换一档（先往上、再往下）。
- **思考强度**（2026-11-26 起）：pi-acp 自己报 ACP 的 `configOptions`、认 `session/set_config_option`，桥照转，只改三处：
  去掉 `category`（或 `id`）是 `model` 的那一项和结果里的 `models`（pi-acp 0.0.35 会报 pi 看得到的模型，就是我们那一个）；
  思考档位的 `name` 去掉 pi-acp 加的 `Thinking: ` 前缀（只留档位名）；记下每个会话报过的档位，客户端改成不在里面的值、改模型
  （`configId: "model"`、`session/set_model`），桥直接回 `-32602`、不转给 pi-acp（pi 会把不认识的档位悄悄夹到最近一档）。
  `session/new`、`session/load`、`session/set_config_option` 的结果和 `config_option_update` 通知都这么处理；pi-acp 另发的旧写法 `modes`
  （`current_mode_update`）原样转。档位是 pi 的名字（`off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max` 里的几个），
  桥写的 `models.json` 按模型给 pi 的 `thinkingLevelMap`，让它和上面 `retainpdf` 的档位表对上：Claude 是 `low` / `medium` / `high` / [`xhigh`] / `max`
  （不发就不思考的多 `off`）；Qwen、DeepSeek 是 `off` / `high`（pi 的 `high` 就是开，Qwen 写成 `enable_thinking`，不带 effort）；GPT 等照 pi 默认
  （`off` / `minimal` / `low` / `medium` / `high`）。和 `retainpdf` 的差别：Qwen、DeepSeek 开的那一档叫 `high` 不叫 `on`；GPT 的档位是 pi 的默认，不按模型分。
- **和 `retainpdf` 不一样的地方**（pi-acp 0.0.35 的行为）：`loadSession: true`（会话存在 `<数据目录>/ask-pi/sessions`，pi-acp 的会话对照表在
  `<数据目录>/ask-pi/home`）；工具卡片的 `title` 是工具名（`read_pages`），`kind` 是 `other`；没有 `_meta.retainpdf.usage`，
  `usage_update` 只有 `used` / `size`；另发 `session_info_update`（标题）、`available_commands_update`（pi-acp 的斜杠命令）；
  桥不补 `retainpdf mcp`（pi-acp 不把 `mcpServers` 交给 pi，书由扩展自己读）。

## 回答里的互动块（OpenUI，2026-11-26 起）

回答照常是 Markdown；需要动手的地方插一个 ```` ```openui-lang ```` 代码块（前端也认 ```` ```openui ````），里面是一段
[OpenUI Lang](https://github.com/thesysdev/open-intelligent-ui) 程序，提问窗把它画成能操作的界面（滑块、闪卡、图表、示意图……）。
**一直开**，不用握手参数；三类 agent 都一样。需求见 [互动块分层提示词](../../ops/planning/reader-ask/20261126-互动块分层提示词.md)，
后端怎么做见 [互动块后端实现](../../ops/planning/reader-ask/20261126-互动块后端实现.md)。

**说明分层**：前端从组件库生成 `contracts/openui/` 的两个文件（前端生成、后端只读）。`ask-openui-prompt.v1.json` 的 `intro` 是
**L0**（约 450 token：什么时候值得写、怎么包、先取说明后检查、可取的段的目录），**每个会话都带**；`sections` 是 17 段说明，
模型用工具按 `id` 取。`ask-openui-library.v1.json` 是组件库的 JSON 规格，检查器用。

| agent | L0 放哪 | 两个工具 |
|---|---|---|
| `retainpdf`（Python） | 系统提示词：`ask_system.txt` → L0 → 有书时读书那段（固定，走缓存） | 和 `read_pages` 等并列（没有书也有） |
| `retainpdf-pi` | 同上（桥把 L0 写进私有配置目录的 `openui-intro.md`，包装脚本 `--append-system-prompt`） | 扩展注册（没有书也有），`--tools` 白名单里有 |
| 本机 agent | 补进 `session/new` 的 `retainpdf mcp` 的 `instructions` 后面 | 同一个 MCP 多两个工具（不调后端） |

两个工具：

| 工具 | 参数 | 回什么 |
|---|---|---|
| `openui_spec` | `sections`：段的 `id` 列表（只给一个字符串也认） | 这几段的 `text` 按给的顺序拼起来（去重，段之间空一行）；不认识的 id 回「不认识的段：…。可取的段：」加每段的 id、简介和约多少 token（全不认识算工具出错；有认识的照取，末尾说一句哪些没取） |
| `openui_check` | `program`：代码块里面的程序（不带围栏；带了也替它去掉、提醒一句） | 没错「没问题。」；有错「有 N 处问题，改完再用 openui_check 检查一次：」逐条 `序号. [code] statementId：message`（最多 20 条）。`code` 来自解析器的 `meta.errors`（`unknown-component` 带可用组件列表、`missing-required`、`type-mismatch`、`unknown-function`……），另补四种：`incomplete`（没写完）、`unresolved-reference`（用了没定义的名字）、`orphaned-statement`（定义了没引用，画不出来）、`empty-program` |

- 检查器是后端的 Node 包 `backend/openui-check`（`@openuidev/lang-core` **1.2.0**，`createParser(组件库, "Col").parse(程序).meta.errors`），
  命令行 `node bin/openui-check.mjs --library <组件库>`：stdin 收程序，stdout 出一行 JSON `{ok, errors: [{code, statementId?, message}], statements, text}`；
  跑不了（组件库读不到、lang-core 没装）退出码 2，`{ok: false, fatal}`。
- 遥测：起它时一律设 `OPENUI_TELEMETRY_DISABLED=1`、`DO_NOT_TRACK=1`，去掉 `OPENUI_RUNTIME_TELEMETRY_ENABLED`（脚本加载 lang-core 前自己也再设一遍）。
  装依赖一律 `npm ci --ignore-scripts`（lang-core 的 postinstall 是安装统计）。
- 上限：程序最多 4 万字符，等 15 秒，stdout 最多读 256 KB。Node 没有、依赖没装、超时、输出不对都回一段说明给模型（工具出错，
  「这次没法检查……」），整轮回答照常；检查出问题不算工具出错（卡片是 `completed`）。
- 每一问的额度（防失控，和读书分开算）：`openui_spec` 最多 2 次、`openui_check` 最多 3 次，超了的不执行、回一句话；读书照旧最多 4 轮
  （一轮里调了读书的工具算一轮），总共最多 9 轮。Python 自带 agent 和 pi 扩展一样；本机 agent 由它自己管。
  Python 自带 agent 额度用完、下一轮不许再调时（读书的 4 轮用完也是），在最后一个工具结果后面接一句「这一问调工具的额度用完了……
  互动块没通过检查就不要放进回答，用文字讲清楚」。
- 工具卡片（`retainpdf`）：`openui_spec` 的 `title` 是「取互动块说明：core、components:inputs」、`kind: "read"`，摘要是「core、components:inputs（约 1874 token）」；
  `openui_check` 的 `title` 是「检查互动块」、`kind: "other"`，摘要是「没问题」或「2 处问题：unknown-component、type-mismatch」。
- `_meta.retainpdf.usage` 多一个 `openui`（这一问调过互动块的工具才有）：`spec_calls`、`sections`（取了哪几段）、`check_calls`、
  `check_problems`（几次没过）、`refused`（超额度没执行的）。没有书时也有 `rounds`、`tool_calls`。
- `retainpdf` 带进下一问的历史不带工具来回：下一问要再写互动块，得重新取说明（额度每一问重算）。

**文件怎么找到**：桥按 `RUST_API_OPENUI_DIR`（没设是 `<项目根>/contracts/openui`）、`RUST_API_OPENUI_CHECK_DIR`（没设是 `<项目根>/backend/openui-check`）
找，Node 先找 `RUST_API_NODE_DIR`，再找 `RETAINPDF_NODE_BIN`（桌面版指向 Electron 本体，起检查器时带 `ELECTRON_RUN_AS_NODE=1`；2026-11-26 加），最后找 PATH；经环境变量交给 agent：`RETAIN_OPENUI_PROMPT`、`RETAIN_OPENUI_LIBRARY`、`RETAIN_OPENUI_CHECK`、
`RETAIN_OPENUI_NODE`（找不到 Node 就不给，agent 自己再找 PATH）。说明文件读不到（或不是 v1）就什么都不给，回答照旧没有互动块。
Docker 镜像带了两个文件和装好依赖的检查器（`/app/contracts/openui`、`/app/services/openui-check`）。

## 问答记录：`/api/v1/documents/{document_id}/ask-threads`

> 2026-11-26 起**只读保留**：新的问答进全局主对话（[主对话和记忆](./02-主对话和记忆.md)），不再往这里写；旧记录不迁，这组接口原样留着。

2026-11-25 起（第 3 步，数据库 v39）。按书存每次提问——书页上的一个「?」：问的是哪儿（锚点）、用的哪个 agent、ACP 会话编号、问答。
契约 `ask-threads.v1`（`@retainpdf/contracts/ask-threads`）。删书时跟着删；不同步到别的设备。设计见
[第 3 步：问答记录](../../ops/planning/reader-ask/20261125-第3步：问答记录.md)。

| 方法 | 地址 | 请求 | 返回 |
|---|---|---|---|
| `GET` | `/documents/{document_id}/ask-threads` | — | `{threads: [提问]}`，最近改过的在前，**不带问答正文**（画「?」、列出来用） |
| `POST` | `/documents/{document_id}/ask-threads` | `{agent_id, session_id?, anchor, messages?}` | 一次提问连同问答 |
| `GET` | `/documents/{document_id}/ask-threads/{thread_id}` | — | 一次提问连同问答 |
| `PATCH` | `/documents/{document_id}/ask-threads/{thread_id}` | `{agent_id?, session_id?, messages?}` | 一次提问连同问答 |
| `DELETE` | `/documents/{document_id}/ask-threads/{thread_id}` | — | `{thread_id, deleted: true}` |

都是 signed，包在 `{code, message, data}` 里。请求体不认识的字段 400。

一次提问（列表里的一项；读、建、改回的再多一个 `messages`）：

```json
{
  "thread_id": "ask-20261125103000-a1b2c3",
  "document_id": "<书的编号>",
  "agent_id": "retainpdf",
  "session_id": "sess-1",
  "title": "这句是什么意思？",
  "anchor": {
    "pane": "translated", "page": 3, "item_id": "p3-b7",
    "selection": "选中的一句", "source_text": "Original paragraph.", "translated_text": "原文段落。",
    "section": "2 方法", "point": {"x": 0.1, "y": 0.42}
  },
  "message_count": 2,
  "created_at": "2026-11-25T10:30:00Z",
  "updated_at": "2026-11-25T10:30:00Z",
  "messages": [
    {"role": "user", "text": "这句是什么意思？", "thought": null, "usage": null},
    {"role": "assistant", "text": "意思是……", "thought": "先看上下文",
     "usage": {"model": "claude-haiku-5-5", "input_tokens": 1400, "output_tokens": 120, "cache_read_tokens": 1100}}
  ]
}
```

- **锚点**和阅读器的 `ReaderAskAnchor` 一一对应，字段名改成下划线（`itemId` → `item_id`、`sourceText` → `source_text`、
  `translatedText` → `translated_text`）。请求里只有 `pane`（`source` / `translated`）、`page`（从 1 起）必填；`item_id`、`point`
  没有给 `null` 或不给，几段字没有给空串、`null` 或不给。`point` 是占整页的比例，`x`、`y` 都在 0–1。返回里每个键都在。
- **问答**：`role` 是 `user` / `assistant`；`text` 是正文（Markdown）；`thought` 是思考摘要（只有空白当没有，返回 `null`）；
  `usage` 是用量对象，原样存（自带 agent 的 `_meta.retainpdf.usage` 直接放进来），没有是 `null`。
- **标题**由后端取：第一句问，空白压成一个空格，最长 80 字；还没问是空串。
- **写法**：前端每答完一轮把整段对话 `PATCH` 一次（`messages` 整份换掉原来的，重发同一份结果一样）。第一轮答完再 `POST`
  也行，`messages` 一起带上。`session_id`：不给不改，`null` 或空串清掉；换 agent、重开会话时连 `agent_id` 一起改。改了 `updated_at` 就换成现在。
- **ACP 会话**：`session_id` 现在只是记着。重新打开一次提问时 agent 那边是新会话，前端把记下的问答带进第一问；
  自带 agent 的 `session/load` 以后做（`loadSession` 还是 `false`）。
- **删除**（2026-11-26 起）：删一次提问、删书时，`retainpdf-pi` 存在 `<数据目录>/ask-pi/sessions/` 下的会话文件（整段对话的第二份）
  按 `session_id` 一起删：认的是会话文件第一行会话头的 `id`（就是 ACP `session/new` 回的 `sessionId`）。还有别的提问记着同一个
  `session_id` 的留着；**没记 `session_id` 的提问对不上，它的会话文件留着**——要删得干净，建提问或换会话时把 ACP 的 `sessionId`
  写进 `session_id`。别的 agent（本机 Claude Code、Codex）的会话存在它们自己那里，后端不碰。

上限和错误：

| 情况 | 结果 |
|---|---|
| 没有这本书；这次提问不在这本书上（换了别的书的地址） | `404` |
| 书上已经有 500 次提问 | `409`，`error.details.reason = ask_thread_limit`、`details.limit = 500`：先删旧的 |
| 一次提问超过 200 条问答；一条正文超过 50000 字、思考超过 20000 字；正文和思考加起来超过 1000000 字节；用量不是对象或写成 JSON 超过 4096 字节 | `400` |
| `pane` 不认识、`page` 小于 1、`point` 出了 0–1；`agent_id` 不是 1–64 个字母、数字、`-`、`_`、`.`；`session_id`、`item_id` 太长（256、200 字） | `400` |
| 锚点里选中的字超过 4000 字、原文译文各超过 8000 字、章节超过 200 字 | 截断，不报错（只是出处） |
