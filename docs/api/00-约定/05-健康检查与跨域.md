# 健康检查、端口与跨域

2026-11-24 从 `docs/core/api/index.md` 第 1、1.1、13 节和 `backend/api/docs/api-spec/runtime-and-events.md` 的
「Health and Readiness」合并过来。

## 端口

- 完整 API 默认端口 `41000`，业务前缀 `/api/v1`。
- 第二个端口默认 `42000`（`RUST_API_SIMPLE_PORT`）：只有 `GET /health`、`GET /ready`，其它地址一律 `404`。
  以前它上面的 `POST /api/v1/translate/bundle`（multipart 扁平字段一步上传并建翻译任务）2026-10-19 删了，
  从脚本提交照常先 `POST /api/v1/uploads` 拿 `upload_id`，再 `POST /api/v1/jobs`。
- 运维指标 `GET /metrics` 只在完整 API 端口上，要 `X-API-Key`，见 [运维指标](../08-调试诊断/04-运维指标.md)。

## 健康和就绪

两个都不要 `X-API-Key`，第二个端口上也有。

### `GET /health`（进程活着）

总是 `200`，`data`：

| 字段 | 说明 |
|---|---|
| `status` | `up`；任务库 ping 不通是 `degraded` |
| `db` | `ok` / `error`，同一个检查 |
| `queue_depth`、`running_jobs` | 排队、在跑的任务数。读不出来时是 `null`（2026-10-22 以前当 `0`，看着像空闲） |
| `provider_backends` | 这个版本支持的 OCR 服务商 |
| `jobsd` | 监督器的状态：`starting`、`healthy`、`unhealthy`、`unsupervised` |
| `ai_service` | 固定 `disabled`：RetainPDF 自己的 AI 服务 2026-11-03 删了，键留着不删（以前和 `jobsd` 一样是监督器状态） |
| `disk` | 数据目录所在磁盘（2026-10-24 起）：`free_bytes` 剩余可用字节（拿不到是 `null`，例如 Windows）、`min_free_bytes` 下限（`RUST_API_MIN_FREE_DISK_MB`，`0` 不查）、`low` 低于下限。低于下限时新上传、新任务 503 `insufficient_storage`（见 [认证与错误](02-认证与错误.md#磁盘快满了503-insufficient_storage)）；`status` 和 `/ready` 不跟着变（磁盘满了更要能打开页面删任务） |
| `time` | 服务器时间（ISO 8601） |
| `version` | 应用版本（2026-11-24 起）：构建时注入的 `RETAIN_PDF_VERSION`，和前端 `APP_VERSION` 同一个来源；没注入是 `0.0.0+unknown`。每个回应的 `X-RetainPDF-Version` 头也是它 |
| `build` | 构建的提交号（2026-11-24 起，`RETAIN_PDF_BUILD`）；没注入是 `null` |

版本和提交号先读运行时的环境变量 `RETAIN_PDF_VERSION`、`RETAIN_PDF_BUILD`（Docker 应用镜像在最后一层 `ENV` 写进去，
构建工作流传 build-arg），没有再用编译时注入的同名变量（桌面包的 Rust 构建步骤前写进 `GITHUB_ENV`），见
`backend/packages/retainpdf-platform/src/version.rs`。Rust 包自己的版本（`0.1.0`）不是应用版本。

### `GET /ready`（能接请求了）

就绪 `200`，不就绪 `503`。**看 HTTP 状态码**（Docker 用 `curl -f`，开发栈等 2xx）。`data`：

| 字段 | 说明 |
|---|---|
| `status` | `ready` / `not_ready` |
| `components` | `db`、`jobsd`、`ai_service`，每个是 `{required, status}`。`db` 总是必需；jobsd 只在本进程监督它时必需，否则 `status` 是 `not_required`；`ai_service` 2026-11-03 起固定 `{required: false, status: "not_required"}` |
| `reasons` | 不就绪的原因：`db_unavailable`、`jobsd_not_healthy`；就绪时是空数组（`ai_service_not_healthy` 不会再出现） |
| `time` | 服务器时间 |

不就绪时信封是 `code: 50300`、`message: "not ready"`，带 `error`（`SERVICE_UNAVAILABLE`，`details.reasons` 和 `data.reasons`
一样），`data` 照旧给全；2026-10-22 以前 503 时信封仍是 `code: 0`、`message: "ok"`。

```json
{
  "code": 50300,
  "message": "not ready",
  "error": {
    "code": "SERVICE_UNAVAILABLE",
    "http_status": 503,
    "details": { "reasons": ["jobsd_not_healthy"] }
  },
  "data": { "status": "not_ready", "components": { "...": "..." }, "reasons": ["jobsd_not_healthy"], "time": "..." }
}
```

## 单机模式的来源和主机

2026-10-22 起，单机模式不再对任何来源都回 CORS 头（以前是 `CorsLayer::permissive()`）。方案见
[单机来源和主机校验](../../ops/planning/api-reorg/20261022-单机来源和主机校验.md)。

- **CORS 只回给三类来源**：回环页面（`localhost`、`127.0.0.0/8`、`[::1]`，端口、http/https 不限）；
  主机和请求的 `Host`（或反向代理写的 `X-Forwarded-Host`）相同、只是端口不同的页面（局域网 / 公网 IP、
  域名分两个端口访问开发栈）；`RUST_API_ALLOWED_ORIGINS` 列出的来源。`null`、`file://` 不放行。
  来源不在名单里只是**不回 CORS 头**，请求照常处理（同源代理会把页面的 `Origin` 原样转发过来）。
  方法、请求头照预检回显（`X-API-Key`、`Content-Type`、`Range`……），响应头全部暴露
  （`Access-Control-Expose-Headers: *`，PDF 按段读要的 `Accept-Ranges`、`Content-Range`、`Content-Length`、
  `Content-Disposition`、`ETag`、`X-Job-Id` 都读得到），不回 `Access-Control-Allow-Credentials`。
- **`Host` 校验（防 DNS rebinding）**：后端监听回环地址时，`Host` 必须是 `localhost`、IP 字面量或
  `RUST_API_ALLOWED_HOSTS` 里的主机名，否则所有地址（含 `/health`、第二个端口）都回 `403`
  （`message` 为 `request host is not allowed`）。监听非回环地址时只有配了 `RUST_API_ALLOWED_HOSTS`
  才查。不带 `Host` 的请求（HTTP/1.0 直连）不查。
- **Docker 的 web 容器（`40001`）另有一道**（2026-11-24）：容器里后端监听 `0.0.0.0`、上面这条默认不查，而 NGINX 会替
  没带 key 的请求补上后端 key，两条叠在一起 DNS rebinding 就能拿到全部权限。所以 NGINX 自己按 `Host` 判断：只有
  `localhost`、IP 字面量和 `RETAINPDF_ALLOWED_HOSTS`（`web.env`）里的主机名才补 key；别的主机名、没带 key 的
  `/api/` 请求 403（`error.details.reason` 为 `host_not_allowed`），自己带 `X-API-Key` 的照常转发。
  见 `ops/deployment/docker/nginx.conf.template`、交付包 README。
- 浏览器的 CORS 预检（`OPTIONS`）不要 `X-API-Key`，中间件直接放行。

多用户模式不受这些影响：跨域照旧只认 `RETAIN_ALLOWED_ORIGINS` 并带凭据，不查 `Host`。
