# 响应格式

除文件下载接口外，后端 JSON 响应统一使用包装对象。

## 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

字段说明：

- `code`: 业务状态码。`0` 表示成功。
- `message`: 面向人类的短消息。
- `data`: 具体响应体。

## 错误响应

```json
{
  "code": 400,
  "message": "invalid request",
  "data": null
}
```

错误响应也可能携带结构化失败信息，具体看 [失败结构](../08-调试诊断/01-失败结构.md)。

## 文件响应

这些接口直接返回文件流，不使用 JSON 包装：

- `GET /api/v1/jobs/{job_id}/pdf`
- `GET /api/v1/jobs/{job_id}/pdf/side-by-side`
- `GET /api/v1/jobs/{job_id}/cover`
- `GET /api/v1/jobs/{job_id}/thumbnail`
- `GET /api/v1/jobs/{job_id}/preview/pages/{page}`
- `GET /api/v1/jobs/{job_id}/markdown?raw=true`
- `GET /api/v1/jobs/{job_id}/markdown/images/{path}`
- `GET /api/v1/jobs/{job_id}/download`
- `GET /api/v1/jobs/{job_id}/artifacts/{artifact_key}` 在 artifact 是文件时返回文件流

前端下载文件时应以 HTTP status 和 `Content-Type` 为准，不要按 JSON 解析。
