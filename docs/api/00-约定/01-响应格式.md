# 响应格式

除文件下载接口外，后端 JSON 响应统一使用包装对象。

## 成功响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

字段说明：

- `code`: 业务状态码。`0` 表示成功。
- `message`: 面向人类的短消息。
- `data`: 具体响应体。

## 错误响应

```json
{
  "code": 400,
  "message": "invalid request",
  "data": null
}
```

错误响应也可能携带结构化失败信息，具体看 [失败结构](../08-调试诊断/01-失败结构.md)。

## 压缩

2026-11-03 起：请求带 `Accept-Encoding: gzip` 时，8KB 以上的 JSON 响应用 gzip 压缩再发（`Content-Encoding: gzip`，
`Vary: Accept-Encoding`）。浏览器自动解压，调用方不用改；不带这个头照旧原样返回。下面的文件响应和事件流不压缩
（PDF 等文件要按段读）。

## 文件响应

这些接口直接返回文件流，不使用 JSON 包装：

- `GET /api/v1/jobs/{job_id}/files/output/{name}`（译文 PDF、双语 PDF、Word、原文 Markdown、图片、打包下载）
- `GET /api/v1/jobs/{job_id}/files/pages/{page}.jpg`
- `GET /api/v1/jobs/{job_id}/files/internal/{name}`（中间产物，多用户下只给管理员）
- `GET /api/v1/documents/{document_id}/files/{name}`（原文 PDF、封面、缩略图）
- `GET /api/v1/documents/{document_id}/files/pages/{page}.jpg`

旧地址（`/jobs/{job_id}/pdf`、`/pdf/side-by-side`、`/cover`、`/thumbnail`、`/preview/pages/{page}`、
`/markdown?raw=true`、`/markdown/images/{path}`、`/download`、`/artifacts/{artifact_key}`）已于 2026-10-18 删除；
对照见[下载总览](../07-产物下载/01-下载总览.md)。

前端下载文件时应以 HTTP status 和 `Content-Type` 为准，不要按 JSON 解析。
