# 阅读接口

阅读页（以及别的阅读宿主）读书要用的接口。2026-11-24 从 `backend/api/docs/api-spec/reader-read-model.md`、`artifacts.md`
和 `docs/core/api/index.md` 第 7、8 节合并过来。返回的结构以契约
[`contracts/reader-data.v1.schema.json`](../../../contracts/reader-data.v1.schema.json) 为准。

阅读宿主只用公开的接口地址和结构化返回，**不要**去看任务目录、产物相对路径、检查点、服务商原始结果或凭据；
也不要按 `message` 文字分支，看 `error.code`。

## 用哪个接口

| 要什么 | 接口 | 返回 | 说明 |
|---|---|---|---|
| 任务当前快照 | `GET /api/v1/jobs/{job_id}` | 任务详情 | 指定 `job_id` 就是那个任务的快照，不要换成这本书更新的任务 |
| 产物链接 | 任务详情的 `artifacts` 字段 | `ArtifactLinksView` | 见下面「产物链接」。按 `ready` 和返回的链接取，不要按文件名猜 |
| 文件清单 | `GET /api/v1/jobs/{job_id}/files` | `JobFilesView` | 见 [下载总览](../07-产物下载/01-下载总览.md) |
| Markdown（JSON） | `GET /api/v1/jobs/{job_id}/reader/markdown` | `MarkdownDocumentView` | 见下面 |
| 原始 Markdown 按段读 | `GET /api/v1/jobs/{job_id}/files/output/ocr.md` | 原始文本 | 支持 `Range`、`ETag`，见 [下载总览](../07-产物下载/01-下载总览.md#长-markdown-分段读) |
| 原文和译文的对应区域 | `GET /api/v1/jobs/{job_id}/reader/regions` | `ReaderRegionsView` | 见下面 |
| PDF 页数和页面尺寸 | `GET /api/v1/jobs/{job_id}/reader/metadata` | `ReaderMetadataView` | 见下面 |
| 排版引擎排的版面（HTML 页照它画） | `GET /api/v1/jobs/{job_id}/reader/layout`、`…/reader/layout/pages/{page_idx}` | `ReaderLayoutView`、`ReaderLayoutPage` | 见下面 |
| 边翻边看 | `progress/layout`、`progress/pages/{page}`、`progress/stream` | | 见 [边翻边看](../02-进度事件/04-实时译文.md) |

书本身（原文 PDF、封面、原文页预览）在 `/documents/{document_id}/files/…`，见 [下载总览](../07-产物下载/01-下载总览.md#书的文件)。

## 身份和坐标

- `document_id` 是书库里书的稳定身份，书的任务历史挂在它下面；`job_id` 指一个具体任务的快照。
- `item_id` 由后端规范化：区域、边翻边看的版面、边翻边看的页快照里同一个 `item_id` 就是同一块。
- `reader/regions` 的 `source.page`、`translated.page` **从 1 起**；框是 `[x0, y0, x1, y1]`，单位 `pdf_point`，原点 `top_left`。
- 边翻边看的 `page_idx` **从 0 起**，框同样是 PDF point、左上角原点。只在界面边界换算一次，不要混用。
- `reader/metadata` 的尺寸是**可见页面**（和 PDF.js scale=1 的视口一致）：CropBox 和 MediaBox 的非空交集，算上继承的页面框、
  旋转和本页的 UserUnit；裁切框为空或不合法时用 MediaBox。区域坐标已经相对可见页面的左上角，不要再减一次 CropBox 偏移，
  也不要按没裁切的 MediaBox 缩放。

## 区域：`reader/regions`

```json
{
  "items": [
    {
      "item_id": "p001-b0003",
      "source": { "page": 1, "bbox": [59, 176, 304, 445], "unit": "pdf_point", "origin": "top_left", "text": "…" },
      "translated": { "page": 1, "bbox": [59, 176, 304, 445], "unit": "pdf_point", "origin": "top_left", "text": "…" },
      "markdown": "…",
      "region_type": "text",
      "status": "translated",
      "asset_ids": [],
      "asset_urls": [],
      "reading_order": 3,
      "sub_type": "body"
    }
  ]
}
```

- 后端把规范化的原文块和已发布的译文拼好给出来，阅读页不用自己解析 OCR、翻译产物。前端用 `item_id` 做译文悬停到原文框的映射，
  `text` / `markdown` 直接用于复制。
- `items` 按 `(source.page, reading_order)` 排，只有原文的块穿插其中。
- `sub_type`：规范化文档的小类（`body`、`heading`、`title`、`page_number`、`reference_entry`、`figure_caption`、`image_body`、
  `display_formula`……，取值随 OCR 服务商）；`heading_level`（1～6）只有标题块有。
- `continuation_group_id`：翻译时跨块、跨页接起来的同一段共用；这时 `translated.text` 是整段译文，`translated_block_text` 是这一块自己分到的那份。
- `asset_ids` / `asset_urls`：这一块引用的图片，`asset_urls` 指 `files/output/ocr/images/…`；复用 OCR 的任务也挂在自己的 `job_id` 下。
- 表格（2026-11-22 起）：建任务时 `translation.tables` 选了 `translate`、表格 agent 整表翻了的表，这一块的 `translated.text` 和
  `markdown` 是整表译文的 HTML（`<table>…</table>`，跨行跨列照原表），`status` 是 `translated`；位置照旧用原文的
  （`translated.bbox` 和 `source.bbox` 一样）。没开表格翻译、整表保留原文、结构不可信没送的表，照旧是 `source_only`。
  读的是翻译目录里的 `tables.v1.json`，表格翻完后 ETag 跟着变。
- 缓存（2026-11-03 起）：响应带弱 ETag（`W/"…"`）和 `Cache-Control: private, no-cache`。带着上次的 ETag（`If-None-Match`）再来、
  规范化文档、译文文件、OCR 图片和服务端版本都没变时回 `304`，不带数据；重译、重新识别以后 ETag 跟着变。浏览器的 `fetch`
  默认就会这样做。后端在内存里留着最近几本算好的结果。8KB 以上照常 gzip（见 [响应格式](../00-约定/01-响应格式.md#压缩)）。
- 只取一块的 `GET /api/v1/jobs/{job_id}/reader/regions/{item_id}` 2026-11-14 删了，要一块就从 `reader/regions` 里找。

打开阅读页并跳到某一块：`reader.html?job_id={job_id}&page_idx={source.page - 1}&block_id={item_id}`。

## 页面元数据：`reader/metadata`

```json
{
  "source": { "page_count": 533, "pages": [{ "page": 1, "width": 595, "height": 842 }] },
  "translated": { "page_count": 533, "pages": [{ "page": 1, "width": 595, "height": 842 }] }
}
```

两侧各自可以是 `null`（那一侧的 PDF 还没好）。它只是叠加层用的信息，不代表 PDF 能不能取。

区域、元数据都是可选的叠加层：取失败不能让已经打开的原文 PDF 也跟着失败，单独报错、照常阅读。

## 排版引擎的版面：`reader/layout`

2026-11-28 加。译文 PDF 是 rpr_fit 排版引擎排的：引擎先写一份版面（`rpr_layout_v1`），叠加层只从它画出来。
阅读页的 HTML 页拿原文页做底、照这份版面把字摆到同样的位置，画出来就和译文 PDF 一样，每个字又是能加动效、能选的 DOM。

**清单** `GET /api/v1/jobs/{job_id}/reader/layout` → `ReaderLayoutView`：

| 字段 | 说明 |
|---|---|
| `available` | 有没有版面 |
| `reason` | 没有的原因，有版面时 `null`。`no_translated_pdf` 还没有译文 PDF；`not_engine_route` 这次是 Typst 排的；`unsupported_render` 引擎排不了的设置（双栏对照、字体不是思源宋体）；`merged_reading` 合并阅读的虚拟任务；`not_kept` 引擎排的、但版面没留下（2026-11-28 以前的任务，或这次回退了 Typst）。以后可能加值，认不得的当 `not_kept` |
| `schema` | 版面格式，现在是 `rpr_layout_v1` |
| `engine_version`、`engine_commit` | 排这份版面的引擎版本、提交号 |
| `page_count`、`pages[]` | 有版面的页：`{index, width, height, etag, blocks, url}`。`index` 是原文页号，**从 0 起**；没有译文的页（整页图、不翻的参考文献）不在里面，照原页画 |
| `fonts[]` | 画字用的字体（按书子集化的 woff2）。还没做，现在是空的 |
| `generate` | 能补排时给出请求 `{method, url, body}`，照原样发就行：原地重新渲染（`actions/retry-stage`，`stage=render`），不调模型、不花钱；任务原来是 Typst 路线时 `body` 还带 `overrides.render.engine = "rpr_fit"`。在跑的任务、补不了的情况是 `null` |

没有版面不是错误，照常回 200。

**一页** `GET /api/v1/jobs/{job_id}/reader/layout/pages/{page_idx}` → `ReaderLayoutPage`，就是引擎写的那一页原样：

```text
{ index, width, height,
  covers: [{ block, rect: [x0, y0, x1, y1], fill: [r, g, b] }],        // 先画：盖掉原文
  blocks: [{ id, fontSize, weight: "regular" | "bold", color: [r, g, b],
    lines: [{ text, x, baseline, width, justified,
      items: [{ x, t } | { x, t, mode: "dflt" } | { x, tex, display, w, h, d }] }] }] }
```

- 坐标单位 pt，原点在页左上、y 向下（和 OCR 框一样）；颜色各分量 0–1。
- `covers` 先画。`fill` 是估的这一块原页底色，没有就用这页的底色，再没有是白色；彩色底上是近似色，不是逐像素。
- 块 `id` 和 `reader/regions` 的 `item_id` 是同一套（规范成 `p001-b0002`）；跨页、跨栏续段每一截各是一块。
- 字簇 `{x, t}` 画在这一行的基线上；`mode: "dflt"` 是只有标点、数字的一段，按西文整形。公式 `{x, tex, display, w, h, d}`
  的盒子按字号的 em 算：宽 `w`，基线以上 `h`、以下 `d`。行的 `text` 只给读和搜（公式写成 `$...$`），画的是 `items`。
- 不在版面里的：表格（表格译文是正文排完以后另一遍叠到 PDF 上的，先用原页或 `reader/regions` 的表格 HTML）；
  公式查不过、改回原文的块（PDF 上那块盖回了原件，HTML 页那里就是原页）。
- 以后只加字段（比如字簇用哪个字体的 `font`、公式图），旧字段不改。
- 带弱 ETag，等于清单里这页的 `etag`；`If-None-Match` 一样回 304。重新渲染以后版面整份换掉，ETag 跟着变。没有这页 404。

版面存在译文 PDF 旁边（渲染时写，`render/output/rpr_fit/reader_layout.py`），只经这两个接口读。重新渲染期间上一份 PDF 挪开了，
清单回 `available: false`（`reason` 是 `no_translated_pdf`），跑完就有新的；这期间先退回按 OCR 框画。
