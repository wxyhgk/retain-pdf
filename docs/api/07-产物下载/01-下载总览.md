# 下载总览

所有文件只有两种地址：**任务的文件** `/jobs/{job_id}/files/…` 和**书的文件**
`/documents/{document_id}/files/…`。文件名一律是"内容.格式"，看名字就知道是什么、什么格式。
旧的文件地址已于 2026-10-18 全部删除（返回 `404`），本页末尾留着新旧对照，方便改老代码。

整理的来由和完整的新旧对照见
[任务与文件接口整理](../../ops/planning/api-reorg/20261015-任务与文件接口整理.md)。
返回的状态码、类型、下载文件名、缓存头钉在 `backend/api/docs/file-responses.txt`。

任务详情、书籍详情、文档列表、Markdown 视图里返回的文件链接（`pdf_url`、`markdown.raw_url`、`bundle_url`、
`cover_url`、`source_pdf_url`、产物清单的 `resource_url`……）2026-10-17 起都是这两种新地址；
原来默认下载的（全部打包、原文 PDF、中间产物）带 `?download=1`。
产物列表、产物清单的链接（`manifest_path`/`manifest_url`、`links.artifacts_*`、`links.artifacts_manifest_*`、`actions.open_artifacts`）
也已换成 `/jobs/{id}/files`（见[产物清单链接换成文件清单](../../ops/planning/api-reorg/20261017-产物清单链接换成文件清单.md)）；
产物清单里 `source_pdf` 一项知道书编号时是 `/documents/{doc}/files/source.pdf?download=1`。
查不到书编号时不再退回旧地址：`cover_url`、`thumbnail_url` 给 `null`，`/files` 的 `source.url` 是空串、`ready` 是 `false`
（2026-10-18；有原文的任务都会登记成书，实际只有原文文件不在的任务会这样）。
这些字段名没动，只是值变了；`/files` 返回的结构和已删除的 `/artifacts`、`/artifacts-manifest` 不一样，读这些链接的代码要按 `/files` 的结构解析。
逐个字段的对照见[返回链接换新地址清单](../../ops/planning/api-reorg/20261017-返回链接换新地址清单.md)。

## 通用约定

- 默认在浏览器里打开（`Content-Disposition: inline`，带好文件名，另存为时名字是对的）；
  加 `?download=1` 直接下载（`attachment`）。
- 查询参数只认 `download`、`dpi`（Word、页预览）、`width`（页预览）、`watermark`（译文 / 对照 PDF、Word）、`version`
  （读书的原文时前端带的原文版本，只给浏览器缓存分版本，后端不看）。别的参数 `400`
  ``unknown field `<名字>`, expected one of ... in the query string``（只回名字、不回值），任务、书和书的文件都一样。2026-11-24 起，以前不认识的参数悄悄忽略。
- 标着"按需生成"的文件第一次请求时才生成，会慢一些；同一份同时被请求只生成一次，之后走缓存。
  缓存按生成**开始前**记下的输入（大小、修改时间、inode）判断还能不能用：输入变了（重渲染、原地重跑换了
  `translated.pdf`）就重新生成；生成期间输入被换掉，这一次返回按请求时的输入生成的结果，下一次请求重新生成（2026-10-19）。
- 生成有时限：页预览、封面、缩略图 60 秒，对照 PDF 120 秒，Word 600 秒。超时整个生成进程组被杀掉，
  返回 `500`，`message` 是 `<名字> builder timed out`（页预览 `page-preview`、封面缩略图 `book-image`、
  对照 PDF `side-by-side`、Word `layout-docx`）。占着的生成名额随之释放，不会堵住别的文件请求（2026-10-19 起页预览、封面也有时限）。
- 任务不存在：普通 `404`，`error.details` 是 `{}`，提示 `job not found: …`。
- 文件名写错、或者这一组没有这个文件：普通 `404`（`no such file: …`），`details` 是 `{}`。
- 任务在、文件还没产出（任务没跑完、这一步还没做）：`404`，`error.details.reason = "not_ready"`，
  提示统一是 `<名字> not ready`，`<名字>` 是缺的那个文件（2026-10-19 起；以前各处措辞不一样、没有 `reason`）：

  | 请求 | 缺什么时 | 提示 |
  |---|---|---|
  | `output/translated.pdf`、`pages/{page}.jpg` | 译文 PDF | `translated.pdf not ready` |
  | `output/side-by-side.pdf` | 原文 / 译文 PDF | `source.pdf not ready` / `translated.pdf not ready` |
  | `output/translated.docx` | 任务还没有输出目录 / 原文 PDF | `translated.docx not ready` / `source.pdf not ready` |
  | `output/ocr.md`、`output/ocr.zip` | 原文 Markdown | `ocr.md not ready`（`ocr.zip` 的打包还没登记是 `ocr.zip not ready`） |
  | `output/ocr/images/{path}` | Markdown 图片目录还没有 | `ocr/images not ready`（目录在、那张图不在是普通 404） |
  | `output/all.zip` | 任务没成功（排队、在跑、失败、取消） | `all.zip not ready` |
  | `internal/{name}` | 这份中间产物 | `{name} not ready`，如 `typst/render.pdf not ready` |

  全部打包只给成功的任务：以前没成功时是 `409 job is not finished successfully`，2026-10-19 改成上面的 `404` + `not_ready`，和别的文件一样。
- 原地重跑（原地重渲染、精修）排队和运行期间 `translated.pdf` 也是上面的 `not_ready`；这一次没跑成（失败 / 取消）就接回上一份 PDF，照常能下载。
- 客户端分「任务没了」和「还没好」只看 `error.details.reason`，不要解析提示文字。规矩见
  [错误约定](../00-约定/02-认证与错误.md#还没产出404)。

## 任务的文件

```http
GET /api/v1/jobs/{job_id}/files
GET /api/v1/jobs/{job_id}/files/output/{name}
GET /api/v1/jobs/{job_id}/files/pages/{page}.jpg
GET /api/v1/jobs/{job_id}/files/internal/{name}
```

按"给谁用"分三组：

| 组 | 给谁用 | 多用户模式 |
|---|---|---|
| `output/` | 用户：下载、在浏览器里看 | 网站账号可用（自己的任务） |
| `pages/` | 界面：译文单页预览图 | 网站账号可用（自己的任务） |
| `internal/` | 排查问题 | **只给管理员**；网站账号请求返回 `403`，清单里也没有这一组 |

### `output/`：成品

| 文件名 | 内容 | 按需生成 |
|---|---|---|
| `translated.pdf` | 译文 PDF | |
| `side-by-side.pdf` | 中英对照 PDF | 是 |
| `translated.docx` | 译文 Word；`?dpi=` 选背景清晰度（72～300） | 是 |
| `ocr.md` | 原文 Markdown（OCR 识别结果，**不是译文**） | |
| `ocr.zip` | 原文 Markdown + 图片 | 是 |
| `ocr/images/{path}` | Markdown 里引用的图片；复用 OCR 的任务从产出 OCR 的那个任务取（`reader/regions` 的 `asset_urls` 就指这里） | |
| `all.zip` | 全部成品打包（只给成功的任务） | 是 |

- `side-by-side.pdf`：读原文 PDF 和译文 PDF 生成，缓存在任务的 `artifacts/{job_id}-side-by-side.pdf`；每页左边原文、右边译文，
  页数取两边较多的，缺的一边留白；下载文件名 `{job_id}-side-by-side.pdf`。
- `all.zip` 里有译文 PDF，有 Markdown 时还有 `markdown/full.md` 和 `markdown/images/**`。

**水印**（2026-11-20）：`translated.pdf`、`side-by-side.pdf`、`translated.docx` 默认在每页右下角带「logo + RetainPDF」水印
（浅灰半透明；PDF 里是矢量、不含文字，复制和搜索不会带出 "RetainPDF"）。加 `?watermark=0`（`false`、`off` 也行）取不带水印的。
带水印的是下载时按需生成的另一份（缓存在任务的 `artifacts/`，PDF 首次请求要多花一点时间），渲染产物本身、`pages/` 预览图不带。
**阅读页显示译文也是加载 `translated.pdf`，要带 `?watermark=0`**（否则译文页右下角会有水印）。`all.zip` 打包里的译文 PDF 目前不带水印。

### 按段读（Range）

`output/translated.pdf`、书的 `source.pdf` 支持 HTTP Range 请求，PDF.js 用 URL 模式按需加载，不要先把整个 PDF `fetch` 成
`ArrayBuffer`。机器上有 `qpdf` 时首次下载懒生成线性化的 `*.linearized.pdf`（120 秒时限）并缓存，没有 `qpdf` 或生成失败就照旧发原 PDF。

```http
GET /api/v1/jobs/{job_id}/files/output/translated.pdf
X-API-Key: your-rust-api-key
Range: bytes=0-65535
```

```http
206 Partial Content
Accept-Ranges: bytes
Content-Range: bytes 0-65535/12345678
Content-Length: 65536
Content-Type: application/pdf
```

跨域读取时（来源在[允许的名单](../00-约定/05-健康检查与跨域.md#单机模式的来源和主机)里）所有响应头都暴露，`Accept-Ranges`、
`Content-Range`、`Content-Length`、`Content-Disposition`、`ETag`、`X-Job-Id` 都读得到。

前端可以先请求第一页的预览图做秒开，再在后台加载 PDF.js。

### 长 Markdown 分段读

`output/ocr.md` 是 `text/markdown; charset=utf-8`，从文件流式发出（不整份读进内存），带 `Accept-Ranges: bytes` 和按大小、修改时间算的
`ETag`；`Range: bytes=<start>-<end>` 回 `206` 和 `Content-Range: bytes <start>-<end>/<total>`。阅读器的分页就靠它：先取第一段、
渲染，滚到底再取下一段。没有单独的游标接口，`Content-Range` 已经给了总大小。

字节偏移不管文本结构，下面两件事客户端自己处理：

- **字符边界**：一段可能停在多字节 UTF-8 字符中间。用 `TextDecoder(..., { stream: true })` 连续解码，把半个字符带到下一段；
  不要每段单独解码。
- **行边界**：一段可能停在一行中间，会把代码块、表格行、公式切开。把最后一个换行之后的文字留着，拼到下一段前面再渲染。

每段比一下 `ETag`。发布的 Markdown 由流水线写一次，现在没有原地改写它的路径，所以偏移实际是稳定的——但这是今天任务生命周期的性质，
不是这个接口的保证。读到一半 `ETag` 变了，说明偏移属于另一个版本，要从 0 重来，否则会把两个版本拼在一起。`If-Range` 也可以用。

### `pages/`：预览图

`pages/3.jpg` 是译文第 3 页（页码从 1 开始）。`?width=`（240～2400，默认 1200）、`?dpi=`（≤300）。
译文 PDF 重渲染（原地重跑、重试渲染阶段）以后同一个地址的图会变：后端发现译文 PDF 和生成页图时不一样了就重新渲染，
响应带 `Cache-Control: private, max-age=0, must-revalidate`，浏览器每次带 `ETag` / `Last-Modified` 来问，没变回 304。
页码超过总页数（`files` 清单里 `pages.page_count`）返回 404 `no such file: pages/N.jpg`，和 `pages/0.jpg` 一样，不会起渲染进程。
原文页在书下面（`/documents/{document_id}/files/pages/{page}.jpg`）：书的原文会变（单机下 Agent 文档操作提交以后换成新版本，
书的编号不变），后端发现原文和生成页图时不一样了就重新渲染，响应头和译文页一样是 `Cache-Control: private, max-age=0, must-revalidate`
（2026-10-19 以前是 `immutable` 一年，原文换了版本浏览器还在用旧图）；页码越界同样是 404。

预览图缓存在任务的 `artifacts/` 下，旁边的 `.<文件名>.inputs.json` 记着生成时输入的大小、修改时间和 inode。

```json
  "source": {
    "name": "source.pdf",
    "url": "http://…/api/v1/documents/<document_id>/files/source.pdf",
    "content_type": "application/pdf",
    "ready": true,
    "on_demand": false,
    "size_bytes": 329,
    "updated_at": "2026-10-17T08:00:00Z",
    "stage": "upload"
  },
  "output": [
    {
      "name": "translated.pdf",
      "url": "http://…/api/v1/jobs/…/files/output/translated.pdf",
      "content_type": "application/pdf",
      "ready": true,
      "on_demand": false,
      "size_bytes": 329,
      "updated_at": "2026-10-17T08:05:00Z",
      "stage": "rendering"
    }
  ],
  "pages": { "url_template": "http://…/api/v1/jobs/…/files/pages/{page}.jpg", "page_count": 12 },

```

- `ready`：现在能不能取到；按需生成的文件表示生成它需要的东西都在。
- `size_bytes`：已经在磁盘上的文件才有。
- `updated_at`、`stage`：产物登记表里的更新时间和产出阶段；按需生成、还没生成的为 `null`（2026-10-17 加）。
- `attempt`：这是第几次跑，重跑、重试阶段以后加一（2026-10-17 加）。
- `source`：原文 PDF（2026-10-17 加）。它是书的文件，有书编号时指向 `/documents/{document_id}/files/source.pdf`；
  查不到书编号的任务没有地址：`url` 是空串、`ready` 是 `false`。
- 和已删除的产物清单（`/artifacts-manifest`）比，有意不列这几样：
  - `layout_json`：和 `internal/ocr-provider/result.json` 是同一个文件；
  - 目录（`job_root`、`translations_dir`、`provider_raw_dir`、Markdown 图片目录）：下载不了，请求会回 `409`，
    `error.details.reason = "artifact_is_directory"`（2026-11-24 起带）。

## 书的文件

```http
GET /api/v1/documents/{document_id}/files
GET /api/v1/documents/{document_id}/files/{name}
GET /api/v1/documents/{document_id}/files/pages/{page}.jpg
```

| 文件名 | 内容 | 按需生成 |
|---|---|---|
| `source.pdf` | 原文 PDF | |
| `cover.jpg` | 封面（首页，宽 900） | 是 |
| `thumbnail.jpg` | 缩略图（首页，宽 360） | 是 |
| `pages/3.jpg` | 原文第 3 页，参数同任务的预览图 | 是 |

封面、缩略图、原文页都按原文判断新不新鲜：原文换了版本（Agent 文档操作提交）就按新原文重新渲染（以前封面、缩略图文件在就一直用旧的）。
三者都带 `Cache-Control: private, max-age=0, must-revalidate`（2026-10-19 以前封面、缩略图是 `max-age=86400`），
浏览器每次带 `ETag` / `Last-Modified` 来问，没变回 304、不传图。清单返回 `files`（同上的字段，没有
`size_bytes`）和 `pages`。

书不存在是普通 `404`（`document not found: …`）；书的记录在、库里读不出来是 `500`，不说成书不存在。书在、原文 PDF 却不在磁盘上（`source pdf missing on disk for document: …`）
也是普通 `404`，**不带** `not_ready`：书的原文是上传时就有的，不会"过一会儿产出"，不在就是丢了，等也等不来。
