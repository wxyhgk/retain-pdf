# 数据库备份

书库数据库（书目、阅读状态、收藏、AI 对话、术语表、任务记录等）的备份与恢复。备份放在
`<数据目录>/backups/db/`，一份一个压缩文件；原文、译文、成品 PDF 这些文件不在备份里，恢复也
不会动它们。

- **自动备份**：后台每小时看一次，最新的自动备份超过 `RUST_API_BACKUP_INTERVAL_HOURS`
  （默认 24，设成 0 关掉）就再存一份。
- **升级前备份**：数据库结构要升级（新版本第一次启动）之前自动存一份。存不成（备份目录写不进去、磁盘满）
  默认照常升级、日志记一条 `error`；设了 `RUST_API_DB_REQUIRE_UPGRADE_BACKUP=1`（2026-10-24 起）就不升级、不启动，
  先腾出空间或修好权限再起。
- **保留规则**：自动备份最近 7 份全留，更早的每周留最新一份、留 4 周；手动的留最近 10 份；
  恢复前、升级前的各留最近 3 份。多出来的自动删掉。

备份是完整的一致快照（SQLite `VACUUM INTO`），不用停服务。

### 备份不是全量备份

备份里只有数据库这一个文件。数据目录里下面这些都不在备份里，恢复也不动它们：

| 不在备份里 | 是什么 |
|---|---|
| `uploads/` | 上传的原文 PDF |
| `jobs/` | 每个任务的目录：OCR 结果、译文、成品 PDF、派生的 Word 和对照 PDF |
| `documents/` | 书的封面、页预览、合并阅读的结果、AI 工作区 |
| `secrets/credentials.json` | 凭据库：存的模型、OCR 服务的 API key |
| `assets/`、`agent-calculations/`、`operations/` 等 | 其余按文件存的东西 |

所以恢复只是把数据库退回去：

- 备份之后删掉的书、任务，库里回来了，但文件已经没了，打开时报文件找不到。
- 备份之后新加的书、任务，文件还在盘上，库里没有它们；定期清理只看库里的记录，这些文件不会自动删，要手动删。
- 任务里记的是凭据的引用（`credential_ref`），凭据库不跟着退：备份之后删掉的 key，恢复回来的任务用不上，要重新填。

要连文件一起完整备份：先退出程序（或停掉服务），再整份拷走数据目录。

- **备份里没有 WebDAV 密码**（2026-10-22 起）：存备份时在快照上先删掉这一项再压缩。恢复时本来就保留恢复前的同步设置
  （见下面「开着同步时」），所以恢复后同步照旧能连上；备份目录被拷走、发给别人排障时也不会带出 NAS 密码。
  2026-10-22 以前存的备份里仍有，介意的话删掉旧备份。
- 备份文件只给本机用户读写（`0600`，2026-10-22 起）。

## `GET /api/v1/backups`

```json
{
  "dir": "/…/data/backups/db",
  "auto_interval_hours": 24,
  "last_auto_at": "2026-10-09T03:00:00.000Z",
  "running": false,
  "restore_blockers": [],
  "last_restore": null,
  "items": [
    {"id": "auto-20261009T030000000Z-v19", "kind": "auto", "created_at": "2026-10-09T03:00:00.000Z",
     "schema_version": 19, "bytes": 9650000}
  ]
}
```

- `items` 新的在前。`kind`：`auto`（自动）、`manual`（手动）、`before-restore`（恢复前）、
  `before-upgrade`（升级前）。`bytes` 是压缩后的大小。
- `restore_blockers`：现在恢复的话要先等什么（有任务在排队或运行、AI 正在改文档、AI 有计算
  没算完）；空表示可以恢复。
- `running`：正在备份或恢复（含恢复后的对账）。
- `last_restore`（2026-10-22 加）：最近一次恢复（不论成败），没恢复过为 `null`。只在内存里，服务重启后为 `null`。
  恢复的请求中途断开（关了设置页、CLI 超时）时恢复照样做完，刷新后看它就知道结果：

  ```json
  {"backup_id": "auto-20261009T030000000Z-v19", "ok": true,
   "safety_backup": "before-restore-20261009T101500123Z-v19", "reason": null, "error": null,
   "started_at": "2026-10-09T10:15:00.100Z", "finished_at": "2026-10-09T10:15:02.400Z"}
  ```

  `safety_backup` 是这次存的恢复前备份，没走到那一步为 `null`；`reason` 是被拒时的原因（同下面 `409` 的
  `error.details.reason`，没有这份备份时是 `not_found`），成功或内部错误为 `null`；`error` 是给人看的说明。

## `POST /api/v1/backups`

立即备份一份，等它存完后返回这一份（`items` 里的一项）。请求中途断开时备份照样存完，`running` 存完后回到 `false`
（2026-10-22 以前会一直停在 `true`，「立即备份」按钮禁用到下一次自动备份）。

## `POST /api/v1/backups/{id}/restore`

用这份备份替换当前的书库数据库，返回：

```json
{"restored": "auto-20261009T030000000Z-v19",
 "safety_backup": "before-restore-20261009T101500123Z-v19",
 "status": { "…": "同 GET" }}
```

- 顺序：查有没有任务在跑 → 等正在跑的那一轮同步结束、停住同步 → 解开备份、检查完整性和版本 → 存一份
  `before-restore` → 在解开的副本上补结构升级、重置同步记账、清 pid → 换库前再查一次有没有任务在跑 → 一步换进去
  → 对账恢复出来的任务。换库是最后一步：之前任何一步失败（含 `500`），正在用的库都没变。
- 恢复前先自动存一份 `before-restore`：恢复错了，用它再恢复一次就退回去了。备份坏了、来自新版本时
  不存（2026-10-22 起；以前每次失败的恢复也存一份，按 3 份清理，连点几次坏备份就把真正能退回的那份挤掉了）。
  换库前又查到有任务在跑而放弃时，刚存的那份删掉。
- 整段在后台做完（2026-10-22 起）：请求中途断开时恢复照样做完，同步、别的备份和恢复要等它真正结束才开始；
  结果看 `GET` 的 `last_restore`。恢复期间改同步设置（`PUT /sync`）要等恢复结束才生效，不会被恢复盖回去。
- 在服务运行中直接恢复，不用重启；别的进程下一次读数据库读到的就是恢复后的内容。界面上
  恢复后应整页刷新。比本机程序旧的备份恢复后自动把结构升级到最新。
- **备份时在排队或运行的任务**（2026-10-19 起）：恢复出来还是排队 / 运行中，但没有任何进程在跑它们。
  恢复时清掉它们备份里记的 worker pid（那些进程早已不在，号码可能被别的进程复用，不能拿去杀），
  再按服务重启时同样的规则对账：有可续断点的放回排队并自动续跑，没有的落成 `failed`
  （`failure_code=worker_process_missing`），书卡、全文索引照常更新。任务跑在 API 进程里（默认）时，
  恢复接口返回前就做完；任务跑在独立的任务服务（jobsd）里时，由它的运行期巡检接手（30 秒一轮，
  放回排队的任务约 2 分钟后重新发射）。备份之后新建的任务目录、文件不会被清理。
- `409`：什么都没改，`error.details.reason` 说明是哪种（2026-10-22 起有 `reason`）：

  | `reason` | 什么时候 |
  |---|---|
  | `restore_blocked` | 有任务在排队或运行、AI 正在改文档、AI 有计算没算完（`message` 说明在等什么）。恢复开头查一次，换库前再查一次；等它们结束再试 |
  | `backup_damaged` | 备份文件坏了（解不开或完整性检查不过）。2026-10-22 以前是 `400` |
  | `backup_newer` | 备份来自更新版本的程序，先升级再恢复。2026-10-22 以前是 `400` |

- `404`：没有这份备份。
- 同一时间只做一件事：正在备份或恢复时再点恢复，会排在后面等。
- **恢复中**（2026-10-28 起）：从检查备份、存恢复前备份到换库的这段时间里，上传、建任务、原地重跑返回 `409`
  `restore_in_progress`，什么都不写（以前这几秒里建出来的会被换库盖掉，留下没有记录的任务目录和上传文件）。恢复开始前已经
  在建的先做完，换库前那次复查照样挡得住它们建出来的任务（`restore_blocked`）。AI 对话写消息、改术语表、改书的元数据这些
  别的写入不挡，这几秒里写的会随换库丢掉。
- **开着同步时**：恢复后这台电脑换一个新设备号，备份里的旧内容不会当成新改动发出去（不会
  盖掉别的设备上更新的内容）；下一轮同步从头读同步文件夹，备份之后已经同步出去的改动（包括
  这台电脑自己发出去的）都会收回来。备份之后没来得及同步出去的改动随恢复丢失。

## `DELETE /api/v1/backups/{id}`

删掉一份备份，返回最新的状态（同 GET）。`404`：没有这份备份。
