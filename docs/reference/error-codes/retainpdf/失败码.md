# RetainPDF 失败码

任务失败时 `failure`（`GET /api/v1/jobs/{job_id}/reports/failure`，任务详情里也有）的 `failure_code` 取下面这些值。回到[错误码索引](../README.md)；失败结构的字段见[失败结构](../../../api/08-调试诊断/01-失败结构.md)。

分类有两个产生方：

1. **Python 流水线**：[`structured_errors.py`](../../../../backend/pipeline/retainpdf_pipeline/foundation/shared/structured_errors.py) 的 `classify_exception`。worker 把异常归类后打一行 `structured failure json: {...}`，Rust 解析到就直接用。只有包在 `run_with_structured_failure` 里的代码才会出这一行，import 期崩溃没有结构化失败。
2. **Rust 兜底**：[`job_failure.rs`](../../../../backend/packages/retainpdf-core/src/job_failure.rs) 的 `classify_job_failure_inner`，没有结构化失败时按错误文字和日志尾巴匹配；OCR 阶段失败时按 OCR 诊断里服务商的分类（`OcrErrorCategory`）给失败码：鉴权、额度、文件不合规、参数不对、限流、服务商处理失败（[`job_failure_structured.rs`](../../../../backend/packages/retainpdf-core/src/job_failure_structured.rs)、[`job_failure_ocr_provider.rs`](../../../../backend/packages/retainpdf-core/src/job_failure_ocr_provider.rs)）。

「续跑起点」「恢复提示」来自恢复目录 [`job_failure_catalogue.rs`](../../../../backend/packages/retainpdf-core/src/job_failure_catalogue.rs)（`auth_failed` 在翻译阶段失败时从翻译续跑，见目录里的 `STAGE_OVERRIDES`）；前端只渲染后端给的 `summary`、`recovery_hint`。「上游大类」是[服务商错误码](../README.md#大类)里对照到这个码的大类。
