# 阅读页：悬停框的「改」「复制」放哪

2026-11-20 改，用户原话：「设计一个算法，将"改"，"复制" 放到区域外面去，这样才不会挡住阅读」。
以前只看左右页边，页边不够 64px（双栏论文、窄页边）就放进框里右上角，正好压在第一行字上。

## 做法：候选位置 + 碰撞检测

代码在 `packages/reader/src/pdf/hover-tools-placement.ts`（纯函数，`placeHoverTools`）。

按顺序列出工具条可以放的地方，每个算出它实际占的方框：

1. 框外右边、左边，竖排完整按钮（「改」「复制」）；
2. 同上，只有图标的小按钮（✎、复制，24px），给页边窄的论文；
3. 框外上方一行（先完整按钮，再图标版）；
4. 框外下方一行（同上）；
5. 图标版伸出页边几像素（伸进书页外 8px 的留白，不出横向滚动条）；
6. 段尾：框里最后一行右边空着的地方，整条工具条和框里的字都不碰才算。

然后和页上的东西比：

- 第一轮：框外、不碰任何字、也不进别的块的范围，第一个合格的就用；
- 第二轮：框外、只要不碰字（可以落在别的块的空白里）；
- 第三轮：段尾；
- 都不合格：在图标版里挑压到字最少的（按面积算）。

「字」是文字层（`.textLayer span`）里的字，不只是块的范围：页眉、页边印章不在任何块里，译文也常常溢出原文块。
竖排的页边印章（又高又窄，比如 `Downloaded from …`）不算字。缩小看的时候一行字比工具条还矮，所以段尾要拿整条工具条去查，
不能只看最后一行右边空不空。

## 其他

- 图标版的名字在悬停提示和读屏里；「改过几次」放进「改」的提示里。复制成功图标变勾、失败变叉。
- 工具条在框外上方或下方时，鼠标在工具条那一小块范围里不换框（`inHoverToolsZone`），斜着移过去不会先碰到别的块。
- 实测：接开发栈把一页的每一块都悬停一遍，统计放在哪、有没有压到这一块的字。正常大小（1440 宽对照）论文 33 块、书 8 块，
  全在框外，压到这一块字 0 次；820 宽（缩到 50%）95 块，压到这一块字 0 次，两栏间只剩几像素时由最后一轮挑压字最少的位置。
