# 协作与边界

这篇讲后端协同开发怎么不把结构写乱。

## 模块职责

本文里的 `services/<领域>/…`、`job_runner/*`、`models/*` 是逻辑路径，真实代码在独立的包里：`services/<领域>` 在 `backend/packages/retainpdf-<领域>/src`，`job_runner` 在 `backend/packages/retainpdf-runner`，`models` 在 `backend/packages/retainpdf-core`。

- `routes/*`
  - 只做 HTTP adapter
- `services/jobs/*`
  - 做任务查询、展示、创建、恢复、控制
- `job_runner/*`
  - 做真实执行链
- `models/*`
  - 只放 DTO 和持久化模型

## 依赖方向

默认方向：

- `routes -> services -> job_snapshot_factory / job_launcher / runtime_gateway / db`
- `job_runner -> db / config / runtime state`
- `models` 不反向依赖 `routes` 或 `services`

## AppState 约定

`AppState` 只放在真正需要运行态协同的地方：

- 路由入口
- 生命周期入口
- 运行态执行层

如果只需要：

- `&Db`
- `&AppConfig`
- `&Path`
- `&RwLock<HashSet<String>>`
- `&Arc<Semaphore>`

就不要再传 `AppState`。

## 常见反模式

- 在 route 里拼业务 view
- 在 models 里做文件系统读取
- 在 job_runner 里继续乱传 `AppState`
- 把 file layout 当公开 API 契约

## 接口清单与模块依赖（防止越改越乱）

- **接口清单**：`backend/api/docs/routes.txt` 列出全部路由（方法、路径、网站账号的访问策略），由
  `src/api_tests/route_manifest.rs` 从接口登记表（`app/router/**` 里的 `crate::endpoints!` 表）生成，接口目录 `docs/api/00-接口目录.md` 也是同一次生成的。增删接口、改访问策略后这个测试会红；确认是有意的，
  用 `UPDATE_ROUTES=1 cargo test -p retainpdf-api --lib route_manifest` 重新生成，变化会出现在提交的 diff 里。
  加接口之前先看能不能用已有的：读任务里已有的数据走 `GET /jobs/:id/data/:dataset`（在
  `contracts/job-data.v1.schema.json` 登记数据集），不要再单开读取接口。
- **services 按 8 个领域分目录，每个领域一个门面**（已经拆成独立包的领域见 `EXTRACTED_DOMAINS`，现在有账号 `retainpdf-accounts`、文件 `retainpdf-files`、术语表 `retainpdf-glossaries`、入口 `retainpdf-ingest`、任务 `retainpdf-jobs`、书库 `retainpdf-library`、平台 `retainpdf-platform`、服务商 `retainpdf-providers`）：`accounts`、`providers`、`ingest`、`files`、`jobs`、
  `library`、`glossaries`、`platform`（`ai` 领域 2026-11-03 删了），一个领域以后拆成一个包。领域包的 `lib.rs` 是唯一的门面，子模块私有，
  领域外写 `crate::services::<领域>::<子模块>::…` 编译不过。`check_service_domains` 不许在 `services/` 下另开
  顶层模块，`check_domain_facades` 不许把子模块改回 `pub`。
- **领域之间只能往下依赖**：允许的方向登记在 `check_architecture.py` 的 `ALLOWED_DOMAIN_DEPENDENCIES`，
  多出一条或者有一条没人用了都会报错（`check_domain_dependency_direction`）。`check_service_dependency_cycles`
  按领域建依赖图，出现任何环也报错，`KNOWN_SERVICE_CYCLE_EDGES` 是空的。两个领域都要用的东西往下放。
- **按编号读出任务和错误类型在 services 下面一层**：独立的包 `retainpdf-api-base`
  （`backend/packages/retainpdf-api-base`），里面是 `job_loading`（`load_supported_job`、`load_job_or_404`，以及合并阅读的虚拟任务）
  和 `error`（`AppError`）。`retainpdf-api` 里照旧写 `crate::job_loading`、`crate::error`（`lib.rs` 转出口）。
  它是单独的包，用不了 `services`、`routes`、`AppState`，由编译器保证。以后拆出去的领域包都往下依赖它。

## 加路由时的访问控制（多用户）

网站账号能访问什么由 `enforce_access` 中间件执行：路由策略写在接口登记表里（`backend/api/src/app/router/*.rs`），
路径参数和请求里资源编号的归属规则在账号包的 `backend/packages/retainpdf-accounts/src/access.rs`。
新加路由要过三关，都有测试兜底：

- **路由策略**：登记表里每条写明 `public` / `signed` / `admin` / `closed`，中间件直接查表
  （`app/endpoints.rs` 的 `route_policy`）；没登记的路由当关闭。2026-10-17 以前是账号包按地址前缀判断，已删掉。
- **路径参数**：每个参数名都要在 `classify_param` 里分类（`Owned` 核归属 / `Nested` 父资源已核过），
  没分类的请求一律 403。`every_route_param_is_classified` 会扫全部路由（它要读 rust_api 的路由源码，放在 `api_tests/route_access.rs`）。
- **路径里没有资源编号的开放路由**（列表、新建、搜索……）：中间件替它做不了隔离，处理函数必须按
  `principal.owner_filter()` 过滤或记 `owner_id`，并把路由登记到 `SIGNED_WITHOUT_OWNED_PARAM`、写明怎么
  隔离的；`every_signed_route_without_owned_param_is_reviewed` 会扫全部路由（登记表和测试同在 `api_tests/route_access.rs`）。

内部错误用 `AppError::internal(...)` 时可以写清楚原因（含路径、底层报错）：它只进日志，响应里只有编号。
要让调用方看到的原因，用带稳定错误码的领域错误或 `bad_request` 这类。

## 稳定边界

- `provider raw`、`normalized`、`published artifact`、`download API` 是四层不同边界
- `failure` 是正式失败真源
- `runtime.stage_history` 是主时间线真源
- `failure_diagnostic` 只保留兼容投影

## 大模型权限约定

大模型可以参与语义层修复，但不能接管结构层、布局层或产物层。

### 允许做的事

- OCR 噪声的语义归一化
  - 例如明显的 LaTeX 误识别修正
  - 例如把 `\\langlen` 这类稳定可规则化的噪声收敛成确定结果
- 翻译草稿与标题候选
- 轻量分类
  - 标题 / 脚注 / 正文的语义判断
  - 是否需要特殊翻译规则的候选判断

### 只允许给建议，不允许直接落地的事

- 是否缩进
- 是否微调行间距
- 是否调整字号
- 是否改变段落布局
- 是否修改遮盖 / 删除策略

### 明确禁止的事

- 改 bbox
- 改分页
- 改原始结构
- 改任务状态
- 改产物路径
- 绕过确定性规则直接重写渲染输入

### 落地原则

- 大模型输出“候选修复”
- 确定性规则层最终生效
- 只要能稳定规则化的内容，优先进入预处理或归一化层，不要依赖模型临场猜测
- 结构层、布局层、产物层必须保持可测、可回放、可复现

## 提交前检查

改到 `backend/api` 时，至少做对应检查（命令从仓库根目录执行）：

- `cargo check --manifest-path backend/api/Cargo.toml --quiet`
- 改了 presentation / query，补测试
- 改了 runner / lifecycle，补测试
