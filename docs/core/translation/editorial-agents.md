# 翻译编辑部：多 agent 编排（设计草案）

状态：设计已定（2026-10-09），未开工。替换「精翻」档现在的直线流水线；「普通」「统一术语」两档不变。

## 为什么要改

现在的精翻是一条直线，每步只走一次：

```text
术语预扫 → 风格指南 → 翻译 → 检查 → 挑错 → 修改（一轮）→ 排版
```

2026-10-09 在《Theorems of Molecular Quantum Mechanics》（34 页、330 块）上真跑了一次，问题都出在编排上：

- 后面发现的问题回不到前面：一块初翻漏了两句、把 $D_e$ 写成 $R_e$，只能交给「定点修改」打补丁，补丁碰到公式占位符被拦，成品里还是错的（旧的普通译文这一块反而是对的）。
- 没人审术语表：预扫收了 367 条，夹着人名、期刊、文献书名，全被锁定；精修照着把参考文献里的人名音译、把「J. Chem. Phys.」改成「《化学物理杂志》」。
- 各说各的：术语表定「位力定理」，挑错模型改成「维里定理」，全书两种叫法混用。
- 问题一律打补丁：没有「整块重翻」「交给人」这样的分流。

## 原则

1. **分工**：七个角色，各管一摊；**只有指定角色能改指定的东西**（术语表只有术语专员能改，译文只有译者和修订能改，且都要过质检）。
2. **通过台账协作，不直接对话**：每件事是台账里的一条记录，谁负责谁接，处理结果写回台账。不做多个模型自由讨论（成本数倍、还爱往译文里加东西）。
3. **裁判是确定性质检，不是模型自评**：每次改动重新检查，只能变好不能变坏。
4. **有界**：每块的修改 / 重翻次数有上限，超了交给人；花费默认不设上限，但开始前给估算、运行中实时记账，并且可以随时叫停。
5. **可续跑**：台账落盘，中断后从台账恢复，已经定稿的不重做。

## 角色

| 角色 | 做什么 | 读 | 能改 | 并行 |
|---|---|---|---|---|
| 主编（模型） | 拆章节、派活、看进度、裁决争议、决定何时定稿；在规则框内做决定 | 台账摘要（不读全文） | 任务分配、裁决 | 1 |
| 术语专员 | 预扫术语并审定：分成专业术语 / 人名 / 机构 / 文献 / 通用词，定每类怎么处理；回答术语疑问；处理改术语的申请 | 原文、术语表、疑问 | **术语表**（唯一） | 1 |
| 译者 | 按章节翻译；术语拿不准提问，不自己定 | 原文、冻结的术语表与风格指南 | 自己那一节的译文 | 多个 |
| 审校 | 审已译完的章节，只报准确性问题，必须引用原文和译文的原句 | 原文、译文、术语表、质检结果 | 只能开问题单 | 多个 |
| 修订 | 接问题单，决定局部改还是整块重翻，或说明为什么不改 | 问题单、原文、译文、术语表 | 被指到的块的译文 | 1–2 |
| 排版 | 处理排不下的块：出几个短版本，挑放得下且意思不变的 | 排版报告、原文、译文 | 被指到的块的译文 | 1 |
| 质检（程序） | 每次改动后检查：数字、占位符、术语、漏译、引用、标点、排版 | 原文、译文、术语表 | 无（只判） | — |

术语专员定的处理方式：专业术语锁定译法、首次出现加括注；人名 / 机构 / 期刊 / 文献保留原文、不锁定成中文；通用词不进术语表。

## 台账

`<任务目录>/editorial/ledger.jsonl`（只追加）+ `state.json`（当前状态快照，可由台账重放出来）。每条记录：`id`、`from`、`to`、`at`、`refs`（关联的块、章节、记录）、`kind` 与内容。

| kind | 谁发 → 谁接 | 内容 |
|---|---|---|
| `section.assign` | 主编 → 译者 / 审校 | 哪一节（页范围、块列表） |
| `term.query` / `term.answer` | 译者 → 术语专员 | 某个词怎么译；答案进缓存，同一问题只问一次 |
| `term.change_request` / `term.decision` | 审校、修订 → 术语专员 | 建议改术语表；术语专员定，定不了交主编 |
| `issue.open` | 审校、质检 → 修订 | 块、类别、严重程度、原文片段、译文片段、说明 |
| `issue.resolve` | 修订 → 台账 | `patched` / `retranslated` / `wontfix`（附理由）；附质检结果 |
| `issue.escalate` | 修订、主编 → 人 | 超过次数或判不了，进「待人看」 |
| `dispute` / `ruling` | 任一角色 → 主编 | 互相矛盾（如审校与术语表），主编裁决 |
| `layout.request` / `layout.resolve` | 主编 → 排版 | 排不下的块 |
| `section.status` | 主编 | 节的状态变化 |

## 流程

```text
准备    术语专员：预扫候选 → 审定分类 → 冻结术语表；风格指南
          └─ 主编过目后冻结（可选：交给人确认）
翻译    主编按章节派给译者（并行）；译者遇到术语问术语专员；每节译完质检
审校    每节译完就交给审校（并行），开问题单
修订    修订按问题处理 → 质检 → 不过就再试，到上限交给人
排版    渲染 → 排版报告 → 排版 agent 处理排不下的块 → 再渲染
收尾    主编看全书台账：未决争议、待人看清单 → 定稿，输出编辑报告
```

各节独立往前走：第 3 节在审校时第 5 节可以还在翻译。

### 一块译文的状态

```text
待译 → 已译 → 已检查 ─干净→ 定稿
                   └有问题→ 修订中 → 已检查 …（最多 N 次）→ 待人看
```

修订的分流（修订 agent 在规则框里选，不越界）：

| 问题 | 默认处理 |
|---|---|
| 漏译、数字 / 公式丢失（严重） | 整块重翻，把「上次漏了什么」作为反馈带上 |
| 错译 | 定点修改；改不动（碰占位符、重复片段）就整块重翻 |
| 术语不符 | 按术语表规则直接改，不调模型 |
| 英文引用标签没译 | 规则直接改（已有） |
| 与术语表冲突的审校意见 | 不改，转术语专员 / 主编 |
| 排不下 | 交给排版 |

## 硬规矩

- 锁定术语只有术语专员能改；任何改动若换掉了锁定术语，质检直接判不过。
- 审校的问题单必须能在原文和译文里逐字找到引用的片段，找不到的丢掉。
- 修订每次改动都要过质检，问题数只能减少；新增问题即回滚。
- 每块最多改 2 次、重翻 1 次（可配置）；超了交给人。
- 参考文献、人名、期刊等「保留原文」类内容，任何角色都不改成中文。

## 并发与锁

- 译者、审校按章节并行，块级请求在节内并发（沿用现在的并发数设置）。
- 同一块同一时间只有一个角色持有写锁；写回走现有的修订写回接口（`revise_translation_item`），留修订历史。
- 主编和术语专员单实例，处理台账里排队的记录。

## 花费

- 估算（待实测校准）：普通翻译的 3 倍左右——翻译 1 倍、审校约 0.6 倍、修订约 0.3 倍（按问题量）、术语预扫与审定约 0.4 倍、主编按章节决策占比很小。
- 2026-10-09 实测参考：精修（挑错 + 修改）330 块约 20 万 token。
- 默认不设上限；开始前按页数给估算，运行中台账实时记账，可以随时叫停，停下时已定稿的部分保留。

## 各角色的模型

每个角色（主编、术语专员、译者、审校、修订、排版）各有一套模型配置：服务商、模型、接口协议（OpenAI 格式 / Anthropic 格式）、思考深度（自动 / 关闭 / 浅 / 中 / 深 / 最深）。不单独配的角色沿用翻译模型。建议的默认思考深度：

| 角色 | 思考深度 | 理由 |
|---|---|---|
| 主编 | 深 | 决策少、影响大 |
| 术语专员 | 中 | 审定分类要判断，量不大 |
| 译者 | 自动 | 量最大，翻译用不着思考 |
| 审校 | 中 | 找错要推理 |
| 修订 | 浅 | 定点改，范围已经划好 |
| 排版 | 关闭 | 只是缩写 |

协议与思考深度已经是任务参数（`translation.api_protocol` / `translation.thinking`，见 `docs/api/04-翻译/01-翻译参数.md`）和 `~/.retainpdf` 的服务商配置项；发请求时可以按调用显式指定，所以同一个模型可以给不同角色配不同的思考深度。
