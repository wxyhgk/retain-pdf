# Security

Purpose: Trang nay mo ta security boundaries da thay trong implementation: API key auth, credential handling, path safety, CORS/proxy behavior, desktop local key, and external provider secrets.

## Responsibilities

Security model hien tai la API-key based local/private deployment model. Rust protects `/api/v1/*` with `X-API-Key`. Frontend sends configured key. Desktop uses a local fixed key shared by frontend/Rust/AI service. Python workers receive secrets through env refs. retainpdf-ai validates API key and uses Rust API for data plane.

## How It Works

Rust requires an API key source (`auth.local.json` or `RUST_API_KEYS`) in [`config/auth.rs`](../../../backend/rust_api/src/config/auth.rs). The router applies auth middleware to API route groups in [`router.rs`](../../../backend/rust_api/src/app/router.rs). Frontend includes `X-API-Key` from runtime config in [`runtime.ts`](../../../frontend/src/js/config/runtime.ts).

Secrets for workers are not meant to be stored as plain spec values when possible. Translation stage specs use `credential_ref: env:RETAIN_TRANSLATION_API_KEY`; provider stage specs use provider credential env refs when configured. [`process_runner.rs`](../../../backend/rust_api/src/job_runner/process_runner.rs) has tests/logic around env injection and redaction.

retainpdf-ai receives the same API key through Rust proxy. Rust forwards `X-API-Key` to `/v1/ask` in [`ai_proxy.rs`](../../../backend/rust_api/src/routes/ai_proxy.rs), and retainpdf-ai validates it in [`app.py`](../../../backend/ai_service/retainpdf_ai/app.py).

## Configuration

| Runtime | Secret/config |
| --- | --- |
| Docker app | `auth.local.json`, `RUST_API_KEYS`, provider/LLM envs |
| Docker web | `FRONT_X_API_KEY` embedded into browser runtime config |
| Desktop | local `retain-pdf-desktop` key generated by Electron env |
| Python translation | `RETAIN_TRANSLATION_API_KEY` env ref |
| retainpdf-ai | `RETAIN_AI_API_KEYS`, `RETAIN_AI_RUST_API_KEY`, LLM key env/per-request |

## Failure Modes

Wrong frontend key returns 401. Publishing Docker web with a real model/provider key in `FRONT_*` exposes that key to the browser runtime; use only deployment-appropriate defaults. AI service down returns 502. Unsafe artifact paths should be rejected by Rust storage path handling or retainpdf-ai safe path checks. CORS is permissive in Rust router, so public exposure should be controlled at deployment/proxy/network layer.

Architectural interpretation: The codebase appears optimized for local/private deployments and desktop rather than internet-exposed multi-tenant auth. Do not expose `/api/v1/*` publicly without an external auth/proxy model.

## Extension Points

For stronger auth, replace or wrap `auth::require_api_key`, update frontend runtime config and Docker/Electron env injection. For secret redaction, add tests around stdout/log persistence. For new external calls, avoid putting secrets in persisted specs and prefer env credential refs.
