# RetainPDF 渲染优化变更总结

## 1. 优化目标

本次优化主要解决翻译后 PDF 的混合渲染排版问题。

核心目标是：

- 避免英文替换为中文后，正文被过度压缩到很小字体。
- 避免文字、公式、列表项互相重叠。
- 对高风险页面自动切换到更合适的 FLOW 重排策略。
- 在保持原 PDF 视觉背景的同时，让翻译内容更完整、更可读。

## 2. 总体技术路线

整体方案从“硬塞原框”改为“先检测风险，再选择渲染方式”。

流程如下：

1. 先扫描翻译后的页面数据，判断页面是否存在排版风险。
2. 如果风险较低，继续使用原 overlay 覆盖渲染。
3. 如果风险较高，改用 Typst visual 背景渲染。
4. 对高风险页面执行 FLOW 重排。
5. 对短公式行、列表项、相邻小块进行本地区域合并。
6. 如果本地区域仍不够，受控降低字号，但不再无限压缩。

## 3. 阈值检测方案

新增了渲染风险扫描逻辑。

扫描对象是翻译阶段生成的页面 JSON 数据，包括：

- 文本块坐标。
- 文本长度。
- 字号。
- 公式数量。
- 文本框高度。
- 相邻块距离。
- 文本与公式、文本与文本的重叠情况。

主要判断指标：

- 字号过小：说明原框内强行压缩，阅读体验差。
- 文本高度溢出：说明内容放不进原始 bbox。
- 相邻块碰撞：说明上下两个块可能重叠。
- 公式密度过高：说明页面对排版更敏感。
- 文本/公式重叠：属于高风险或硬风险。

技术方法：

- 每个块计算一个风险分数。
- 每页汇总风险分数。
- 页面分为 low、high、extreme 等级。
- 高风险页面进入 FLOW rebuild。
- 风险报告写入 `render-risk-report.json`，便于后续定位问题页。

## 4. 渲染模式切换

原本一般做法是把中文压缩进英文原框。

本次优化后改为：

- 先尝试正常 overlay。
- 如果检测到高风险，不再继续硬压字体。
- 自动升级为 Typst visual 背景渲染。
- 背景保留原 PDF 的视觉内容。
- 翻译文本重新按更合理的版面输出。

这样避免了“字体越压越小，但仍然放不下”的情况。

## 5. FLOW 重排策略

FLOW 重排不是简单把内容丢到页面空白处。

当前策略更偏向“本地重排”：

- 优先保持中英文位置大体对应。
- 尽量在原始栏位、原始区域附近调整。
- 对连续正文进行自然换行。
- 对无法放入原框的内容，拆分到后续 FLOW 页面。
- 对短公式行、小列表项，优先合并相邻块形成更大本地区域。

这种方式比单纯覆盖渲染更稳，也比全文重新排版更接近原文结构。

## 6. 短公式行和列表项优化

这部分是后续重点优化点。

问题表现：

- 公式行高度很小。
- 中文翻译后需要更多行。
- 原框强行渲染会造成重叠、截断或逻辑错位。
- 例如 `(a)`、`(b)`、`(c)` 本应同级，但渲染后挤在一起。

优化方法：

- 检测短公式行。
- 检测相邻列表项。
- 将上下相关的小块合并成一个本地 FLOW group。
- 合并后重新估算文本所需高度。
- 如果高度仍不够，继续吸收同列紧邻块或空白行。
- 换行边界保留，避免 `(b)` 被接到 `(a)` 后面。

新增限制：

- FLOW group 不再从前一个已经重排过的 FLOW group 继续回收空间。
- 避免多个 FLOW group 之间二次重叠。
- 字号最低控制在 9pt 左右，避免回到不可读的小字。

## 7. 页面目录和页码映射

FLOW 重排可能导致页数增加。

因此同步优化了页面映射逻辑：

- 原始页和渲染页建立映射关系。
- FLOW continuation 页面仍能追踪来源页。
- 后续目录、页码、对照阅读可以基于映射关系处理。

## 8. 日志与诊断

本次优化增加了更完整的诊断信息。

重点日志包括：

- 哪些页面触发了风险扫描。
- 哪些页面进入了 FLOW rebuild。
- 哪些页面使用了 Typst visual 背景渲染。
- 是否产生 continuation 页面。
- 风险报告路径。

常用诊断文件：

- `pipeline_summary.json`
- `render-risk-report.json`
- `render-only.stdout.log`
- `rendered/typst/.../book-background-overlay.typ`

这些文件可以直接定位某个问题块为什么没有正确排版。

## 9. 主要涉及文件

核心新增或修改位置：

- `services/rendering/analysis/risk/`
  - 风险扫描、阈值、报告模型。

- `services/rendering/workflow/executor.py`
  - 渲染流程中接入风险扫描和模式切换。

- `services/rendering/workflow/context.py`
  - 保存渲染诊断信息。

- `services/rendering/workflow/modes.py`
  - 支持 FLOW rebuild 触发后的模式升级。

- `services/rendering/layout/page_specs.py`
  - FLOW 重排核心逻辑。
  - 短公式行合并。
  - 本地区域扩展。
  - 受控字号回退。

- `services/rendering/output/typst/book_renderer.py`
  - Typst visual 背景渲染接入。

- `services/rendering/output/typst/emitter.py`
  - 渲染页面规格输出。

- `services/rendering/document/page_map.py`
  - 原始页与渲染页映射。

- `devtools/tests/rendering/`
  - 风险扫描测试。
  - FLOW rebuild 测试。
  - Typst/source cleanup 回归测试。

## 10. 测试验证

已覆盖的测试重点：

- 高风险页面能被识别。
- FLOW rebuild 能正确触发。
- 行内公式不会被拆坏。
- 短公式行会合并成更大的本地区域。
- `(a)`、`(b)`、`(c)` 等列表边界能被保留。
- FLOW group 不会互相抢占空间。
- Typst 源清理 fallback 不会回退到错误路径。


## 11. 当前效果

优化后整体表现：

- 大部分字体不再被压到过小。
- 公式密集页更稳定。
- 短公式行的内容完整性更好。
- 列表项逻辑关系更清楚。
- 原文和译文位置仍基本对应。
- 对照阅读体验明显提升。

## 12. 后续可继续优化方向

后续可以继续加强：

- 更精细地识别列表层级。
- 对公式行使用更稳定的独立公式排版策略。
- 对表格附近的文本块增加特殊规则。
- 对图片上下的空白行做更准确的可用空间判断。
- 在前端增加问题页诊断展示，但当前不是必须。
